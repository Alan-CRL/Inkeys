# 实现及验证计划

本轮进入实现。后续在当前 `refactoring/draw` 实现，长文自动注入有 32 KiB 上限；实施与检查时从磁盘按章节读取完整 input-and-ink 规范及 research 中的调查，尤其是笔锋和实机验收部分。实施前复核工作树及与第二步共享的 Draw3 源文件。

**分工（2026-11-20 用户指定）：** 代码由 Codex `gpt-6.2-astra`（High，`service_tier=default`，workspace-write）按下列步骤逐步编写，Astra 只写代码；每步检查点由 `gpt-6.2-sol` 只读验证；问题修复、构建与测试由 Claude 完成。全部完成后 Claude 与 Sol 各做一次完整独立验证。重点防范 Astra 偷懒、未达要求和超出要求的改动。全部完成后再提交，不 push。

1. 核对双轴与直接角的金样本，修正生产 RTS 解码和对应测试预期，建立现有后端基线。
2. 在配置与 Host 中实现首选／实际后端状态；完成 Pointer producer、标准属性转换、鼠标去重、生命周期清理和 Win7 动态装载。接通“性能”选项与实际后端警告。
3. 将 Pointer + DM 的变换与 Win11 RTS 模式下触控板消息识别出的平移分别接入白板“拖动”。逐系统覆盖 Win8.1/10 的 RTS 禁用、WM_POINTER + DM 启用，以及 Win11 的 WM_POINTER + DM 和 RTS + 窗口注册两种启用组合。用初始化调用顺序记录覆盖直接启动和 Pointer 失败后回退 RTS，确认 RTS 就绪前未创建或激活任何触控板导航入口。逐个启用组合验证惯性开／关的快速松手、滑行中关闭惯性，以及中途切回绘制：停止惯性，丢弃已排队的旧位移，确认双指不误画、第一笔正常。另测设备热插拔和窗口退出，记录失败原因。
4. 在“绘图效果”加入总开关与设备子项，接入普通笔 L0、终态及保存。按调查的固定轨迹测试 65% 几何目标、停笔回宽、轻重压变化和非硬件压感回归。
5. 按下述层次记录验证结果，单列缺少设备或系统的项目。

## 验证

- 配置往返、旧配置、后端选择矩阵、RTS 方向、Pointer mask／时钟／坐标、导航准入、重复终态及笔锋几何采用确定性用例。目标构建用现有 `InkeysRepo.sln`，定位 ARM64 原生 MSBuild，同一 PowerShell invocation 先规范化 PATH，再以 `/p:Configuration=Debug /p:Platform=ARM64 /nr:false` 构建，至少预留五分钟。
- 运行 `Build/ARM64/Debug/InkeysHeadlessTests.exe --no-window` 及相关已有无窗口探针，核对退出码。测试路径与实际版生产入口一并核实。不得将仿真结果写成设备验收。
- 实机记录系统构建、设备、驱动、所选和实际后端。重点是 Win8.1 PTP 的命中到 transform、Win10 Pointer + DM、Win11 RTS 同窗共存及真笔端到端延迟，另验教师大屏掌擦、压力轻重、旋转／双屏和普通鼠标。
- Win7 在本步只核对兼容加载、RTS／鼠标输入；第二步的 Win7 呈现实机测试继续由第二步追踪。GUI 和真机测试按用户之后的安排进行。
