# 第4步 Draw3 输入后端、白板触控板拖动与实时笔锋

## 目标与排期

在 `refactoring/draw` 上规划同一条 Draw3 绘制链的可选输入、白板双指平移与普通笔笔锋。第四步先于第三步多画布／窗口架构实施。第二步保留开启，等待 Win7 实机验证；该验证不阻塞本步规划。完整字段对照、实机矩阵和计算示例见 [11 月 19 日调查](<research/第4步 Inkeys3_WM_POINTER输入与白板触控板拖动调查_20261119.md>)。11 月 12 日路线图用于历史对照，产品规则采用本次确认的版本。

## 产品要求与验收

| 项目 | 可观察的验收结果 |
|---|---|
| 性能 → 输入方式 | 提供自动（推荐）、RealTimeStylus、WM_POINTER、鼠标兼容输入。手动选择直接尝试所选后端（2026-11-20 修正：大屏触控模式不覆盖手选）。自动：大屏触控模式选 RTS；桌面交互模式在 8.1、10 选 Pointer，其余（Win7、8.0、11）选 RTS。升级缺项按自动，Win7 不可手选 Pointer（选项置灰）。任一首选失败按 RTS（扩展属性）→ RTS（基础 X/Y）→ WM_POINTER → 鼠标兼容输入回退（跳过已试项），并在“软件调试 → 画布初始化输出”的警告条位置显示输入方式回退警告。输入方式与大屏模式切换均**重启后生效**：后端只在 Host 启动时解析一次。设置项说明固定为面向用户的“决定设备消息的输入方式，一些选项可能与白板的触控板手势冲突。”，不显示当前后端或重启提示。 |
| RTS 姿态 | 验证自然方向四向、旋转屏、直立和倒置笔。双轴路径正 Y 的 (0°, +45°) 产生 90° 模型方位；负仰角 −60° 对应 30° 倾斜幅度，与倒置信号独立。 |
| Pointer 绘制 | 笔压、姿态、触摸面积、设备身份与终态正确进入各自消费者。缺失和真实零可区分；掌擦、笔尾、鼠标和多触点不重复或卡住。双屏、高 DPI 和后端切换后首笔正确。 |
| 白板拖动 | 原生双指平移仅在白板“拖动”生效，要求 Win8.1+ 和精确式触控板。按实际绘制后端启用：Win8.1/10 + RTS 关闭，Win8.1/10 + WM_POINTER 启用 DM；Win11 + WM_POINTER 启用 DM，Win11 + RTS 在 RTS 就绪后启用窗口级触控板消息。每个启用组合都接入白板现有的触控板拖动惯性：开启时快速双指拖动松手可续滑，关闭时仍可拖动、松手即停。各组合分别验收：选中白板“拖动”时双指可横纵平移；在手势或惯性中切回绘制后，白板立即停止平移，后续双指手势既不移动画布也不产生笔迹，笔和触摸屏仍可正常书写。Win11 共存失败时保持 RTS，报告手势不可用。Win11 + RTS 路径本步实现：SDK 10.0.26100 未收录相关声明，按微软文档手写结构与原型、全部动态解析，并以系统实际导出为准（本机 26300 的 ninput 无 `ProcessPointerFramesInteractionContext2`）；缺任一项即保持 RTS 并报告手势不可用。 |
| 拖动提示 | 系统低于 Win11 且实际后端为 RTS 扩展或基础 XY 时，在“设置 → 绘制 → 白板”分区的“白板拖动惯性”上方显示 ⓘ「当前使用的是 RealTimeStylus 消息输入，不兼容触控板白板拖动。」覆盖手选、自动、大屏和失败回退。“白板拖动惯性”描述为“在白板拖动模式下，松开后继续滑动。可按输入类型单独调整。”；其上方常驻 ⓘ「白板的触控板手势需要 Windows 8.1 或更高版本及精确式触控板。」 |
| 绘制效果 → 实时笔锋 | 位于设置现有“绘制效果”分区，配置放在 `Drawing` 下，与“抬笔笔锋修正”互相独立。总开关下内联鼠标、触摸、笔，初始全部开启；关闭总开关保留子项，重启可恢复。落笔锁定本笔选择。真实压感逐点叠乘半强度笔锋，充分展开时尖端保留当地压力笔宽的 65%，停笔追上后回到 100%。模拟模式保持原曲线，关闭笔锋仍有原有笔宽变化。实时、定稿与重新载入一致。 |
| 延迟 | 同机同笔、等帧率／预测／采样策略下比较首墨、连续跟笔和末段，在空闲、窗口繁忙及 4K 下记录 p50/p95/p99 和漏帧。报告区分入口以后耗时和物理笔尖至显示的延迟。本步只在现有诊断日志中加入入口、发布、消费 QPC 及 Pointer `PerformanceCount`；统计工具与真机对比另行安排。 |

## 边界

沿用现有 HWND、协调器、Modeler 与呈现架构。此次不做第三步多窗口重构、白板缩放、绘制模式下触控板导航、其他工具的笔锋改造或第二步 ULW 收尾。Win8.1 的显式命中链、Win11 同窗共存和实机延迟是待验技术项，不能以无窗口测试代替。
