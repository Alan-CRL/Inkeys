# F-014 更新链范围修订与兼容合同

日期：2026-09-28。用户明确要求：本任务不增加更新包的发布者签名/来源认证；HTTP 与 HTTPS 更新都保留，HTTPS 失败后的 HTTP 回退必须可用；保留早期 Inkeys2 `old_name` 缺失时启动旧 `智绘教.exe` 等的回退。用户看过本任务此前的更新改动分类后表示其它修复基本可以，需做以上两处兼容调整。此前更新链改动暂不整批撤销，也不把“开源”写成来源认证证明。

## 本任务可保留的已做修复

- 下载/元数据的大小、写入和响应边界，ZIP 只提取指定 EXE 至应用生成的路径，不使用 ZIP entry name 落盘，不递归删除未知 installer 内容。
- `update.json` 与新 EXE 先暂存/校验再发布，替换旧 EXE 前准备备份，失败尽力回滚；路径和哈希格式校验仍保留。
- 更新 HTTP/HTTPS 可用性必须恢复到用户要求的兼容合同。HTTPS 校验证书与主机名，但失败可按固定源原有顺序回退 HTTP。HTTP 风险按用户范围选择记录，不在本任务新增签名 manifest、公钥、Authenticode 固定发布者或更换发布渠道。

## 旧 EXE 失败回退

- 有 `old_name` 时只接受安全的单文件 `.exe` basename，优先选主安装目录内确实存在的普通非 reparse 旧文件。
- `old_name` 缺失/不可用时优先 `智绘教.exe`，其次 `Inkeys.exe`，兼容早期 Inkeys2 不写当前文件名的更新指令；选择结果为空则不执行未知路径。
- 选择顺序用产品共用的纯 helper 和 no-window 测试证明；真实旧版更新/Office/Win7 与可写安装目录攻击面单独报告。不能因恢复旧名而重新允许目录穿越。

## 状态与边界

这是用户针对 F-014 的后续范围修订，优先于本任务初版“禁 HTTP/必须发行者认证”的建议。当前代码仍处在修改中：HTTP parser 的 Headless 红三项已取得，另有 F-041 旧 ordinal 测试并行红三项，不能混算。完成后需由独立 reviewer 复核更新链最终 diff，并以 Release/Win7 可达性单独记结果。更新包来源未独立认证是明确残余风险，按用户决定不在本任务强行实施或宣称已解决。
