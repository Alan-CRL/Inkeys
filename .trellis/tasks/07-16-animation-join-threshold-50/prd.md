# 统一动画批次加入阈值为 50%

## Goal

将 UI3 动画批次的统一重新加入上限由 70% 调整为 50%，使新状态只在当前过程前半段复用原截止时间；越过中间关键帧后改用完整的新批次，避免后半程改变布局时出现过快或重复收拢的视觉异常。

## Background

- `BarUiTimelineClass::CanJoin()` 当前默认上限为 `0.7`。
- 主栏布局变化与绘制属性加入主栏批次均使用该默认值。
- 主栏及换边动画的唯一中间关键帧位于线性时间轴 `0.5`。

## Requirements

- 将 `BarUiTimelineClass::CanJoin()` 的默认 `maxProgress` 从 `0.7` 改为 `0.5`，异常输入的兜底值同步改为 `0.5`。
- 保持边界语义为 `progress <= 0.5` 可以加入，`progress > 0.5` 必须创建新批次。
- 更新主栏与绘制属性相关注释，使其准确描述“前 50% / 后 50%”规则。
- 不修改动画基础时长、速度倍率、缓动曲线、关键帧位置或目标值计算。
- 保持修改文件原有 UTF-8 无 BOM 与 CRLF。

## Acceptance Criteria

- [x] 所有未显式传参的 `CanJoin()` 调用统一使用 `0.5` 上限。
- [x] 主栏布局在进度超过 50% 后发生变化时创建新批次，不再次继承旧换边关键帧。
- [x] 绘制属性在主栏批次超过 50% 后变化时使用完整独立过程；前 50% 内仍可加入并共享截止时间。
- [x] `InkeysRepo.sln` 的 `Debug | ARM64` 使用 ARM64 MSBuild 完整编译通过。
- [x] 构建产生的 tracked `Inkeys/PptCOM.dll` 不保留在最终差异中。

## Out of Scope

- 不重新设计动画时间轴或关键帧续接算法。
- 不调整任何动画视觉参数或设置界面。
