# UI3 自动脏区统一（主栏与翻页控件）

## Goal

把脏区从「各宿主手工登记」改为 UI3 统一、自动的机制：视觉对象登记一次，每帧根据最终绘制状态自动得出最小脏区。主栏渲染循环（主栏、More、绘制属性、形状/橡皮/撤回属性面板）与白板/PPT 翻页控件全部迁移到这套机制；画面与现状逐像素一致，不能因脏区过小出现残影或缺漏。

## 背景（用户 2026-11-18）

- 用户实机观察：主栏按钮、翻页控件、More 面板的脏区正确；绘制属性部分交互整块刷新；形状属性、橡皮属性及其二级展开、撤回属性的所有按钮悬停/点击都刷新整个面板。
- 根因（Codex 调查 + 主 Agent 读码）：UI3 按钮/图元只返回「是否变化」并提供可选回调，脏区的键、包络、登记时机由每个宿主手写——主栏在 `Bar.RenderLoop.cpp` 手工标脏（58 处 `MarkChanged`、72 处带键 `ChangeValue`），翻页控件另写 `Include()` 累计矩形，属性面板只上报「面板变了」，直接写值的视觉（每帧摆放、派生颜色等）没有任何回调。
- 用户要求：按钮已经封装，脏区应当与 UI 计算联动、自动得出；通过整体架构统一来修改，主栏与翻页控件一起迁移。

## Requirements

- R1 UI3 提供统一的自动脏区机制：视觉对象（按钮、Shape、超椭圆、SVG、文字、PNG、面板组、自绘内容）向登记表登记一次；每帧在动画与布局完成后、绘制前，自动比对最终绘制状态与上次成功呈现的状态，变化的对象登记「旧包络 ∪ 新包络」，成功呈现后才推进快照，失败重试不丢旧像素。
- R2 状态比对覆盖所有影响像素的属性（位置、尺寸、圆角、描边、颜色、透明度、按压缩放、文字、图标、材质、继承的组位姿/透明度等），不论该值由动画、直接写入还是每帧重新摆放产生；值未变不产生脏区。
- R3 面板/组：组的位姿、透明度、裁剪变化时，组内成员随之判定变化；面板开合与移动自然得到整块脏区，成员单独变化只得到成员脏区。
- R4 自绘内容（橡皮预览、粗细胶囊、精调拨盘、滑块、状态指示器、Logo、翻页主题预览等）以「自定义对象」接入：组件提供包络与输入摘要，不再在宿主散落手工标脏。
- R5 光影（主光、鼠标光）继续使用现有光影脏区计算，不纳入状态比对；结果与现状一致。
- R6 迁移主栏渲染循环全部内容（主栏、主按钮、More、绘制属性含取色器与连续控件、形状/橡皮/撤回属性、构造提示、底栏吸附指示、状态指示器）与翻页控件（`UI/PageControl/` 与 `Bar.Scene` 的页面表面），删除被取代的手工标脏代码。
- R7 不改变窗口尺寸/容量预留逻辑与状态指示器窗口约定（小图标不影响窗口大小，见 `rendering-and-ui.md`）。
- R8 遵守 UI3 分层：机制放 UI3（不得引用 Bar/PageControl），产品宿主只负责登记与坐标变换。

## Acceptance Criteria

- [ ] 形状、橡皮（含二级展开）、撤回属性每个按钮的悬停/点击帧：脏区只覆盖变化成员（含光晕/按压/边缘光外扩），不再等于整个面板。
- [ ] 绘制属性按钮与连续控件：脏区只覆盖实际变化的元素；光影变化帧保持现状。
- [ ] 主栏、More、翻页控件：迁移后脏区不大于迁移前（逐交互对比），画面一致。
- [ ] 局部脏区帧保留的画面与同状态整幅重画逐像素一致（自动化比较）。
- [ ] 新增自动化测试：逐按钮/控件断言脏区包含必需包络且不超过上限；UI3 登记表有 Headless 单元测试（比对、组传播、失败重试、出现/消失）。
- [ ] 35 golden 逐字节一致；第1步全量验证维持现有结果。
- [ ] 被取代的手工标脏代码已删除（主栏渲染循环与翻页控件不再有按对象手工 `MarkChanged`/`Include`，光影与窗口级例外除外，并在设计中列明）。
- [ ] 用户实机检查：开启脏区调试显示，各面板与翻页控件悬停/点击只闪变化元素；无残影、无缺边。

## Out of Scope

- 光影变化引起的脏区大小。
- 分层窗口只能提交单个脏矩形（`UpdateLayeredWindowIndirect::prcDirty` 限制，多矩形需第2步 DirectComposition）。
- 形状样式栏（选区覆盖层窗口）、白板窗口内其他 UI、设置窗口——后续可接入同一机制。
- 状态指示器窗口尺寸约定（保持现状）。
