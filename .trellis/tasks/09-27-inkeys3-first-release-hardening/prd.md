# Inkeys3 首次发布工程收口

## 约束

- 保持已有视觉、功能语义、输入样本、手感、最低系统要求和兼容分支；不得关闭效果、降低帧率/质量或增加可见延迟作为优化。未开放、Unsupported、NotReady 入口保持原 gate。
- 只改当前要求所需第一方代码，保留原编码与换行；不批量格式化、改第三方/生成文件、无关重构或擅自升级依赖。UI3 和 Draw3 的设备/线程所有权保持独立。
- 只读历史与远端查询可用；不覆盖用户编辑，不 stash、reset、clean、切换/合并分支。任务结束不自动提交或归档；Trellis journal/archive 默认自动提交，本任务若使用必须采用正式的 no-commit 方式。
- 仓库规则禁止默认启动应用/GUI 或 Computer Use。本次未另行授权 GUI 注入/真机手感测试；相关项必须标为需要人工/未验证，不能冒充 PASS。headless、静态、编译可继续。
- 产品取舍和平台支持声明不从旧代码猜测；已关闭入口不得自动打开。
- Win7 SP1 仅 KB2670838 是明确目标配置，不以额外补丁成立；Win7 不提供 DComp，透明链应安全落到 ULW。代码或构建证据不等于 Win7 真机通过。
- 用户明确报告目标 Win7 环境实测支持 FLIP_SEQUENTIAL；保留现有 FLIP，不引入 bitblt 或其他 swap effect 回退。微软通用文档的不同描述仅记录为证据冲突，不能覆盖目标环境实测。

## 总体验收标准

1. 七个子任务各有独立的 `prd.md`、`design.md`、`implement.md`、真实 JSONL context、验证与审查结论；父任务记录依赖、跨模块合同、状态与风险，规划独立 review 后才开始改代码。
2. R0–R7 均有可追溯证据。H0/HF 用 HEAD 加工作区指纹标识；HC/H2 来源与环境不可比时明确标为未验证。UI3、Draw3 分别记录场景、warm-up、至少三轮、原始数据、有效样本量、median/P95/P99、长帧、延迟和资源趋势。
3. 状态迁移表覆盖按钮、快捷键、PPT、配置恢复和异步回调；跨入口等价、重复调用、快速切换、取消与旧结果覆盖有生产逻辑回归。拆分/规范化必须有最小 diff 与同等行为证据。
4. UI3 和 Draw3 各有输入至成功 Present 的成本分布。优化后关键场景 median 不超过测量噪声以上的 5% 实质退化，P95 不超过测量噪声以上的 10% 实质退化；按每轮离散度判断，不用单次最好结果。已确认 Canary 回退应恢复，落笔与尾延迟不能被总分掩盖；缺乏可比性则保持未验证。
5. 审计集合逐 commit 记 SHA、双时间、父提交、分支/是否进入 H0、模块、diff 深度、当前映射、finding 和复验；精确报告总数、已审、待审及缺口。已确认严重崩溃、死锁、数据损坏、输入失效和高危可利用问题没有未处置项。
6. 崩溃捕获、自动重启、正常退出、主动重启与最后已提交数据恢复分别给结论。无 GUI 授权下，真实进程重启和视觉/笔输入体验列为人工门禁，不用函数存在或编译通过替代。
7. 按仓库实际配置构建完整 `InkeysRepo.sln` 的 Debug|ARM64 和 Release 路径，运行适用 no-window、Draw3、PptCOM 测试，检查资源与产物。构建、运行、兼容矩阵分开记账，失败保留首个有效错误与环境/源码归因。
8. 最终 reviewer 独立检查 H0→HF 全部 diff 与审计覆盖；修补后重测受影响项。报告区分实现完成、自动验证、人工体验和可发布，保留可直接接续的 handoff。
9. Draw3 正式自动与强制选择均不启用两种 DWM 透明模式；Win7 SP1+KB2670838 的硬件 FL11.0 有/无两类设备，以及 HARDWARE/WARP、DComp 不可用→ULW、resize/device-lost/透明/输入各有代码与可得运行证据；缺少真 Win7 设备时保留人工发布门禁。

## 不在范围

重写产品、强行统一所有 UI 框架、合并 UI3/Draw3 设备线程、开放关闭入口、升级最低系统要求、未经独立评估的大规模依赖升级，以及实际发版或修改远端内容。

## 规划阻塞问题

无必须先由用户决定的产品行为。HC/H2 和真机环境能否取得是证据问题；取得前保持相应验收项未验证。若后续出现不可逆产品取舍，再单独请求决定。
