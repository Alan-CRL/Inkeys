# UI3 底栏居中与吸附帧几何修复

> 2026-10-26 接力更新：用户已明确授权继续全部实现，并追加 Freeze 隐藏退场回归。下文“本轮只调查/待审批”描述的是 10-25 原规划阶段，已由本次授权取代；GUI/Computer Use 仍按根 AGENTS.md 另行授权，不提交、不归档。

## Goal

恢复 UI3 底栏在动态宽度、模式切换和吸附状态切换中的连续、居中且完整可见的几何表现，避免单帧偏移、跳变和提示裁剪。

## Background / User Value

用户报告的原始设计意图是：居中底栏不以某个 UI 子元素的固定位置充当布局基准，而是在渲染时让包含主按钮的主栏水平中心对齐所在屏幕的水平中心。这样即使主栏宽度通过非线性动画变化，竖直移动也应保持居中直上直下。

当前用户观察到：

- 进入或退出 PPT、白板等模式时，竖直移动和主栏宽度变化同时发生，主栏会偏离中心。
- 底栏和居中底栏进入或退出可吸附区域时，首帧窗口位置可能从远离目标的位置直接跳到任务栏上方，下一帧又恢复并继续果冻动画；靠近居中底栏位置时也可能有水平跳变。
- “底栏模式”或“底栏模式 居中”提示矩形的顶部被窗口区域截断。窗口外框调试已指向窗口区域不足，但脏区是否正确尚未确认。

上述为用户报告；调查和运行验证按子任务分别记录，不把症状描述直接当作根因。

## Investigation Results

- 居中：Enter/Switch 的 `displayTransitionActive` 会关闭逐帧联合中心反推，而主栏宽度继续独立动画，静态根因明确；最终 Leave 是不同路径，需独立逐帧验证。详见 `../10-25-ui3-centered-bar-dynamic-centering/research/centering-investigation.md`。
- 吸附/裁剪：普通捕获已有首帧保护；当前可确定的缺口是脱离首帧交接不对称、释放吸收快照不完整和最终 source/target 无包含检查。间歇三帧现象尚无唯一直接根因，真实抓点、dirty/glyph 和 ULW/DWM 分支必须逐帧判因。详见 `../10-25-ui3-bottom-dock-transition-clipping/research/dock-transition-clipping-investigation.md`。
- 当前 HEAD 的完整 ARM64 Debug Solution 构建成功，0 警告/0 错误；同一 `InkeysHeadlessTests --no-window` 产物退出码 0。既有测试未复现本任务完整视觉序列，不能据此否定症状。
- 本轮未启动 GUI、Office/WPS 或真实 ULW/DWM 逐帧复现；这些验证缺口在计划中明确保留。

## Task Map

- `10-25-ui3-centered-bar-dynamic-centering`：动态宽度与竖直移动同时发生时的居中不变量。
- `10-25-ui3-bottom-dock-transition-clipping`：吸附切换帧的位置连续性，以及提示矩形的窗口区域与脏区完整性。
- 父任务负责统一几何/帧合同、跨子任务回归矩阵和最终集成审查，不默认作为独立实现目标。

## Requirements

- R1：居中底栏应以包含主按钮的主栏实际渲染几何为准，在每个呈现帧保持其水平中心与所在屏幕水平中心一致，包括宽度非线性变化与竖直移动同时发生时。
- R2：进入、退出 PPT 和白板等现有模式以及返回桌面时，不得因布局基准、动画取值或窗口更新顺序造成水平偏心。
- R3：底栏和居中底栏进入、退出吸附状态时，窗口位置、内容位置和果冻动画必须帧间连续，不得出现一单帧跳到吸附目标再返回的现象；水平方向同样适用。
- R4：“底栏模式”和“底栏模式 居中”提示必须完整可见；窗口外框、客户区/更新区域和脏区应使用同一帧的一致几何。
- R5：保留现有吸附交互、非线性动画和果冻效果，不以关闭动画或固定主栏宽度作为规避方案。
- R6：本轮只完成调查、证据持久化和修复规划，不修改产品代码，不启动实现阶段；后续实现须另行审批。

## Acceptance Criteria

- [ ] AC1：两个子任务的可观察验收条件均满足，并有对应自动化或逐帧运行证据。
- [ ] AC2：进入/退出 PPT、进入/退出白板及桌面恢复的组合场景中，主栏在宽度与竖直位置同时变化的每个呈现帧保持居中；误差仅允许来自既有整数像素取整。
- [ ] AC3：底栏与居中底栏跨越吸附边界时，不再出现用户报告的一帧竖直或水平位置跳变，后续果冻动画从连续状态继续。
- [ ] AC4：两种吸附提示的顶部及全部文字/矩形均完整可见；窗口外框调试和脏区检查不再显示由区域不足导致的裁剪。
- [ ] AC5：相关现有 UI3 算法/窗口测试通过；对现有支持的 DPI、屏幕和任务栏配置执行有针对性的回归，不扩大既有平台支持承诺。
- [ ] AC6（本轮规划交付）：任务中包含可追溯的根因证据或明确标注的未验证假设、技术设计、有序实施步骤及验证命令；产品源码保持不变。

## Out of Scope

- 重新启用或修改不参与产品编译的旧 `IdtFloating` / `IdtWindow` 路线。
- 与上述症状无关的动画性能、动态光影或 UI3 视觉重设计。
- 未经审批的产品代码修改、提交或任务激活。
