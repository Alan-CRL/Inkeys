# 形状编辑浮条开合时文字取整目标随当前缩放变化

## Goal

让画布形状编辑浮条（工具栏、参数浮层、色板、取色器）文字的整数像素取整目标取展开态姿态（含工作区 fit），开合全程文字与浮条等比，静止展开仍为整数像素。

## 背景

- 来源：`11-26-bar-text-scale-anim-mismatch` 的 Codex 实现审阅发现，属基线既有问题，与主栏属性窗 / More 修复同一契约（`.trellis/spec/native-desktop/rendering-and-ui.md`“开合式弹出面板”条）。
- 用户实机观察：底栏模式提示、形状步骤指示栏正常（代码确认二者取整目标固定，不在本任务范围）；形状编辑浮条“问题不大”，用户选择在本会话处理。

## 调查结论（详见 design.md）

- 浮条持有独立 `UIRendering renderer`（`Bar.ShapeEditor.cpp:605`），从未调用 `BeginFontFrame`，也从未设置字号目标变换。
- 渲染器因此走立即模式：每帧以**当前** DC 缩放计算 T，并直接 `SetDirect(floor(T)/T)`，等价于 spec 已废弃的“初版逐帧 floor”。
- 现象：开合（Back 回弹 + 紧凑倍率）过程中文字物理字号按整数像素阶梯跳变，比等比小 0–1 px（中途 6 px 时最多约 16%）；静止时为整数像素，所以实机观感“问题不大”。

## Requirements

- 开合全程四层浮条文字与各自表面等比，不再逐帧阶梯取整。
- 展开静止时文字仍落在整数像素（含窄屏 fit 后的尺寸）。
- 不改浮条几何、开合曲线、时长、布局与命中。
- 遵循主栏已定契约：取整目标 = 展开态姿态；后续用户展开倍率乘在展开态姿态上。

## Acceptance Criteria

- [ ] 工具栏开合过程中，代表性文字按钮的 `fontCorrection.Target()` 全程不变，且等于展开态 `floor(T)/T`。
- [ ] 参数浮层 / 色板 / 取色器使用各自展开态（含 fit）倍率。
- [ ] 静止画面（golden）不变；`--ui3-shape-editor-test` 及既有门禁通过。
- [ ] 新增用例在旧行为下失败（变异验证）。
- [ ] 用户实机观感确认。
