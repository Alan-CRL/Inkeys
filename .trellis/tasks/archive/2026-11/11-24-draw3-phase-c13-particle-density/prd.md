# 阶段 C1.3：画布粒子数量上限档位

## Goal

在“画布粒子效果”设置里，飘散方向（向左上 / 向右上）下方新增“粒子数量上限”：低 / 中 / 高 / 极致，默认中。

- 档位只决定单次飘散的粒子数量上限，以及与之匹配的粒子池容量（极致档最多 64 MB）。
- 生成密度保持原算法不变：清空每平方 DIP 0.5 粒，激光飘散每 DIP 3 粒。
- 目的：大范围涂抹或写满后清空时，不会因为触顶而整体变稀，亮度不骤降。

同时把清空飘散改为由 GPU 生成，消除清空当帧的 CPU 卡顿；激光飘散改为 CPU 直写；行进粒子单独成池。

属于父任务 `11-16-inkeys3-midterm-refactor` 的阶段 C1.3，排在 C1.4（UInk 1.1 适配）之前完成。

## 背景（2026-11-24 调查与实测）

- 粒子不是一个像素一个：
  - 激光飘散沿中心线按长度生成，每 DIP 3 粒，每个圆点保底 3 粒。
  - 清空飘散按墨迹面积生成，每平方 DIP 0.5 粒（透明度 < 48 的像素不算墨迹），颜色取出生像素。
  - 碎裂遮罩按像素哈希决定每个像素何时消失；粒子的释放时刻对齐它出生像素消失的时刻。
- 单次上限 16384。超出时整批同比变稀（这就是大面积涂抹时亮度骤降的原因）。粒子池 32768 槽、2 MB，三种粒子共用，满了按先进先出覆盖最旧批次，被覆盖的粒子当帧消失。
- 实测（`research/clear-frame-benchmark.md`）：清空当帧的瓶颈是 CPU 生成种子和打包（约 140 ns/粒），上传很便宜。低档约 9.5 ms，20 万粒约 30 ms，另外读回还要约 4 ms。

## Requirements

### R1 设置项

- 位置：设置 → 绘制效果页 → 画布效果 → “画布粒子效果”总开关下方的内联区，排在“飘散方向”下方，中间不加分割线；之后才是分割线和三个子项复选框。
- 名称“粒子数量上限”，选项：低、中、高、极致（下拉框，与飘散方向同一种样式），默认“中”。
- 总开关关闭时随整块一起收起，保留选择。
- 配置字段 `Drawing.Particles.Limit`（整数 0–3，默认 1）。类型错误或越界时按默认值处理，与 `Direction` 的校验规则一致。
- 补全所有语言的文案。

### R2 档位规格

| 档位 | 飘散池槽数 | 飘散池显存 | 单次飘散上限 | 不变稀的最大清空墨迹面积 |
|---|---|---|---|---|
| 低 | 32768 | 2 MB | 16384 | 约 3.3 万平方 DIP（1080p 屏幕的 1.6%） |
| 中（默认） | 131072 | 8 MB | 65536 | 约 13 万平方 DIP（6.3%） |
| 高 | 524288 | 32 MB | 262144 | 约 52 万平方 DIP（25%） |
| 极致 | 1048576 | 64 MB | 524288 | 约 105 万平方 DIP（51%） |

- 低档与现状完全一致，作为回归基准。
- 密度不随档位变化；粒子数 = 墨迹面积 × 原密度，只有超过本档上限时才同比变稀。
- 单次上限取飘散池的一半：一次清空和一次激光飘散（或连续两次清空）同时存在时，两批都能完整放下。
- 粒子相关显存只由档位决定，与事件数量无关。
- 行进粒子另用固定 8192 槽的小池，不随档位变化。

### R3 并发与溢出

- 清空飘散 + 激光飘散 + 行进粒子同时进行时，任何一方都不被提前抹掉。
- 只有三个以上的满额批次在寿命内叠加时，才按先进先出淘汰最旧批次（现有行为）。

### R4 档位切换

- 切换后立即生效：飘散池现存粒子直接清掉，按新档位重新创建（仍是首次有粒子时才创建，空闲时归还）。行进粒子与点击光波不受影响。

### R5 失败降级

- 飘散池创建失败时逐级降档，直到低档；降档后本次设备会话一直保持降级后的档位，并记一条日志。低档也失败，激光飘散和清空飘散都不出，行进粒子照常。
- CPU 侧分配失败时只是不出粒子，不能让绘制循环停止（Win32 要特别注意）。

### R6 性能

- 清空当帧的 CPU 开销与粒子数无关（GPU 路径），本机不出现可察觉的卡顿。
- 飘散期间的帧时间需实测记录。弱核显（Win7、兆芯）在父任务最终集成时验收。

### R7 清空飘散由 GPU 生成

- 清空时，计算着色器直接读清空快照纹理，**每个物理像素一个线程**并行处理，生成粒子记录并写进飘散池。之后照旧交给现有顶点着色器按“出生参数 + 时钟”求值，再由像素着色器绘制，数据不离开 GPU。
- 逐像素取样，概率按每个像素对应的 DIP 面积换算（200% 缩放下一个像素是 1/4 平方 DIP），统计上与原来 CPU“每 2×2 像素取一个代表”的密度相同。区别是每粒的颜色和位置取自它自己的像素，不再取格子左上角的像素，边缘更准确。
- 墨迹范围由 CPU 从页面历史已有的笔画像素包围盒得到，不从 GPU 读回。这部分做成可复用的查询，供 C2 的页面级空间索引接手。GPU 只异步回报实际粒子数，用来缩短预留的槽位。
- 视觉效果与现在一致：取色、碎裂遮罩对齐、风场、寿命都不变。
- 计算着色器不可用时退回 CPU 路径（原算法，保留 2×2 抽样），效果一致，只是慢。

### R8 激光飘散 CPU 直写

- 激光飘散仍在 CPU 生成，但直接写 64 字节的记录，不再经过 88 字节的中间种子；每粒重复计算的常量提到循环外。外观与现状一致。

### R9 行进粒子单独成池

- 绘制行进粒子时不遍历飘散粒子，反之亦然。行为与外观不变。

## Out of Scope

- 不改密度、运动模型、外观（半径分布、寿命、风场）和点击光波。
- 不按设备性能自动选档（默认中）。
- 激光飘散不改为 GPU 生成；行进粒子仍由 CPU 发射。
- 不做 C2 的页面级空间索引本身，只提供“当前视口内可见内容的屏幕范围”这一查询，接口按 C2 能接手的方式设计。
- Win7、WARP、兆芯实机验收留到父任务最终集成。
