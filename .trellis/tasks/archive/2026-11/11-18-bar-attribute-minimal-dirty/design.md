# 设计：UI3 自动脏区统一（主栏与翻页控件）

依据：Codex 三轮只读调查（V0 开工核对 `research/codex-v0-startcheck.md` 已据此修订本文；`research/codex-d1-investigate.md` 现状与清单；`research/codex-d2-architecture.md` 统一架构可行性），关键事实主 Agent 已抽查读码确认：未分类兜底在继承同步之前判定（`Bar.RenderLoop.cpp:7143–7149`）；翻页控件 `Render()` 内再次 `Advance(now)`（`Bar.Scene.cpp:1042`）；按钮角标几何/颜色在绘制函数里写入（`UI3.Button.cpp:383–398`）；翻页控件按候选序号确认后才消费脏区（`Bar.Scene.cpp:962–974`）。

## 1. 为什么现在不是自动的

UI3 的按钮/图元只负责动画推进，返回 `changed/active` 并提供可选 `observe` 回调；「刷新哪里、包络多大、何时登记」由宿主手写：主栏 `Bar.RenderLoop.cpp` 手工标脏（58 处 `MarkChanged`、72 处带键 `ChangeValue`、逐图元 `Observe`），翻页控件另写 `Include()` 累计矩形，属性面板只上报「面板变了」。每帧直接写值、绘制时才派生的状态没有任何回调。任何一处漏写就会刷多或刷少。

## 2. 目标架构

一句话：**视觉对象登记一次；每帧在「准备完成、绘制之前」把每个对象的最终绘制状态与「上次成功呈现」的状态逐字段比较，变化的对象贡献「旧包络 ∪ 新包络」；成功呈现后才推进快照。**

```
动画推进 → 布局/继承/派生（准备阶段，产出全部最终绘制状态）
        → VisualDirtyRegistry::Prepare（采样、比较、出脏区与呈现需求）
        → 光影脏区（原逻辑）、窗口尺寸/容量（原逻辑）
        → FrameTransaction：BeginDraw（脏区裁剪）→ 只读绘制 → 提交
        → 成功：Registry::Commit(attempt)；失败：不推进（下一帧仍与旧快照比较）
```

### 2.1 模块与分层

| 内容 | 位置 | 依赖 |
|---|---|---|
| 登记表核心：登记身份（地址 + 代次）、组树、状态采样缓冲、与已提交状态比较、候选（attempt）捕获/确认/保留、注销后的擦除墓碑、坐标重基准 | 新独立模块 `Inkeys.UI.UI3.VisualDirty`（纯数据，Headless 可测） | 仅 `Inkeys.UI.UI3.DirtyRegion` 的矩形工具 |
| 适配器：`UiShapeClass`、`UiSuperellipseClass`、`UiSVGClass`、`UiPNGClass`、`UiWordClass`、`ButtonClass`（含 badge、secondary、separator、按压）、面板组（位姿/透明度/裁剪）的采样与局部包络 | 新分区 `Inkeys.UI.UI3:VisualDirty` | `:Primitive`、`:Envelope`、`:Button`、`:Panel` |

UI3 不引用 Bar/PageControl；产品类型（面板、状态指示器条目）只在宿主侧登记。

### 2.2 状态采样与比较

- 每个对象把「影响像素的有效输入」写入一个小的采样缓冲（`VisualStateWriter`：追加规范化后的 double/int/bool/颜色/内容版本），按字节精确比较；不依赖可能碰撞的哈希判定相同。规范化：`-0` → `0`，NaN 统一；不加统一 epsilon（亚像素变化也可能改像素）。
- 采样字段按 `codex-d2-architecture.md` §2 清单：几何（继承后的最终位置、`w/h`、圆角/描边）、`pct/enable`、填充/边框色与透明度、`frameLightPct`、`lightMaterial`、`themeSurface/residentSurface/lightFillOpacityScale`、边缘光配置（frameRendering、颜色来源、主光开关、鼠标光强度倍率）、SVG 内容版本/颜色/角度/contentScale/appearanceKey、PNG 载荷版本/角度、文字内容/字号/颜色/字体修正/对齐/粗细、按钮 iconKind/pressScale/badge 状态。
- **不采样**：动态光源的位置/颜色/强度（主光、鼠标光，R5，走原光影通道）；动画内部状态、缓存、锁。
- SVG/PNG 需要新增内容版本号（内容替换时递增），现有字段没有通用版本。
- **采样坐标用局部坐标**：对象采样记录映射前的局部有效状态；映射（Body/Grip/Rigid/None、翻页 presentation 偏移/缩放）作为宿主「映射状态」单独采样。映射状态变化 → 使用该映射的对象全部变化。`TranslateCommitted` 同时平移已提交包络与已提交映射基准，避免重基准后误判。
- **绘制上下文与选项也入采样**：Word 的 `w/h/size` 目标值、`fontTargetSize`、字号策略与最终解析字号、字重/对齐/fitButtonLabel；按钮的 secondary、separator、drawIcon、扩展内容版本；绘制顺序与门槛。
- **环境输入每帧冻结一次**（字体族/locale/字体集合修订、DPI/unit mode、diffuse reference/geometry scale、常驻背景透明度覆盖、常驻内容透明度、idle fade、材质权重、自绘直接读取的主题色）：按实际作用范围挂到对应组的组状态；采样与绘制读取同一份冻结值，不再分别读全局。
- 逐类型「字段 + 上下文 + 绘制选项」完整表在 V2 实施时写入 `research/sample-fields.md` 并经独立审查；资源缓存不采样，资源失败后的失效/重试责任保留在原处。
- **可见性**用真实绘制门槛（与 Renderer 跳过绘制的条件一致；Shape 在 `pct==0` 但 `frameLightPct>0` 时仍可见）。已呈现 → 隐藏要贡献旧包络。

### 2.3 组（面板）

**组树表达实际绘制作用域（位姿/透明度/裁剪/绘制顺序），不是业务归属。** 例如 More 按钮继承 MainBar 坐标但单独先画、主栏退场按钮分两轮绘制；橡皮主面板与自动粗细菜单分别合成；形状类别有独立 clip、参数行另有 opacity/clip；翻页主题与菜单各有 pose/opacity 并共同受最外层 opacity 作用。已烘焙进成员几何的位姿不得在组上重复施加。各作用域的归属表与绘制顺序在 V3 实施时写入 `research/draw-scopes.md`。

- 组成树（禁止环）：主栏根、More、绘制属性、各属性面板、二级菜单、弹窗、翻页每个面板等。组采样其有效位姿、透明度、裁剪、映射类别和组内环境（常驻背景透明度覆盖、常驻内容透明度、PPT 闲置淡化、材质权重）。
- 组状态变化 → 组内成员全部视为变化（旧∪新）。因此面板开合/移动自然得到整块脏区；成员单独变化只得到成员脏区；选中转移时旧、新成员都因自身状态变化而登记。
- 组自身背景（面板底、阴影、外框柔光）作为组的一个成员对象登记。

### 2.4 自绘对象

不经过标准图元的内容以「自定义对象」登记：组件在准备阶段算出 prepared state（绘制也只消费它），并提供采样（输入摘要）与局部包络。清单见 `codex-d2-architecture.md` §3：粗细预览/激光芯/滑块轨道、FineDial、三档圆点与数字、thumb 与预览数字浮窗、橡皮三档位图预览、形状粗细胶囊与类别长按环、状态指示器（按稳定条目身份，不用临时绘制载体地址）、底栏吸附指示、取色器色盘/marker/保持环、粗细保持环、构造提示环、翻页主题色样与网格/点阵、翻页加载环、分页背景扩展回调（调用方须提供内容版本与包络）。主 Logo 主要是标准 SVG + appearanceKey，按标准对象登记。

### 2.5 准备阶段合同（绘制只读）

现在有若干状态在绘制阶段才派生（`codex-d2-architecture.md` §1 表）：按钮绘制时重解析继承、角标几何、PNG 复制 SVG 字段；三档数字绘制时改内容/颜色；popup 临时改文字尺寸再恢复；FineDial 绘制时算几何；翻页 `Render()` 再推进并摆拖柄；文字字号修正在绘制中读取 DC 变换。

合同：**这些派生全部移到准备阶段，绘制只读消费准备结果，不得修改任何被采样的视觉状态。**

- 准备结果按**绘制实例**组织：同一个视觉载体一帧内画多次（三档数字先画锁存数字再画高对比数字；状态指示器复用图标/文字载体）时，每次绘制各有一份准备参数（内容、颜色、透明度、顺序），而不是一个对象的最终字段。
- popup 不再「临时改值—绘制—恢复」：准备出专用绘制参数（逆缩放几何、anchor、关闭按钮参数、目标字号），源布局对象不被改写。
- FineDial：几何与标签布局一起准备；向交互状态发布当帧视觉宽度的副作用改由准备阶段完成。
- 翻页：区分「一次动画推进」与「可重复几何准备」；晚到 bounds 后重做几何准备；`Render()` 不再推进或摆放。
- 字号：准备阶段用与绘制等价的有效变换（组位姿 × 按钮按压缩放 × 缩放/DPI/unit mode、当前与目标字体尺度）解析最终字号；不得用根 DC 变换代替按钮/popup 作用域。
- 时点：设备/字体相关准备在资源就绪后、BeginDraw 前完成即可，不要求早于窗口容量计算；与布局有关的准备必须早于呈现分类决策（见 §2.7）。
- **细化（V2b 实施，2026-11-18）**：为把像素风险降到最低，绘制代码里「可重复执行、结果确定」的写入（继承位置 `Inherit/UpInh`、按钮 PNG 从 icon 复制几何等）可以保留——准备阶段先按同一算法写出相同值，绘制再写一次不改变采样；由绘制纯度检查（`VisualDirtyRegistry::VerifyPurity`）保证。一帧内被改写多次或临时改写再恢复的载体（三档数字、popup 文字等）不按标准对象登记，改登记为按输入采样的自定义对象。按设计在绘制中推进的输入（文字字号修正）写入采样的「易变段」（`VisualStateWriter::BeginVolatile/EndVolatile`）：正常比较计入，纯度检查跳过。
- 防护：① 绘制函数改为只接受准备结果的只读接口；② 测试与调试构建的「绘制纯度检查」——绘制后对全部登记对象再采样并与绘制前比较；③ 「临时写入再恢复」采样检测不到，靠只读接口与代码审查兜底。

### 2.6 候选与提交（attempt）

- `Prepare` 产出一个不可变 attempt：本帧各对象的采样、映射后的包络、可见性，以及合并后的脏区。
- 主栏：成功呈现后 `Commit(attempt)` 推进快照；失败时不推进。**失败恢复不由登记表负责**：复用位图可能已被失败帧部分改写（例如已提交 A、绘制 B 失败、状态又回到 A，比较结果「无变化」），所以现有失败路径（`RetainForRetry(true)` 强制全脏、目标尺寸/设备变化的完整替换、display transition 与 capacity/source 变化的替换决策）全部保留，摘要相等不能取消这些重画。`IncludeDamage` 并入的范围持续到成功提交才清空（读码确认），跨帧累计大于本帧旧∪新属于合法重试范围；`IncludeDamage` 必须在 `BeginFrame` 设好窗口范围之后调用。
- 翻页控件：四个目标窗口各自一个登记表实例（读码确认视觉对象不跨目标共享）。扫描在最后一次 bounds/scale/字体目标/光照映射准备之后、「等待旧候选」复用判断与 `PendingDamage` 之前完成，不放进会被同时间戳短路的 `Advance`。**实际绘制的 attempt** 绑定随后捕获的 `sceneSerial`，回执确认（`CommitPresentationCandidate`）时只提交该 attempt，不重新采样；隐藏或无像素候选可确认输入/窗口状态，但不推进像素快照（沿用 `pixelsSubmitted` 保护）；捕获后的新失效保留到下一帧；旧回执、重复回执不推进；presentation 原点变化、目标重建、显隐恢复继续走原 full replacement。
- 坐标重基准（`TranslateCommitted`）同步平移登记表里的已提交包络。

### 2.7 与现有机制的衔接

| 机制 | 处理 |
|---|---|
| `DirtyRegionTracker` | 主栏保留：登记表脏区经 `IncludeDamage` 并入；光影键、全脏、调试合并、重试、重基准照旧。翻页控件把登记表脏区接到现有 `PendingDamage/ConsumeDamage` 接口与 full replacement 路径 |
| 呈现需求 | 新增显式「帧准备」步骤：放在 `AdvanceAnimationsAndDeriveLayout` 之后、`PrepareLightingAndDemand` 之前，完成继承同步、派生视觉准备与登记表扫描；扫描结果必须早于未分类兜底、`hasActiveRendering`、最终 idle 框闩锁与 `alphaOnlyDemand` 判断。现有 `CalculateDirtyAndDrawPresent` 内的同步改为复用准备结果。只在循环已唤醒的帧运行，不增加轮询，也不因「存在登记对象」维持续帧；生产写入口原有的 wake/invalidate（`UpdateRendering` 等）全部保留。`ObserveRole`（有限观察者）报告与标脏同处回调，删除标脏时保留；字号准备新启动的 active 回接调度 |
| 未分类兜底 | 迁移期保留；完成后只对显式 `needRenderOnce`/外部失效保留。增加显式「全脏原因」诊断标记（未分类、失败重试、目标替换、display transition 等），新测试据此断言交互过程中不出现未分类全脏（不能用 `prcDirty==nullptr` 判断，映射替换同样合法使用它） |
| 光影 | **光影脏区算法与输入完全不动**：主光/鼠标光键、普通图元的边带算法（遍历 `shapeMap` 等）、属性面板/状态指示的「整块 bounds ∩ 影响范围」、翻页主光全脏与鼠标光面板边带，全部沿用原代码。业务脏区成员化不等于光影范围成员化 |
| 底栏吸附指示首次显现峰值 `IncludeDamage` | 保留（零缩放帧的峰值预留无法由当前包络替代） |
| 窗口尺寸/容量/预测包络 | 完全不变（R7）；`Changed()/Active()` 继续服务尺寸与调度，删除旧标脏时不得删除它们 |
| 状态指示器窗口约定 | 登记进脏区不等于登记进尺寸；小图标不影响窗口大小 |

### 2.8 删除的旧代码（按责任，不按字样）

可删：动画 helper 的带键标脏参数、map 图元与按钮逐对象 `MarkChanged`、逐图元 `Observe`、形状/橡皮/撤回/构造提示/状态指示的组键与整组 Observe、拖动 sustain 的组键（坐标已被扫描）、翻页 `Include/IncludeButton` 与内容/动画累计。保留：光影键与影响范围、全脏与未分类兜底（收窄后）、首次峰值、重基准、失败重试、翻页 full replacement/fallback/回执核对、`Changed()/Active()`。详细行号区间见 `codex-d2-architecture.md` §4。

## 3. 正确性论证

- 局部重绘：`FrameTarget` 先压脏区裁剪再透明清空，宿主按原顺序完整绘制，裁剪只限制写入；面板 opacity 层有界、阴影为有限轮廓带（`codex-d1-investigate.md` §5）。只要包络覆盖对象全部像素，局部帧 = 整幅重画。
- 包络：沿用 `UI3.Envelope`（描边 + 点光 6 DIP + 阴影 + 3 像素抗锯齿）；按压释放 EaseOutBack 峰值约 1.005，被外扩覆盖；外侧环、箭头旋转、长按环、自绘胶囊由自绘对象自报包络。
- 比较基准是「上次成功呈现」：动画中每帧变化即每帧脏；失败重试自然覆盖旧像素；值不变不脏。
- 单矩形提交：分层窗口 `prcDirty` 只接受一个矩形，多处同时变化取外接矩形（范围外，第2步 DComp 可解）。

## 4. 测试策略

1. Headless `visual_dirty_tests.cpp`：等值不脏、直接写值、组传播、出现/消失/注销墓碑、失败保留、候选确认（旧/重复回执）、地址复用代次、重基准、规范化（-0/NaN）。
2. 影子模式：迁移每个宿主前，新旧脏区并行计算（只诊断不生效），离屏测试中记录「新 ⊆ 旧」比例与「像素差集 ⊆ 新」，确认后再切换。影子登记表与生产 tracker 隔离：不调用生产 `IncludeDamage`、不产生生产呈现需求；影子快照随旧路径的真实成功提交推进。
3. 新离屏测试 `--ui3-attribute-dirty-test`：逐面板逐按钮/控件驱动悬停、按下/抬起、选中转移、二级菜单开合、连续控件拖动；截获每帧 `prcDirty`；断言 ① 包含对应对象旧/新包络 ② 不超过其外接矩形加余量 ③ **每个成功的局部帧**保留画面都与同状态整幅重画 BGRA 逐像素一致（参考重放消费同一份准备结果，不再推进动画/字号）④ 绘制纯度检查通过 ⑤ 无未分类全脏（按全脏原因标记）⑥ 联动元素与光影帧按单独定义的合法上限判断。翻页控件同类断言扩展到 `PageControl.cpp` 内置检查（含旧回执、晚 bounds、隐藏恢复）。
4. 现有回归全部维持（golden 35 逐字节、第1步全量清单）；`dirty_region_tests.cpp` 不改预期。

## 5. 风险

| 风险 | 防护 |
|---|---|
| 漏采样某个影响像素的字段 → 少刷 | 字段清单逐类型审查；像素差集独立验证（不复用包络算法）；用户实机脏区显示检查 |
| 准备阶段前移改变计算顺序 → 像素变化 | golden 逐字节对照；每次前移单独验证 |
