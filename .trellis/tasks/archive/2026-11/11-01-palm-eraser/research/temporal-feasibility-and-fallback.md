# 时间Z序可行性、撤销边界与落笔Z序回退

> **已停止／本期范围外（2026-11-01）**：用户明确决定不实现真实时间交错覆盖，理由是目标场景为不同位置的多人擦写。本文件仅保留历史研究，不是当前要求或实现指引；停止后不继续扩展。本期已选择沿用抬笔/完成提交顺序。

日期：2026-11-01。用户补充已授权研究墨迹架构内的方案、UInk私有协议，暂不考虑第三方擦除互操作；允许难度过高时考虑按落笔顺序决定Z序。本文件是技术评估，不是已完成实现或生产测试。

## 当前判断

保留时间交错作为主目标，现阶段没有充分证据表明必须回退。数学上已有有序仿射合成，逻辑整笔Undo与片段Z序也可分离；真正代价集中在CPU表达、完成/重建路径和缓存事务，不能用几行Up排序补丁解决。

相比“每片段都创建一个RenderItem再额外发明非连续分组Undo”，优先研究一个较局部的表达：**仍然一整笔对应一个逻辑InkStroke/历史动作，交错片段存在同一混合组的私有有序日志里**。历史动作的完成顺序负责Undo选择，日志顺序负责像素Z序，二者不互相代替。这是对前一篇研究候选表达的收敛方向，最终接口还未冻结。

私有UInk解除的是第三方互操作负担，不会自动解决runtime缓存、L0可变尾部、输入合并或Redo语义。当前采用私有协议的理由是保存产品自身所需的逻辑动作/时间片信息，不顺带修改UInk的公共标准或其他软件。

## 可复用点与必须改变的点

| 边界 | 可复用 | 必须新增/改变 |
| --- | --- | --- |
| 图形运算 | 现有Draw/Erase仿射组合与Tile绘制 | 混合组严格按日志顺序合成，不把不同时间片CoverageUnion |
| 文档/历史 | 一笔一逻辑动作、现有尾部Undo/Redo栈和每页隔离 | 墨迹架构增加混合组及动作到片段的映射；片段不暴露成用户撤销步骤 |
| 活动/Up | Runtime独立状态、共享层重建与控制命令收笔边界 | 部分Up只完成动作，不把整笔再次叠到最上层；组内日志与可变尾保留正确顺序 |
| Undo | 最后完成动作选择、visibility候选提交与失败回滚原则 | 混合组用候选可见性重放相关区域，不能直接用该动作旧前像覆盖所有后效 |
| Redo | 原动作/redo身份、redo分支管理 | 混合组重做恢复原日志位置，不能调用普通路径把整笔重新盖到最上层 |
| UInk | 应用extra容器、owned snapshot、串行worker、原子写入 | 私有版本化混合组协议以及捕获/合并/Clear投影/导入/冷页的完整传递 |
| 普通独立绘制 | 现有单笔、热前像和直接Redo快路径 | 不属于混合组的行为继续复用；不借本需求整体重写modeler或renderer |

### 代码依据

- `Inkeys/Inkeys/Drawing/Draw3/Assets/inkPixelShader.hlsl:421`：有序仿射组合已存在。
- `Draw3.InkHistory.cpp:949`/`:974`：按逻辑尾动作切换visibility和redo栈，可维持一个物理动作一个历史项的接口习惯。

- `Draw3.DrawingController.cpp:14038`附近的Redo会DrawStoredStroke并直接Apply到当前L2：这在时间交错组中不正确，必须用组内原位置重放。

## 建议的运行期表达

1. 每个物理接触有稳定的逻辑动作ID，一整笔仍只产生一个历史动作；Up完成顺序不再决定它的绘制Z序。
2. 混合组拥有按接受时间/确定性总序排列的操作日志，片段引用逻辑动作ID，包含足以重放的稳定几何与必要版本。不得借用已回收contact的地址作为持久身份。
3. 混合组中的完成动作在CPU真值上可被保存/标记dirty；活动者保持运行状态，已完成者保留自有日志。任一Up不能导致整组重排，也不能重复绘制已接受前缀。
4. 每次重建从同一日志按当前可见动作集合计算结果；L1/L2/文件只是投影。按动作完成次序维护历史栈，因此可以保留“一次撤销最后完成的一笔”。
5. 首版可让混合组按Tile有序重放，普通页/普通笔保持现有快路径。不能为少改代码而每帧无条件全页重放；增量、组内脏区、可变尾版本和缓存正确性需在局部原型阶段证明。

是否最终将组作为新的复合文档节点，或Canvas侧车中引用已有逻辑Stroke，要由原型对照现有存储/重建接线决定；这是技术选择，不把接口细节转交用户决定。

## Undo/Redo边界矩阵

| 操作 | 必需结果 | 禁止的捷径 |
| --- | --- | --- |
| Undo一笔绘制A | 隐藏A的全部片段，B的擦除仍按原位置影响更早内容 | 仅撤掉A最后一个片段 |
| Undo一次擦除B | 恢复B之前被擦内容，并保留B之后A重写的部分 | 将B之前整张前像贴回，丢掉后写内容 |
| Redo B | 在原B各时间片的位置恢复擦除，后写A仍在它上面 | 将整条B作为最新橡皮重新盖一次 |
| 连续Undo/Redo，双方Up顺序互换 | 历史按完成动作选择，画面始终按日志Z序 | 按Redo发生时刻重新排序片段 |
| Undo后新画C | 旧redo动作整组丢弃，C成为新分支；旧片段不能从缓存/文件复活 | 仅清redo按钮而保留可恢复分组引用 |
| 部分动作Up，另一个继续写/擦 | 完成动作保留原Z序，活动动作可继续交错 | 将先Up动作烘到错误层级，活动者重建后反盖 |
| Clear/换页/退出/取消 | 复用精确页边界，封存可接受内容；日志/身份不跨错页 | 无限等物理Up，或用Cancel丢掉已要求保留内容 |
| Tile缓存淘汰、尺寸/viewport改变 | 按日志和visibility得到相同像素结果 | 用缓存代替CPU真值 |
| 某次栅格/序列化失败 | 保留原分支及可重试状态，候选失败不提交半个动作 | 先弹redo/改visibility再尝试重放 |

对时间组，缓存键至少需关联组日志/几何修订、动作可见性与显示栅格代次；旧缓存不匹配只降低性能，不能改变结果。具体复用现有range tree的方案不能仅根据同一RenderItem数量假定合法。

## 规划阶段模型验证

已运行无文件/无GUI的简化两像素模型：底层(0.2,0.3)，日志A写x→B擦x→A写x→A写y→B擦y。

- A/B均可见得到(1,0)。只显示A为(1,1)，只显示B为(0,0)，二者都撤回恢复底层(0.2,0.3)。
- 分别用完成顺序A→B和B→A按整动作Undo到空、按原身份Redo，均恢复(1,0)，没有重排日志。
- 对Undo后新分支，验证了被丢弃动作不再进入可恢复集合。

这仅证明“逻辑撤销顺序与时间Z序分开”在模型上成立；没有覆盖真实AA/模型尾段、GPU故障、性能、文件I/O或生产代码，不能称为新功能测试通过。

## 私有UInk协议边界

按用户新要求，不再把旧读取器的交错擦除显示或撤销能力列入本期验收。优先使用已有应用extra承载带版本的私有时间组数据，保持原文件容器/原子写入与worker结构。

至少表达：时间组身份、逻辑动作身份与完成次序、有序几何片段/范围/版本、所属Clear区间，以及各工作区既有保存范围所需的可见性/redo。私有负载成为混合组重放真值，不依赖公共undoId跨非相邻片段复用。

- Desktop/PPT沿各自既有可见快照/当前进程恢复合同，不无故新增跨进程完整redo功能；白板沿既有全历史冷页合同保存完整visibility/redo。无论保存范围如何，恢复出的可见动作必须保留完整分组和时间Z序。
- canonical合并、Clear区间提取、PPT拓扑重排和冷页重编号都需带着私有负载处理，不能只修初次Export/Import。
- 旧文件没有私有负载时维持普通Stroke路径；私有版本/引用不合法时报告无法恢复该数据，不能默默把它当普通Up顺序并声称画面正确。
- 本期不修改公共标准、不要求第三方支持、不预先承诺未来标准化。

## 与落笔Z序回退的比较

| 维度 | 时间Z序（当前主目标） | 落笔Z序（允许的回退） |
| --- | --- | --- |
| 按住时互相覆盖 | 同一笔可在擦后重写，橡皮又可继续擦 | 整个动作的相对层级固定，后落下的橡皮始终在早落下绘制之上 |
| 时间数据 | 需要保留有意义的交错顺序及稳定片段 | 只需逻辑动作Down序，明显较简单 |
| Up后正确性 | 按日志重放，Up不重排 | 仍需保持Down顺序，不能继续按Up追加像素 |
| Undo/Redo | 一个逻辑动作，组内按原时间位置重放 | 一个逻辑动作，按原Down层级重放 |
| 活动组/部分Up | 要保留混合组与有序片段 | 同样要处理混合组/保留已完成上层，不能直接略过这个边界 |
| 私有保存 | 动作与片段时间日志 | 动作Down顺序及相应分组 |
| 风险集中 | 输入合并、模型尾/AA、缓存组重建、持久化闭环 | 部分Up层级、历史选择顺序与Down层级分离 |

因此，落笔Z序确实可以减少复杂度，但也不是零成本开关；尤其是先落笔绘制仍按住、后落笔橡皮先Up时，仍须保留橡皮在上层，不能让旧绘制因为重建回到它上面。

## 后续执行计划中的技术验证门

在用户确认最终规划并进入实现后，先完成最小墨迹架构原型及无窗口验证，再接入完整设置页：

- 同帧A/B/A及多次交错、两种Up顺序、部分Up后继续输入。
- 单次逻辑Undo/Redo、Undo后新笔、Clear、局部重建与保存读取。
- Pen可变尾与荧光笔透明接头，不允许为通过验证关闭用户既有功能。
- 有界输入/日志与重建代价可控，不需要持续全屏回读、每帧重放整页历史或为本功能改造所有普通笔路径。

若这些核心条件只能靠大范围重写或不可靠的副作用实现，应明确向用户报告原型证据，并据其已给出的回退空间提出落笔Z序版本，修订PRD/验收后再推进。不在一次交互中途或同一文件内悄悄混用两种Z序。
