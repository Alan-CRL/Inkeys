# 阶段 B 设计

实施基线 `refactoring/draw@cd942ed0`。本文记录 2026-11-22 与用户逐项讨论后定下的设计；早期调查的候选方案见 `research/`，与本文不一致处以本文为准。行号为基线时的位置，仅用于定位。

## 层的表示

L2 是一张 BGRA 纹理，是当前页面视口已完成墨迹的栅格缓存，权威内容是文档与有序历史。L1、L0 各是一对纹理：Add（B8G8R8A8_UNORM）与 Retain（R16_FLOAT）。每个像素的含义是“盖到下层后，结果 = Add + Retain × 下层”，空像素是 (0, 1)。

| 操作 | 实现 | 语义 |
| --- | --- | --- |
| 往层里画线段 | `strokeOperatorBlendState`：Add 取 MAX，Retain 取 MIN | 同一笔的线段只算一次覆盖 |
| 双层合成到目标 | 像素着色器类型 1：先取 max(Add)、min(Retain)，再双源混合 | L1、L0 视为同一笔的两段 |
| 单层合成到目标（新增） | 像素着色器类型 25：只读一层，再双源混合 | 一层独立盖到目标 |

书写时：稳定前缀追加进 L1，尾段、预测、图形预览每帧重画进 L0；橡皮的真实点全部进 L1；激光不进这三层。

## 写域登记与清除规则

现有 `OperatorContentTracking` 只服务 L0，且只记一个外包矩形。改为按层通用（L0、L1 各一份），每份记录：

- `untracked`：有未声明范围的写入。
- 至多 8 个矩形。新矩形与已有矩形相交或相邻时合并；满了并入合并后面积增量最小的一个。

写入在绑定渲染目标时登记（先于绘制），上传中途失败只会多清，不会漏清。清除入口 `ClearOperatorLayerContent(layer)` 的规则：

```
要清某层
 ├─ 上次清除后没写过                      ──▶ 不发命令
 ├─ 写域未知 / 设备不支持 ClearView       ──▶ 整屏清
 └─ 写域已知且支持 ClearView
      ├─ 各矩形面积之和超过 1/16 屏       ──▶ 整屏清
      └─ 否则                             ──▶ ClearView 一次清全部矩形
```

矩形清除时每个矩形外扩 `kOperatorContentClearMargin`（2 像素）并裁剪到画布。新增只读查询 `OperatorLayerEmpty(layer)`：没有未知写入且没有登记矩形。

保持整屏清的入口：改尺寸、设备恢复、换页、清屏、视口刷新。这些时刻纹理内容确实未知或 L2 同时被整清。

未声明写域的写入者（历史回放把 L1/L0 当工作区、焦点层绘制、自检里的直接绑定）会让该层进入“写域未知”，下一次清除自动退回整屏。书写热路径上的 L1 写入（稳定前缀追加、橡皮追加、前缀重画）补上写域声明；其余不要求本任务补齐。

绕过绑定直接改写层内容的地方必须调用 `MarkOperatorLayerUntracked`：改尺寸时把旧 L1 拷回新纹理就是这种情况，否则有墨迹的 L1 会被登记成空层。

## 单层合成

- `inkPixelShader.hlsl`：新增 `type == 25` 的独立早返回分支，位置在类型 1/2 分支之前或之后均可，但必须在末尾“默认笔”段之前返回。只采样 `LiveOperatorAdd`、`LiveOperatorRetain`（t4、t5），输出 (add, retain)。
- `inkVertexShader.hlsl`：把 25 加入现有 `type == 1 || type == 2` 的合成矩形分支。
- `InkRenderer::ApplyOperatorLayer(dstRTV, layer, rect)`：与 `ApplyOperatorLayers` 相同的矩形上传和状态设置，`shapeType = 25`，只绑定 t4、t5。
- Win7 保护版：`Draw3.Win7GuardedShader.h` 用归档脚本 `Generate-Win7-GuardedShader.ps1`（`.trellis/tasks/archive/2026-10/10-18-draw3-cursor-policy/research/`）重新生成。保护版尾部条件是“类型为 0、3、小于 0 或大于 22”，类型 25 提前返回后不会落入该段。记录新哈希，自检的保护版比对加入类型 25。

## 上屏合成的选择

`CompositeLayersToBackBuffer` 与平移帧的合成处统一为：

| L1 | L0 | 做法 |
| --- | --- | --- |
| 空 | 空 | 只拷贝 L2，不跑合成 |
| 有 | 空 | 单层合成 L1 |
| 空 | 有 | 单层合成 L0 |
| 有 | 有 | 现有双层合成 |

调试用的有序合成模式（类型 2）保持走双层。调试底板、白板纹理、粒子、激光主体、光标的顺序不变。

## 抬笔

### 路径 B（通用）

L1 里各触点的前缀已被 MAX/MIN 合在一起，无法单独取出某一笔，所以这一笔按入库笔画整笔重画；但用 L0 当隔离工作区，不清 L1 来重画。

```
 ① CPU 定稿并写入文档、登记历史（现有顺序不变）
 ② 清 L0（登记入口）
 ③ 最终整笔画进 L0，声明写域
 ④ 采集 L2 前像
 ⑤ 单层合成 L0 ──▶ L2（笔画矩形内）
 ⑥ 清 L0（登记入口）
     └─ 同帧还有别的笔结束 ──▶ 回到 ③，按现有遍历顺序（触点接纳顺序）逐笔进 L2，不改变现有先后
 ⑦ 清 L1（登记入口），重画仍在书写的各触点前缀
 ⑧ 重画仍在书写的各触点尾段与活动图形到 L0（与普通书写帧相同）
```

第 ⑦、⑧ 步继续由 `RebuildActiveLayers` 完成：它会遍历所有未结束的触点，包括等待断触续接、本帧没有重画的触点，按缓存的前缀、尾段和活动图形恢复两层；随后照旧补画焦点层和多步构造预览。只把它开头的两次整屏清除换成登记入口。

像素来源与现在相同（入库笔画整笔重放），结果应逐像素一致。

### 路径 A（快路径）

```
 ① CPU 定稿并写入文档、登记历史
 ② 清 L0（登记入口）
 ③ 从入库笔画的分界点起，只把最终尾段画进 L0
 ④ 采集 L2 前像
 ⑤ 双层合成 L1 ∪ L0 ──▶ L2（整笔矩形内）
 ⑥ 清 L1、清 L0，各一次
```

条件，全部满足才走路径 A，否则走路径 B：

1. 本帧开始时 L1 的内容只来自这一个触点：没有其他活动或同帧结束的非激光触点，没有待落定的焦点图形，L1 没有未知写入。
2. 这一笔不是图形，也不会留作焦点层。
3. 定稿（拟合、收尖、公切线约束全部完成）后的点列中，下标 0 到分界点这一段与**当时实际画进 L1 的点**逐点相同（位置与半径按位相等），且分界点下标未变。不能拿定稿结果与抬笔时的 `realPoints` 比：模型 Up 回退会覆盖 `realPoints.back()`，手掌晋升会替换整个笔画，公切线约束会反向改写分界点半径。做法是每个触点保存“L1 前缀指纹”：
   - 每次往 L1 追加或重画前缀时，对实际提交的点（x、y、r 的位模式）累加 64 位哈希，并记下最后一个已提交点。
   - 追加时先核对本批起点与记录的最后一个已提交点按位相等，不等则把指纹标为“不精确”。
   - 画进 L1 的内容不是这些点的线段时（橡皮只有一个点时画的右伸短胶囊、没有真实点时的落点兜底）标为“不精确”。
   - `DrawStablePrefix` 整段重画前缀时按重画的点重新计算指纹。
   - 抬笔时对定稿点列的前缀算同一哈希并比较；“不精确”或不相等都走路径 B。
4. 橡皮：把抬笔帧尚未提交的真实点经同一个提交函数补进 L1（同样更新指纹）后，按“尾段为空”处理，第 ⑤ 步改为单层合成 L1。
5. 荧光笔：定稿不改点列，条件 3 恒成立；尾段是不含预测的真实尾段。

追加条件（实现与审查中补充）：

6. L1 内容世代：渲染器对 L1 的每次清除、未声明范围的绑定、绘制后补登记、标记未知、纹理重建都递增一个世代号；书写中“声明写域的绑定”不递增。触点起笔（或整段重画前缀）时 L1 必须为空并记下世代，之后每次追加与抬笔时世代都必须不变。这排除历史直接回放等留在 L1 的残留。
7. 入库坐标往返：入库坐标 = 局部坐标 + 画布偏移，重放时再减回。定稿点列必须逐点往返还原（偏移为 0 时恒成立）；否则 L1 里按局部坐标画的前缀与日后的整笔重放在抗锯齿边缘可差十几级，荧光笔的去重划分也可能不同。
8. 荧光笔不用点指纹，改用“已画进 L1 的图元列表恰为整笔图元列表的前缀”（按位比较），避开 0.25 像素去重在分批与整笔之间的划分差异。

满足全部条件时路径 A 与整笔重放逐字节相同，验收容差为 0。画布平移后偏移通常带小数，路径 A 主要在屏幕批注和未平移的白板上生效，其余情况走路径 B。

### 各入口

| 入口 | 做法 |
| --- | --- |
| 普通抬笔（笔、硬笔、荧光笔、橡皮） | 路径 A 或 B |
| 同帧多笔结束、另一指仍在写、边擦边写 | 路径 B |
| 图形抬起 | 路径 B 去掉 L1 部分：最终对象画进 L0，单层合成，清 L0；L1 不动 |
| 自动进入编辑的图形（焦点层） | 不进 L2。抬笔时先在 L0 栅格一次但不合成（验证栅格成功后才发布待编辑对象），共享层重建后再由焦点层绘制画进 L1 |
| 多步构造的中间步骤 | 不进 L2；不清 L1；L0 走登记入口 |
| 取消、零面积图形 | 不进 L2；只清理该触点留下的内容，再重建仍在书写的内容 |
| 激光抬起 | 不碰 L1、L0 |
| 重做（20393 行附近） | 入库笔画画进 L0，单层合成进 L2，清 L0。L1 仍在前后各走一次登记入口：补背景和失败回滚会进入历史直接回放，它把最后一笔留在 L1（`Draw3.InkHistoryGpu.cpp` 775–791 行），不清掉会在下一次上屏重复盖到 L2 |
| 焦点层落定 | 改为单层合成 L1。现状用双层合成并默认 L0 为空，但多步构造存在时 L0 留有预览，可能被一并烘进 L2 |

`RebuildActiveLayers` 开头的两次整屏清除改为登记入口。失败路径（栅格失败、合成失败、可见性登记失败）保持现有回滚语义，清除改为登记入口。

## 图形临时层

`DrawShapeRenderData` 中 `shapeCompositeLayer_` 每个对象整屏清一次、`shapeMaterialLayer_` 每个材质组整屏清一次，而后续合成只在图形矩形内。两处改为只清该图形矩形（支持 ClearView 且矩形不超过 1/16 屏时清矩形，否则整屏清）。`DrawOrderedLegacyShapePrimitive` 的整屏清与整视口合成收进图元外包矩形。临时层是私有的，不走 L0/L1 的登记结构，按“上一次写域”就地判断即可。

## 窗口交接（B2）

现状：状态线程先设穿透样式，绘制线程在隐藏的目标窗口上准备全帧，状态线程等到就绪后用一次 HDWP 批量“显示新窗 + 隐藏旧窗”；失败分支会先两边都隐藏再显示目标。

改为两段回执：

```
请求切换 ──▶ 目标窗口准备全帧（旧窗保持显示）
          ──▶ 只显示新窗（旧窗仍在）
          ──▶ 确认上屏：辅助窗等一次系统合成；主画布显示后重新呈现一帧且未被遮挡
          ──▶ 复核场景、页面、输出版本仍是这次请求
          ──▶ 隐藏旧窗，回收资源
```

- 第一段（目标窗口仍隐藏时的准备）保持现状：隐藏主窗的呈现可能返回 `DXGI_STATUS_OCCLUDED`，这里仍视为“已准备”，否则新窗永远不会被显示。第二段（显示之后的确认）才要求未被遮挡的呈现；同版本的旧就绪标志不能充当第二段回执。
- 版本过期时保留仍有效的一方并按新请求重新开始。上屏确认每次期限 1 秒、最多 3 次；耗尽后退回原先的直接成对切换（最坏情况与改动前一致），不停在“模式已切、窗口未切”。两段交接的正常路径上不出现两边同时隐藏。
- 同一工作区内翻页不走两段交接：旧窗此时显示的是上一页，叠加比一帧空白更糟。
- 半透明场景下短时叠加可接受（用户明确同意）。
- 不改 A2 的呈现方式自动选择与调度策略；白板、空页、主 ULW 单窗保持各自的显隐语义。

## 粒子的预留

本轮不改粒子代码。约束只有两条：帧内顺序保持“L2 拷贝 → 墨迹合成 → 粒子 → 激光主体 → 光标”，空层跳过只跳过墨迹合成那一次绘制；粒子脏区继续并入同一个帧脏区。四处关闭开关、强制关闭的自检断言、初始化时创建的计算着色器资源保持现状。

## 诊断计数

为验收清除次数，在渲染器里加一组只增不减的计数：整屏清、矩形清、跳过、双层合成、单层合成、合成跳过；控制器里加路径 A、路径 B 命中数。计数只在无窗口自检和调试输出中读取，不进入发布版的热路径分支判断。
