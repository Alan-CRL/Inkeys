# 设置窗口触摸与笔输入框架（父任务）

## Goal

设置窗口目前完全依赖 ImGui Win32 backend 处理系统派生的兼容鼠标消息：触摸长按会被系统转成右键、还有系统触摸/笔点击视觉反馈，组件页（卡片长按起拖）上尤其容易误触发右键。本任务让设置窗口按主栏的输入框架接入触摸与笔，最终以带设备类型的事件导入 ImGui，并把页面拖动滚动封装成独立模块、屏蔽鼠标拖动滚动、为触摸/笔提供惯性。

独立顶层任务（用户 2026-11-26 确认），不挂在中期重构或组件编辑器父任务下。

## 来源需求（用户原话要点，2026-11-26）

1. 设置页（有组件拖动支持）触摸很容易触发右键。给设置窗口像主栏窗口一样禁用触摸右键反馈和触摸点击反馈。
2. 将触摸和笔消息通过 HiMsg 处理（和主栏一样），支持触摸长按、笔操控等，完全按照主栏的框架来；处理完最后导入 ImGui 的消息输入，并且可以区分设备类型。
3. 封装页面滑动部分的 ImGui 代码，屏蔽鼠标滑动；对触摸和笔滑动提供滑动惯性，参考其他软件和 WinUI3 的惯性。

### 用户补充决定（2026-11-26）

- 笔悬停（笔尖未接触）保留 ImGui hover 反馈，以 Pen 来源导入；只丢弃接触阶段的兼容鼠标副本。
- 惯性/拖动越过页面顶部或底部：ImGui 内容在边界硬停，越界量学习文件资源管理器，用窗口整体位移表示阻力（折中方案，不做内容橡皮筋）。
- 本任务为独立顶层任务。

## 任务映射

| 子任务 | 交付 | 依赖 |
| --- | --- | --- |
| `11-26-setting-touch-feedback` | 设置窗口不再出现系统触摸长按右键、触摸/笔点击及长按视觉反馈 | 无，可最先独立完成 |
| `11-26-setting-pointer-route` | 触摸/笔接触按主栏框架（Pointer 解码 → 路由上下文 → 值型样本 → 消费者）进入设置，HiMsg 过滤派生鼠标；以 `AddMouseSourceEvent` 区分设备后导入 ImGui；对外提供活动接触的样本轨迹 | 建议在 touch-feedback 之后；不依赖其代码 |
| `11-26-setting-scroll-inertia` | 页面拖动滚动封装为独立模块；鼠标不再拖动滚动；触摸/笔拖动滚动带惯性；越界用系统 panning feedback 窗口位移 | 依赖 pointer-route 提供的设备类型与样本轨迹 |

顺序：touch-feedback → pointer-route → scroll-inertia。每个子任务单独规划、实现、检查、提交和归档。

## 跨子任务验收

- [x] 设置窗口任意页面（重点组件页）触摸长按：不弹右键菜单、不触发任何右键语义、无系统长按圆环/点击涟漪；组件卡片长按仍能抓起。
- [x] 触摸、笔、鼠标三类输入在 ImGui 中 `io.MouseSource` 分别为 TouchScreen / Pen / Mouse，现有按设备分支（组件起拖阈值、hover 动效只对鼠标等）行为正确。
- [x] 笔悬停有 hover 反馈；触摸抬起后没有残留 hover。
- [x] 鼠标在正文空白处按住拖动不再滚动页面；滚轮、滚动条拖动不变。
- [x] 触摸/笔拖动滚动跟手，快速甩动后有惯性并自然减速；惯性中再次按下立即停住且这次按下不激活下方控件。
- [x] 拖到/惯性撞到边界时内容不越界，窗口整体按资源管理器方式位移并回弹。
- [x] 标题栏拖动窗口、标题栏按钮、缩放边框的触摸/笔操作不受影响。
- [ ] Win7 SP1 + KB2670838（无 Pointer API）退回 WM_TOUCH/兼容鼠标路径仍可用，不崩溃、不卡住按下状态。
- [x] 主栏与分页（五窗路由）行为、日志与现有测试不回归。

## 约束

- 兼容 Windows 7 SP1 + KB2670838；MSVC v143 / C++20；Win8+ API（`GetPointerInfo`、`SetWindowFeedbackSetting`）一律动态获取。
- 设置窗口位于独立的 setting owner 线程，五窗触摸路由（`UiTouchRouting`）的登记表属于 overlay 线程且无锁，不得把设置直接登记进去或跨线程访问。
- 最小化修改；不改主栏/分页的输入行为；不修改 HiMsg 库本身。
- 改动的 `.cpp/.cppm/.h` 保持 UTF-8 BOM + CRLF。
- 规划阶段不改代码；实现在各子任务 `task.py start` 之后进行。
