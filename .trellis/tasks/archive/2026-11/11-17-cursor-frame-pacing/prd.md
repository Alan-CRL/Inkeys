# 第2步-A2 绘制时光标跟随画布帧率与压力测试工具

> 状态：规划完成，**待用户批准后开工**。父任务 `11-17-win7-ulw-presentation`；分支 `refactoring/draw`；位于阶段 A（`11-17-dcomp-waitable-latency`，已提交 `0c8a7337`，仍 in_progress）之后、阶段 B 之前。
> 依据：`../11-17-win7-ulw-presentation/research/hover-cursor-layer-20261117.md`（§1.4–§1.7 读码结论与用户决策）、`../11-17-dcomp-waitable-latency/research/field-test-20261117.md`（实机日志分析）。

## Goal

1. 鼠标按下（绘制）期间，光标移动不再逐个打断画布帧节拍，绘制帧按预设帧率运行，与笔一致。
2. 输入被拒收（不出墨）时，鼠标光标、笔光标以及有光标的触摸光标仍然跟随移动，节奏同样是画布帧率。
3. 设置 → 性能新增“绘制时鼠标移动不受画布帧率限制”（默认关），打开即恢复现状行为。
4. 提供一个手动使用的 CPU/GPU 压力工具：打开即持续施压，关闭窗口即停止；不进自动测试，不需要熔断注入。

## 用户已确认的决策（2026-11-17）

- 采用方案 A：接触中（绘制时）光标跟随画布帧率；两条鼠标处理分支（RTS 模式主消息分支、Win32Mouse 兼容模式）都遵守。
- 鼠标笔迹采样率随之降为预设帧率（每帧消费一次最新快照），与笔、触摸一致，**符合预期**（推荐预设为 120 FPS；设成 30 FPS 说明设备性能或显示器本身就低）。
- 悬停（未按下）保持按事件唤醒，不限速。
- 新选项名称：“绘制时鼠标移动不受画布帧率限制”，附说明文字。
- 预测尖刺在对照复测中未复现（用户推测与日志写入跟不上有关），本任务不处理预测。
- 压力工具只做施压，不做熔断/故障注入。

## Requirements

### R1 鼠标接触中不打断帧节拍

- 鼠标在按下期间的**纯位置变化**只更新光标信箱并发出“不打断帧节拍”的唤醒；按下、抬起、有效性变化仍使用现有的打断式唤醒。
- 两条鼠标分支都汇合到 `WindowController::PublishMouseCursorSample`，只在此处改条件，不分别改两个消息分支。
- 移动模式（CanvasPanMode）、选择模式现有行为不变。

### R2 拒收时光标仍按帧率跟随

- 无活动笔画但有处于接触中的光标（鼠标、笔）时，帧循环按预设帧间隔渲染光标帧（每个帧间隔最多一帧），落笔/抬笔仍立即唤醒。
- 笔光标在接触中也改发“不打断帧节拍”的唤醒（现在完全不唤醒，拒收时光标会停住）。正常绘制时不改变笔的帧节奏。
- 有光标的触摸（触摸软/硬笔光标、触摸橡皮光标）在被拒收时也显示并按帧率跟随（单独步骤，见 design §4）。
- 拒收范围（按 Claude 建议，开工前请在批准时确认）：
  - 显示光标：① 准入阻塞（工作区切换、快捷键租约等）；② 关闭多指时多出来的手指。
  - 保持现状：③ 手掌判定；④ 触摸平移期间抑制笔；⑤ 选择模式；⑥ 笔兼容鼠标消息抑制。

### R3 设置项

- 配置键 `Experimental.Inkeys3.Draw3.UnthrottledMouseMoveWhileDrawing`，`bool`，默认 `false`，**即时生效**（不需要重启；若实现时发现现有状态下发链路无法即时生效，再改为重启生效并在汇报中说明）。
- 性能页“渲染与兼容”节，排在“waitable 模式下启用等待”之后。zh-CN 文案见 design §5，其余 19 种语言由 Claude 补译。
- 打开后语义：鼠标按下期间的位置变化恢复为打断式唤醒，**整帧**（墨迹与光标）按鼠标报点率刷新，鼠标笔迹恢复高采样率，GPU 负载随之上升；说明文字需写明。

### R4 压力工具

- 独立的 Win32 + D3D11 小程序（单个 `.cpp`），由脚本调用本机 Visual Studio 工具链编译，产物放在已忽略的 `Build/` 下；**不加入** `InkeysRepo.sln`、不进 CI、不进自动测试。
- 打开即开始施压（CPU 忙线程 + GPU 重负载像素着色器），关闭窗口即停止并退出；窗口内实时显示当前强度与实测数据，可用按键调节强度、暂停/继续。
- 默认构建 ARM64，可选 x64（便于拷到其他测试机）。产物只依赖系统 `d3d11.dll` / `d3dcompiler_47.dll`。

## 非目标

- 不改悬停帧节奏（记录在案，阶段 B 实测后再议）。
- 不处理预测尖刺、多矩形脏区、光标分层、大橡皮合成成本（属第5步）。
- 不改阶段 A 的 waitable 逻辑与参数。
- 压力工具不做熔断注入。

## Acceptance Criteria

- [ ] 预设 30 FPS、鼠标快速书写：画布调试帧率接近 30（现状会明显高于 30）；打开新选项后恢复高帧率。
- [ ] 鼠标/笔按下、抬起的首帧延迟不变；正常鼠标/笔书写时光标与笔迹同步。
- [ ] 准入阻塞期间按住鼠标/笔拖动：光标按帧率跟随，不出墨；关闭多指时第二根手指（软笔/橡皮且触摸光标开启）光标跟随、不出墨。
- [ ] 手掌、触摸平移、选择模式、移动模式、鼠标速度橡皮回缩、鼠标激光行为与现状一致；橡皮 F3 idle 交接合同不被破坏。
- [ ] 悬停行为与现状一致（仍按事件唤醒）。
- [ ] 新增/更新的无窗口测试全部通过；相关既有测试（光标/唤醒/鼠标兼容/橡皮 idle）按新预期更新并通过；`InkeysRepo.sln` Debug|ARM64 构建通过；i18n 检查通过。
- [ ] 压力工具：脚本一键编译运行；打开即施压，窗口显示强度与实测；可调；关闭窗口后进程与线程全部退出、GPU 负载归零；长时间运行无 TDR（单次绘制有耗时上限）。
- [ ] 规范更新：`draw3-cursors.md`、`input-and-ink.md`（唤醒合同）、`settings-performance-and-drawing.md`（新选项）。
