# 屏幕尺度阶段方案（待用户评审）

## 1. Goal / 状态

用户要求接续屏幕尺度适配并先给方案。本轮仅调查与设计，不改生产代码、不编译、不GUI、不commit/push。当前HEAD为4b4edb91；工作区开始时干净，现有Mouse/Touch手感已获用户确认。本阶段仍沿用原任务in_progress，不能因已有状态直接开始下一阶段实现。

目标：以已确认的本机手感为标定基线，让直接Touch在不同分辨率/系统缩放下具有一致、可解释的动作尺度，同时提供桌面与大屏的不同响应。Mouse保持现有DIP策略；笔保持hover/落笔停止，不增加笔拖动。

依据：research/scale-stage-units.md、research/scale-stage-integration.md；旧display-scale-audit.md的单位原理仍可参考，但其中Physics/PPI96数值不再是当前产品。当前产品合同为.trellis/spec/native-desktop/canvas-pan.md。

## 2. 当前事实

- 当前唯一产品内核为可靠尾段估速、向量摩擦、当前残余投影，tau=.30s、c=1000 DIP/s²、模长上限12000 DIP/s。Physics/Legacy是参考组件，固定ppi96不参与当前产品摩擦。
- CanvasPanScale只含两轴DIP/px，Register在无contacts且无fling时锁存；已有DisplayScale含物理尺寸/映射/输出/旋转/revision，但pan尚未消费。
- 产品paintDevice仅0/1：Host映射为LargeScreen/Laptop，没有现成Automatic模式UI。橡皮的解析函数支持Automatic，不等于设置已有第三项。
- 显示revision也会因橡皮debug或非当前输出的更新改变，不能把任一revision增长都当作应停止pan的事件。
- 本机实际可信rhoX/rhoY、来源映射、当前模式尚未取得，不能从测试fixture/旧日志模拟值推断。

当前摩擦公式下，相同500mm/s、未触限的代数对照：

| mm/DIP | 滑行mm | 停止s |
| ---: | ---: | ---: |
| .166666667 | 114.032 | .719369 |
| .234375 | 105.846 | .627970 |
| .390625 | 91.591 | .498419 |

主会话已用独立Python公式计算，非设备实测。这说明当前已比旧平方模型稳健，但DIP仍不能代表真实物理尺度。

## 3. Requirements / 拟议验收

- S1 已确认参考设备、参考模式上的正常拖动/释放/连甩不应无意改变；当前稳定内核、输入顺序、停止和高频保护继续保留。
- S2 直接Touch的整条平移动作采用同一物理尺度，包括首次slop、反向证据、估速、释放/boost门限、摩擦和上限；Mouse继续系统DIP。此条明确扩展到起步门限，不只修改滑行距离，需用户确认。
- S3 手按住时内容像素位移与手指像素位移1:1；起滑扣除及多指基线按选定统一尺度计算。不能只为大屏滑远就放大释放初速。
- S4 相同可信物理轨迹、相同解析场景参数，在改变分辨率/系统DPI后，物理释放速度、滑行距离、时长和门限应一致；场景参数不同造成的体验差异单独验证。
- S5 桌面/大屏有明确不同参数，物理长边提供连续权重；不复制两套输入/估速/控制器，不直接搬橡皮速度或面积数值。
- S6 标尺或映射不可信时回退可诊断DIP；不伪造PPI或毫米，不将外置板的动作解释为显示器毫米。
- S7 同批次锁存单位/模式；实际输出、映射或单位变化停止旧导航，旧残余/样本不得跨域；非当前输出或橡皮调试变化不能误停。
- S8 现有诊断能解释来源、单位、模式、标定版本、阈值与最终曲线；关闭仍无高频格式化。

## 4. Reference：保护当前电脑基线

推荐将当前电脑作为一次性的开发标定参考，而不是直接写死25.4/96 mm为一单位：

1. 先在现有行为不变的条件下，采集当前输出的真实InputSource、DIP/px、可信mm/px、物理长边、用户模式与解析w_ref。记录证据，排除模拟/复制屏/未知映射。
2. 近等比标尺下设rho_ref为参考机mm/DIP，固定参考模式w_ref与版本。后续所有设备使用相同已选基准，不在各机首次运行、每次启动或EDID刷新时自动重选基准，也不自动修改用户配置。
3. 参考机Touch输入v_U=v_px*m/rho_ref；在参考机m≈rho_ref*dipPerPixel，因此与原v_DIP一致，当前15/1/30/150/350/12000及1000可作为参考单位参数沿用。时间参数保持原秒值。
4. 标量rho_ref不能在显著各向异性下同时精确复制旧DIP两轴。应先检查测得差异及尺寸精度，在校准容差内对照；显著异向的参考数据不能静默取平均后承诺完全保持，先回退或单独评审。普通目标设备仍保留每轴mm/px独立换算。
5. 若本机无可信物理标尺，不能承诺零体验漂移：保持DIP基线，先补采集证据/必要的显式物理测量，再选参考值。固定0.264583或橡皮0.25仅可作离线对照，不能冒充已确认硬件事实。

场景参数同样必须在w_ref处归一化。即使参考机当前选大屏，也不能直接给它乘1.2后声称原样保持。

## 5. Coordinates：统一入口/出口，避免单位混用

### 5.1 推荐路径

```text
Touch物理像素 -> 每轴mm/px / rho_ref -> 参考运动单位U -> 现有产品内核 -> 每轴逆变换 -> 物理像素
Mouse物理像素 -> 现有系统DIP/px        -> 系统DIP       -> 现有产品内核 -> 现有逆变换 -> 物理像素
```

每批由ResolvedPanContext明确单位，不在每个触点、每一帧临时切域。

- Touch：q_x=m_x/rho_ref、q_y=m_y/rho_ref；输入p_U=diag(q)*p_px，输出d_px=diag(1/q)*d_U。线性变换与质心可交换，几何差分经逆变换保持1:1。
- 同一标量进度的向量曲线经逆变换仍保持像素释放方向，不重新引入逐轴平方。
- 15+.05起步、.1滚动epsilon、1反向/末段证据、30释放、150/350续接、12000上限以及1000摩擦均在U中使用；必要像素量化误差界也在同一单位计算。
- 50/20/30/70/40/2/1ms等窗口、QPC、tau不乘屏幕倍率。
- 1U几何证据需同时考虑设备像素量化下限；大屏噪声参数可标定，但不能把新抖动阈值与单位换算混为同一变化。

### 5.2 必须全部处理的出口

- delta U -> px ->现有viewport，世界安全范围/页面/存储/背景仍遵守现有合同。
- contentVelocity U/s -> px/s给tile/预取，再乘systemDipPerPixel得到系统DIP/s给blur/其它现有消费者。
- CanvasPanInput::VelocityDip/VelocityPixels、Frame.velocityDip/velocityPixels均需按其名字返回真实对应单位，不能直接返回内核U。
- focus/span、raw/selected/boost速度、fling offset等日志明确标unit；可信时额外记录mm/s。不让v-content-dip字段装U。
- viewportSizeDip等因为单位变化不再准确的接口必须明确更名/标注，仅改受本次单位语义影响的字段。默认DIP单元测试入口继续可运行；参考Chromium组件不改。
- 不把blur的300/6000/12、viewport保护值、像素tile尺寸一起缩放；它们属于显示或安全域。

## 6. Profile：桌面、大屏响应候选

复用现有全局桌面/大屏模式选择，不新增Automatic产品选项。以橡皮320–1200mm平滑长边权重为初始场景分类，再施加既有显式模式约束（桌面w≤.25、大屏w≥.25）。它是响应先验，不参与真实毫米换算。

第一版只给统一内核传少量PanFlingTuning：tau、c。残余投影增益保持当前1，不为了场景分类同步更换连甩策略。可靠估速算法和时间窗口不因设备切换；模长上限先保持12000U/s，不增加峰值速度。

| 行为段 | 桌面目标 | 大屏目标 |
| --- | --- | --- |
| 慢拖/轻放 | 保持当前精细定位、短尾 | 同样精准，不因大屏一律滑远 |
| 正常甩动 | 当前手感作为参考 | 连续平滑过渡，避免力度稍变即跳档 |
| 明确快速甩动 | 适度续滑 | 较长行程，但增长饱和、峰值不提高 |
| 同向连续甩动 | 当前残余投影及上限 | 保留同一受限残余策略，峰值不上调，场景差异先由减速参数提供 |

初始标定候选（不是已验证最佳值）：快速大屏相对桌面tau最多+20%、c最多−20%，低速保持基线；若参考模式恰是桌面端，端点对应tau .30→.36、c1000→800。高档动作速度区间可先在参考1000–4000U/s基础上随w最多提高约50%，避免把大屏正常手臂动作全判为猛甩。具体值先重放、再用户实测裁决，不写成固定兼容承诺。

锚定形式：tau=.30*F(w,s)/F(w_ref,s)，c=1000*G(w,s)/G(w_ref,s)。F/G在速度和w上连续、有界，分母正；F在1..1.2、G在.8..1为初始候选范围。跨全部可能w_ref时归一后的tau可达.25.. .36、c可达800..1250；.30→.36/1000→800仅是参考点在桌面端点时的例子。这样w=w_ref时整条速度范围仍等于旧参数，不只校准某个速度点。

若后续要额外削弱大屏残余增强，需要单独用实测评审：参考机若已在大屏端，不能同时保它旧增益1、要求所有增益≤1并严格让桌面更强；首版不做这个不必要的取舍。

速度s取可靠selected手速（boost前），避免boost自我放大选参。每次释放选定并锁存本条fling参数；滑行中不随速度降档重建曲线。下一次Down仍立即停止，下一条fling可以重新选参。

## 7. Facts与橡皮策略隔离

建议纯解析ResolvedPanContext(display事实, source, userMode, reference)：保存输出身份/边界/旋转、systemDipPerPixel、可信mmPerPixel、unit/unitsPerPixel、mode/w、referenceVersion、fallbackReason。

- 复用已有来源映射和物理有效性校验，优先提取小型纯校验helper；保持橡皮原响应/数值不变并用现有测试证明。也可使用仅事实的适配层，不把完整EraserConfig作为pan配置。
- 不采纳橡皮DevelopmentOptions的response override、penBeta、面积、灵敏度或橡皮专用ManualSurface作为平移真实标尺。若将来需要共享手动校准，应先明确归属，不把调试override默默迁成全局事实。
- 在现有WindowController同锁下取得display事实与mode，避免分次读取拼装；不要求重构全局显示服务。
- 第一指锁存本批上下文；后续同输出兼容来源使用同一坐标域；不兼容/映射冲突的新来源沿已有DiscardUntilTerminal准入处理，不能切换当前批次的单位。
- 根据有效签名判断变化：当前monitor/输出bounds/分辨率/旋转/system DPI/有效物理密度/映射/模式/referenceVersion。变化先Stop并吞旧触点至终态，后续新手势解析新值。原始snapshot revision、橡皮debug变化、别的monitor无关变化不能触发停止。
- RTS来源映射随显示热插拔刷新是否完整，需要在实施预检中核对；输出签名变化后不得继续采纳旧映射为可信物理事实。若刷新未完成则DIP回退/拒收，直到事实可验证。

## 8. Fallback与输入边界

| 条件 | 策略 |
| --- | --- |
| Touch +可信输出映射/物理尺寸 | 物理参考U，桌面/大屏profile |
| Touch + EDID缺失/复制屏/映射未知/无快照 | 明确DIP回退，场景选择仍有效，记录原因，不声称物理一致 |
| 大屏Touch无物理尺寸 | 可沿用有界DPI/分辨率启发式辅助动作强度；只影响选参，不伪造mm、不乘几何和释放初速 |
| Mouse | 原系统DIP和当前响应，不因大屏/EDID切换Touch增益 |
| Pen/外置数位板 | 保持既有停止/非平移准入，本阶段不实现它们的独立平移profile |

大屏fallback具体启发式系数属于后续标定项；第一段单位实现默认严格DIP回退，不以估算密度启用物理域。鼠标既有capture/cancel/source隔离持续回归。

## 9. Diagnostics

沿用现有CanvasPan开关，增加按上下文变化/手势开始输出：mode、resolvedProfile/w、source/context/generation、monitor/输出、DIP/px、可信mm/px、units/px、reference版本和值、scaleSource/fallbackReason。

释放时输出raw/selected/boost前后U/s、px/s、系统DIP/s及可信mm/s，所选tau/c/residualGain、理论目标距离/时长、限速/限位与Stop reason。时序仍区分sample/frame/consume；物理尺度日志与输入历史/输出队列丢弃独立。

## 10. Implementation plan / 最小步骤

A. **参考采集与纯解析**：先只补事实解析/诊断，不改变生产运动；取得当前参考值/模式，处理各向差与可信度。若本机没有可信数据，明确阻塞的是标定值，不凭猜测启用物理默认。
B. **Touch统一单位闭环**：引入上下文、入口/全部出口、起步与估速单位、签名变化Stop；本段F/G均保持1，先证明当前设备不退化和分辨率/DPI不改变同一物理轨迹。
C. **桌面/大屏响应**：加入有界连续选参并在w_ref归一；逐段对照，不同时再换估速/输入队列/曲线族。必要时先通过诊断比较参数，不新增调参设置页作为前提。
D. **整合与实测**：保留4b全套防回归，补尺度矩阵和真实生产入口；ARM64 solution+无窗口测试后由用户实测桌面/大屏。后续commit需本阶段另行授权，先前提交授权不延续。

预计文件：CanvasNavigation.cpp/.cppm（可注入的friction/boost参数与单位合同）、DrawingController.cpp（上下文/全部出口/Stop/诊断/生产probe）、WindowControl.cpp/.cppm（一致display+mode快照）、必要的Host接线、SpeedEraser/PalmEraser周边仅小型共享校验、现有Headless测试。除非实际缺少工程登记，不动solution/vcxproj；不改显示枚举算法、输入后端或第三方。

## 11. Verification

1. 当前参考设备与4b：相同输入轨迹在参考模式下，对比slop越限、逐帧几何、释放/残余速度、总距与时长；标尺近等比误差必须明确记录，不能虚称位级一致。
2. 同一物理屏幕/手势在100/150/200/300%DPI及不同分辨率/横竖屏：单位与方向闭环、起步长度/物理距离/时间一致；Mouse按系统DIP合同另验。
3. 桌面、大屏及中间权重：慢拖定位、普通甩、快甩、连续同向、短反向、末段减速；边界连续，无初速跳增，无跨域旧boost。
4. EDID失效、复制屏、source错配、跨输出/尺寸/模式变化：fallback原因可见，Stop后旧触点不复活；仅橡皮debug/别屏snapshot变化不误停。
5. 异向密度、像素量化、高报点率960Hz/10MHz、1DIP/2ms边界：正确转换不破坏当前反向/压缩保护。
6. `InkeysRepo.sln Debug|ARM64`原生MSBuild、Headless --no-window及canvas-pan-only、control-fence、pan-feel、diagnostic-output；原37文件编码/EOL约束持续。GUI/Computer Use仍需明确授权，不自动启动。

## 12. 评审选择与未标定数据

推荐：以当前电脑及当前模式为固定参考，采用整条Touch平移物理尺度（含起步门限），Mouse保持当前响应，桌面/大屏独立有界选参。

另一种较窄范围是仅适配惯性、保留起步15系统DIP；风险较小，但屏幕之间开始拖动所需的真实毫米仍不一致，不能称整条手势完成尺度适配。本方案推荐前者。

待实际采集的是rho_ref、w_ref及其可信证据；候选大屏参数需重放与用户体验确认。当前没有新生产实现或编译结果。本文件是本轮供评审的完整方案，不覆盖已提交4b实现合同，也不表示已获下一阶段编码批准。
