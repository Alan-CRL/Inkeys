# 多指大橡皮卡顿调查（2026-11-23）

起因：有用户反馈多指大橡皮严重卡顿，单指大橡皮好得多；用户怀疑存在重复计算和渲染，并指出橡皮与荧光笔的重叠区域似乎可以优化。

基线 `refactoring/draw@cbcccf9a`。只读调查，未运行、未实测。路径省略前缀 `Inkeys/Inkeys/Drawing/Draw3/`，`DC` 指 `Draw3.DrawingController.cpp`。行号为调查时的值，脏区统计接入后 `DC` 中 24098 行之后的行号后移约 20 行。

标注：**[读]** 直接读到；**[推断]** 由代码推出。主体由只读子代理读码得出；主 Agent 复核了抬笔路径选择（`soleInkContact`）与 `RebuildActiveLayers` 的清层和整条前缀重画，一致。

## 结论

1. **稳态帧没有重复渲染**：每个橡皮接触每帧只画自己的新增段，N 指就是 N 份，线性增长。没有“每个接触重画全部接触”，也不会每帧重建。
2. **抬指帧有成倍的重画**：只要除激光外的运行时不止一个，任何一指结束都走路径 B：结束的那一笔整笔重画，其余仍按下的接触从起笔到现在的全部前缀也重画。单指抬笔走路径 A，只画尾段。
3. **大橡皮把第 2 点放大了两个数量级**：橡皮每一小段都要画一个约“直径 × 直径”的方块，相邻段几乎完全重叠。整笔重画就是把几百个这样的方块再画一遍。
4. 多指时外接矩形趋近整屏（本任务的主题）是另一项放大，作用在合成与呈现上。

## 事实

### 稳态帧 [读]

- 每个橡皮接触每帧一次 `CommitEraserRealPointsToL1`（DC:24830-24838）：一次绑定 L1 的 Add、Retain，一次顶点上传，一次常量更新，一次绘制（`Draw3.StrokeGeometry.cpp:2818-2821`，`Draw3.RendererPrimitives.cpp:58-113`）。各接触不合批。
- 只画新增段，带一个重叠端点（`Draw3.StrokeGeometry.cpp:2791-2792`）。没有新点直接返回。
- 橡皮不预测，不写 L0。纯橡皮帧的 L0 清除因写入登记为空而跳过（阶段 B 已状态化）。上屏走单层合成。
- 活动期间没有每帧的 CPU 命中测试、笔画分割或历史瓦片失效。

### 每段的像素量

- **[读]** 每段是一个有向包围盒，尺寸 (段长 + r1 + r2 + 4) × (2·最大半径 + 4)（`Assets/inkVertexShader.hlsl:300-310`）。每个像素算一次距离场，写 Add（BGRA8）与 Retain（R16F）两张目标，混合为 MAX、MIN，需要读回目标。
- **[推断]** 直径 300 每段约 9 万像素，直径 600 约 37 万像素。段长远小于直径，新露出的面积只有“直径 × 段长”，其余都是重复覆盖。
- **[读]** 输出点率：60 帧档 240 Hz，120 帧档 360 Hz（`Draw3.StrokeGeometry.cpp:472-475`）。**[推断]** 移动中每接触每帧 3 到 4 段；直径 600 时每接触每帧约 150 万像素乘两张目标，5 指约 730 万。

### 抬指帧 [读]

- 路径选择：`soleInkContact` 要求 `active` 中除激光外恰好 1 个运行时（DC:25086-25088）。计数包含仅观察的手掌接触、等待断触续接的候选和已取消的接触。
- 单指（路径 A）：只把尾段画进 L0，L1 与 L0 一次并入 L2；随后的 `RebuildActiveLayers` 只清层。
- 多指抬一指（路径 B）：
  1. 清 L0。
  2. `DrawStoredStroke` 把结束的那一笔整笔重画进 L0（DC:25181-25184）。
  3. 单层合成进 L2，范围是整笔外接矩形。
  4. 再清 L0；大橡皮笔画超过画布 1/16，是整屏清。
  5. `CapturePreimage` 按 128 像素撤销瓦片从 L2 拷贝（`Draw3.InkHistoryGpu.cpp:1245-1263`）。
  6. `RebuildActiveLayers`（DC:6565 起）清 L1，对每个仍按下的接触调 `DrawStablePrefix` 重画整条前缀；橡皮的已提交位置始终是最新点，所以就是从起笔到现在的全部段。
  7. 历史修订号变化，整张 L2 拷贝到可信快照（`Draw3.RendererSnapshot.cpp:172`）。
- 触发“有接触结束”的不只是正常抬起：断触续接候选被淘汰或 80 毫秒续接窗到期、手掌激活时收掉邻近接触、仅观察的手掌接触退休，都算。

### 抬指帧的量级 [推断]

一条 3 秒、直径 600 的擦除约 720 段，整笔重画约 2.6 亿像素乘两张目标，约等于 1080p 的 127 屏。5 指中抬 1 指是 1 条结束笔加 4 条前缀，约 13 亿像素。5 指在相邻的不同帧先后抬起，共 5+4+3+2+1 条整笔重画。

### 其他 [读]

- 没有“多指整笔重画”的开关，整笔重画是路径 B 的固定行为。
- 多个触点不会合并成一个大橡皮，每个触点是独立的运行时。
- 橡皮尺寸变化、新手指落下、已是橡皮的接触晋升手掌，都不触发重建。
- 每个触摸橡皮接触一个光标，各一次绘制；精灵按外观缓存，不会每帧重新栅格化。光标脏区并入方式见 `dirty-current-state.md`。

### 荧光笔的层内语义 [读]

- 着色器输出 `add = rgb·α`、`retain = 1−α`（`Assets/inkPixelShader.hlsl:634-636`、`:693-697`）；层内混合是 Add 取 MAX、Retain 取 MIN，注释写明“整笔覆盖率只累计一次”（`Draw3.RendererPrimitives.cpp:148`）。
- 上屏时 L1 与 L0 取并集；落 L2 时每条笔画独立合成，`结果 = Add + Retain × 下层`（`Draw3.Renderer.cpp:217`）。
- **[推断]** 同一笔自交不加深；多笔同时活动且重叠时在 L1、L0 内也不加深；落到 L2 后才与其他笔叠加变深。与用户的说法一致。

## 多指相对单指额外放大的工作

| 项 | 性质 | 放大方式 |
| --- | --- | --- |
| A. 任一接触结束即整笔重画结束笔与其余接触的全部前缀 | [读] | 每次结束 = (1 + 剩余指数) 条整笔，每段约“直径²”像素 |
| B. 结束事件更频繁（N 次抬起，加上触点分裂合并、续接窗到期、手掌邻近收尾） | 触发路径 [读]；实际频率 [推断] | 每次都触发 A |
| C. 仅观察、等待续接、已取消的运行时也计入路径选择 | [读] | 手掌场景下只有一个真实橡皮也走路径 B |
| D. 稳态每帧填充：N × 每帧 3–4 段 × 约“直径²” × 两张目标 | 结构 [读]；数值 [推断] | 线性 |
| E. 外接矩形趋近整屏，合成与呈现（ULW 含 CPU 读回）按整屏 | 并入方式 [读]；后果 [推断] | 取决于手指间距 |
| F. 每次有笔入库：整张 L2 快照拷贝、撤销瓦片拷贝、瓦片足迹 CPU 计算 | [读] | 乘以结束次数 |
| G. 每帧 N 次绑定、上传、绘制与 N 个光标 | [读] | 线性，量很小 |

判断（未实测）：A 与 B、C 的组合最能解释“单指好得多、多指严重卡顿”，因为它只在多指出现，填充量比稳态帧高两个数量级。如果卡顿是持续低帧率而不是抬指、换指瞬间的顿挫，则更可能是 D 加 E，尤其在核显或 ULW 下。

## 不改代码的对照（待用户实机）

1. 多指大橡皮持续擦除、所有手指不抬，看是否流畅；然后只抬一指，看那一瞬间是否卡。再比较短擦后抬指与长擦后抬指：A 随已擦路径长度增长。
2. 多指并拢与分散到屏幕四角对比：只有分散时慢是 E；并拢也慢是填充量（A 或 D）。
3. 橡皮直径减半，A 与 D 都应降到约四分之一；固定直径改指数，D 应线性变化。
