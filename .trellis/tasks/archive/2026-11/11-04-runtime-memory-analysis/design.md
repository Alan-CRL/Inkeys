# 运行时内存调查技术方案

## 范围与阶段

本轮已完成安装工具验证、生产源码所有权梳理与候选排序；技术依据见 `research/memory-overview.md` 及三份专题报告。用户于2026-11-05已批准采样并直接实施低风险优化，Trellis实现阶段已获授权。以最新prd.md的架构、设备隔离、流畅度和高风险确认边界为准。

第一轮目标是确认大块内存来自哪里、何时分配、何时回落。优先沿用已有工具和探针，不创建新的构建系统或先改架构。

## 采样边界与数据流

```text
固定源码/二进制/符号/配置身份
  → 不带profiler运行：场景动作 → 时间戳/Private Bytes/Working Set/handles/threads
  → 同场景短时追踪：进程Heap/VirtualAllocation → ETL + 同一时间轴
  → WPAExporter表格，必要时VS原生快照/GUI
  → 对照源码资源账、分配栈、文档/缓存状态
  → 有证据的优化排序与最小改动方案
```

优先CLI、既有无窗口或离屏路径。用户已允许启动/操控本任务相关窗口，但明确不使用Computer Use工具；锁屏不尝试绕过，改用不依赖解锁的采样。PPT/Office与其他用户文档不纳入首次场景，不自行打开。

## 身份与一致性

- 固定当前commit、构建配置、ARM64架构、EXE hash及PDB GUID/Age；现有Debug产物不能仅凭存在或时间戳当作与HEAD匹配。
- 记录实际画布像素、屏幕/DPI、UI缩放/语言、硬件或WARP、DComp或ULW、功能选项和诊断开关。初轮使用现有默认，不擅自改兼容策略。
- 如需刷新构建，动态查找ARM64原生MSBuild，使用`InkeysRepo.sln`的`Debug|ARM64`，同一次PowerShell执行PATH规范化与node-reuse禁用；至少允许5分钟，不因短时无输出重启。
- 源码构建验证与性能基线分开。Debug适合归因；要判断发布收益，须以相同发布构建分别测before/after，不能将Debug/Release混作优化对照。

## 统计合同

| 指标 | 用途 | 不能作出的推导 |
| --- | --- | --- |
| Private Bytes / PrivateUsage | 进程私有提交量、场景稳态和峰值 | 不等于当前物理RAM，也不是所有图形系统成本总和 |
| Working Set，必要时private/shared拆分 | 当时驻留物理页，观察图像触碰和映像资源驻留 | 回落不必然说明对象释放；不得与Private Bytes相加 |
| 原生Heap存活分配/栈 | CPU对象、像素副本、vector容量、解析结构归因 | Heap表不覆盖全部VirtualAlloc、图形/系统侧分配 |
| VirtualAlloc reserve/commit和线程栈 | 大块提交、保留地址、高水位、线程成本 | 线程数量乘默认栈reserve不能当RAM使用量 |
| 图形资源描述和DXGI/ETW | 纹理数量、尺寸/格式、缓存页、硬件/WARP差异 | 资源payload/allocated slices不是OS residency，不能与进程指标重复累计 |
| 映像/映射与CLR | 字体资源页、模块加载、托管堆/JIT/GC结构 | DLL/PDB/字体文件体积不等于private heap；CLR堆属于进程统计的一部分 |

各表使用同一MiB单位（2^20 B）和单调时间/场景标记。像素公式只作为交叉核验。RTV/SRV与同一纹理的引用不重复计算。UI WARP与Draw3独立device分别建账，Office外进程与DWM成本另列。

## 首轮场景

| 场景 | 观测点 | 要验证的假设 |
| --- | --- | --- |
| 冷启动、桌面空闲 | 正常首次稳定帧、空闲30s/60s；未打开设置/未写字 | Freeze DIB、Setting resident、全屏图层和CLR是否已成为基线 |
| 设置生命周期 | 首开、打开橡皮演示、隐藏、再开；相同尺寸重复3次 | 未用资源是否预加载、关闭回收边界、atlas/预览高水位 |
| 普通笔与Laser | 空白页、固定笔数、Undo/Redo、新笔分支、Clear；首次选Laser/绘制/尾消失后 | 历史页阶梯、不可达分支、Laser按需资源及清空后回落 |
| 白板与桌面切换 | 首次进入、绘制/切页、退出桌面；重复3次 | Freeze DIB与背景target共存、冷页持有和隐藏backing |
| 后续独立场景 | 更大历史、保存峰值、PPT/Office、resize/设备故障 | 在首轮发现后再扩展；需要Office/桌面操作另遵循授权边界 |

固定动作、笔数与数据量后进行两次独立进程对照；出现不一致再定位启动/异步保存/堆高水位来源。首次运行与第二次热缓存分开记录，不为了回落而强制GC或修剪Working Set。

## 工具路径

1. 先做不带profiler的进程计数器基线，避免采集器本身改变结论。
2. 复用无HWND/GPU的`--draw3-history-benchmark`用于CPU历史增长；必要时再用已有无窗口字体专项。离屏WARP、隐藏HWND和完整产品的结果分开标记，隐藏窗口不等同no-window。
3. 使用固定版本WPR，目标限定Inkeys，优先短时file mode。Heap、HeapSnapshot、VirtualAllocation按目标问题分开采，不默认全开所有profile。
4. 完整启动分配栈需在目标启动前准备按进程名Heap配置；按PID快照仅解释配置后的分配。查询/保存原配置，结束后精确恢复。当前仅查询帮助，没有执行这些配置命令。
5. 用已有WPAExporter和合适的`.wpaProfile`导出目标表；若没有合适的profile或需要C++类型/对象细节，可在授权后操作WPA/VS。CLI help成功不替代真实ETL/堆栈有效性验证。

接受追踪数据前，确认目标PID、时间窗、Heap/VirtualAlloc记录确实存在，Inkeys调用栈能解析且检查丢事件数。若丢事件或符号不匹配，保留失败证据并纠正采集条件，不能据缺失数据宣称对象不存在。

## 开销、权限与恢复

本机WPR默认Memory模式配置的buffer数明显高于File模式，应记录trace开销、分开观察录制器和目标进程。追踪自身可能启用诊断sink或改变堆行为，所以未追踪基线始终保留。

WPAExporter/VS采集器帮助已在沙箱外验证；真正ETW/COM操作是否需额外管理员权限待实测。环境拒绝访问不触发产品源码/依赖修改。录制前确认没有他人WPR会话，只停止本任务创建的会话并恢复本任务改变的配置，不清理他人录制状态。

修改前保存基线和产物身份。代码只由实现子代理在明确文件边界内做低风险改动；需要诊断接缝时优先复用既有harness。回滚保留任务前版本，不动其他人的更改。采样结束关闭自有程序/会话并恢复本任务改变的诊断配置。

## 优化决策边界

采样后为前几项候选分别给出实际存活/峰值贡献、可回收时机、首次显示/Undo/切页延迟风险及功能回归清单。保持撤销、页面内容、视觉回退、语言fallback与PPT兼容合同。字体Alpha8、FT_Face共享、白板冷页、保存队列合并等既有机制不重复列作新方案。

低风险优化在源码及采样后直接实施，不承诺降低百分比。任何会改变L0/L1/L2、双device与WARP/hardware分工的方案均排除；可能将重分配/解码带入正常绘制、输入、首次显示或Undo/切页路径的方案留待用户确认。流畅度按用户要求仅作静态确认，不要求额外动态性能证据。

## 最新常驻优先策略

用户澄清：普通静止常驻为主，可自行回落的瞬时峰值宽松处理。候选1保存副本后置；候选2图片恢复副本、3Laser功能生命周期、4辅助输出真实活跃状态、5有效Freeze/白板/隐藏UI回收、6缓存页持有为本轮讨论重点。Laser选中时准备、离开时回收是已接受方向，活动接触/淡出/待提交帧需安全收尾，不能以长期热缓存推翻用户策略。辅助SelectionUlw参与普通电脑交互模式，是否可回收须看当前输出、内容及成功透明/隐藏交接。此次仅记录方案，不实施新代码。
