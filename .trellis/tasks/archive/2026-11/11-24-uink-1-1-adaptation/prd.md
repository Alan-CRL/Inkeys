# 阶段 C1.4：适配 UInk 1.1（统一文件与规范化私有字段）

## 背景

- C1.5 实测发现白板的存储方式有根本问题：每页保存都重写整个多页文件，并额外存一份与正文重复的历史 JSON；PPT 是一份文件、白板却是另一套按页读写的实现。用户决定先插入本任务，把 UInk 1.1 规范完成并适配，再回到 C1.5 的加载提速与 C2。
- UInk 1.1 规范由**其他 Agent** 编写。本任务先为规范作者整理 Draw3 的需求，之后按定稿规范改造读写。

## 用户已定的方向（2026-11-24）

1. **白板也是一个文件**，与 PPT 一致；白板单独保存在自己的文件夹中。
2. **所有场景同一套 UInk 逻辑**：桌面、PPT、白板共用一个封装，各自只扩展不同的部分（例如白板未来会有图层）。
3. **图形**：保持原有逻辑——文件里存的是直接可画、未经解析的笔画；元数据里存图形属性，Inkeys 导入后可以继续修改。现有的大量私有字段要想办法放进规范片段。
4. **私有片段**：需要的放进规范，不需要的去掉。例如 SHA-256 完全多余：文件读不出来就报错，不需要完整性校验。
5. **兼容**：UInk 1.1 尽量兼容 1.0，但允许破坏性修改。不需要兼容之前的白板路径等，因为 Inkeys3 正式版尚未发布，PPT 跨进程恢复和历史画布预览也还没做，用户不知道 .uink 的用途，用户体验不受影响。
6. C1.5 的计时插桩暂停，不再扩展（已有的白板计时代码保留在工作区、未提交）。

## 第二轮决定（2026-11-24）

详见 `research/uink-1-1-draw3-requirements.md` §7。

1. **图形**：沿用标准 Shape 项作为人人能画的一层，重点扩展元数据。
2. **重做不进文件**，撤回粒度由软件决定。每页最多保留一个 Clear（Inkeys 保证最多撤回到上一个 Clear 区间，更早的丢弃）；以后的手动导出只保存最后一个 Clear 之后的内容。
3. **PPT**：一份演示文稿一个文件夹、一个 .uink；绑定方式、SlideID、页码、保留页、结束页写进页面元数据，软件自行排序；去掉索引文件与多轨。
4. **白板**：一个 .uink，单独文件夹；PPT 与白板都**按页追加写入**；1.1 不保证页在文件中的顺序（以页码元数据为准）；**导出时整文件重写**。中期重构第3步之后读取库会支持实时写入与崩溃自动恢复。
5. **笔尖描述**：每笔存形状、宽高比、方向、宽度含义，用于荧光笔与矩形/方形橡皮。
6. **白板翻页丢弃重做**：离开的页照常释放，翻回来后没有可重做的内容，图形编辑的修改前版本也不保留。

## 第三轮决定：与 C1.5 联合实施（2026-11-25）

规范已定稿为 **UInk 1.1 Beta**（`Header.version = 11`），单文件版 <https://www.inkeys.top/dist-standard/uink-v11/spec.md>（规划时的副本见 `research/uink-v11-spec.md`）。我们需求文档里的 R1–R13 基本都已进规范：按页追加（SAVE-10–19）、页面元数据（`background`、`pageState`、`pageKind`、`binding`）、笔尖 `nib` 与端帽、图形对象层 `object` 与预设注册表、Clear（Inkeys 附加级）。

用户决定 **C1.4 与 C1.5 联合进行**，需求与验收以本文件为准；C1.5 的计时插桩与基线数据并入本任务。

### 适配原则

1. **私有片段改为官方字段**：规范已有对应字段的私有片段（`inkeysEraserShape`、`inkeysShape`、`inkeysPageState`、`inkeysBindingMode`、`inkeysPageKind`、`inkeysWorkspace`、`inkeysWhiteboardHistory` 等）一律改为按规范读写；同时修正与规范不一致的地方。
2. **不支持旧版本写出**：写入器只写 1.1；不写 1.0，不做“无 Inkeys 层”的兼容导出（不烘焙橡皮）。不兼容旧版 Inkeys 产生的私有字段。
3. **读取 version 10**：按 1.1 的规则尽力读（规范 VER-5），读不懂的内容跳过；旧 Inkeys 私有字段不再识别。
4. **橡皮尺寸只在读写时换算**：UInk 的笔尖高度是直观的（矩形笔尖 `H = width`、`W = aspect × H`）；Inkeys 内部的矩形/方形橡皮尺寸是“等面积圆直径”。软件内部逻辑和 UInk 逻辑都不改，只在写入时换算 `H = (s / 2) × √(π / aspect)`，读取时反算。
5. **大幅提速、少做验证**：去掉 SHA-256、保存后回读比对、重复的历史 JSON 等。整个文件损坏（Header 无效、读不出任何页）才失败；个别损坏尽量显示，显示不了就跳过并给出 warning。
6. **接入日志系统**：UInk 读取的失败、跳过与回退写入现有日志系统（`Inkeys::Log`），按页汇总，不逐笔刷屏。
7. **绝不因加载 UInk 崩溃**：任何输入（截断、乱码、超大数量、深层嵌套、非有限数）都不能让软件崩溃或卡死；性能与兼容性同等重要。
8. **读取范围**：Inkeys 自己写的文件读回无损；外来文件中 Draw3 画不了的合法内容（FollowDirection 笔尖、任意虚线、箭头 Marker、HDR 颜色、非 1 的缩放、Media 等）按规范回退表就近显示，回退不了的单项跳过并写 warning。这次不扩展渲染器去支持完整级。

### 存储

- **根目录** `<exe>\Inkeys\Save\Ink\`（以后 `Save\` 下还会有预设记录等）。旧的 `Inkeys\AutoSave\` 及其中的 1.0 文件、旧白板会话目录**完全不访问、不清理**。将来 UInk 1.2 会兼容 1.1，所以这次的破坏性修改只发生一次。
- **白板**：每个进程新建一个 .uink，放在白板自己的文件夹。
- **PPT**：一份演示文稿一个文件夹；每个进程在其中新建一个 .uink；同一进程内再次进入同一份演示文稿时续写这个文件。页码、SlideID、绑定方式、保留页、结束页写进 Canvas 官方字段。识别同一份文稿沿用现有逻辑（规范化路径派生的 key，只保证同进程内识别）；以后再考虑在 pptx 中加 Tag 或把 .uink 嵌入 pptx 来跟随文稿。
- **白板与 PPT 的页写入**（两者文件结构相同，只是 PPT 多 `hostId` 与 SlideID 等绑定字段、白板多背景）：
  1. **Clear 时**：把这一页按页追加，内容为“上一区间 + Clear”（当前区间为空）。写好后上一区间的内存副本可以释放，跨 Clear 撤回从文件读回。
  2. **翻页、离开工作区、退出时**：再次按页追加这一页的完整记录，即软件内的撤回范围：能撤回到上一区间时写“上一区间 + Clear + 当前区间”，否则只写当前区间。每页最多一个 Clear；不写重做。
  3. 翻页后是冷读取，读回的上一区间作为撤回数据，所以翻走再翻回后仍能撤回到上一区间，**保持原有行为**。
  4. 不做任何“修正”，退出时也不修正。
  5. C1.6 的抬笔追加发生在当前页，可以直接接在这一页最后写入的版本后面。
- **桌面**：仍然每次 Clear 一个快照文件，**只写当前区间**（文件里不带 Clear）；退出时照常写当前区间，不修正。跨 Clear 撤回仍可从该快照读回。
- **新旧进程**：崩溃重启、主动重启与更新时，新进程会在旧进程完全退出前启动。每个进程只写自己新建、名字唯一的文件，不打开、不修改其他进程的文件，所以不会冲突。
- **为 C1.6 做准备**：C1.6 将支持抬笔立即追加写入，崩溃后重启可以恢复（恢复在“教学安全模式”完成后一并进行）；以后的实时追加直接新建文件。本任务的文件布局与写入接口要能直接承接“向最后一个 Canvas 追加”（SAVE-6–9）与崩溃截断恢复（SAVE-22–24）。

### 与 C1.5、C2 的分工

- 并入本任务：冷页加载链路的 CPU 与 IO 部分（读盘、解码、历史恢复、足迹、离页序列化与保存），沿用 C1.5 已加的分段计时做前后对比。
- 留给 C2：翻页后的 GPU 冷重建（实测占冷页加载 40–45%），与瓦片缓存改造一起做。

### 协作方式

- Codex（`gpt-6.2-sol`，High，`service_tier=default`；Fast 与 Astra 均不可用）写大部分代码并做独立审查；Claude 负责规划、简报、构建、自检、逐行读差异、变异验证与验收，重点防止偷懒、未达要求与越界改动。

## 本任务的交付

### 第一部分：给规范作者的需求整理（已完成，规范已定稿）

- 需要新规范支持的 Draw3 能力（已知：方形/矩形橡皮、不同比例的荧光笔笔尖、端帽是方是圆，及盘点中发现的其他项）。
- 图形元数据进入规范片段的方案。
- 现有私有片段与校验机制的清单，以及哪些进规范、哪些删除。
- 各场景 .uink 的存放位置与文件结构。

产出放在 `research/`，供规范作者使用。

### 第二部分：按定稿规范适配，并完成 C1.5 的加载提速（联合实施）

- 统一的 UInk 1.1 读写封装，桌面、PPT、白板共用；白板与 PPT 改为单文件按页追加；去掉多余校验与重复数据。
- 详细设计见 `design.md`，实施计划见 `implement.md`。
