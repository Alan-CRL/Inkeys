# 手掌橡皮第一阶段：RTS 坐标与接触尺寸修正

## 目标与阶段
修正部分设备触摸接触框及手掌橡皮尺寸异常，并让鼠标、笔、触摸的位置使用有明确坐标契约的窗口映射；以椭圆近似等面积圆规范手掌橡皮直径。

本任务只负责第一阶段。2026-11-06 用户已授权创建任务并进入规划，已回答识别口径问题；规划工件已收敛，用户通过对话提问明确选择“批准规划并开始实施”，本轮实现与自动化验证已完成，真实设备验收仍待进行，任务保持in_progress。

## 背景与已确认事实
- 当前分支 bugfix/hand-erase，核查基线 42f4b9a8；参考调查基线 565ff07f 已在当前历史中。用户反馈 Surface Pro 11 正常，部分其他设备面积明显偏大。
- F1：生产 Draw3 仍从 GetAllTabletContextIds()[0] 读取共享位置倍率，不能将设备枚举首项视为窗口像素映射的 API 保证。锚点：Inkeys/Inkeys/Drawing/Draw3/Draw3.RealtimeStylus.cpp:1762、1810。
- F2：当前宽高转换先变成 digitizer 轴计数，再直接乘处理 ink 坐标的位置倍率，遗漏两种空间间的逆变换；调用层未传入已缓存的当前 context 倍率。锚点：Draw3.SpeedEraser.cpp:501、Draw3.RealtimeStylus.cpp:526、916。同目录完整路径及官方依据见 research/code-and-api-evidence.md。
- F3：State::Observe 使用 W×H 识别、保留最大面积，按 2×sqrt(W×H/π) 定尺。阈值为可信物理标尺 25cm² 或估算 10000 系统 DIP²，再乘配置倍率。锚点：Draw3.PalmEraser.cpp:61、109。
- F4：现有规范和测试含旧公式；实现时必须同步更新对应合同，不能以旧测试通过证明换算正确。生产 RTS 测试 helper 不等于已被主产品测试执行。

## 需求
| ID | 要求 | 验收 |
| --- | --- | --- |
| R1 | 生产 RTS 的 Mouse/Pen/Touch 位置统一从 ink space 映射到目标 Drawpad HWND 客户端像素，消除首 context 顺序依赖和把 digitizer 计数当像素的错误；Win32Mouse 已有客户端坐标不能重复转换。 | AC1、AC4 |
| R2 | WIDTH/HEIGHT 按自身单位/分辨率解释，再经过完整空间转换；原始值保留，元数据无效时不伪造可用面积。正常输入热路径保持缓存运算。 | AC2、AC4 |
| R3 | 手掌橡皮保持圆形，直径 D=sqrt(W×H)，半径 D/2，W/H 是已转换的完整画布像素宽高；光标和实际擦除使用同一尺寸。 | AC3 |
| R4 | 按已确认的A方案，识别使用W×H，保留阈值数值、配置语义、设置预览及既有识别窗口/最大面积/长宽比/Up锁定/续接策略。 | AC3、AC5 |
| R5 | 最低兼容 Windows 7 SP1 + KB2670838；不假设 KB2533623 等其他补丁，不让新坐标路径依赖 Win8 Pointer 或 Win10 DPI API 的存在。 | AC6 |
| R6 | 对共享接触尺寸的调试显示、手掌和笔速面积辅助做必要联动回归；不调整笔速曲线/阈值来补偿输入错误。 | AC2、AC5 |

## 验收标准
- AC1：相同目标窗口下，改变 context 枚举顺序或设备原生计数倍率，不改变相同 ink X/Y 的画布位置；覆盖鼠标、笔、触摸和各生命周期入口，禁止用坐标裁剪掩盖倍率错误。
- AC2：等价设备描述同时按 k 缩放轴分辨率和 ink→digitizer 倍率后，同一接触输出宽高不变；覆盖倍率小于/等于/大于 1、不同单位/分辨率、X/Y 不同倍率、无效和缺失元数据、非有限值、声明范围边界。长度不减 logicalMin、不使用位置平移。
- AC3：100×100px 的合格已激活接触得到 100px 直径；160×90px 得到 120px。同比扩大宽高时直径同比扩大；既有擦除点半径不回写，后续点和圆形光标一致。
- AC4：启用、映射更新、设备增删/重建时位置映射、各 context 元数据和宽高变换属于一致代次；旧接触按既有边界取消，不能混用新旧参数。映射失败不发布猜测坐标。
- AC5：验证识别窗口与续接、无面积数据的绘制/普通橡皮、Touch 面积辅助以及显示调试的消费口径；相同修正后 W/H 下识别判定与原 W×H 规则一致，25cm²/10000DIP²、倍率和设置预览不额外乘 π/4。
- AC6：源码/API 导入检查不引入基线外硬依赖；本机以 ARM64 原生 MSBuild 构建 InkeysRepo.sln Debug|ARM64，构建至少允许 5 分钟，检查退出码及首个有效错误。Win7 x86/x64 实机、Surface 和异常设备测试分别记录，不用 ARM64 构建或静态公式代替实机结果。
- AC7：最终 diff 仅覆盖需求必要文件，原编码/EOL 保持；不创建 commit、不 push。无用户额外授权不启动 GUI/Computer Use。

## 不在本阶段范围
- 历史 Draw2/IdtRts 或独立 demo 的同步改造，RTS 替换为 WM_POINTER/WM_TOUCH。
- 实际椭圆/旋转掌形擦除、接触峰值滤波、识别时间窗和重连接续算法重设计。
- EDID/显示器物理标尺重构、笔速响应曲线调参、用户手动校准或新增设置开关。
- 无关重命名、项目文件/依赖版本升级、GUI 自动化、提交和发布。

## 产品决策与验收边界
- 2026-11-07 范围收紧（用户决定，取代下述 R1、AC1、AC4 及 design.md 第2、3、6节）：36b418b0 引入的 HDC 窗口映射、WindowMappingRevision/Host 主动失效链、启动映射预检与 `--draw3-rts-coordinate-test` 违反最小修改原则，且之后实机出现连续绘制报点变疏/抽动。RealtimeStylus/Host/RtsStartup/IdtMain 恢复为 42f4b9a8；位置继续使用经大量实机验证的首 context 共享倍率。本阶段保留的修复仅为：R2 宽高补除当前 context 的 ink→digitizer 倍率（PrepareAreaTransforms 传入已缓存 contactScale，仍在 decoder 发布时预计算），以及 R3 手掌直径 sqrt(W×H)。多显示器/DPI 主动刷新与位置来源替换不在本阶段。
- 2026-11-06：用户选择A，已落实为R4与AC5；后续问题使用对话提问功能。
- 修正输入宽高本身仍可能改变触发结果；Surface及异常设备的真实接触尺寸、多显示器和Win7运行须单列验收证据，当前没有执行。
- 没有剩余阻塞的产品问题；技术方案见design.md，实施顺序/命令/风险见implement.md。本轮已完成产品编译与无窗口回归；详细证据和未执行实机项见validation.md。
