# 白板桌面快捷方式与启动转发

## Goal

在“设置 > 通用 > 快捷方式”中，于“应用程序”类之后新增“白板”类，可创建、命名并保障指向白板的桌面快捷方式。白板快捷方式通过启动参数进入白板：目录内已有实例时转发请求由现有程序打开白板，没有实例时启动后直接打开白板。同时提供一枚区别于程序图标的白板专用彩色图标。

本任务是已归档任务 `11-03-shortcut-settings-integration` 的延伸；11-03 PRD 中“不新增远程激活/IPC”的约束被本任务有限替代（仅限下述白板请求）。11-01 单实例合同其余部分保持。

## Confirmed Decisions（会话问答 2026-11-04）

- 新建独立 Trellis 任务，不重开 11-03。
- “应用锁”指同目录防重复启动（单实例）门。
- 白板名称预设精简为三项（见 R3），不含“批注/批注工具”后缀。
- 已有实例无法接收请求时：提示并退出，不启动第二份、不应用更新、不提权、不终止已有实例。

## Requirements

### R1 页面结构

“快捷方式”页自上而下：

1. 标题“应用程序”：创建条目（含内联名称区）、“修正桌面快捷方式指向和名称”开关、“缺失时创建桌面快捷方式”开关。
2. 标题“白板”：与上完全相同的布局（创建条目 + 内联名称区 + 两个保障开关），作用于白板快捷方式。

原独立的“快捷方式保障”标题移除，其两个开关并入应用程序类，且只保障应用快捷方式。布局/弹层/动画/校验提示复用 11-03 已有实现，不另造控件。

### R2 白板快捷方式的内容

- 目标仍为当前 Inkeys exe，附启动参数 `-Whiteboard`（与现有 `-Restart`/`-WarnTry` 风格一致）。
- 使用白板专用图标（R8），而非程序图标。
- 应用快捷方式保持无参数、使用程序图标，行为不变。

### R3 白板名称预设与自定义

| 持久化 ID | 含义 | 显示 |
| --- | --- | --- |
| 0 | 缺省 | 简中 `Inkeys白板`；其他语言本地化的 `Inkeys Whiteboard` 等 |
| 1 | 品牌 | `智绘教Inkeys白板`，仅简体中文显示 |
| 2 | 自定义 | 用户输入 |

- 下拉顺序：简中 [1,0,2]，其他语言 [0,2]；缺省 ID=0。
- 品牌项在非简中回退为 0（沿用 11-03 R8）；自定义进入、保存恢复、仅保存不立即动文件（R4/R9 同 11-03）。
- 名称校验沿用 Windows 文件名规则，并新增：白板名称不得与应用快捷方式的当前解析名称相同（按 Windows 不区分大小写比较，双向校验）；冲突就地提示，创建按钮禁用，不覆盖最后有效配置。

### R4 独立配置

白板类有独立的名称预设、自定义名称、修正开关、补建开关，写入 `Inkeys/Config/main.json`（NoUpload），缺省：预设 0、自定义空、修正 true、补建 false。不迁移旧配置，缺失/非法回退缺省。

### R5 保障不得互相破坏

现有“修正”逻辑会删除桌面上所有指向本 exe 的其他名称 `.lnk`，白板快捷方式同指向本 exe，必须避免被误删。快捷方式按“目标 + 参数”分类为应用类（无参数）与白板类（参数恰为 `-Whiteboard`）；两类各自只修正、删除、统一同类的其他名称快捷方式，互不触碰。指定名称上类别不符（含图标/参数错误）按修正语义纠正。

### R6 启动参数与进入白板

- 无已有实例：正常启动链，待启动完成且工作区服务可接受请求后，一次性请求进入白板；失败不重试循环。
- 已有实例（见 R7）：新进程把“打开白板”请求转发给现有实例后退出。
- 白板已处于活动状态：不关闭白板；从最小化恢复并尝试前台，已显示则无操作。
- 实例处于 PPT 放映：沿用现有 PPT↔白板互切合同；桌面：沿用进入白板合同。
- 一次性意图：仅响应本次启动参数；重启（`-Restart`/崩溃重试）不重放。
- 参数只能是精确匹配 `-Whiteboard`；未知参数行为不变；测试/监督器早退入口不受影响。

### R7 单实例、更新与异常边界

- 转发发生在单实例准入判断处，早于更新替换与 SuperTop 提权，因此：已有实例时，新进程**不**读取/应用 update.json、不提权、不改文件。
- 现有实例有待应用更新（update.json 存在）：仍照常转发，更新留待现有实例下次正常重启。
- 无实例且存在待应用更新：先走更新/回滚/交接链，更新后的实例仍须收到一次白板意图（参数需在更新替换及 SuperTop 三段式中保留）；更新或交接失败则意图作废，不重放。
- 现有实例尚在启动中：请求排队，启动完成后处理；启动失败则丢弃。
- 现有实例正在退出/重启或管道不可用/超时：提示并退出（沿用现有提示能力），不启动第二份。
- “允许软件重复启动”开启：带 `-Whiteboard` 同样转发给目录内已有实例（用户 2026-11-04 确认）。多个实例并存时由系统选取其中一个正在监听的实例接收，不保证特定实例；没有任何可连接的实例时才启动新实例并进入白板。
- 转发通道仅接受同用户、同安装目录实例的受限请求，定长带版本，不携带路径/命令；无法从其他安装目录实例互相触发。

### R8 白板图标

新增彩色 SVG 源文件，并生成多尺寸 ICO 内嵌到 exe 作为第二个图标资源，快捷方式通过 `IconLocation` 引用。按后续用户确认与交接，最终采用原蓝色圆角点阵卡片、去掉笔和圆盘、中间白色书写线的版本。程序主图标 `icon.ico` 不变；最终预览已由其他 agent 完成并获用户确认。

### R9 i18n 与工程约束

- 新页标题“白板”、白板预设、冲突提示等进现有 i18n，运行 `Scripts/i18n.ps1 sync/check`，禁止手改生成头。
- 最小化修改，保持原编码/换行，关键逻辑加适量中文注释；复用设置控件、业务队列、配置系统。
- 不启动 GUI，不使用 Computer Use，不 commit/push；`task.py start` 前须审阅通过。
