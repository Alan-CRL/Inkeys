# UI3 分层封装与通用 UI3 模块迁移

> 父任务：`11-16-inkeys3-midterm-refactor`（第1步）。
> 技术设计：`design.md`。实施计划：`implement.md`。事实依据：`research/` 下四份调研（2026-11-16）。
> 背景调查：`../11-16-inkeys3-midterm-refactor/research/第1步 Inkeys_UI3_Bar_分层封装现状调查_2026-11-16.md`（基准 `c06697b1`）。
> 代码基准：分支 `refactoring/drawpad-ui` @ `7047db94`。

## Goal

把目前集中在 `Inkeys/Inkeys/UI/Bar/` 下的 UI3 公共显示能力，按「基础绘制与动效 → 基础控件 → 序列与面板 → 宿主与呈现」四层责任整理成清晰的公共边界，并迁出 Bar 目录成为通用 UI3 模块。

用户价值：

- UI3 各处（主栏、翻页、形状样式栏等）体验一致，样式可统一调整；
- 新功能接入时复用控件与面板，不再各写一套自绘；
- 为后续「白板独立成窗口后由白板直接绘制主栏」准备好不依赖主栏独立 HWND 的内容边界。

四层是责任划分，不要求四级继承、四个大类或递归控件树。

## Background

### 用户原始需求要点

1. 第一层：最基础的 UI3 能力——动效元素与底层图元（圆角矩形、超椭圆、图片、字体、SVG）。
2. 第二层：基础控件——按钮（尺寸差异、角标、环形进度条、字号/颜色变化）、按钮交互、通用光影绘制；现有按钮自绘过于杂乱。
3. 第三层：按钮序列、外框矩形、光影的发布。
4. 第四层：决定显示到哪个窗口及窗口表面。
5. 服务对象：主栏（本体、二级菜单、底栏文字提示、多步形状底栏操控栏）、翻页控件（四个，PPT 与白板共用）、形状绘制完成后的样式栏。
6. 特殊内容（如主栏绘制属性里的专有控件）保留扩展能力；颜色选择浮窗封装为可复用单元，供主栏与样式栏共用。
7. UI 能力独立后不再放在 `Bar` 文件夹，而是通用 UI3 文件；新建文件按 `.cppm` + `.cpp`。
8. 给改动的部分添加适当日志，使用统一日志系统，只需覆盖 UI 部分。

用户说明以上是参考方向，不要求完全照搬。

### 现状要点（详见 research）

- 背景调查基准 `c06697b1` 之后，`UI/` 下只有日志重构 `cfe8329d` 的调用替换，结构性结论仍有效。
- `UI/Bar/` 约 6.8 万行；最大的是 `Bar.RenderLoop.cpp`（13377）、`Bar.Interaction.cpp`（10280）、`Bar.ShapeEditor.cpp`（4469）、`Bar.Rendering.cpp`（3537）、`Bar.Button.cpp`（2866）。
- `Inkeys.UI.Bar` 现有根模块、12 个分区、11 个独立子模块。第一、二层能力（`:UI`、`:Rendering`、`:Button`、`:Format`）是主模块分区，绘制器还通过 owner 构造器与友元反向依赖主栏。
- `UI/Bar/` 下有 23 个 `.h`，加 `UI/Superellipse.Geometry.h` 等共调查 26 个头，全部含函数或类，没有纯引用头。
- Bar 目录外有 13 个产品源文件导入 `Inkeys.UI.Bar*`；`InkeysHeadlessTests` 工程另有 11 个测试源导入 Bar 子模块、约 20 个测试源直接包含 Bar 头，并直接编译一部分 UI 源。该工程不编译完整主栏。
- 仓库已有无窗口主栏绘制入口 `CreateBarOffscreenRenderCallback` 与多个命令行离屏测试，但它们使用主栏自有的 GDI 兼容目标，默认不校验主栏像素。
- 两套连续颜色选择器的静态几何、位置标记、RGB 区、长按计时已一致；不同的是默认色系、关闭时长、紧凑态、透明度过渡、放置与避让、亮暗图标切换方式。
- 统一日志 `Inkeys::Log` 已就绪；`Module::UI3` 已有使用者（管线诊断桥与 3 处输入异常）。渲染路径上现有若干阻塞式 `Log::Error` / `Warn` 调用，与「热路径只用非阻塞接口」的规范不符。

## Decisions

- **D1 交付范围**：四层在本任务内一次规划、一次交付，不拆成按层的子任务。实施顺序与检查点写在 `implement.md`。
- **D2 第四层深度**：定义宿主边界，现有三类宿主（主栏窗口、四个翻页窗口、`SelectionOverlay`）均经由它接入；增加不显示窗口的离屏目标，把主栏内容画进去作为「第二宿主」的验证。绘制器对目标位图、GDI interop、`BeginDraw`/`EndDraw` 的所有权与内容绘制拆开。验证沿用主工程内命令行测试入口的做法，不新建测试工程。白板窗口实际接管主栏绘制属于父任务第3步。
- **D3 目录与命名**：通用 UI3 位于 `Inkeys/Inkeys/UI/UI3/`；模块根 `Inkeys.UI.UI3`；文件名 `UI3.<功能>.cppm` + `UI3.<功能>.cpp`；filter `Modules\Inkeys\UI\UI3`。可采用分区并由根模块聚合导出，沿用 Bar 以分区解决相互引用的做法。
- **D4 既有头文件**：`UI/Bar/` 下的 `.h` 与 `UI/Superellipse.Geometry.h` 全部纳入转换范围。含类、封装函数等实质实现的头改写为 `.cppm`（+ `.cpp`）；仅起引用作用、没有函数的头可保留 `.h`；`.cppm` 内允许在全局模块片段 `#include`。主栏专有的头转换后留在 `UI/Bar/`，通用能力的头进入 `UI/UI3/`。
- **D5 颜色选择器基准**：统一后的连续颜色选择器以主栏版的外观与手感为准，形状样式栏改为与之一致，由此产生的可见变化属于有意变更。改变颜色的时机保持不变：主栏拖动时实时改当前笔色、松手记忆；样式栏拖动时只做本地预览、松手提交一次样式。
- **D6 规范沉淀**：把 `.cppm` + `.cpp` 模式、D4 的头文件判定标准、`.cppm` 内 include 的写法、分区聚合的用法写入 `.trellis/spec/`，供后续开发遵循。
- **D7 控件统一政策**：统一普通控件时允许出现可见的细微差异，每一处列入 `design.md` 的有意变更清单，实施不得产生清单外的变化。适合用统一控件的都改成统一实现，尽量减少自有实现；只有确实需要专有绘制或专有交互的内容才保留，并写明理由。
- **D8 验收方式**：自动部分为完整构建、既有测试入口、像素基线比对与新增的第二宿主验证；人工部分为 `implement.md` 中按服务对象组织的实机检查清单，由用户执行。
- **D9 文件编码**：本任务新建或修改的源文件（`.cpp` / `.cppm` / `.h`）一律 UTF-8 带 BOM；不带 BOM 视为错误。

规划中由设计给出、随规划摘要一并审阅的默认选择（见 `design.md`）：

- 被 `InkeysHeadlessTests` 单独使用的能力做成独立模块，重型运行时做成 `Inkeys.UI.UI3` 的分区，根模块聚合两者（§2.1）。
- 进入 UI3 的符号去掉 `Bar` 前缀；迁移期间用垫片保留旧名，最后单独做一次机械改名（§2.5）。
- `UI/StartupPlacement.h` 因依赖 `Bar.BottomDock.h` 必须一并转为模块；`UI/StartupPreview.Effect.h` 不转换（§2.3）。
- 翻页场景 `BarPageSurface` 与形状编辑场景 `ShapeEditorSurface` 是产品内容，留在 `UI/Bar/`（§7.5）。
- 取色器默认色系与放置避让规则保留为各场景的参数，不随 D5 统一（§9）。
- `.vcxproj` / `.filters` / `.sln` 与 `.trellis/` 下的 Markdown 不适用 D9，保持现有格式（§2.6）。
- 动产品代码前先建立像素基线导出入口作为回归护栏（§11）。

## Requirements

### R1 第一层：基础绘制与动效

- 图元（Shape、Superellipse、SVG、PNG、Word）、继承坐标、动画值与时间线、DWrite 文字与格式缓存、光影绘制、脏区包络、通用控件尺寸常量、主题语义色与材质，作为通用 UI3 能力对外提供。
- 通用能力不依赖主栏独立窗口，不读取主栏全局状态。
- 主 Logo 外观、笔型/粗细预览、常驻表面透明度取值、主栏光源锚点选择等产品策略保留，归属主栏侧。

### R2 第二层：基础控件

- 以现有 Retarget / Configure / Advance / Draw / HitTest 入口与 `ButtonPointerState` 为基础继续统一，不另起一套控件体系。
- 通用按钮覆盖：尺寸变体、SVG/PNG 图标、主副文字及字号/颜色变化、角标、圆环与沿框进度、按压/hover/选中/禁用状态、基础指针交互与点击/次键/双击/长按手势判定。
- 通用按钮与主栏按钮的产品定义（preset、注册、用户可见性、More 分流）分离。
- 自绘扩展保留，并能声明可视包络与动画活跃状态。

### R3 第三层：序列与面板

- 面板能描述：成员序列与排布、外框、开合动效与透明度、局部姿态、可视与可交互范围、候选与已呈现状态、留白阻挡；叠层能回答某点属于哪个面板。
- Main、More、图形网格、分页等各自的产品排布规则保留。
- 光影分清「怎么画」「光源如何演进」「输入从哪来」「谁消费、如何定位」；同一进程只有一份共享光照状态；跨表面通知不再绑定主栏窗口句柄。
- 连续颜色选择器成为完整可复用单元，主栏与形状样式栏共用，提交时机按 D5 各自保持。

### R4 第四层：宿主与呈现

- 由宿主决定窗口、帧目标、坐标映射、原生输入接入与提交方式。
- 保留既有约束：像素提交成功且宿主确认后才推进命中与已呈现状态；设备代次、捕获取消、失效唤醒、失败重试语义不变。
- 主栏内容能画入由别的宿主提供的目标（D2）。

### R5 文件与模块

- 通用 UI3 能力迁入 `UI/UI3/`，新建文件为 `.cppm` + `.cpp`（D3、D4）。
- 所有新增、移动、删除的源文件同步登记 `Inkeys.vcxproj`、`Inkeys.vcxproj.filters`、`InkeysHeadlessTests.vcxproj`，filter 层级与磁盘目录一致。
- 文件格式按 D9。

### R6 日志

- 本任务新增或改动的 UI 代码使用 `Inkeys::Log`，不新增 stdout 或调试器通道。
- `UI/UI3/` 内使用 `Module::UI3`；产品目录沿用各自既有 Module。
- 记录生命周期与异常事件（资源创建与失败、设备重建、帧提交失败与恢复、宿主与输入表面的绑定、面板开合、颜色选择器开关与提交等），不做逐帧日志。
- 渲染线程、交互 worker 线程、窗口过程中只用非阻塞日志接口；被改动代码中现有的阻塞式调用一并改正。

### R7 行为保持与兼容

- 除 `design.md` 有意变更清单所列项目外，外观、动画、命中与交互结果不变。
- 兼容性沿用父任务约束：Windows 7 SP1 + KB2670838、MSVC v143 / C++20，不升级依赖。

### R8 规范沉淀

- 按 D6 更新 `.trellis/spec/`，并改正调研指出的过期表述。

- [ ] `InkeysRepo.sln`（`Debug | ARM64`）完整构建通过。
- [ ] `InkeysHeadlessTests.exe --no-window` 与四个既有命令行离屏入口（`--ui3-geometry-attribute-test`、`--bar-eraser-offscreen-test`、`--ui3-shape-editor-test`、`--ui3-multitarget-benchmark`）的结果不比动代码前的基线差。
- [ ] `UI/UI3/` 目录存在并承载四层通用能力；该目录内没有 `import Inkeys.UI.Bar`，没有包含 `IdtMain.h` / `IdtState.h`，没有读取 `barUISet`、`floating_window`、`currentBarThemeStyle`。
- [ ] Bar 目录之外的源文件不再为了使用图元、动画、尺寸常量、材质、帧节拍等通用能力而导入 `Inkeys.UI.Bar*`（`RenderPipeline.cpp`、`StartupPreview*.cppm` 等改为导入 UI3 模块或经由保留了产品常量的模块取得）。
- [ ] `UI/Bar/` 下原有的 23 个 `.h` 与 `UI/Superellipse.Geometry.h`、`UI/StartupPlacement.h` 已不存在，对应内容以模块形式提供；本任务没有新增 `.h` + `.cpp` 形态的源文件。
- [ ] 主栏内容可画入测试自建的非 GDI 离屏目标与外部设备上下文，像素与现有路径逐像素一致，过程中 `floating_window` 为空且未创建窗口（`--ui3-host-offscreen-test` 通过）。
- [ ] 主栏、四个翻页窗口、`SelectionOverlay` 与白板背景都经由 UI3 的帧目标与帧事务呈现；`BarPageSurface`、`ShapeEditorSurface` 不再对外暴露绘制器或自行提交。
- [ ] 主栏与形状样式栏使用同一个颜色选择器组件，仓库中不再有第二套取色器绘制与手势实现。
- [ ] 主栏选色仍在拖动时实时改变当前笔色并在松手后记忆；形状样式栏选色仍只在松手时提交一次样式，拖动中对象样式不变。
- [ ] 像素基线比对：除有意变更清单所列场景外逐字节一致；清单内的每项差异都已核对。
- [ ] `vcxproj` 与 `.filters` 中每个迁移或新增项都已登记，filter 与磁盘目录一致，没有指向不存在文件的条目。
- [ ] 本任务新建或修改的 `.cpp` / `.cppm` / `.h` 均为 UTF-8 带 BOM、CRLF。
- [ ] 运行离屏测试后，日志文件中可见 `UI3` 模块的生命周期记录；被改动的渲染线程、交互 worker、窗口过程代码中没有阻塞式日志调用。
- [ ] `.trellis/spec/` 已记录 `.cppm` + `.cpp` 模式、头文件判定标准、独立模块与分区的选用规则、UI3 分层与日志规则，并可从 spec 索引找到。
- [ ] 用户按 `implement.md` 的实机检查清单确认行为（本任务不做 GUI 自动化）。

## Out of Scope

- 白板独立窗口、板中板、多画布、同窗多内容的输入路由（父任务第3步）。
- Win7 ULW 流水线（第2步）、输入后端（第4步）、Draw3 性能（第5步）。
- 设置界面（Dear ImGui）迁移到 UI3；插件 SDK。
- 新的呈现后端；RenderPipeline 新增客户端或窗口角色。
- 通用滚动条等本任务未列出的新控件；递归控件树或通用布局引擎。
- 把翻页场景与形状编辑场景迁出 `UI/Bar/`。
- 为 `InkeysHeadlessTests` 新建 `.filters`；清理 `Other.Config.cppm` 的疑似遗留导入；裁定浅色常驻透明度 0.88 与 0.92 哪个是预期值（均记录在 `implement.md` 遗留事项）。
