# Inkeys3 圈选、墨迹变换与擦除兼容性技术调查

> 用户于 2026-11-05 提供的外部调查原文，原样存档，只删去了网页引用图标。调查基于 dev 分支 2026-10-31 的提交 `5ec5be3a`。其中的结论尚未定案，用户仍在研究中；已定内容见 `user-decisions-and-notes.md`。

结论：可以实现，Draw3 现有的 GPU 合成架构有相当一部分可以保留。真正需要改造的不是墨迹绘制算法，而是墨迹的数据模型和编辑语义。

我认为最适合 Inkeys3 的方向是：保留当前高性能的墨迹渲染与橡皮合成，另外建立对象级编辑模型。普通绘制继续走现有路径；只有需要圈选、移动或修改的墨迹，才逐步转换为可独立编辑的对象。

这样既不用牺牲目前的实时书写性能，也能处理擦除后变得不连续的墨迹。

## 一、对 dev 分支的核验结果

| 模块 | 已确认的设计 | 对未来功能的影响 |
|---|---|---|
| `InkDocument` | 最终墨迹不可变，保存样式和点序列 | 还没有对象变换、局部擦除和片段身份 |
| `InkHistory` | Append-only 墨迹记录，每个历史项独立维护可见性 | 可以扩展对象属性和编辑历史 |
| `InkHistoryGpu` | 撤回 Tile 为 128px，合成 Tile 为 256px | 可以复用局部重建机制 |
| `CompositionRangeTree` | 按顺序组织可缓存的合成操作 | 能为选区移动提供增量更新的基础 |
| `InkRenderer` | Add/Retain 双通道仿射合成 | 可以扩展为支持带局部蒙版的墨迹对象 |
| `inkPixelShader.hlsl` | 胶囊几何的 SDF 覆盖率与抗锯齿 | 可以继续保留原有的笔迹边缘质量 |

### 当前橡皮的真实数学模型

Draw3 的每个墨迹操作都可以写成 `C_out = A + R·C_in`，其中 C 是预乘 Alpha 的 RGBA，A 是这次绘制增加的颜色，R 是原有画面颜色的保留比例。

- 普通画笔：`A = α·C_pen`，`R = 1 − α`。
- 橡皮：`A = 0`，`R = 1 − α_eraser`。

橡皮不是把原来的路径切断，而是让之前的合成结果乘上一个保留系数。源码对 Add 用 `MAX` 累积，对 Retain 用 `MIN` 累积，避免同一笔相邻胶囊段在边缘重复混合；之后通过双源混合完成 `Add + Retain × Destination`。

这意味着 Draw3 已经有很好的保真基础：擦除边缘的覆盖率没有丢失，不需要靠分析最终截图来猜哪些像素被擦掉了。真正缺少的是：某次橡皮操作具体修改了哪些墨迹，以及被擦掉的部分要怎样跟随原墨迹一起移动。

## 二、先确定圈选对象的定义

需要区分三种身份：

| 概念 | 意义 | 是否独立 |
|---|---|---|
| 原始 Stroke | 用户最初完成的一次绘制 | 一个对象 |
| 可见 Fragment | 被擦除后剩下的连通区域 | 可能有多个 |
| Edit Object | 能被平移、旋转、改样式的实体 | 一个或多个 Fragment |

WPF 的 `StrokeCollection.HitTest` 支持按「墨迹位于套索内的长度占比」判断是否选中，它的 `Erase` 会直接把原始 Stroke 替换成多个新 Stroke。Inkeys 不能照搬这个模型，否则可能失去当前擦除边缘的精度。

建议分三个渐进的交互层级：

| 模式 | 圈中 A 时的行为 | 优先级 |
|---|---|---|
| 整笔圈选 | 同一原始 Stroke 剩下的 A、B、C 一起选中 | 首版必须 |
| 可见片段圈选 | 只选中 A，B 和 C 留在原处 | 第二阶段重点 |
| 区域剪切圈选 | 即使笔迹仍连通，也能只截取圈内部分 | 后续高级功能 |

不要把「原始 Stroke 数量」和「可独立移动的可见墨迹数量」绑定在一起。

## 三、问题一：如何让圈选判定足够快

采用「空间索引 + 几何粗筛 + 可见性精筛」：套索输入 → 简化轨迹并计算 AABB → 空间 Tile 索引得到候选 Stroke/Segment → 几何相交、包围率与可见性检查 → 选中 Stroke/Fragment → 生成编辑会话。

- 3.1 现有的 `BuildStrokeTileFootprint()` 可以复用；但 `CompositionRangeTree` 的 `tileBlocks_`（每块 32 个 Item）是为合成重放设计的，不适合做圈选的精确索引。建议另外维护 `InkSelectionSpatialIndex { TileToStrokeMap strokeTiles; TileToSegmentMap segmentTiles; }`：抬笔时增量插入；撤回、删除、移动时只更新相关 Tile。长笔迹按固定线段数建立局部包围盒。
- 3.2 第一层用包围盒过滤；第二层做多边形与笔段相交（考虑笔宽，套索按 0.5～1 DIP 的误差简化）；第三层判断擦除后实际可见的部分。可以用 `Score(S,L) = VisibleInkInside(S,L) / VisibleInkTotal(S)` 打分，快速模式用带宽度和透明度权重的采样近似，精确模式用真实覆盖面积。
- 3.3 不要在橡皮移动期间实时做连通域分割。采用延迟计算：只标记缓存失效，等首次精确圈选或进入片段编辑时再生成片段信息。连通性以二维可见覆盖区域为准，不以中心线为准，因为中心可能被擦掉而只剩边缘。可以在局部 ROI 生成单通道覆盖率图来提取连通域，复杂轮廓再用 Direct2D 的 `CombineWithGeometry(EXCLUDE)` 辅助。抗锯齿边缘需要固定的覆盖率阈值和小区域过滤，避免判定结果随 DPI 变化。

## 四、问题二：为什么不能直接移动原始 Stroke

在操作序列 `DrawRed → DrawBlue → Erase` 中，如果只移动红色，红色的缺口不会跟着走；如果连橡皮一起移动，蓝色原有的擦除结果又会改变。原因是全局橡皮没有对象归属。

半透明情况也不等价：两个 0.5 的 Stroke 重叠，α = 0.75；用 0.5 的橡皮擦过之后，全局合成结果是 0.375；而如果给每条 Stroke 分别乘 0.5 再混合，结果是 0.25 + 0.25·0.75 = 0.4375。因此把全局橡皮转成每条 Stroke 各自的蒙版后，再全部改用普通 Alpha 混合，并不能保证像素与原来一致。所以不建议在做圈选时顺带重写整个橡皮渲染架构。

## 五、推荐的核心方案：编辑对象 + 局部擦除蒙版

```
struct EditableInkObject {
    InkObjectId id;
    InkObjectId sourceStrokeId;
    Matrix3x2 localToCanvas;
    StoredInkStyle style;
    EraseMaskRef eraseMask;
    FragmentClipRef fragmentClip;
    uint64_t revision;
};
```

- 5.1 局部保留蒙版 `M_i(x) = ∏_k (1 − e_k(x))`，只计入该 Stroke 创建之后对它生效的橡皮。合成树还能给出笔迹的可见贡献 `A_i^visible = A_i·∏_{j>i} R_j`，可用于精确的可见性判定；但它和「编辑用擦除蒙版」必须分开保存，因为前者包含后来画在上面的其他颜色笔迹。
- 5.2 保留旧渲染路径，首次编辑时再提取：未编辑的墨迹走现有操作流；首次编辑时生成 Editable Object，提取擦除蒙版，并在逻辑上抑制原历史项的绘制贡献（不是 Undo）；之后按对象级渲染。旧 `.uink` 文件不需要立即转换。首版限制：提取出的对象放到末尾渲染时会变成最前面，首版可以采用「移动后的对象置于前景」的语义；如果要保持原 Z 序，同时让旧橡皮只对未选中的对象生效，复杂度会明显上升。

## 六、如何移动擦除痕迹并保留抗锯齿

- 原始 Stroke 和擦除蒙版共用局部坐标，再统一施加仿射变换 `T = T_translate·R_θ·S_{sx,sy}`。Pixel Shader 用逆变换取局部坐标 `q = T⁻¹p`，计算 `α_edited(p) = α_stroke(q)·M_erase(q)·M_fragment(q)`，然后 `A = α_edited·C`，`R = 1 − α_edited`。
- 抗锯齿有两种做法：
  - 矢量橡皮轨迹在着色时计算覆盖率：缩放后质量高，但计算多。
  - 预生成 R8/R16F 蒙版纹理：快，但放大时需要更高分辨率。

  推荐以矢量为权威数据、GPU Mask 作为可重建的缓存。每次变换都从原始数据重新取样，不对上一次的贴图再做缩放。保留现有 SDF + `fwidth()` 的边缘算法，蒙版只额外乘上去。非等比缩放时，几何和笔宽要一起做二维变换。荧光笔是平头、固定方向的笔尖，需要单独处理。
- 多片段：`M_B = M_erase·M_componentB`，剩余部分用互补的归属蒙版。片段归属必须按像素或几何互补，未分离之前仍按原始单笔覆盖率合成，并需要 GPU 像素回归测试。

## 七、移动过程中保持性能

- 开始拖动：在逻辑上移除选中对象，按 `RestoreComposition` 的思路重建旧位置涉及的 Tile，并创建临时 GPU 预览资源。
- 拖动中：L2 保持不变，只更新选区的仿射矩阵；选区画在独立的 Selection Overlay 中，再与实时层合成。
- 拖动结束：一次性提交最终变换，更新空间索引，让旧位置和新位置的 Tile 失效，写入一条可撤回的事务。

现有可用基础：`CanvasRuntimeHistory::UpdateItemGeometry` 可以更新 Footprint、维护 Tile 引用并增加修订号；`CompositionRangeTree::UpdateItemGeometry` 可以让新旧位置的 Tile 缓存失效。还缺少编辑事务、批量排除历史项和独立的选区渲染。`excludedItem` 目前只支持单项。建议编辑预览使用独立层，不长期复用 L0/L1，以免与多触点实时绘制互相争用。

## 八、颜色、笔型、粗细与线型修改

| 编辑操作 | 推荐方式 | 特殊情况 |
|---|---|---|
| 颜色、透明度 | 修改对象样式，重新生成 Add | 不能给最终合成贴图统一染色 |
| 粗细 | 修改路径宽度参数或宽度倍率 | 可能出现以前没有覆盖的新区域 |
| 软笔与硬笔 | 复用中心线点序列和宽度数据 | 保留笔锋和模拟压感 |
| 荧光笔 | 用同一原始轨迹重新生成平头几何 | 覆盖区域与圆笔不同 |
| 实线、虚线、点线 | 按原始路径弧长生成线型 | 擦断后的片段要保持虚线相位一致 |
| 平移、旋转 | 修改仿射变换 | 原始几何和宽度不变 |
| 缩放、拉伸 | 几何与蒙版同步变换 | 需要明确是否同步缩放笔宽 |

建议缩放时默认同步缩放线宽，同时允许在样式面板里单独改粗细。被擦过的墨迹加粗后，原来的洞仍然保留。

## 九、改造顺序

| 阶段 | 范围 | 验收 |
|---|---|---|
| P0 圈选基础 | Stable Stroke ID、独立空间索引、普通笔迹整体圈选 | 大量 Stroke 时能快速稳定地选中 |
| P1 整体变换 | 整笔平移、旋转、缩放，颜色与样式修改，撤回 | 没被擦过的墨迹完整可编辑 |
| P2 擦除兼容 | 局部橡皮蒙版、延迟转换、被擦过整笔的移动 | 缺口随墨迹一起移动，其他对象不受影响 |
| P3 Fragment 编辑 | 连通域分割、片段身份、独立选取与移动 | 一笔被擦成多段后，每段可以分别编辑 |

各模块：
- `Draw3.InkDocument`：稳定的对象 ID、可编辑属性。
- `Draw3.InkHistory`：编辑事务和对象可见性。
- 新增 `Draw3.InkSelection`：套索、空间索引、Fragment 识别。
- 新增 `Draw3.InkEdit`：变换、样式覆盖、蒙版。
- `Draw3.InkHistoryGpu`：多对象排除、局部重建。
- `InkRenderer` / HLSL：仿射变换、Mask SRV、选区预览。
- `DrawingController`：编辑会话状态机。
- `.uink` / AutoSave：对象 ID、变换、片段和擦除语义，需要向后兼容；GPU 蒙版缓存不能作为唯一的持久数据来源。

## 十、关键验证场景

- 一条笔迹从中间被擦断。
- 多条重叠笔迹被同一橡皮擦过，只移动其中一条。
- 橡皮只擦掉了笔迹边缘。
- 一条笔迹被完全擦除。
- 擦完之后又画了新笔迹（新笔迹不应继承之前的擦除）。
- 旋转、放大被擦过的墨迹。
- 选中大量笔迹连续拖动。
- 保存并重新加载。
- 编辑后撤回、重做，再继续绘制。
- Win7 SP1、WARP、设备丢失。

性能基准：10,000 条 Stroke 下的局部圈选、复杂擦除片段的首次识别、选区连续 120Hz 预览，三项分开测。片段连通域计算不能放进 120Hz 的绘制热路径。

## 最终建议

优先采用「原始墨迹不可变 + 编辑对象 + 局部擦除蒙版 + 延迟生成 Fragment」。需要接受的现实是：全局橡皮合成与完全独立的对象编辑，在半透明重叠和历史 Z 序上并不天然等价。先把 P0、P1 做成稳定的独立能力，再把「同一橡皮擦过两条笔迹、只移动其中一条」作为 P2 的首个核心验收用例。
