# P7 套索与 Z 序中间移动：用户决策与架构笔记

> 来源：2026-11-05 会话。研究内容见同目录的 `composition-cache-mid-z-move.md`（代码调研）和 `lasso-transform-survey.md`（用户提供的外部技术调查）。本文记录用户对调研的纠正和已定方向，供正式设计套索时阅读。

## 1. 对调研结论的纠正与澄清

- **「上方内容不能合成为普通图片」这一说法有误导性，需要澄清。** 画布本来就是逐项操作符叠加：`dst' = add + retain·dst`，并且操作符满足结合律 `(Al + Rl·Ae, Rl·Re)`。把某个 Z 序范围（例如被移动对象的上方）合成为一对 **Add / Retain 双通道纹理**（类似 L0→L1→L2 的双源信息），可以完全正确地包含橡皮、荧光笔等操作符。不可行的只是把它压成单张、已经做完 alpha 混合的 RGBA 图片。结论：上方范围预合成为双通道操作符纹理是可行的，这也是推荐方案 A 的做法。
- **合成缓存（合成树）的定位。** 它目前主要服务于撤回/重做，但设计之初就考虑了未来在 Z 序中间移动对象的架构。「把某个 Z 范围合成为专用纹理并反复复用」属于以后要做的能力。

## 2. 套索前必须先解决的工程项（用户确认需要做）

| 项 | 现状 | 方向 |
|---|---|---|
| 多对象排除 | `RestoreComposition` 的 `excludedItem` 只支持排除单项 | 开始套索之前，先支持一次排除一组历史项 |
| 缓存预算 | 默认 192 MiB / 512 槽，任意范围加满 4K 时容易反复淘汰 | 提高默认预算，并允许用户自行选择预算；同时必须保证极端环境（几乎没有缓存或完全没有缓存）下的体验，需要有不依赖缓存的降级路径和对应基准 |
| Generation 冲突 | 每份历史副本独立维护代数编号，可能产生相同的缓存键，所以目前每次编辑都要清空整个合成缓存 | 改为全局唯一的 generation，或在缓存键中加入副本身份，使编辑提交时只让受影响的 tile 失效 |
| Z 序合同 | Z 序等于 `RenderItemId.index`，并且只追加 | 写入 spec；未来做 Z 序重排时，需要重新评估以索引为基础的合成树 |

## 3. 套索的真正阻碍（尚未定案，用户仍在研究中）

- **橡皮是 Z 序中独立的操作符，不归属于任何笔迹。** 移动被擦过的墨迹时有两种语义：
  - A：橡皮留在原位。在数学上是精确的，但已擦掉的部分会重新出现，墨迹移到新位置后可能出现新的空洞。
  - B：擦除效果跟随墨迹移动。需要「编辑对象 + 局部擦除蒙版」，涉及文件格式变化。
- 用户外部调查的倾向是：原始墨迹不可变，加上编辑对象、局部擦除蒙版，以及延迟生成 Fragment。普通绘制继续走现有的 Add/Retain 合成路径；只有被编辑的墨迹才转换为对象。分阶段 P0–P3（详见 `lasso-transform-survey.md`）。
- 已知的不等价之处（来自外部调查）：全局橡皮与「每条笔迹各自乘蒙版后再混合」，在半透明重叠时像素结果不同。提取出的对象如果放到末尾渲染，会改变 Z 序（首版可以接受「移动后置于前景」的语义）。
- 圈选判定速度：需要独立的选择空间索引（tile→stroke/segment），判定分三层：包围盒粗筛、几何相交、可见性精筛。合成数学可以给出某笔迹在最终画面中的可见贡献 `A_i·∏_{j>i} R_j`，用于精确的可见性判定；但它和「编辑用的擦除蒙版」必须分开保存，因为前者还包含后来画上的其他颜色笔迹。

## 4. 当前 P3 图形编辑已做的前置准备（11-05-shape-ux-edit-performance）

- 用户方案：刚完成的图形在编辑期间留在 L1，失去焦点时才落定到 L2。任何其他操作（新笔迹、平移、翻页、按键、主栏操作、切换工具/页面/工作区、读取 L2 像素、尺寸变化等）都会先结束编辑并落定。任意时刻最多只有一个编辑对象。
- 为套索预留的低成本准备：
  - 「L2 尚未包含的对象」用集合表示，并断言它们是 Z 序的后缀；
  - 统一的 `EndCanvasFocus(reason)` 焦点会话入口，以后选区会话复用同一套触发列表；
  - L1 的 pending 绘制接口同时接受墨迹和图形；
  - 保留 InkHistoryGpu 中的叠加模式（`rangeBegin` 加 `clearTargetTiles=false`）、`excludedItem` 和 tile helper。
- 外部调查建议「编辑预览使用独立层，不长期占用 L0/L1」。当前图形编辑通过「失去焦点即落定」避免了与实时笔迹争用 L1；如果套索选区需要在拖动时允许多触点同时绘制，需要重新评估是否使用独立层。
