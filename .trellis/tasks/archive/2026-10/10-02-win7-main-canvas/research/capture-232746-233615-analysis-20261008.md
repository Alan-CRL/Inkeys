**原版 reference 的细分很关键：**

- 6 个 unavailable 全部是 backbuffer/offscreen × cursor.production / cursor.blend_disabled / cursor.retain。原版透明或保持底图而没有正确画出光标，候选独立正确性通过。其 `comparison=unavailable` 且日志 `mismatch_pixels=0 max_channel_delta=0` 是不可比较时的占位值，**不能解释为这 6 项与原版等价**。两份终态 `:2160,2175,2190,2295,2310,2325`；原版正确性 FAIL 例如 `:2152,2167,2182`。
- 其余 12 项原版 reference 有效，全部 **comparison PASS / mismatch_pixels0 / max_channel_delta0**：普通 type0 笔、亚像素 thin、varying-radius、type3 荧光笔、erase-retain、draw-retain 各双纹理；终态 `:2205,2220,2235,2250,2265,2280,2340,2355,2370,2385,2400,2415`。
- 因此，本次补充证据不支持“DefaultInk 自己所有笔计算在 Win7 WARP 都失败”。原版真实 type0/3 直接绘制本来可以正确，而**同一个完整程序内的其他 type 路由至少包括 type4，被 DefaultInk 输出尾部的程序结构影响**；末端呈现颜色层仍可能因此透明。候选保留笔数学，同时恢复共享程序其他路径。
- 两份 `pixel-test.stderr.txt:4-5,14` 明确 WARP FL11_0 成功、实际 Software Adapter。`pixel-test-hardware.stderr.txt:4-5` 明确独立 Hardware FL11_0 **0x887A0004**，状态 unavailable，CLI exit3；**没有 Hardware GPU 用例运行，也没有自动偷偷回落 WARP 冒称 Hardware**。

计数只统计 `console.stdout.txt` / `console.stderr.txt` 中明确终态；原始数据没有过滤拒绝记录，RTS Down/Up 计 published1（不是 arrival 和 published 两次累计）。mouse buttonDown 字段是当时状态，**不能把每条 buttonDown1 当一次 WM_LBUTTONDOWN**。

- 原版共 **50 份 ULW 源 alpha/RGB 全零**；主窗最终 DIB 的 alpha1 是原有命中 underlay，RGB 仍零。例 D1 original `console.stdout.txt:31,65530`，D2 original `:31,74670`。
- 候选共 **116 份 ULW 采样，112 份源与最终 DIB RGB 非零**；另 4 份是两应用初始透明主/辅助清屏。源/最终 DIB 各采样 premul 都为1。
- 四轮共 **166 份 ULW 采样全部 api=success / error0**。普通 dirty-rect 参数仍然工作。典型 D1 guarded `console.stdout.txt:504`：dirty100像素，源alpha/RGB17，source/final sample BGRA(0,16,255,255)，API成功；`:4627` 后续有1237源RGB像素。
- D1 guarded `:219471` 辅助全帧源RGB352561，源/最终 DIB count、max、bounds和代表像素相同；D2 guarded `:2711` 主源RGB450，`:136730` 辅助 dirty 源RGB45397，代表像素相同。多数主窗有墨代表像素 source==final；无墨像素增加 underlay 的alpha1是预期，不能要求每个主窗source/final完全相同。
- 示例输入 D1 guarded `console.stdout.txt:496-497,6465-6466` 提供 Down/Up 的 arrival→published 配对；全量事件数量及每条 ULW 原始路径/行号都在 JSON。
- 这将“输入已接收但源透明→最终也透明”与“同 presenter、完整候选源非透明→DIB非透明→用户实际可见”连成了证据链。**当前两个 Aero 条件下的主要完全不出墨/光标消失症状，已被 guarded shader 候选恢复。**
- 两 VM 的屏幕尺寸、内存与使用序列不同，不能当作其他变量全相同的性能/Aero实验；但原版与候选成对结果在两个条件一致。

### 控制结构、数学保留和可证明的根因边界

相关源码：

- `Assets/inkPixelShader.hlsl:466-479` 计算 type0/type3 距离并提前返回 type7；`:487-537` 是 DefaultInk 尾部导数、AA、薄线补偿、discard 和 Add/Retain 输出。此前该尾部在默认落入路径无外围正向 route guard。
- `research/Generate-Win7-GuardedShader.ps1:32-48` 只把原尾部缩进到 `type==0 || type==3 || type<0 || type>20`，同时逐字符还原检查 prefix/tail/suffix。类型0/3和未知type原d0输出保持，其他合法类型本来已提前返回。
- 同生成器 `:64-79` 核验正式/候选输入输出签名一致，优化后 DXBC 中导数/discard 的实际控制深度≥1；不是仅在源文件里加了可被优化掉的 if。
- `Draw3.Renderer.cpp:641-658` 是 exact diagnostic env 双门控选择及创建；`:56-86` 是所选字节 SHA 报告。本次现场已验证加载路径。
- 先前独立报告 `guarded-gpu-implementation-20261008.md:7-13`、`verification-guarded-20261008.md` 记录 17 资源、全部 helper/数学/AA/细笔/光影/混合、ISGN/OSGN 保留和 Win11 全18参考图零差。此次 Win7新增12有效参考亦零差，真实画布视觉主要症状恢复。

可认定：**原完整 PS 的 DefaultInk 尾部与此前提前返回的工具/合成路由之间，在这版 Win7 WARP 上存在 shader 程序控制结构兼容问题；明确正向隔离尾部足以恢复主要输出，故主症状不应再归于鼠标/RTS或ULW窗口样式。**

尚不能认定：某一条 fwidth/discard、单个 thin helper、特定 SDK/FXC 指令就是唯一根因，或已证明微软 WARP 内部某个具体 JIT bug；程序字节布局与控制流同时变化，没有 WARP 内部执行追踪。不能以 type0 直接输出PASS推断所有生产合成路由原版PASS，也不能以候选cursor恢复推断所有历史/光影/多层MAX/MIN从此毫无问题。

### 荧光笔定格偶发变深：独立残留线索

- D1 `observations.txt:3`：荧光笔之后第一次定格曾使半透明颜色变深；激光局部 dirty 后变浅正常；撤回整页刷新后恢复；随后重复无法复现。D2 仅记录全部正常，没有同样异常。
- D1 guarded `idt1791473373014.log:20,23,24,25` 确认定格更新与显示已提交 request1/3/5/7；没有“变深那一帧”的标记、同一 ROI 的前后 BGRA、桌面截图和 Magnifier 捕获内容，所以不能把某一次 request 唯一对应异常。
- 两轮候选所有采样premul合法只能说明抽样合法。重复source-over仍可保持premul1并加深，因此不能据此排除叠加/dirty缓存问题。
- 从“局部重绘修正+全页重绘修正”看，更优先怀疑定格快照/窗口合成或绘制缓存失效时机；这是**推断**，不是已证明是哪一层。没有证据表明细笔/荧光笔公式被改；有效 highlighter reference 两目标完全零差。
- 正式整合 guarded 时应保留这条残留观察，针对同一既有半透明 ROI 测“定格前/定格刚开/不重画/局部激光/全页撤回”及背景是否重复包含墨迹；不为此删效果或扩大无关重构。当前无需继续大范围87项定位以证明主要不出墨边界。
