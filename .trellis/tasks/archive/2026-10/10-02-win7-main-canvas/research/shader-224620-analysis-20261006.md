## 2. 为什么完整 type4 常色也失败，不等于已证明进入 Cursor 后数学失败

`FullCursorEntryConstant`不是函数顶层无条件常色：保留 `int type=(int)(input.shapeType+0.5)`，先排除type9/10，再进入4..6 gate，在内部type4 gate后输出Add=Retain=0.5。实际DXBC首路径为 `add v4.z,0.5 -> ftoi -> ieq(9/10) -> if -> ige(4..6) -> if -> ieq(4) -> if -> mov o0/o1=.5 -> ret`。这次FAIL仍不能证明type4 gate实际到达。

上轮完整哨兵并未编译成常色小程序：资源、其它分支、采样、导数与discard仍全部存在。入口常色跳过Cursor的距离、alpha计算与本分支discard，但不移除全程序的声明和控制流。若旧WARP对其中之一处理异常，哨兵仍可全透明。

顶层源码p1/p2 `isnan`检查在/O3实际DXBC中消失，原程序和完整变体均没有该early discard。不能用源文件存在isnan直接推定执行故障。

`FullCursorAhead`的实际DXBC确实先4..6 gate/完整Cursor计算/ret，再9..10；它失败降低了“只是先执行Laser分支引起错误”的解释力，但声明资源和其它body仍存在。

Fields验证的是float shape=4及其它输入，不验证PS `ftoi`和动态if行为；CursorOnly完全不用shapeType、没有形状分支。VS本身也用了type转换且产生了正确quad，可降低“ftoi普遍不可用”的可能，但不能代替PS场景中的对应控制。

官方ftoi是SM4/5合法PS指令，向零转换，有限4.5应得到4。不是Win8独有。[Microsoft ftoi](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/ftoi--sm4---asm-)。这个尚未单独控制的变量应通过微型实际ftoi/if gate对照核验，不应凭平台标签删去整数路由。

## 3. 完整资源表与当前 Cursor绑定之间的差异

真实full PS仅有17个资源条目：

| 类型 | 真实槽 | 当前独立Cursor提交 |
| --- | --- | --- |
| 常量缓冲 | b0[3]，b1[7]，b2[3]，b3[3] | 显式仅绑定b0；其它buffer112/48/48字节 |
| sampler | s0 | Cursor不调用PSSetSamplers |
| Texture2D | t1,t2,t4,t5,t6,t7,t9,t14 | Cursor不调用PSSetShaderResources |
| Texture2DArray | t10,t11,t12,t13 | Cursor不绑定 |

**PS没有InkData t0、Highlighter t3、粒子t8声明或ld_structured。** t0的两个槽只在生产VS读取，字段validator已经证明真实VS输出正确。不得将未初始化的InkData其余DISCARD区当成完整PS直接读到的字节。

从新context/Init和Cursor代码可以推断上述额外槽为NULL；当前日志只直接读回b0、VS t0和shader对象，没有逐槽PSGet，因此下一候选应该实际核槽，而不是仅按源码打印期待。

完整Cursor路径只读取b0[2].yzw与v1/v2/v3/v4，访问均落在48字节b0内。哨兵type4路径甚至不读b0。b1..3与Texture SRV只在其它type路由读取。没有找到type4直接越界或未初始化字段读取的代码证据。

NULL不是立即确证的API合同违规：官方功能规范§7.10说明空CB读取返回0，§7.18.17空texture读取返回各分量0；PSSetSamplers说明NULL映射定义的默认采样状态。[Direct3D functional specification](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm)、[PSSetSamplers](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-pssetsamplers)。该规范归档包括后续版本，本文只引用基础NULL读取/绑定合同，不扩大Win7支持能力。

因此“额外声明资源未绑定”目前是**可判别的旧WARP资源状态相关兼容假设**，不是已证明的应用错误。所有五个full序列保留同一声明资源集，均未控制此变量；需要保持原PS字节/对象不变，仅改变绑定验证。

某些未选择Laser数学在NULL CB下可产生零除/NaN，但在合法动态控制流中不能据此污染type4输出。实际前移版本在Cursor返回后才有Laser/texture body，不存在DXBC文本层面的强制执行；如果是WARP全程序特殊化/推测执行，则属于另一个尚待实证的实现假设。

## 5. 下一最小验证方案（待主会话决定，不在本报告实施）

建议同一显式自检增加两个彼此独立的分界，继续保留18项结果和正式退出判定。

### A. compact实际整数路由哨兵

保持原PS_INPUT字段顺序/ISGN register/mask，微型PS实际执行 `ftoi(shape+.5)`、4..6/==4比较和if。type4输出Add/Retain=.5白；其它路由返回明确非透明红色错误哨兵，防止错误类型再被透明输出隐去。必要`[branch]`只用于这个诊断程序，并核实际DXBC ftoi/ige/ieq/if_nz，不能让优化成float比较或纯常色。

- 若FAIL且RGB哨兵可见，可直接取得路由错值证据；不能只看“白色不匹配”。
- 若也全透明，独立PS整数/控制流/该签名路径已出现最小复现；再拆float-only同gate与ftoi结果编码。
- 若PASS，降低简单type转换/gate假设，优先完整资源/其它body影响。

### B. 同一原PS对象的分组完整绑定 A/B/A

仅在独立renderer中创建并初始化专用dummy资源，保持原PS字节、对象、VS、Cursor上传、target与正式blend不变：

1. 查询并记录PS实际b0..3/s0/t1..14、原PS指针；保留当前基线。
2. 只显式绑定生产已有operatorSampler s0，画原PS。
3. 仅绑定已知内容b1/b2/b3（尺寸112/48/48，匹配CB声明；b0沿原生产上传），s0保持原NULL，画原PS。
4. 仅绑定全部12个匹配维度SRV，b1..3/s0保持基线，画原PS。
5. 三组全部绑定，画原PS；若恢复，可用同配置再跑full入口哨兵，但不是必需首轮。
6. 恢复全部基线NULL，原PS再画；随后精简CursorOnly末尾控制。

dummy Texture2D和Texture2DArray分别创建，按float4兼容格式；四个array SRV必须真实TEXTURE2DARRAY视图，不能给它们填2D SRV。已知零内容和明确slice范围即可与NULL读取合同对应。Dummy是独立小资源，不能使用当前offscreen/目标、不能与任何RTV/UAV别名，不依赖未初始化纹理。b1..3全零可对照NULL语义；零内容在其它路由数学下依然可能出NaN，但合法type4路由应不访问，其影响另行解释。

每一组必须实际PSGet验证bindings/资源身份和维度，不能只记录setter执行；恢复state和引用，creation失败报告ERROR不假PASS。不需要新生产shader编译或正常GUI。query仍有界，collector现有150s是否足够需按最终例数评估。

| 结果 | 可以支持 | 尚不能支持 |
| --- | --- | --- |
| compact route PASS，NULL full FAIL，all-bound full PASS，NULL full再FAIL | 相同字节/对象随声明资源绑定改变，资源状态相关强因果边界 | 自动宣布代码原NULL非法；哪一组唯一触发尚需分组 |
