## Goal

让居中底栏在主栏宽度与竖直位置同时变化时，仍在每个呈现帧以包含主按钮的主栏实际渲染几何保持屏幕水平居中。

## Background / User Value

用户说明最初设计是在渲染时以主栏水平中心对齐屏幕水平中心，而不是依赖可能随宽度动画失效的 UI 固定位置。当前进入 PPT、白板以及退出这些模式返回桌面时，竖直移动和主栏宽度变化同时发生，用户观察到运动轨迹并非居中直上直下。

## Confirmed Facts

- 当前 UI3 生产实现已有稳定居中的逐帧联合外框反推与 `MainBar.Inherit(Center, MainButton)`：`Inkeys/Inkeys/UI/Bar/Bar.RenderLoop.cpp:5537-5588`、`Inkeys/Inkeys/UI/Bar/Bar.BottomDock.h:889-917`。
- 对 Desktop→PPT/Whiteboard 和 PPT↔Whiteboard（Enter/Switch），该反推被 `displayTransitionActive` 关闭；场景就位期间主按钮 X/Y 改由 0.4 秒 `displayCenterX/Y` 插值直接控制，而主栏 `x/w` 继续独立动画：`Inkeys/Inkeys/UI/Bar/Bar.RenderLoop.cpp:1413-1425,1467-1469,2763-2767,2792-2806,2825-2838`、`InkeysHeadlessTests/bar_bottom_dock_tests.cpp:1165-1201`。
- 因此静态代码已能证明 Enter/Switch 中间帧的联合中心不成立，稳定后才重新对齐。最终 Leave→Desktop 使用 `desktopRestorePending` 并提前清除 display transition（`Bar.RenderLoop.cpp:12934-12950,13053-13071`），必须独立验证，不能直接套用 Enter 根因。
- 真实 GUI 像素幅度和每条操作序列仍需逐帧验证；完整证据与历史见 `research/centering-investigation.md`。

## Requirements

- R1：修复必须基于当前 UI3 唯一生产底栏的主按钮、主栏、继承、窗口位置和动画采样关系，不另建位置真值。
- R2：以主栏实际渲染宽度和所在屏幕为基准定义逐帧居中不变量，不能用固定宽度或静态子元素位置替代。
- R3：进入/退出 PPT 和白板等现有模式时，宽度非线性动画与竖直动画可同时进行，但不得引入水平偏心。
- R4：保留现有动画曲线和交互设计，不以禁用宽度动画、锁死宽度或只对齐最终帧作为修复。
- R5：本轮只调查并规划，不修改产品代码。

## Acceptance Criteria

- [ ] AC1：代码证据明确主栏中心在每个相关阶段的计算方式，并解释用户症状的直接根因；无法运行确认的环节须明确标注。
- [ ] AC2：进入 PPT、退出 PPT、进入白板、退出白板及桌面恢复的逐帧记录中，主栏实际水平中心与所在屏幕水平中心一致，误差仅允许来自既有整数像素取整。
- [ ] AC3：上述场景中主栏宽度与竖直位置同时变化时，轨迹仍保持水平居中，不能只对齐动画起点或终点。
- [ ] AC4：普通居中底栏拖动、吸附附近居中以及不改变宽度的竖直移动无回归。
- [ ] AC5：相关 UI3 算法与窗口自动化测试通过，并补充能复现原问题的回归覆盖。
- [ ] AC6（本轮规划交付）：形成带文件/行号和历史证据的调查文档，以及可执行的设计、实施与验证计划。

## 新增用户验收：定格退场

- Freeze 在有内容桌面进入空 PPT 时仅隐藏，List 身份/顺序不变，按既有布局批次收拢到前一可见按钮下层并渐隐；保持逐帧居中，不改变 DPI 或另设动画。
- 自动化覆盖合并/分离模式、左右展开和 100%/150%；真实视觉验收仍单独保留。
