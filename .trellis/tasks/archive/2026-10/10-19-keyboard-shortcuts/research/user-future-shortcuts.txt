我建议 Inkeys3 采用 **“一组真正的全局往返快捷键 + 按批注状态生效的功能快捷键 + 弹层和文本输入优先处理”** 的方案。

默认键位上，我倾向于：

- **`Ctrl + Alt + X`：切换「批注 / 操作电脑」，保留墨迹，并恢复上次使用的工具。**
- **`Ctrl + 1 / 2 / 3 / 4`：选择 / 画笔 / 图形 / 橡皮**，按主栏中这组工具的配置顺序调整。
- **`Ctrl + Z`：撤回；`Ctrl + Y`、`Ctrl + Shift + Z`：重做。**
- **`Ctrl + Delete`：清空当前页，保持当前工具。**
- **`Ctrl + Q`：定格；`Ctrl + D`：当前工具属性；`Ctrl + [` / `Ctrl + ]`：减小 / 增大粗细。**

这里最重要的规则是：**进入选择或穿透、开始操作下层软件以后，普通快捷键就交还给下层软件；跨穿透返回批注，由那组专门的全局快捷键负责。** 这样才能同时保留快捷返回能力和 PPT、浏览器的正常操作。

我查看的是 dev 分支的固定提交 [`5d319bbf5c52`](https://github.com/Alan-CRL/Inkeys/commit/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb)。下面先说明代码现状，再给完整的设计和实现建议。

## 一、当前代码有几个必须纳入设计的事实

### 1. 旧全局键盘钩子已经退出当前产品编译路径

这个发现需要先说明：**当前 dev 里，旧 `WH_KEYBOARD_LL` 代码虽然还保留在文件中，但实际没有按旧路径运行。**

项目文件把 `IdtDrawpad.cpp` 列为了 `None`，实际编译的是 `IdtDrawpadFacade.cpp`。后者的 `DrawpadInstallHook()` 是空实现，注释也明确写了旧低级键盘钩子不再安装。因此，这次应当建立新的统一快捷键服务，再接到现有业务入口。

代码依据：[产品编译清单](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys.vcxproj#L912-L931)、[键盘钩子兼容入口](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtDrawpadFacade.cpp#L42-L50)。

旧代码还有一些不适合迁回来的行为：绘制时整片拦截字母和数字、执行线程等待按键松开、处理后清空键盘消息队列。这些会影响前台应用，也容易丢失快速连续输入。它们属于**旧实现的迁移风险**，不能当作当前 dev 已经发生的运行故障。[旧键盘处理代码](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtDrawpad.cpp#L63-L179)、[旧快捷键消费者](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtDrawpad.cpp#L330-L411)。

### 2. “选择”与“保留墨迹往返”已经有不同语义

当前实现可以概括为：

| 模式 | 点击“选择” | 点击独立“穿透” | 再次点击后的行为 |
|---|---|---|---|
| **合并式** | 保留墨迹，进入选择状态以操作电脑 | 没有独立入口 | 再点选择仍是选择，当前不会恢复画笔 |
| **分离式** | 有墨迹时先提交清空，再进入选择 | 保留墨迹，进入穿透 | 再点穿透恢复上次的笔、图形或橡皮 |

分离式还有明确的提交约束：清空必须先被 Draw3 队列接受，随后才能进入选择。穿透恢复则已经利用 `lastAnnotationMode` 保留最近工具，具体笔型、颜色和粗细也有原来的状态记忆。[选择按钮入口](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtState.cpp#L1103-L1145)、[穿透切换入口](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtState.cpp#L1148-L1184)。

因此应定义两个明确的命令：

- **选择工具**：对应主栏的选择，遵守合并式、分离式各自的含义。
- **切换批注 / 操作电脑（保留墨迹）**：专门用于往返，两种模式下都不清空。

否则，把全局切换直接接到分离式“选择”按钮，会造成用户本来只想暂时操作 PPT，却清空了墨迹。

### 3. 主栏和画布不抢焦点，但设置窗口已经可以正常获取焦点

你说的无焦点问题适用于主要批注界面。不过，当前窗口服务会为设置窗口去掉 `WS_EX_NOACTIVATE`，打开设置时还会交还键盘焦点。

所以，**设置里的快捷键录制、搜索框、文本输入，应走正常窗口输入；屏幕批注和悬浮主栏才需要后台键盘路由。** 不需要把所有场景都塞进全局钩子。

代码依据：[窗口样式分流](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Window/Window.cpp#L1125-L1150)、[设置窗口激活处理](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Window/Window.cpp#L1672-L1696)。

## 二、真正解决冲突，要先定义快捷键的“归属”

无焦点批注软件存在一个无法靠换 API 消除的问题：

> PPT 仍然是前台窗口时，Windows 无法知道这一次 `Ctrl + Z` 是要撤回 Inkeys 墨迹，还是撤回 PPT 内容。这个决定必须由 Inkeys 的交互规则作出。

我的建议是建立一个明确的**批注会话状态**。它决定当前由谁处理普通快捷键，并且与画布是否接收书写保持一致。

### 建议的默认规则

| 当前场景 | Inkeys 的普通功能快捷键 | 下层应用键盘操作 | 全局往返键 |
|---|---|---|---|
| 正在使用笔、图形或橡皮 | 生效，匹配的组合由 Inkeys 接管 | 未被绑定的按键继续传递 | 切到操作电脑 |
| 合并式选择 | 暂停 | 正常处理 | 恢复上次批注工具 |
| 分离式选择 | 暂停 | 正常处理 | 恢复上次批注工具 |
| 分离式穿透 | 暂停 | 正常处理 | 恢复上次批注工具 |
| 正在操作 Inkeys 属性弹层 | 弹层需要的按键优先 | 其余按键按当前会话规则处理 | 普通情况下仍可往返 |
| 正在编辑设置或输入文字 | 当前输入控件优先 | 不涉及下层文档 | 快捷键录制时只记录，不执行动作 |
| 正在切页、加载墨迹等暂不可编辑阶段 | 已归属 Inkeys 的组合不向下泄漏，暂不可执行时给予反馈 | 保留未绑定的原生操作 | 按状态转换规则处理 |

**空白画布也可以处于批注会话。** 不能拿“有没有墨迹”决定快捷键是否生效，否则刚清空后 `Ctrl + Z` 就可能突然落到下面的文档。

同样，主栏收起也不应自动取消批注快捷键。用户仍在画布上写字时，撤回就应当继续撤回墨迹。

### 穿透状态下，为什么不能继续保留 `Ctrl + E` 往返？

因为它本来就有明确的外部用途：PPT 放映中是橡皮，Edge 中是地址栏搜索；`Ctrl + 数字` 在 Edge 中也用于切换标签页。若穿透后仍由 Inkeys 接管这些组合，用户就没有真正拿回电脑的完整操作权。[Microsoft Support](https://support.microsoft.com/en-us/accessibility/powerpoint/use-keyboard-shortcuts-to-deliver-powerpoint-presentations?utm_source=chatgpt.com)

因此，我建议：

**新默认取消 `Ctrl + E` 的穿透绑定，由专门的全局往返键统一负责。** 老用户仍可以自行把它改回去，但设置界面要明确说明该绑定的作用范围。

### 切换到其他软件时，建议自动暂停批注

例如，在 PPT 上批注到一半，用户 `Alt + Tab` 切到浏览器输入文字。此时，不能只因为内部还记着“画笔模式”，就继续抢走浏览器的 `Ctrl + Z`、`Ctrl + 2`。

建议默认开启：

**“切换到其他应用窗口时暂停批注”。**

具体行为是：

1. 保留墨迹和最近工具。
2. 画布进入实际可操作下层的状态。
3. 普通快捷键同步交还下层应用。
4. 用户再次按全局往返键或点击工具，恢复批注。

这必须同时约束键盘和指针。**不能出现鼠标还在 Inkeys 写字，而 `Ctrl + Z` 已经撤回下层正文的稳定状态。**

自己的设置窗、颜色编辑窗和确认框则作为内部输入场景处理，不应误判为用户已经切换到别的软件。

## 三、我建议的完整默认键位

以下是**新方案的建议默认值**，不是说当前 dev 已经实现了这些键。

### 1. 真正全局的快捷键

| 功能 | 默认按键 | 精确行为 |
|---|---|---|
| **切换批注 / 操作电脑，保留墨迹** | **`Ctrl + Alt + X`** | 批注中切到操作电脑；操作电脑时恢复最近工具；首次使用没有记忆时回到默认画笔 |

选择这组键，是因为它有明确的普通终键 `X`，左手也能操作。按住 `Ctrl + Alt` 后，每次重新按下 `X` 都能完成一次往返，不需要像旧方案一样等待三组修饰键全部松开。

我核对的微软常规与辅助功能快捷键表中，没有发现它对应标准系统功能；不过，它仍可能和第三方软件或用户自己的绑定冲突，不能称为绝对无冲突。`Ctrl + Alt` 还需要考虑国际键盘的 AltGr 情形。[Microsoft Support](https://support.microsoft.com/en-us/accessibility/windows/keyboard-shortcuts-in-windows?utm_source=chatgpt.com)

这个命令应明确做到：

- 合并式：批注 → 选择；选择 → 最近工具。
- 分离式：批注 → 穿透；选择或穿透 → 最近工具。
- 往返时保留墨迹、笔型、颜色和粗细。
- 进入操作电脑时关闭定格，恢复批注时保持定格关闭。
- 长按只切换一次，松开 `X` 后才允许再次触发。

这里尤其要补齐合并式的定格收尾。当前分离式穿透已经会关闭定格，但直接进入合并式 Selection 的入口没有同样的取消步骤。[当前相关实现](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtState.cpp#L1148-L1218)。

### 2. 主栏工具快捷键

当前默认工具排列确实是**选择、画笔、图形、橡皮**，图形在橡皮之前；后面才是撤回和清空。[当前默认布局](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Other/Other.Config.cppm#L199-L225)。

| 功能 | 默认按键 | 行为 |
|---|---|---|
| 选择 | **`Ctrl + 1`** | 与当前模式下的选择入口一致；分离式有墨迹时会清空 |
| 画笔 | **`Ctrl + 2`** | 回到记忆的笔型，包括软笔、硬笔、荧光笔或激光笔 |
| 图形 | **`Ctrl + 3`** | 回到记忆的图形类型 |
| 橡皮 | **`Ctrl + 4`** | 回到橡皮 |

这几个键应当是**直接选择工具**。重复按已经选中的工具键，保持该工具即可。

当前鼠标按钮有“再点一下展开属性”的交互，所以键盘入口不宜原样调用按钮的点击回调。工具选择和属性面板开合应拆成两个命令。[画笔按钮当前行为](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/UI/Bar/Bar.Button.cpp#L309-L343)。

### 3. 编辑与界面快捷键

| 功能 | 建议默认键 | 具体约定 |
|---|---|---|
| 撤回 | **`Ctrl + Z`** | 当前页撤回；没有可撤回内容时不向下层传递 |
| 重做 | **`Ctrl + Y`** | 当前页重做 |
| 重做的兼容键 | **`Ctrl + Shift + Z`** | 与 `Ctrl + Y` 是同一个命令 |
| 清空当前页 | **`Ctrl + Delete`** | 清空墨迹，保持当前工具；长按不重复 |
| 定格开关 | **`Ctrl + Q`** | 保留旧习惯；仅在定格可用的场景执行 |
| 当前工具属性 | **`Ctrl + D`** | 打开或关闭当前工具的属性面板 |
| 减小粗细 | **`Ctrl + [`** | 调整当前可调工具，使用现有粗细规则 |
| 增大粗细 | **`Ctrl + ]`** | 同上 |
| 主栏展开 / 收起 | **`Ctrl + Shift + H`** | 只改变主栏展开状态，保留当前批注工具 |
| 更多菜单 | **`Ctrl + Shift + M`** | 打开或关闭更多菜单 |
| 打开设置 | **`Ctrl + ,`** | 打开现有设置窗口，并交给窗口正常处理键盘输入 |
| 关闭弹层 / 取消当前操作 | **`Esc`** | 仅在 Inkeys 确实有需要取消的操作时接管，PPT 特殊规则见后文 |

所有这些组合，默认都属于**批注期间快捷键**。

#### 清空与选择的差异，要在产品中表达清楚

我建议把 `Ctrl + Delete` 定义成稳定的“清空当前页”。当前清空按钮还有“空页再点进入选择”等鼠标交互；键盘清空不应因重复消息而顺便退出批注。[现有清空按钮逻辑](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/UI/Bar/Bar.Button.cpp#L62-L95)。

这样，两个操作流程就很明确：

- **`Ctrl + Delete` → `Ctrl + Z`**：清空后仍在批注，直接恢复墨迹。
- **分离式 `Ctrl + 1` → 操作电脑**：此时普通 `Ctrl + Z` 已归下层应用。要恢复 Inkeys 墨迹，应先按全局往返键回到批注，再撤回。

不要在“清空并进入选择”之后，额外偷偷保留几秒钟的全局 `Ctrl + Z`。用户在那几秒钟内可能已经开始编辑下层文档。

当前 Draw3 已有通过普通撤回恢复**最近一次有效清空**的实现，可以接入这个设计；但不宜把它描述成无限跨清空、跨重启的完整历史栈。[清空恢复点与 Undo 处理](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Drawing/Draw3/Draw3.DrawingController.cpp#L12291-L12413)。

### 4. 可以自定义，但默认留空的命令

支持自定义后，有些功能适合进入命令列表，用户需要时再绑定。

| 功能 | 默认处理 |
|---|---|
| 直接选择软笔、硬笔、荧光笔、激光笔 | 留空；默认由画笔键恢复记忆笔型 |
| 直接选择某一种图形 | 留空 |
| 选择指定颜色、上一个 / 下一个颜色 | 留空 |
| 选择细 / 中 / 粗预设 | 留空 |
| 单独进入操作电脑、单独恢复批注 | 留空；提供给希望分别绑定两个键的用户 |
| 打开历史面板、特定橡皮属性 | 留空 |
| 第三方组件、点名工具等 | 留空，按组件命令 ID 配置 |
| 通过 Inkeys 按钮路径结束放映 | 留空；自定义绑定后沿用当前结束放映流程 |
| 手动保存、超级恢复、白板等尚未开放的能力 | 能力接通后再允许启用 |

最后一行是当前代码的实际限制：普通 `Save`、`SuperRecovery` 等命令仍返回 `Unsupported`，白板也有关闭的发布开关。不能仅因为枚举存在，就在快捷键设置里显示成可正常使用的功能。[命令能力检查](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Drawing/Draw3/Draw3.Bridge.cpp#L119-L142)、[白板发布开关](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtState.h#L199-L201)。

## 四、Ctrl 数字提示可以保留，但编号规则需要明确

我赞成你说的“按 Ctrl，在按钮右上角显示数字”。

**我建议对编号范围做一个小调整：默认给选择、画笔、图形、橡皮四类工具编号，撤回、清空等显示各自固定快捷键。**

原因来自当前布局：Undo/Redo 会动态增加、交换主按钮与浮窗身份；分离式会插入穿透按钮；PPT 场景也会改变按钮显隐。如果把整条主栏当前可见按钮从头数一遍，同一个数字可能在不同状态下变成不同操作。[动态布局实现](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/UI/Bar/Bar.Button.cpp#L1373-L1465)。

默认规则可以定为：

1. 从用户保存的主栏排列中，取出这四类工具，依次编号。
2. 用户重排这四个工具时，数字随之改变。
3. 主栏左右展开、镜像显示时，号码跟着按钮移动，不因展开方向重新编号。
4. 撤回或重做出现、PPT 按钮显隐，不改变工具号码。
5. `Ctrl` 单独按下只显示提示，不吞掉 Ctrl 本身。
6. 在选择、穿透以及文本输入期间，不显示会让用户误以为可用的工具数字提示。

另外，**角标显示和按键匹配必须使用同一份映射快照**。不能让 UI 显示“3”，后台却根据另一份实时按钮列表执行别的功能。

如果你希望整条主栏都支持编号，也可以提供“完整主栏编号”选项，扩展到 `1–9、0`。此时应在 Ctrl 首次按下时冻结一份布局映射，直到松开；期间按钮失效就停用该目标，不能把原号码立即挪给另一个按钮。撤回、清空仍保留固定功能键，方便不看界面直接操作。

自定义键也要区分两种绑定：

- **位置绑定**：例如 `Ctrl + 2` 对应第 2 个工具位置。
- **功能绑定**：例如用户额外把某个组合绑定为“荧光笔”，重排主栏后仍然是荧光笔。

这样，后续布局定制和快捷键定制才不会互相覆盖。

## 五、PPT 场景怎么处理，才能保留原生操作

### 1. 默认保留 PPT 的翻页、动画和退出按键

下面这些按键，本来就是 PPT 放映操作的一部分。[Microsoft Support](https://support.microsoft.com/en-us/accessibility/powerpoint/use-keyboard-shortcuts-to-deliver-powerpoint-presentations?utm_source=chatgpt.com)

| 按键 | PPT 原生用途 | Inkeys 建议 |
|---|---|---|
| `PageDown`、右 / 下方向键、空格、Enter | 下一动画或下一页 | 没有 Inkeys 弹层明确需要时原样传递 |
| `PageUp`、左 / 上方向键、Backspace | 上一动画或上一页 | 同上 |
| 数字后按 Enter | 跳转指定页 | 保留普通数字输入 |
| `Esc` | 结束放映 | 没有 Inkeys 待取消操作时传递 |
| `Ctrl + P / A / E / L` | 笔、箭头、橡皮、激光 | 新默认不占用这些组合 |
| `Ctrl + H / M` | 隐藏指针、显示或隐藏墨迹 | 新默认不占用 |
| `Ctrl + S` | 显示所有幻灯片 | 当前不要定义成 Inkeys 的可用保存键 |

因此，PPT 在前台时，物理翻页键的处理应是：

**让 PPT 收到原按键，再由现有 PPT 会话和页变化同步机制更新 Inkeys。**

不能既把按键传给 PPT，又调用一次 COM 翻页，否则会发生双翻页或跳过动画。用户另行绑定的 Inkeys 翻页命令，则可以接管那组组合后只走一次 COM 命令。

### 2. Esc 用“当前操作优先”，不要一概拦截

建议顺序为：

1. 有快捷键录制、文字编辑或模态框时，由对应界面处理。
2. 有当前正在操作的属性弹层，关闭弹层。
3. 有未完成的图形或临时操作，取消该操作。
4. 没有以上情形，传给前台应用；前台为 PPT 放映时，就正常退出放映。

**如果第一下 Esc 已被 Inkeys 用于关闭弹层，这次按压的自动重复也要继续由 Inkeys 消费，直到松开。** 否则用户长按一次 Esc，可能先关弹层，紧接着同一次长按的重复消息又退出 PPT。

### 3. 不要只判断“PPT 正在运行”

当前代码已经有包含放映窗口、PID、会话修订等信息的 `PptSessionToken`，焦点交接也会检查当前前台和设置窗口。快捷键可以复用这些状态。[PPT 会话身份](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Business/PptSession.h)、[当前前台校验](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtPlug-in.cpp#L464-L485)。

至少要区分：

- 当前放映窗口；
- 演讲者视图；
- 普通编辑窗口；
- Office 对话框；
- 用户已经切换到的其他软件。

同一个 `powerpnt.exe` 进程中的不同窗口，也可能具有不同的键盘意图。

### 4. 原生批注自动接管继续走现有机制

dev 已经有 `AutoTakeOver`：读取 PPT 原生批注工具、确认退出原生工具，再在同一会话和模式修订下切到 Draw3。

新增快捷键时，可以保留这条路径。不要又在新钩子里对 `Ctrl + P` 添加第二套工具切换逻辑，造成相互覆盖。[现有原生批注接管](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/IdtPlug-in.cpp#L918-L936)。

## 六、底层实现：采用混合机制，并统一命令入口

### 1. 三种 Windows 机制分别承担什么

| 机制 | 建议用途 |
|---|---|
| **`RegisterHotKey` → `WM_HOTKEY`** | 少量真正全局的命令，例如批注 / 操作电脑往返 |
| **`WH_KEYBOARD_LL`** | 按当前批注会话匹配快捷键，观察 Ctrl 按下 / 松开，并按需阻止匹配事件传到下层 |
| **正常窗口键盘消息** | 设置、文本输入、快捷键录制等有真实焦点的界面 |
| **Raw Input** | 需要后台观察或识别输入设备时使用，不能替代这里的快捷键抑制 |

`RegisterHotKey` 能把系统热键消息发给注册窗口或线程；低级键盘钩子则能在正常条件下阻止事件继续传递。Raw Input 的 `RIDEV_NOLEGACY` 只约束注册应用自己的传统消息，不能用它来阻止 PPT 同时处理按键。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey?utm_source=chatgpt.com)

有一个容易写错的地方：

**不能把 `Ctrl + Z`、`Ctrl + 数字` 永久注册成全局热键，再在穿透状态收到 `WM_HOTKEY` 时直接忽略。** 系统已经占用了组合，忽略消息并不会自动还给前台。微软自己的 Terminal 全局唤回说明也明确指出，绑定后的组合将无法正常用于其他应用。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions?utm_source=chatgpt.com)

### 2. 键盘服务只负责“识别和分发”

建议形成下面的分工：

| 层级 | 职责 |
|---|---|
| 输入入口 | 接收热键、低级键盘事件或正常窗口消息 |
| 快捷键路由 | 判断作用范围、精确匹配、按压归属、重复策略 |
| 命令分发 | 携带触发时上下文，转到适当的业务线程 |
| 现有业务入口 | 工具切换、Draw3 历史命令、UI3 弹层、PPT 命令 |

低级钩子应运行在专用消息线程中，回调只读取准备好的状态快照、匹配并轻量入队。微软明确说明：安装线程必须持续处理消息，Win7 及以后钩子超时可能被静默移除；回调发生在当前键的异步状态更新之前，也不能靠此时查询 `GetAsyncKeyState` 判断这个键的新状态。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc?utm_source=chatgpt.com)

结合现有代码，尤其要避免在钩子里直接调用会加锁、同步窗口或触及绘制宿主的业务函数。`GetStateModeSnapshot()`、`PublishProductCommand()` 等入口适合业务层使用，钩子应读单独发布的快捷键上下文快照。

### 3. 一次按压，从按下到松开固定归属

这是防止各种偶发冲突的核心。

假设 Inkeys 接管了某次 `Ctrl + 1`，随后立即进入选择。`1` 的松开消息到来时，不能因为“现在已经选择了”就重新决定把它交给 PPT。

应记录：

- 本次主键最初由 Inkeys 接管，还是向下传递；
- 对应命令和上下文；
- 是否允许自动重复。

后续重复、最终松开都沿用这次归属。暂停批注、关闭弹层、修改绑定时，这份按压记录也应保留到松开。

Ctrl 等修饰键通常保持成对传递，匹配时消费普通终键。修饰组合必须精确匹配，不能让 `Ctrl + Shift + Z` 同时命中 `Ctrl + Z`。

### 4. 没有可撤回内容，也不能把撤回漏给下层

必须区分：

- **该组合不属于当前 Inkeys 会话**：传递给下层。
- **该组合属于 Inkeys，但动作当前不可执行**：消费，保持状态，并按需要提示。

第二种包括撤回栈为空、PPT 中定格不可用、页面加载中、命令队列繁忙等。

例如，画布已经撤回到底，再按 `Ctrl + Z`，应当停在这里。否则用户连续撤回墨迹时，最后一下会突然撤回下面的正文。

队列繁忙时也应明确报告“此次操作未执行”，不能假装完成；反馈需要独立、非阻塞的通道，避免反馈本身也卡在同一个满队列中。

### 5. 文档和页面身份要一直带到 Draw3 执行处

现有 Bridge 在发布命令时已经保存工作区和 PPT 目标身份，这部分值得保留。[当前 Bridge 命令绑定](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/Drawing/Draw3/Draw3.Bridge.cpp#L119-L142)。

新增快捷键队列后，要防止这种情况：

1. 用户在第 5 页按撤回。
2. 命令还在快捷键队列中。
3. PPT 翻到第 6 页。
4. 分发线程才开始发布撤回。

如果此时直接取“当前页”，就撤错页了。

因此，快捷键事件必须携带触发时的文档、页面、会话身份；这些信息应随命令进入 Draw3，在实际执行处校验或按既定目标执行。**只在外层分发线程检查一次，随后无条件调用原入口，仍然存在检查后换页的竞态。**

### 6. 属性弹层也要纳入统一输入归属

当前 `TryQueueColorPickerKeyboardInput()` 中，橡皮和撤回面板的部分按键有前台 / 指针门禁，颜色面板的方向键和 WASD 分支却没有同样的检查。

由于旧键盘入口未启用，这里应视为**重新接通键盘之前要处理的潜在问题**。新方案要由统一路由决定哪个弹层拥有键盘，避免“色盘还开着”就一直抢走其他软件的方向键。[当前面板路由](https://github.com/Alan-CRL/Inkeys/blob/5d319bbf5c520dec97dcb37ad2fcc7e26d029bbb/Inkeys/Inkeys/UI/Bar/Bar.Interaction.cpp#L7428-L7457)。

### 7. 全局热键只执行一次，并检查注册结果

成功注册的全局组合，由钩子放行到系统，再通过 `WM_HOTKEY` 单一路径执行。不要让钩子和热键消息各切换一次。

使用 `MOD_NOREPEAT`，检查注册失败，并在更改快捷键时正确注销旧绑定。注册失败应显示“已被占用 / 未生效”，不能悄悄改为钩子强抢。Windows 键组合和 F12 也不适合进入默认全局键位。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey?utm_source=chatgpt.com)

## 七、UIPI 的处理建议

**`RegisterHotKey` 很适合保护全局入口，但它不能让整个输入系统自动获得跨权限控制能力。**

需要分别验证几件事：

| 项目 | 应观察什么 |
|---|---|
| 全局键是否注册成功 | 返回值与错误 |
| 按键是否触发 `WM_HOTKEY` | 系统消息有没有到达 |
| 低级钩子是否收到事件 | 回调是否到达 |
| 修饰键状态是否正确 | Ctrl / Alt / Shift 是否完整 |
| 匹配按键能否被可靠抑制 | 高权限前台有没有同时动作 |
| 模拟按键是否成功 | 如果某些组件仍使用输入注入，单独检查 |

官方文档明确指出，`GetAsyncKeyState` 可能因 UIPI 返回 0；`SendInput` 也只能向相同或更低完整性级别注入输入。所以不能把这些不同失败都概括成“钩子没用”，也不能用模拟重放来兜底所有未处理键。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate?utm_source=chatgpt.com)

产品上，我建议普通权限作为默认；确实需要操作管理员窗口时，再提供清楚的权限适配说明。`uiAccess` 可以另行评估，但它涉及可信签名、安全安装位置和适用场景，无法仅靠改一个 manifest 属性完成，尤其不适合直接作为便携版的统一前提。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview?utm_source=chatgpt.com)

前台变化的处理同样不能只依赖异步通知。可以用 `EVENT_SYSTEM_FOREGROUND` 主动更新状态，同时在新的键盘和指针操作进入前检查当前目标，避免通知还没处理时继续接管新窗口。[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook?utm_source=chatgpt.com)

## 八、建议按这四个阶段落地

| 阶段 | 实现内容 | 核心验收目标 |
|---|---|---|
| **1. 统一入口和作用范围** | 新键盘服务、全局往返命令、批注会话、按压归属 | 进入和离开穿透可靠，普通键不干扰下层 |
| **2. 核心命令** | 四种工具、撤回、重做、清空、定格、属性面板 | 与现有业务入口一致，没有误清空、重复切换、错误弹窗 |
| **3. 自定义与角标** | 配置保存、录制界面、冲突检测、工具槽位、Ctrl 提示 | 显示什么就触发什么，改布局和改键位不会错配 |
| **4. PPT 与兼容性验收** | 原生翻页、Esc、前台切换、权限、Win7 / ARM64 | 单次按键只执行一次，不影响错误文档或错误页面 |

最关键的验收用例，应直接围绕用户行为来做：

- 批注状态下按 `Ctrl + Z`，只撤回墨迹；撤到底也不影响正文。
- 穿透状态下，浏览器 `Ctrl + 2` 正常切标签，文本框 `Ctrl + Z` 正常撤回文字。
- 分离式 `Ctrl + 1` 与全局往返键的清空行为严格不同。
- 清空后直接撤回，恢复最近清空的墨迹。
- 按住 Ctrl 切换模式、关闭面板、切换窗口再松手，没有残留角标或异常按键状态。
- 一次 Esc 关闭弹层时，同次长按不退出 PPT；普通 Esc 仍能退出放映。
- 一次 PageDown 只推进一次动画或页面。
- 快速翻页时，迟到的清空或撤回不会落到新页。
- 设置输入框里的撤回、复制、粘贴保持正常。
- 高权限前台、Win7 和 Windows 11 ARM64 分别验证接收、抑制和实际模式切换。

这次完成的是 dev 源码核查和实现方案设计，尚未进行 Windows / Office 实机验证。第一阶段应先做到 **“全局往返可靠、普通快捷键归属明确、PPT 原生键盘操作正常”**；后续默认键位和自定义界面都建立在这个基础上。
