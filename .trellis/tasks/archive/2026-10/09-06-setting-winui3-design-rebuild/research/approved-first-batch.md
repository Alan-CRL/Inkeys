# 首批实现批准与范围

用户先认可 v1 大体设计，随后明确要求先迁移左侧导航、主页，再做一个控件较全的页面。主会话将该页具体确定为“常规”，解释文字继续使用 ImGui/ImFluent，校准随页面推进；用户本轮明确回复：“好的，现在我批准你开始写代码。”这满足已有设计审查后的实现批准，无需重复索取同意。

## 本次交付

1. 新导航：248/48 DIP，图标中心和标签轴一致，36 高 item、4 gap，用户宽窗偏好与自动窄窗/覆盖状态分离。所有原导航/底部动作保留；不改窗口标题栏/DWM。
2. 新主页：遵循 preview/02-home-wide.png 与 preview/index.html 的视觉与信息组织，具有书写示意/主操作、绘制/预设/插件入口、常用设置、作者与原外链；功能必须接回真实原页面和现有操作，不交付占位页或示例状态。
3. 常规页：使用新行布局，覆盖原有全部常规设置，保持字段和保存/实时通知/确认行为；文字左对齐、action 实际宽度靠右，32 DIP 控件、72 DIP 双行卡片、28/8/4 分组间距，长文和窄宽度重排。
4. 字体与图标校准：仍由 ImGui/ImFluent 绘制；字体 nominal size / glyph scale / baseline / lineHeight 独立考虑。1.213 为度量起点，不能只扩大字形导致 clip。共用字体调整可以影响其他旧页，但不得使其裁切或改变业务。
5. 新 UI 的公共布局/控件/页面职责要清晰，不能继续往大 switch 塞大量绝对坐标补丁。为本批建立必要的新边界，保留未迁移页面调用。

## 实施取舍

- 本批不迁移语言/配置/版本/绘制/预设/插件详情/组件等其他页面的内部布局，也不做全量大重构。
- 不新建文字引擎或大型独立离屏框架作为前置；优先最小的无 HWND ImGui 文字/控件 DrawData 检查，必要时小型离屏样张；产品沿用共享 D3D/CSO/resident pipeline。
- 允许为字体、导航或可验证的控件布局能力添加最小 ImFluent 适配，需记录来源和 UPSTREAM 本地补丁。优先公开 API；不建立替代 ImFluent 的控件库。
- 中文注释、原编码和 CRLF 保持；真实新文案进入现有 i18n 源/生成链，不扩展配置 schema。
- 不实现窗口 chrome/Mica、深色、新动画、触摸、动态脏区。不 commit。不启动任何原生可见窗口或操控桌面。

## 本批接受条件

- 所有导航保持可达，图标在展开/收起时位置稳定；紧凑/覆盖均不产生负宽度或命中错位；底部操作与菜单同轴。
- 主页接线完整，无审查稿占位动作；常规字段逐项与原逻辑核对，不丢保存与实时同步。
- 960×700、720×520 及紧凑宽内容预算时无文字/action 重叠，长译文有合理换行；字体中文与 Agpqy 不裁切。
- 适当 headless --no-window、国际化 check、ARM64 host 完整 InkeysRepo.sln Debug|ARM64 构建和 diff check 通过。构建允许至少 5 分钟；主会话运行完整构建，子代理避免同时构建。
- 任务总体保留后续全量迁移路线；本批完成后准确记录哪些页面已迁移，哪些仍保持旧实现。
