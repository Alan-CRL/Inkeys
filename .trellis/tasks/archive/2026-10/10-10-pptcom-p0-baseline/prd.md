# PptCOM P0 兼容基线与通信选型核查

> 用户于2026-10-10批准开始实施，仅执行总体规划的第一个阶段P0。后续P1-P5不在本轮实施范围。

## 目标与修改边界

当前缺口是后续迁移缺少可重复的兼容基线和具体IPC依赖决策。该缺口属于任务研究/验证层，本阶段不改变生产联动行为。

- 新增本子任务研究、独立无窗口通信探针与重复执行脚本；运行现有托管fake测试。
- 只读核查PptCOM dynamic/ROT、owner线程、事件与轮询、释放和native页事务，固定原DLL/TLB/manifest散列。
- 不修改生产C#/C++、COM接口/GUID、项目配置、依赖版本、线程模型或部署产物；不创建新构建系统。
- 不启动PowerPoint/WPS、Inkeys、浏览器、UAC或任何GUI。不安装依赖，不commit/push。

## 需求与验收

| ID | 需求/可检查结果 |
| --- | --- |
| P0-1 | 固定源码与随附DLL/TLB/manifest基线；记录原线程入口/COM初始化、动态根对象、ROT单赢家、事件唤醒/慢维护、temporary与长期根释放顺序及产物交接。清楚区分源码事实与真实Office行为。 |
| P0-2 | 核查具体ZMQ绑定当前目标框架/原生依赖/架构与退出约束，核查命名管道API在.NET4引用程序集中的实际可用性及Win7文档最低系统。选择一个首发通道并说明证据、排除理由和待通过的实机门禁。不声称全部ZMQ都不支持net40。 |
| P0-3 | 可重复无窗口探针使用.NET4接口，验证双向UTF-8分帧、部分读取、长度上限、半帧EOF、peer关闭/重连、等待连接/读取取消及有界退出。尽可能覆盖managed server与Win32 client互通；进程退出码与每用例结果明确，不能只以无异常为通过。 |
| P0-4 | 用既有PptCOM.Tests入口验证owner/纯值/COM acquisition合同。先确定现有MSBuild，使用原生ARM64 host及同invocation PATH处理；输出与随附资源隔离。原DLL/TLB/manifest和生产源码散列保持。 |
| P0-5 | 记录当前Active/前台PID/WPS本地优先级与统一观察的边界、实际源码采样周期；给出后续采样/切换/PageChanged时序测量方案。未实测Office延迟时不固定防抖数值、不宣称P95。 |
| P0-6 | 报告Windows11 ARM64本机实际结果、目标.NET4编译与本机实际CLR的区别。Win7 SP1/.NET4运行、双方跨权限ACL/完整性、不同管理员凭据、损坏COM/实际Office释放明确标NOT VERIFIED，留作P3/P4/P5上线前实机门禁。 |

本阶段交付完成定义是本机可执行的证据、首发选择与明确的外部验证门禁已形成并复核；不表示后续helper已经实现、Win7/跨权限/损坏COM已经通过运行验收。
