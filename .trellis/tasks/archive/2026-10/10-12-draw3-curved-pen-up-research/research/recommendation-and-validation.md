# Research: 修复候选与后续验证计划

- Query: 大曲率转弯过程中立即抬笔，如何避免平滑轨迹连接真实 Up 点时弯折？
- Scope: mixed；本次仅研究，不授权实施
- Date: 2026-10-12
- Baseline: `bugfix/penstroke`，HEAD `ed28f668`；主产品为 `Inkeys/Inkeys/Drawing/Draw3/`

> 2026-10-12 后续规划更新：用户希望将终态计算纳入本地 Ink Stroke Modeler，并评估 Modeler 源码/Abseil 静态库拆分。当前架构和阶段门以 ../design.md、../implement.md 及 modeler-terminal-reconstruction-api.md、modeler-source-build-and-abseil-split.md 为准；本文件保留早期候选比较。

## 判断依据

历史用户复测已经确认：运动阶段墨迹可能偏向物理轨迹外侧，突然 Up 接到真实终点产生拐动；局部重建 Up 新增段的 cubic 方案已撤回。见旧任务 `research/release-tail-thin-coverage.md:3-7`。这是一条真实用户现象记录，尚无本次设备轨迹量化数据。

现有端点门禁检查到终点的距离、接近方向上的终点平面和有限值；首次不安全候选触发精确 raw endpoint。它不检查局部方向变化或横向偏差，见 `Draw3.StrokeGeometry.cpp:1532-1597`。因此，“终点精确到位、无过冲”不足以推出“尾段无弯折”。

对历史反例的独立纯几何复算见 [gate-counterexample.json](gate-counterexample.json)：点列 `(0,0)→(8,-1)→(9.7,-.3)→(9.96,-.2)→(10,0)` 到终点距离严格下降，所有点都在终点平面之前，但最后两段方向从约 21.04° 变为 78.69°，突变约 57.65°。此计算只证明门禁条件的不足，**不是**真实设备、模型库或产品运行复现。

需要区分三个问题：原始输入的帧间丢样或稀疏、弹簧位置模型运动阶段的惯性/横向偏差、Up 净化之后的连接方式。预测只影响活动 L0 的未来延伸；已经进入真实中心线的运动偏差不能靠删除预测消除。原始输入坐标也不是无噪声的连续真实曲线，应使用保留顺序的局部轨迹和合理误差容差，而非把每个 raw 点直接钉入几何。

几何边界也有冲突：如果最后一个 pre-Up 点和入射方向都已固定，而 raw Up 位于明显的侧方，继续要求路径到达 raw Up 就必须在某处转向。追加 cubic 可以把角度变化分散，却不能恢复已经错误的运动段，也不能无条件同时保证无回头、低曲率、零视觉修正和精确终点。完整解决应先降低运动期偏差，或明确允许改变尚未固化的尾段；不能把这些取舍隐藏在“最后一点到位”的验收中。

## 优先研究路线

初轮建议先对照库内位置校正。2026-10-12 后续用户选择保留真实 Up、允许未落 L1 尾段重构；当前研究优先级转为库外有界重构及 raw/model 匹配，库内参数仍作对照。具体设计见 ../design.md、后续实验顺序见 ../implement.md，均未授权实施。

本地头文件包含 `loop_contraction_mitigation_params`；产品 `Draw3.InkPrediction.cpp:236` 只填写 spring/drag，未启用该校正，`params.h:74` 默认关闭。产品 `Draw3.InkPrediction.cpp:244` 已开启 `use_stroke_normal_projection`。这提供了一个无需先引入新算法的对照候选，但不能只把布尔值改成 true：速度上下界、两个强度和采样窗口仍为无效默认值，需要完整配置和验证。

`loop contraction mitigation` 通过模型法线投影，把模型位置与原始轨迹投影位置按速度融合。它名字中的“收缩”不能作为排除外偏问题的依据；投影机制在原理上也可能降低横向外偏。然而它不保证 Up 切线连续，极端转弯、稀疏输入及自交处投影有歧义，必须实际测量。本地源仓库 `stroke_modeler.cc:55-75` 使用建模 Result 的 velocity 更新融合速度，而不是简单读取产品 raw speed；参数不要直接套用其他模块的测速阈值。

## 候选方案与取舍

| 候选 | 作用阶段 | 预期作用 | 主要限制 | 建议 |
|---|---|---|---|---|
| 0. 输入保真对照；条件成立后独立设计有界样本保留 | RTS packet / mailbox / model 输入 | 判断并减少包内和帧间采样合并造成的急弯误差 | 尚未证明是根因；不能伪造设备逐点时间，必须维持 producer 非阻塞和预算 | 作为最前置对照；研究阶段不改变队列或采样合同 |
| A. 对照库内已有 loop contraction mitigation | Move 建模输出及预测 | 把横向偏离拉向原始局部轨迹，减少 Up 前的误差来源 | 默认关闭、需要完整参数；可能增加抖动，误选自交分支；改变正常运动形状，不能保证末端方向 | 优先离线实验；通过实际静态库和产品验证后才讨论启用 |
| B. 运动期局部轨迹走廊/有界投影融合 | Move 接纳之前 | 在已产生明显横向偏差时逐步约束模型轨迹，抬笔前减少需要纠正的距离 | 需要有序 raw 尾部与匹配策略；切换强度突变会制造新折点；位置与速度/压感基线要分离 | 若 A 无效，再比较；不能仅按最新 raw 点做圆形裁剪 |
| C. 重建完整未固化 L0 尾段 | Up，必要时同时在活动态应用 | 在 L1 固定连接点与 raw Up 之间，用原始尾部约束拟合平滑中心线 | 需要足够 raw 历史；当前 `terminalFirstPoint` 禁止回写 pre-Up 确认点，必须先讨论改变该边界；抬笔时会有可见修正，极短 L0 可能无可行空间 | 作为第二层方案；与此前“只重建 Up 新增段”严格区分，不无条件回写 L1 |
| D. 全局 spring/drag 或曲率相关参数调整 | 整条笔迹 | 可能减少部分惯性、过冲或相位滞后 | 阻尼更大未必更跟手；不能保证 endpoint/切线，所有速度和设备回归面大；曲率噪声会引入新抖动 | 作为诊断对照，暂不首选 |
| E. Up 不回接 raw、冻结最后可见位置/预测 | 完成态 | 隐藏回接导致的角度变化 | 可能停不到真实抬笔点或持久化预测，改变既有真实终点合同 | 不作为现有需求下默认方案；需独立产品决策 |
| F. 只增大 Up 迭代次数、只改末点、只关闭 prediction、只在 shader 修饰 | Up/显示 | 某些场景外观可能减轻 | 无法消除已形成的运动偏差；可能留下 Stored/重放不一致，或进一步显露回摆 | 不作为完整修复 |
| G. 对照 Google Ink 新 sliding-window，或借鉴其可变尾段机制 | 平滑模型整体与尾部边界 | 近期尾段可重建，端点窗口缩小；避免旧弹簧惯性机制 | 新接口、外部预测来源、稳定游标/窗口和当前合同需适配，迁移风险高；没有本缺陷的已验证收益 | 作为 A/B 后的算法基准，有限核查见 google-ink-new-smoothing.md |

## 后续无 GUI 验证设计

### 1. 先保存同一输入的多阶段证据

- 使用固定轨迹与时间戳，同时记录 raw 输入、经过 wobble 的锚点、弹簧原始 TipState、ModelStylus 后的 Result、prediction、接纳 realPoints、Up scratch、首次完成尾段及 Stored。纯公共 API 无法观察内部阶段时，先做可观测 Result 对比，内部观测需留给单独获批的诊断实验。
- 区分真实输入时间、模型压缩时间和显示时间，不以“同一帧数组索引”匹配 raw 与 model；模型结果时间与弹簧位置滞后也不等价于相同几何进度。
- RTS `Packets` 取包末点（`Draw3.RealtimeStylus.cpp:1357-1375`），Move 快照可能被最新输入覆盖（`Draw3.ContactInput.cpp:789-801`）。后续先核对实际路径，再分别对照完整采样、包末点序列和绘制线程逐帧消费序列；隐藏模型诊断中的 raw 不能自动代表设备原始全部 packet。上述采样策略是待量化的放大因素，不是已证明的根因。
- 保留 L1 提交游标、`terminalFirstPoint`、真实 Up 前后的点数、当前隐藏诊断的 8 点截断状态；仅有这 8 点不能重建整段转弯。
- 从真实库 API 做 A/B，确认 merge.lib 与源码 provenance 的一致性；Python 数学代理或头文件一致不能替代二进制行为验证。

### 2. 轨迹矩阵

- 圆弧半径 8/16/32/64 DIP，速度 100/500/1500/3000 DIP/s；圆弧正反向、直线接急弯、S 弯、折返、自交、短笔和单点。上述是实验取值，不是拟定生产阈值。
- 在 30°/60°/90°/135° 转弯过程中立即 Up；对照继续移动、停住 1/2 帧后 Up、完全停稳同位 Up，以及 Up 坐标少量前移。
- 输入采样率与渲染帧率分别变化；渲染采用既有 30/60/120/240 FPS profile，保留稀疏输入、批次聚合、时间抖动、同坐标/同时间戳边界及长停续画。
- 固定笔宽先隔离中心线问题，再验证模拟压感、硬件压感和 HardPen；Kalman/StrokeEnd/Disabled 分开比较，避免把 prediction 遮盖误认为真实轨迹已经改善。
- DIP/像素转换、不同 DPI、Mouse/Touch/Pen 入口分别检查；真笔设备最终仍需人工验收，鼠标或合成输入不能代替。

### 3. 指标与成功条件

- 对解析圆弧计算 signed radial/cross-track error，对分段轨迹做有序弧长匹配或局部法线投影；同时报告切向滞后，避免把时间滞后全算成空间外偏。自交要限制在当前局部分支。
- 记录 Up 前最后有效轨迹方向、raw Up 回接向量、最后相邻段的转角和最大方向变化；使用固定物理弧长窗口重采样，不能通过增加插值点数把“相邻点角度”指标人为变小。
- 记录修正区的最大位移、长度、曲率突变、路径反向/自交和 radius/arc-length 分布。真实轨迹本身的尖角与噪声要单列，不能把所有大转角统一磨圆。
- raw Up endpoint、非有限输入安全、单调接近/endpoint plane、输出预算、稳定 L1 前缀、物理 Up 时间锁定及 prediction 不持久化均继续满足现有合同。
- 完成后的首次 raster、Stored 几何和重放一致；真实 Move 速度、压感和宽度状态不被合成点或视觉修正污染；10 秒静止和长停恢复保持点数有界。
- 精确终点容差复用现有 `0.05px`；新的横向误差/转角/视觉修正容差必须在轨迹基线和真机样本后制定，不能在研究阶段臆造“已达标”的阈值。

## 决策边界与未确认项

- 最新用户选择已明确：raw Up 和 L1 前缀不变，允许未落 L1 的 pre-Up 派生尾段重构。没有启用新参数、修改代码或开始实施。
- 优先验证运动阶段偏差，是由历史复测与现有门禁语义支持的研究判断；具体偏差由 spring、wobble、采样还是预测主导仍需多阶段轨迹证据。
- 上游状态、源码差异和公开修复覆盖见同目录 `upstream-status-and-diff.md`；本地历史与生产链路见 `local-history-and-current-path.md`。
- 旧库 README 提到的 Google Ink 新平滑实现已作有限核查，见 `google-ink-new-smoothing.md`；它是另一个接口/算法的候选，不是可直接应用于当前库的补丁。
- 没有真实设备重放、实际库新方案 A/B、编译、GUI 或 GPU 验证。纯几何反例只证明门禁并不蕴含方向连续。
