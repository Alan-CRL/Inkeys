# 崩溃重启与恢复

## Goal

正常退出、主动/自动重启、崩溃链路和持久化恢复验证与修复

## 依赖与门禁

只读链路调查可在 Work 0 与审计并行；共享状态/窗口/Draw3 写入须待主 agent 冻结接口与文件 owner，主修复在 Draw3 阶段后。出口：正常退出、主动重启、崩溃捕获、自动重启、已提交数据恢复分别有状态；GUI 不可执行项保留人工门禁，交最终集成。

## Requirements

- 画实际异常来源→捕获/报告→dump/log→旧进程结束→重启触发者→新进程参数/单实例→初始化→数据恢复链路，确认真实 owner。
- 分别检查正常退出、主动重启、受支持未处理异常、工作线程故障、初始化中断；二次异常、重入、单实例交接、路径/参数、权限、有限重试与无重启循环。
- 检查崩溃路径独立于损坏业务锁/对象和正常退出流程；已提交 UInk/索引原子性与跨 workspace/PPT/页面隔离。硬终止/断电等能力边界单列。
- 数据验收分开：A. 最后已提交 UInk/索引仍完整可读且身份不串；B. 新进程启动后当前产品已开放范围内可见恢复。当前仅找到 Desktop SubmitLoad 用于进程内 Clear 回撤，跨进程 PPT 恢复仍未开放；不得把 A 写成 B 的 PASS，也不为验收擅自开放新入口。
- 故障注入仅隔离本项目数据/进程；未获 GUI 授权不启动应用、不终止用户进程、不动真实配置文档。
- 新增用户报告（2026-09-28 附图）：批注模式画布突卡，光标仍有但无墨迹；切选择后画布未消失、清屏无效，主栏/设置 UI 仍响应，画布阻断桌面交互；设置退出按钮响应但程序未退出。需追绘图消费者、命令/输入门、presenter、双窗显隐和关机 join 的实际分歧，不凭截图预断根因。
- 恢复原有统一 15 秒退出/主动重启最后保护：从任何正式结束/重启入口发出请求后，若正常清理未完成，独立于被卡线程的保护须有限次强制终止旧进程；重启只拉起可信当前 EXE 一次，不能无限多实例或把强制终止冒充成功保存。正常提前完成应撤销保护；用户取消不启动保护。

## Acceptance Criteria

- [ ] 正常退出、主动重启、崩溃捕获、自动重启、数据恢复各有独立结论与证据；函数存在不等于通过。
- [ ] idle、绘图/渲染、退出/持久化边界有可执行复现/验证设计；真 GUI 未授权场景为需要人工。
- [ ] 已确认问题最小修复、回归及独立复审；正式默认无可误触发崩溃开关。
- [ ] 已提交文件完整与新进程可见恢复各有独立结论；未开放能力列不适用及依据，已开放但无法运行的列需要人工。
- [ ] 画布卡死报告的多症状能在独立日志/故障注入中区分 Host 已停、绘图线程卡死、呈现持续失败、命令队列积压和 HWND 输入遮挡；确认的等待/锁问题修复后验证切模式、Clear 与正常退出，不以 UI 仍响应判为绘图正常。
- [ ] 任何正式退出/重启共用 15 秒保护；正常路径、卡死路径、重复请求/取消、单实例交接、旧进程终止与至多一次新进程分别记证据。无 GUI 时真实窗口卡死/重启仍列人工，不把纯计时单测当整链通过。
