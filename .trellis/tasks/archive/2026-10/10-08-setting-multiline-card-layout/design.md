# 多行说明卡片动态布局设计（已实现）

## 已确认方向

用户已确认方案一作为默认、方案二作为空间不足时的动态替代，并要求切换动画。项目继续使用现有 ImGui＋ImFluent；方案二不增加独立说明卡片或“详细说明”标题。

## 布局模型

1. 行内模式：图标 | 标题＋完整多行说明 | 按实际宽度测量的操作。
2. 下方通栏模式：上部保留图标/标题/操作，说明移至同一卡片下方；说明左边与标题对齐，右边到卡片内边距。
3. 极窄模式：标题和操作无法并排时，让操作换行并保持右对齐；完整说明继续按真实文字宽度增高。

页面只提供文案、图标、操作天然尺寸及单一操作回调。共享设置行负责预算测量、模式选择、几何与占位；不为置顶间隔单独复制布局实现。

预算应扣除内边距、图标槽、操作天然宽度及必要间隔。按钮组优先按真实自然宽测量，可在允许的操作预算内换行；下拉/滑动条遵守既有最小可用宽度。说明是否过窄以可读预算为依据，不能直接使用按钮数量。

## 断点与抖动控制

说明剩余预算小于 280 DIP 时进入下方通栏模式；返回行内需达到 296 DIP（16 DIP 回程余量），避免临界 resize 反复重定向。标题与操作剩余预算小于现有 160 DIP 极窄阈值时，沿用控件堆叠回退。按实际可用宽度和自然操作宽度计算，逻辑尺寸只换算一次。

这些是本项目工程参数，不是 WinUI 官方断点。三种语言、两种主题、六种倍率以及滑动条、按钮＋下拉和可换行按钮组的真实连续帧回归已通过；代理未进行 GUI 验收；2026-10-09 用户确认人工验证完成，见 research/manual-acceptance.md。

## 过渡设计

优先复用既有 NavigationTween/动画设置和唯一设置渲染帧。状态按当前 ImGui 会话、页面/窗口和稳定行 ID 区分；不能由标题文本作为状态键，也不能跨 context 残留裸指针。

采用避免交叉的两阶段过渡：由行内切到下方时，先使说明避开操作区，再展开说明宽度；反向先收窄，再移回行内。用当前 ImGui 窗口 StateStorage 和稳定行 ID 保存布局 Tween，不保存跨 context 裸指针。

重定向从当前可见进度开始；动画开关和速率变化复用原有语义。时长为 160 ms / 现有动画速率；复用既有 NavigationTween，不新增动画线程或配置字段。首次出现直接解析当前布局；隐藏/缺席后的首帧不计入休眠时间。

文字换行与行数由当前真实字体和当前说明宽度计算。卡片高度、真实 ImGui 占位和下方卡片坐标必须包含当前可见文字包络；不靠裁掉文字使高度看似平滑。需要评估连续换行时高度变化的观感，不能仅插值空的矩形。任何交叉淡入/淡出都不能运行两份可交互控件。
