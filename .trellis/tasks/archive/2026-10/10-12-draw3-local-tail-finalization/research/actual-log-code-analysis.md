# Research: 现场无反色日志的代码归因与修复规划

- Query: 用户提供 Inkeys-Draw3-tail-3032.log，要求继续调查并给出修复规划；本轮不实施代码。
- Scope: internal，实际日志、局部求解器及 Draw3 完成态接入。
- Date: 2026-10-13

## Findings

### 已确认的现场原因

日志有 8 条以 end 结束的完整笔迹记录，全部已经调用局部求解器，全部在求解器内部返回空补丁。因而本批无反色无需用渲染层未接通来解释。前 3 条为 NoChange/no_improvement，后 5 条为 Rejected/excessive_displacement；没有 short_window、调用方 width/prefix 拒绝或成功发布记录。

`Inkeys/additional/ink_stroke_modeler/terminal_tail_reconstructor.cc:699` 把两种情况合并成 no_improvement：候选最后三顶点转角大于 10°，或者相对改善小于 3%。前三笔日志分别为约 83.37→22.00°、64.63→11.46°、66.46→11.75°，实际相对改善充分，失败原因是残余角仍超过绝对门槛。名称 misleading，不能解读为“没算出变化”。这些日志角度原值单位为弧度。

`terminal_tail_reconstructor.cc:705` 才开始累计最大位移，位于该返回之后。前三笔 displacement=0 是未计算的默认值，不能据此判断实际候选位移为零或已经通过 3px 限制。后五筆到达 `:716`，最大位移为 29.623394、27.067231、14.221025、25.723936、25.284214 px，均超过 3px。

所有这些失败通过 `terminal_tail_reconstructor.cc:95` 的 Finish 清空 patch。`Inkeys/Inkeys/Drawing/Draw3/Draw3.StrokeGeometry.cpp:638` 收到非 Apply 返回，不复制新位置；因此原折线和无反色是当前原子回退合同的直接结果。不能仅放宽第一道门就宣布成功，后续位移、长度、相交、属性来源和调用方门仍需检查。

### 拟合与采样的结构性限制

1. `terminal_tail_reconstructor.cc:538` 用最后三模型顶点触发，`:542` 用 `min(窗口弧长×0.4,max(6,pin长度×12))` 选择重构长度。主会话解析结果：现场 pin 为 14.98–44.64px，末前边为 8.05–20.29px，选择的重构区段约 162–524px。时间窗短不等于空间窗短，不能把 160ms 自动等同“末尾几像素”。
2. `:666–668` 使用旧折线弧长参数做模型形状拟合；`:685–694` 仅在原点的参数处输出位置，保持点数。参数分母包括人工 pin 全长，故 pin 越长，曲线末端越可能只用一条较长直边表达。现场最后参数间隔约占重构长度 8.5–9.2%。连续三次曲线具有指定端点方向，不等于最后输出折线足够细、最后三顶点转角足够小。该结构解释风险，不证明当前所有候选残余角全由采样造成；仍需检查曲线本身曲率集中及控制柄。
3. `:699` 的原顶点角依赖采样密度，不能单独代表自然弧线平滑程度；同时不应靠无限加点使这个角自然趋零。需同时测连续拟合曲率/接缝、实际输出折线误差及多空间尺度的方向变化。
4. `:605–644` 从最多四个原始点拟合端点切向，四点时 confidence=1，模型方向被完全替代。raw_position_weight=0.35 只控制位置项，不控制该方向置信度。原始点的位置仍是辅助，但方向目前可占满权重；点数不是噪声、分支或拟合条件数的可靠置信度。
5. `:574–595` raw 在整个模型窗口作单调最近投影，包括人工 pin；非相邻等距分支拒绝。产品 `Draw3.StrokeGeometry.cpp:626` 先取最后 80ms，再由求解器取后半段、最多六点。产品把 raw.source 填为缓存序号，没有传入其 accepted firstPoint 边界。计划可利用物理时序/接纳边界限制有序分支，但不得把 firstPoint 当作无滞后的精确位置对应，亦不能改用被钳制的显示时间。
6. `Draw3.StrokeGeometry.cpp:633` 直接使用默认固定 3px 最大位移。源头说明默认值仅实验起点，实际大弧 14–30px 的候选修正被拒绝是可预测的。正确修复需确定允许形变与模型/raw 分离量、可改局部长度及明确绝对安全上限的关系，不能简单改成 30px 或完全撤销限制。

### 原始点与模型窗口的独立性

`Draw3.StrokeGeometry.cpp:578–584` 缓存物理 160ms、64 raw 点；`:615–616` 又把最早 raw.firstPoint 作为模型窗口起点。长停顿后仅余 Up 会使模型窗缩成单点，这是此前已发现的接入缺陷，但本次 8 笔均有 19–20 raw、实际 80ms 辅助 10–11 点，不是本批原因。

计划应单独维护有界的模型接纳范围/物理时间边界，raw 缺失或稀疏不能决定是否允许平滑。不能简单删掉该起点约束并取整条笔划最后 512 点，否则停顿后可能重构超出已授权物理窗口的早期笔迹。保留正常窗口入口的一个连接锚点与可改区段应有明确区别。

## 修复计划建议（待实施）

### 1. 先固定真实回归和诊断语义

- 把本日志 8 条 reference/raw/Up/元数据保存为确定性 fixture，原始文件 hash 和参数记录在报告；重放同一 C++ 局部 API及产品完成态入口，不重新合成不同笔迹代替。
- 完整输入限制：本日志只含尾窗，缺少 window 之前的点，不能伪称复现了完整笔划的前缀相交检查；模块/局部 caller 回放与完整生产回放分开说明，必要时补完整有界测试上下文。
- 把 no_improvement 拆成残余形状不达标与改善不足；记录未评估字段为 unavailable 或携带 evaluated flags。求解诊断保留候选长度、最大位移、修正起点、输出采样量、失败门及曲线/离散指标。硬失败依然空 patch。

### 2. 在限定区段拟合连续曲线，并按几何误差输出采样

- 保留固定入口位置、入口切向、精确 Up；模型是主要形状先验，少量可信 raw 仅作位置和终向辅助，保护正常前段及真实急转。
- 在物理窗口和硬点数限制内尝试少量候选入口/柄长方案，依目标函数和安全约束选择最小必要变形的通过者；限制候选数与验证总预算，不能无限扩大窗口找通行解。
- 对曲线用弦误差/曲率约束做有界自适应采样，特别补足长 pin 对应区间。明确 max_output_points、最大细分深度、工作预算；超限拒绝。不以顶点数加密掩盖实际曲率或制造新折点。
- 同时记录模型到候选的几何走廊偏差与来源对应位移；变采样后不能把同索引差当真实形变，也不能仅用最近距离丢失分支对应。
- 位移预算按局部异常尺度校准，结合可信 raw 的模型偏离、pin 尺度和可改弧长；保留绝对上限、前段零改动、长度、相交及宽度约束。无 raw 时仍允许纯模型+Up 方案，使用更保守、明确有界的证据。数值需通过真实日志与负例校准，本轮不承诺任意阈值。

### 3. 若变点数，必须同步扩展完成态属性来源合同

当前 `terminal_tail_reconstructor.h` 明确保持点数，产品 `Draw3.StrokeGeometry.cpp:640` 检查相等点数，`:643–645` 要求 source 为一对一原顶点。自适应采样需要更新这些本地扩展合同，而非修改上游 Result。

- 原型可扩展现有 `TerminalTailSource{first,second,fraction}`：新增采样对应原轨迹上的有序位置，范围内、fraction∈[0,1]；原入口/终点保留精确来源。对应参数需在拟合开始时定义，不能事后用无约束最近点补造来源。
- 原位置只用于新几何；产品 InkPoint.r/time 按 source 插值，允许时间平台（Up 回补点同时间很常见），不能按时间唯一反推位置。压感/速度等原模型语义不得伪造或反馈上游。
- `Draw3.StrokeGeometry.cpp:725–732` 原 committedIndex 直接切新 scratch 的做法不再成立，须依据来源把 committed 边界映射到新采样；需要时在边界保留一个锚点。terminal/修正起点、笔宽公切线校验范围、taper 起点、反色段索引同样转换；taper 继续插点后再次映射调试范围。
- 活跃 realPoints/committedIndex 不修改，只有完成副本使用变点数。等待断触接续不提前固化；Stored 重绘仍以最终完成笔划为单位。

### 4. 验收必须覆盖真实表现及负例

- 8 笔现场输入：逐笔展示黑色原折线、蓝 raw、红最终候选；统一坐标、原比例与末端放大图同时提供。报告 Apply/拒绝、原因、实际输出折角/曲率、采样误差、最大偏差、修正长度、点数和耗时。不能只展示成功子集。
- 稀疏、零 raw、停顿后仅 Up、重复 raw、强噪声、真实尖角、S/回环、长度/尺度/速度变化全部测试。相同连续曲线不同采样密度不能任意改变触发和验收结论。
- 前缀位置精确不变、Up 精确、来源单调合法、属性插值可核验、输入不改、失败原子空补丁、点数/迭代/相交预算有界。
- 用实际产品 FinalizeStoredStroke 验证重采样前后 committed/taper/反色映射、接续等待与确认结束、Stored序列化不固化反色。新索引合同是高风险部位，需要专门边界断言。
- 按项目既有 solution 完成 ARM64 Debug 构建及无窗口回归；优化构建计时需包含拟合、采样和验证全链。最后仍需人工笔迹与 GPU 验证。阶段三保持未验收。
