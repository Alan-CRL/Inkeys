# 自动收起规划专项复核

2026-10-19，仅阅读 `decisions.md`、`prd.md`、`design.md`、`implement.md` 和前轮已核实源码证据。未修改产品源码、配置、工程、主规划文档或生成物，未构建、测试、GUI、Git 变更或派生代理。

## 结论

无须推翻当前方案，也未发现配置默认、两种样式适用范围、实际工具分类或受控拖动折叠方面的结构性阻塞。当前决策已经一致覆盖：

- Drawing 默认 1，其余三项默认 0；新 Config 独立，不从旧布尔迁移。
- 合并式/分离式均显示和生效；策略只判三态与竖向 dock，居中不另设例外。
- Drawing 包含画笔、Shape、Laser；本笔实际 Eraser 覆写优先，不能读取全局当前工具冒充本笔。
- 保留聚合 `drawingActivityChanged(bool)` 原有含义；新增窄 accepted-stroke-begin 元数据，不改变绘制算法或输入 producer。
- 本手势受控自动 fold 同步本会话基线并执行必要 presentation barrier；外部 fold、模式、来源和桌面失效仍取消，普通点击与真实拖动阈值保持。
- 栏外点击为可取消的 100ms 候选，由 Bar owner 检验可交互区域、工具、配置和生命周期；不把提升点击重投为 pointer Down。

`autofold-inventory-and-settings.md` 第 7 节曾列 Shape 为待定，但用户随后已明确纳入；该旧调查中的“最小恢复建议不含 Shape”已被 `decisions.md` 覆盖，不得进入最终实现。

## 两项最小补充

### A. 统一“不读旧设置”的措辞

PRD R6 写“四项……不继承、读取、迁移或双写 Inkeys2 旧四布尔”，而 design §3 明确“旧 deploy 读写……暂保留”。功能目的显然是新策略不依赖旧数据，但逐字读会让实现者误以为应删除 `ReadSetting/CaptureSettingJson` 的历史四键，与范围外“广泛清理旧 deploy”产生分歧。

建议仅把 R6 说明为：**新四项策略只读 Inkeys3 Config，不读取旧字段作为策略来源，不迁移、绑定或双写；旧 deploy 原 reader/writer 暂保留，不影响新默认。** 无须扩大代码修改范围，也不重新提出迁移问题。

### B. 新笔迹开始事件不能复用“当前仍活跃”过滤

设计已正确区分 accepted-start 与聚合 activity，但建议在 §4 和验证矩阵明确两个事件时序用例：

1. **短笔迹 Down/Up 均已完成，Bar 稍后才消费开始通知**：仍可根据真实已接受的开始事件进行一次有效折叠，不能复制当前 `HandleCanvasDrawingActivity` 的 `activityCount == 0` 过滤，或要求消费时 `HasPhysicalContact` 仍为 true。那会令轻点画点/快速擦除再次丢失主栏收起。
2. **开始通知排队期间已更换工作区、PPT session 或 Bar 生命周期**：事件必须带有足够的捕获时身份并在 owner 消费时验证，迟到旧场景事件不得折叠新场景。数据可沿现成 Runtime/Workspace identity 提取，保持 value-only，避免把后来的当前工具/场景补进旧事件。

这不要求第二条输入通路或绘制算法改造，只是新元数据消息的准入合同。原聚合 activity 的“当前仍活跃”过滤继续原样服务副面板/光照，不因本项变化而删除。

## 已足够明确、实施时必须按原文执行的细节

- 四个新字段范围只接受 JSON 整数 0..2；非法按各自独立默认，不能统一非法回 0 而误关默认 Drawing=1。旧 deploy 真/假组合与这些默认无关。
- “任何时候”仅解除底栏限制，不能跳过真实触发、工具和有效生命周期。关闭或样式切换不立即展开/收起。
- 拖动内 fold 的例外必须限定当前 session/ordinal，仅允许该手势发起的一次折叠，不能删除整个 fold-at-down 检查。折叠形态变更后延续同一抓取点，不重新计算鼠标与限位窗口的相对抓点。
- 栏外排除要使用实际可交互区域，而不是整张带透明区的 HWND 矩形；颜色/粗细/属性/菜单等 Bar 子区域也属于栏内。关闭设置、模式/dock/工作区变化与新的相关输入都应使旧 100ms 候选失效。
- 触摸/笔提升消息可表达栏外点击意图，但保持原来源过滤、单次幂等消费；不为兼容点击恢复 Draw2，也不改已验收的 Raw Mouse/WM_TOUCH 拖动归属。

上述两项补充可直接写入规划，不涉及新的产品取舍。整个任务继续保持 planning，用户批准整份规划之前不能开始实现。
