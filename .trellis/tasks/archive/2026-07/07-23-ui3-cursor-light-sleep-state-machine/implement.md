# UI3 第三光源休眠状态机实施清单

## Implementation

- [x] 在 `Bar.Main.cppm` 增加跟踪状态、可见区域缓存、Raw Input 动态启停和画布休眠通知接口。
- [x] 在 `barWindowMsgCallback` 接入 UI 进入、5 秒定时器和画布休眠消息。
- [x] 重写第三光源输入更新：区域状态转换、固定截止时间、独立 `240 × zoom` 径向光圈和无关位置更新裁剪。
- [x] 将第三光源 300ms 动画扩展为可逆淡入淡出，并保持动画关闭立即隐藏。
- [x] 从当前外层 UI 几何发布至多三个可见区域矩形。
- [x] 在 Draw2 落笔线程派发前发送一次休眠通知，不直接跨线程修改渲染状态；导出接口保持 Draw2/Draw3 通用语义。

## Validation

- [x] 静态检查 Raw Input 只有激活/宽限状态注册，Dormant 和动画关闭路径注销。
- [x] 静态检查区域外移动不重置 5 秒截止时间，定时器与输入事件均检查绝对截止。
- [x] 静态检查第三光源使用 `240 × zoom` 独立半径，第一光源继续使用 480px。
- [x] 静态检查可见区域邻近状态只裁剪渲染唤醒，不参与第三光源亮度乘法。
- [x] 静态检查生命周期淡出不被邻近裁剪截断、重新进入可从当前强度续接。
- [x] 检查 UTF-8/CRLF、`git diff --check` 和改动范围。
- [x] 使用 ARM64 Host MSBuild 构建完整 `InkeysRepo.sln` 的 `Debug | ARM64`。

> 2026-07-23 使用 ARM64 Host MSBuild 完整构建两次，均为 0 error。首次构建发现本次新增的 `GetMessageExtraInfo` 窄化告警，改用 `ULONG_PTR` 后增量构建通过且该告警消失；其余告警均来自既有代码或第三方代码。实际 CPU 降幅和分层窗口命中行为仍需在 UI3 运行态手工观察。

> 2026-07-23 根据 60 FPS 测试视频复核，发现“到任意可见 UI 的最近距离”作为全局亮度乘数会让主栏替颜色栏托底，造成等距离位置的第三光源贡献不同。已改为第一光源 480px、第三光源 `240 × zoom` 的独立径向半径；可见区域距离只保留为渲染唤醒裁剪。完整 `Debug | ARM64` 构建为 0 error。

> 2026-07-24 将画布休眠通知移到 Draw2 的 `MultiFingerDrawing` 线程派发前，覆盖鼠标、笔和触摸的真实落笔；落笔时仍命中 UI3 则等待 `WM_MOUSELEAVE` 后才允许下一次进入激活。完整 `Debug | ARM64` 构建通过，未新增编译错误。

## Risk and Rollback

- 高风险点是全屏分层窗口的实际命中判定、Raw Input 动态注销以及窗口线程与渲染线程的状态同步。
- 每一步保持独立可回退：画布通知、240px 裁剪和可逆淡出不与 PointLight/Gaussian 绘制重构混合。
