# Approved design

## Position and configuration
Ppt facade owns preferred pair positions/session/layout epochs. PageControl owns candidates and committed geometry. Pair-only versioned handoff replaces full stale snapshots; reset/new session invalidate old gestures. Settings merge only changed fields. Saved baseline is separate. Toggle edges, real session end while enabled, explicit reset are the only save triggers; software normal exit counts as end. Serialize/version all PPT writes with atomic replacement; success acknowledgment advances disk revision, failure retains the exact retry snapshot.
Effective scale is resolved once including monitor/resource fit. Scene does not reclamp effective scale as DPI; draw/hit/damage/presentation share it. Capacity is not viewport; whiteboard has its own layout.

## Session and page path
Add separately queried COM interface: immutable revision-based cached show state + expected-session exit. Old interface/schema unchanged. State carries stateRevision, showSessionRevision, bindingRevision, lifecycle, page status and corresponding descriptor. Getter never walks Office. Events retain current reads and wake existing owner for descriptor refresh before slow maintenance. ROT/binding/poll cadence preserved. Confirmed Begin/End/owner observations drive lifecycle; errors are Unknown. Optional View.State Done classifies end screen. Old DLL may use legacy pages but cannot dispatch unguarded confirmed exit.
Native identity includes service generation, show session/binding and HWND/PID, mapped to local monotonically increasing session id. Lifecycle != visibility/whiteboard. Show sampling starts16ms, idle100ms; unchanged revisions avoid reparse. Wait against revision captured before readiness decision. Keep identity/target/SlideID checks and successful-Present ready.
New target gates contact entry; drawing thread seals accepted persistent old-page strokes and save boundaries, cancels transient Laser, stops reconnect/inertia, quarantines still-down contacts until terminal. Only unaccepted target states coalesce; stamped commands/boundaries stay FIFO. Destination Present -> ready -> target-stamped PageControl publication -> visible UI successful commit -> input opens. Hidden controls require no nonexistent frame. Late ack/I/O cannot reactivate old targets. Unknown/end screen suspend writing without Desktop reset. Preserve correct warm/parked topology order.

## Main bar and exit
Use existing dock serial and successful-frame geometry. Expanded dock enters centered at show-monitor bottom minus5*dpi. Expanded free stays. Folded dock releases constraint from displayed position; folded free stays. True exit expanded centers at workarea line; folded stays. Whiteboard overrides PPT geometry and coverage does not replay lifecycle; real exit during whiteboard only clears PPT scene. Input/render share dock policy, anchor visible body, not shadow.
Main Bar only confirms using MessageBox OkCancel with Cancel default/dismiss and optional system-fallback disabled. Modal in business thread outside locks. Request id + session single-flight; every terminal completes matching request only. Revalidate expected session at managed execution; no early mode change on failed/cancelled/stale. PageControl sources are direct. Focus is explicit once and gated by session/HWND/PID/current editable or modal focus, never continuous.

## Diagnostics
Default-off correlated timing: native observe, descriptor accepted, target publish, contact seal, document switch, canvas Present, page UI commit, input open. Synthetic vs Office results separate; no fabricated COM event timestamp or promised milliseconds.

## Supplemental approved design: true exit and EndScreen

Source evidence: `research/exit-window-supplement.md` and `research/end-screen-storage-supplement.md`. Source proves the lifecycle/Window Service gap and the UInk rejection path; the exact HWND intercepted in the user's Office session remains unverified until a real system input test.

**A — authoritative exit.** `PptInfo` alone identifies reliable Inactive or destroyed/reused slideshow HWND. It publishes Desktop and applies Selection once on that edge, including when the tool enum already reads Selection, but only if the mode revision still equals the value at exit detection. The four production mode-change functions serialize that comparison with their state update, so a later user Pen/Shape/Eraser action wins. Same-iteration rebind, Unknown, EndScreen and whiteboard do not take this branch; button requests only initiate exit. Bridge revision and runtime output readiness separate desired from presented state. While Selection/Desktop waits for its first successful output frame, `IdtState` asks the Window Service owner thread to hide both Drawpad surfaces and retains a bounded retry even when no further runtime revision arrives. The same owner thread releases capture only if the current capture HWND is the main Drawpad; Bar/PageControl capture is left alone. Once successful Present and content/output revisions match the latest bridge state, it shows only the correct selection ULW when ink exists; empty output stays hidden. Before and after Window Service commit it compares the bridge revision so an old ready cannot visibly reactivate a stale scene. Window Service reads back both HWND visibilities and leaves both hidden on failed commit. Default-off, rate-limited diagnostics correlate exit reason/session/service, waiting reason, bridge/runtime/output/page/UI ready/admission and role HWND state. Real Office system hit testing remains a separate acceptance test.

**B — typed end page in the same presentation file.** `PptCOM ReadShow` preserves `View.State==5` and obtains complete validated real SlideIDs from the same `Slides` acquisition even if `View.Slide` is absent. Failures remain Unavailable/TransientBusy and cannot publish a target. The native envelope must say EndScreen and carry the matching binding, show HWND/PID and complete stable topology before the dedicated target factory runs. `PresentationTarget`/ready identity includes `PageKind`; Slide targets have `pageIndex∈[0,N)`, EndScreen has internal `pageIndex=N`, no SlideID, while `totalPages=N` and `slideIds` contain only real slides. UI `-1` is a display sentinel and gets a nonzero target revision only after the separate end canvas successfully Presents. PageControl and native UI ack verify that target/session/revision, including hidden controls. Unknown and ordinary Unavailable keep the gate closed.

The same Draw3 document slot owns N normal pages plus one end page with its own pageGuid/history. Real pages remap by SlideID; the end page is carried independently across reorder and count changes and is never retained as a deleted slide. The existing save worker writes one logical UInk file: active canvases are N normal followed by one end canvas marked exactly once with `inkeysPageKind=end-screen`, no SlideID, then any retained real slides. UInk's unsigned index N and `pageNumber=N+1` are internal; COM/UI total remains N. Codec encode and decode exempt only the exact marked presentation canvas from missing-SlideID temporary identity, and the application importer rejects duplicate/misplaced/ambiguous markers, preserving old N-canvas files. Old files materialize a fresh blank end page. Import projects the saved end page to current N when slide count changes, retaining its pageGuid and content. Existing merge, Clear interval, worker revision and failure retry remain the save route. A separate file was rejected because it would require a second index, failure sequence and association outside the existing one-document transaction.

An all-new SlideID set at the same path is deliberately treated as a possible replaced document: with no stable ID intersection, saved ink and EndScreen remain isolated rather than being attached to an unproven new document. Binding-only rebind position-save behavior predates this supplement and is recorded as a remaining prior-task risk instead of changing the established facade lifecycle here.

Verification requires Encode→Decode→strict import→real Host cold restore with distinct last-slide/end content and pageGuid, plus hidden Host/Window Service output transition. The hidden suite does not prove Office `Slides` at State 5, real lower-window mouse/touch hit testing or cross-process recovery; record those as NOT VERIFIED rather than inferring from code.

## Regression supplement: A/B implementation boundary

**A, confirmed in source.** `DrawingController` owns the content revision and publishes it on document-slot switches even when the `hasContent` boolean is unchanged. `Host::Impl::ObserveCurrentPageContent` currently returns before storing a same-boolean new revision, so `ObservePresented` can report a newer successful content revision than `RuntimeSnapshot().contentRevision`. Selection's output handoff safely hides both HWNDs while the revisions disagree; the lost Host revision prevents recovery. Repair the Host observer's pair-wise idempotence and wake, not the presenter/identity gate. First add a deterministic failing test through the production observer, then a hidden real-Host Selection sequence with two differently inked pages, an empty page and the typed end page. Verify the actual output target/ready revision and window surface; retain Pen and exit behavior. No PPTCOM/UInk changes.

**B, not yet field-proven.** PageControl currently resolves runtime fit in each surface render using local scene outset/backing/device limits, and commits four windows independently. These are candidate causes, not a confirmed account of the user's single-side symptom. Record correlated four-surface geometry, animation, HWND/ULW stage results and retry at the point of failure. Build deterministic tests that distinguish legal offscreen animation start from an offscreen final body, and one-side present/SetBounds/Show failure from layout divergence. If the render-time fit differs by surface, compute one immutable group layout per publication/display/device generation with a conservative shared resource bound. If only a commit fails, keep the failed pair pending and retry without disturbing the successful side's accepted user preference. Reuse existing Scene/Window Service; no new layout framework or persistent setting writes. The exact code changes will be narrowed after the B research and a failing test.

Scope is Host content publication/hidden tests and PageControl layout/presentation tests, plus local diagnostics/spec updates only where evidence demands. The existing Draw3 producer, selection ULW, PPT EndScreen storage, Bar constraints and PptCOM binding remain unchanged.

The B source audit in `research/pagecontrol-large-visibility-regression.md` confirms three repairable state-machine gaps without proving the user's exact field cause: each surface independently fits the whole layout from its own old Scene/device state; `ConfigureSurface` advances its observed revision even if Scene configuration or bounds application fails; and resource/ULW early Retry lacks the original failure stage while stable backing can exceed a newer device limit. Implement a shared, deterministic group budget for a publication/display/device generation, with a bounded resource capacity and visible-body final bounds checks. Keep legal offscreen Side animation starts. A failed Scene/ULW/window stage must keep that surface uncommitted and scheduled for retry; one side's success cannot satisfy the other's page UI mask. Record phase-specific error at failure time and recovery. Add a targeted one-side injected failure and four-surface window/pixel/hit checks before claiming B fixed; if only hidden/offscreen evidence is available, retain real Office field cause as NOT VERIFIED.
