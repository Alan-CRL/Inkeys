# Layout, positions, settings and UI-ready implementation

## Boundary
Owns Ppt facade, shared PageControl, Bar.Scene effective-scale normalization, PPT sections of legacy configuration and settings UI, and ppt_ui/page_control regressions. No Office/ROT code, Draw3 Host, Bar docking rules, project files or unrelated configuration was changed here. Ppt session/target IDs are supplied by the native coordinator. User approved plan overrides older specs that routed PageControl EndShow through Bar confirmation or saved on each drag.

## Confirmed causes and additional findings
- Original ReleasePptDragTracking only requested persistence when rememberPosition was true; only that callback copied positions into Ppt facade. Remember-off therefore let the next page/visibility/configuration snapshot restore old facade positions.
- Original facade copied the complete incoming layout and Settings Notify replaced the complete facade layout from legacy values. The ownership guard ended independently of already captured publications. A newer page publication carrying older pair versions is now deterministically exercised through the production MergePptPublication function after ownership release, for both memory settings.
- Existing drag candidate revisions were global but ObservePendingDrag/CommitDragSurface compared each pair's revision to that global frame revision. Interleaved pending bottom/middle candidates could strand the first pair. Render commit now identifies the corresponding pair revision; the global revision continues to reject stale frames.
- Original PageControl and BarSurfaceScene reclamped effective scale. Runtime layout could resolve DPI2 * user2.5 = 5 while Scene used4, and small-monitor fitting could be lifted back to.5. DPI input (.5..4), user preference (.5..3), fitted control scale (allowed below.5), and final effective scale now have separate normalization contracts; Scene validates the final positive scale without an input upper clamp. DPI above4 is normalized consistently in fitting, layout and drag. Runtime fitting additionally accounts for presentation extent and the actual D2D bitmap maximum (D3D11 bound before first context); stable capacity remains distinct from presentation size.
- PageControl retains its existing primary-monitor layout scope. Render previously took primary bounds but HWND-nearest-monitor DPI, while dragging used primary DPI; a hidden side HWND can lie on a different-DPI neighbor. LayoutMonitor now obtains both bounds/DPI from one primary Display snapshot for render, drag and rollback. No new multi-monitor placement policy was added.
- Window failure still retries the latest candidate; hiding a pair explicitly rolls an outstanding candidate back to its last successful commit and releases ownership instead of retrying a hidden surface forever. No movement tap does not acquire a persistence handoff.

## State ownership and integration
- Ppt::PositionState owns this session's preferred pair positions. session+epoch invalidates old gestures; independent pair versions reject delayed and interleaved commits. PageControl only hands off positions after both HWNDs successfully commit (including direct movement), outside render/presentation locks. It does not write disk or request a new frame on each handoff. Save/session/configuration edges call FlushPositionCommits before taking the facade snapshot, so an already committed geometry is not missed merely because its normal callback has not run.
- Published PptState carries a monotonic publication revision, target revision, and layout stamp. Pair versions continue protecting positions after ownsLayout becomes false; stale publication/epoch/session results are rejected. Page and setting updates can merge without replacing newer pair positions.
- PublishSession(session,active,HWND) is the only session boundary. Entry restores the last explicitly frozen save baseline in this process (initialized from durable disk); immediate reentry cannot bounce while the writer is queued. The successful disk baseline/revision remains separately tracked and only advances after actual commit. Restart restores real file contents. Both remember edges freeze the current preferred positions; end freezes iff enabled; reset always freezes defaults, including when helper is disabled. Visibility/whiteboard/end-page/unknown do not save or reset.
- BusinessCallbacks.persistSettings(string) sends an immutable journal payload through the existing PPT business queue. Settings' existing queue uses the same writer. WriteJournal assigns revisions before queueing, preserves the latest desired saved positions when legacy settings capture other fields, and strips the internal revision before serializing the user file. Older queue entries become no-ops.
- File commit is serialized independently from the short journal lock. It writes a same-directory temporary, flushes and closes it, then MoveFileEx(REPLACE_EXISTING|WRITE_THROUGH). Failure preserves destination bytes and an exact frozen retry payload. Saved baseline/revision advances only after file success. Heartbeat takes at most one pending retry; shutdown drains queued writes through the coordinator. An older completion cannot clear a newer failed request.
- BusinessCallbacks.pagePresented(session,target,current,total) is invoked after all currently visible PPT surfaces successfully render and commit HWND bounds/visibility. The required mask combines requested PPT visibility, last successfully presented PPT visibility, and in-flight PPT presentation. A fade-out still displaying an older number must commit the new number or successfully hide before acknowledgment. Beginning presentation atomically rechecks the publication revision under the snapshot lock, closing the hide/old-frame race. Only truly absent (including no in-flight) surfaces acknowledge immediately. Targets/session/page values are rechecked; changing to target0/unknown and back resets acknowledgment. Callback runs outside render/window locks. TracePptTiming records page-ui-commit or page-ui-hidden, never a COM event time.
- PageControl endShow callback is direct. Ppt facade no longer assigns Bar's EndShow callback or derives Bar/Freeze session activity from page visibility. Freeze lifecycle is published by the coordinator's true session edges; this also removes the old snapshot race in Freeze availability.
