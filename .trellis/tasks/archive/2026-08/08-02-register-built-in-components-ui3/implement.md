# 实施计划

## 实施顺序

1. 按 `trellis-before-dev` 读取 native-desktop 与跨层/复用规范，确认涉及文件的编码和 CRLF。
2. 在 `IdtFloating.h/.cpp` 提取 16 个组件的动作枚举与统一执行函数，并让 UI2 原交互分支复用。
3. 扩展 `Bar.Bottom.cppm`：
   - 注册结构增加共享所有权、旧开关读取器和目录元数据；
   - 保存稳定注册顺序并开放只读查询；
   - 按钮结构增加 PNG 图标载荷、图标种类和独立本地状态；
   - 列表增加原子式有效序列替换能力；
   - 声明内置注册和旧配置同步入口。
4. 扩展 `Bar.Buttom.cpp`：
   - 让注册表持有按钮模板；
   - 用小型构造辅助函数注册 16 个内置组件；
   - 初始化两条长期持有的边界分割线；
   - 启动和设置变更时按旧开关顺序重建运行时 B；
   - 不读取、替换或写回 `config.UI.Bar.ExtensionButtons`。
5. 调整 `Bar.Main.cpp`：
   - 启动时在布局构建前注册内置组件；
   - PNG 按钮走 `BarUIRendering::Png`；
   - 设备资源重建时释放按钮 PNG 缓存；
   - 保持 SVG 动画和着色分支不变。
6. 调整 `Setting.cpp`：
   - UI3 下显示组件导航和现有 toggle 页面；
   - 隐藏 UI2 单组件限制提示；
   - 16 个 toggle 写入旧配置后统一触发 UI3 B 区同步。
7. 必要时补充小型测试或静态验证入口，覆盖注册顺序、开关投影和空/非空 B 边界。
8. 运行格式和差异检查，确认未覆盖颜色选择器的现有未提交修改。
9. 使用 ARM64 `MSBuild.exe` 构建 `InkeysRepo.sln` 的 `Debug | ARM64`，超时不少于 5 分钟。
10. 执行 `trellis-check`，修复发现的规范、编译或行为问题。

## 验证矩阵

| 场景 | 期望 |
| --- | --- |
| 所有旧组件开关关闭 | B 为空，A1/A2 之间一条边界线 |
| 只开启文件管理器 | B 只有文件管理器，位于两条边界线之间 |
| 非连续开启多个开关 | 按设置页固定列表顺序显示全部已开启项 |
| 设置页打开开关 | 旧配置写入后，当前 UI3 主栏立即出现按钮 |
| 设置页关闭开关 | 当前 UI3 主栏立即移除按钮，其余顺序不变 |
| 持久化 ExtensionButtons 含旧数据 | UI3 运行时完全忽略，不改写磁盘内容 |
| PNG 图标按钮按下/悬停 | 图标、文字和背景共同参与现有状态动画 |
| 点击任一组件 | UI2 与 UI3 进入同一动作实现 |
| 切回 UI2 | 旧组件页、单组件规则和配置行为保持不变 |

## 风险点与回滚点

- `Bar.Main.cpp`、`Bar.Main.cppm`、`Bar.State.cppm` 当前存在用户未提交修改；只修改必要位置并逐块核对 diff。
- 动态替换按钮列表涉及渲染/交互线程；必须先完成共享所有权和长期边界实例，再开放设置页同步。
- PNG 缓存属于 D2D device generation；遗漏清理会在设备重建后引用旧资源。
- 组件动作跨线程执行，显示桌面等 COM 操作需在统一入口中正确处理线程 COM 状态。
