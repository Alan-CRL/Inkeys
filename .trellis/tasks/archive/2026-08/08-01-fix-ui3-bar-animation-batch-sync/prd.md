# 修复 UI3 Bar 主栏动画批次不同步

## Goal

修复 UI3 Bar 在展开动画后半程发生二次布局变化时，按钮沿用旧批次较短剩余时间、而主栏重启完整动画批次所造成的速度不同步。主栏背景与按钮应在同一批次内协调推进，不再出现按钮已经快速展开而主栏仍在追赶的现象。

## Background

- 当前 `lateMainBarLayoutChange` 会在主栏时间轴超过可加入阶段后重启完整批次。
- 目标位置未变化的按钮会因 `SetTar` 早退而继续旧批次；主栏宽度和中心位置则按新批次重新开始。
- 普通首次展开已经使用统一时长与曲线，本任务只处理晚期二次布局变化的批次重启缺口。

## Requirements

- 修改范围限制在 UI3 Bar 主栏布局动画同步逻辑，优先只修改 `Inkeys/Inkeys/UI/Bar/Bar.Main.cpp`。
- 晚期布局变化创建新主栏批次时，仍在运动的主栏和按钮布局属性必须从当前值加入同一个新批次，使用一致的时长与曲线阶段。
- 目标值未变化但仍在旧批次运动的按钮不得因 `SetTar` 早退而提前完成。
- 保持普通展开、收起、主栏左右换边、动画关闭和动画速度倍率行为不变。
- 不处理触摸点击主按钮跳变问题，也不做无关动画曲线或布局优化。
- 代码关键同步点使用简短中文注释说明原因。
- 第一阶段完成实现、质量检查和 ARM64 Debug Solution 构建后提交一次 commit，但保持任务为 `in_progress`。
- 用户完成实际运行验证并确认后，再归档任务并提交第二个收尾 commit。

## Acceptance Criteria

- [x] 展开动画超过批次加入阈值后触发布局宽度变化，主栏与仍在运动的按钮不会使用不同的完成时刻。
- [x] 目标位置未变化的在途按钮会正确加入晚期重启批次，不会先于主栏完成。
- [x] 普通展开/收起和左右换边的现有关键帧逻辑不发生行为回归。
- [x] 关闭动画时所有相关值仍在同一帧完成，动画速度倍率仍正常生效。
- [x] `InkeysRepo.sln` 的 `Debug | ARM64` 使用 ARM64 MSBuild 构建通过。
- [x] 第一阶段代码提交完成后任务保持 `in_progress`，等待用户手工验证。
- [x] 用户确认验证通过后归档任务，并用第二个 commit 提交收尾记录。

## Out of Scope

- 触摸或兼容鼠标输入去重。
- 主按钮拖动/点击阈值调整。
- 主栏按钮顺序、尺寸、间距或视觉曲线重设计。
