# UI3 展开按钮点击合并

## Goal

为 UI3 中仅用于展开或收起面板的按钮增加短时间点击合并，避免触摸抖动、双击或重复输入使面板刚展开又立即收回，同时完整保留按钮的状态切换语义。

## Background

- 旧 UI2 在 `Inkeys/IdtFloating.cpp:5889` 附近通过全局 `MouseInteractionManipulated` 和 180ms 时间门控抑制重复操作；该实现会连带阻塞状态按钮，不能直接移植。
- UI3 在 `Inkeys/Inkeys/UI/Bar/Bar.Interaction.cpp:2888` 附近已有 `doubleClickContinuation`，用于保证双击第二击仍命中原按钮，但它不负责合并展开动作。
- 绘制按钮在 `Inkeys/Inkeys/UI/Bar/Bar.Button.cpp:254` 附近区分两类行为：非 Pen 状态下第一击只切换状态，已处于 Pen 状态时才展开或收起绘制属性。
- 几何按钮具有同样的“第一击切换状态、第二击展开属性”语义，因此与绘制按钮一并纳入。

## Requirements

1. 使用 300ms 作为点击合并窗口，以覆盖触摸误双击；同一展开动作在首次成功执行后，窗口内的后续 toggle 不再执行。
2. 第一击必须立即生效，不增加等待或延迟执行。
3. 按动作使用相互独立的合并通道，至少覆盖：
   - 主按钮展开/收起；
   - 绘制与几何属性展开/收起；
   - 更多面板展开/收起；
   - 墨迹粗细调节三角展开/收起；
   - 笔属性三角菜单展开/收起。
4. 仅在即将执行 toggle 时检查门控，并仅在 toggle 真正执行后更新时间；状态切换、普通命令按钮、粗细预设选择、FineDial 确认或提交不参与门控。
5. 不在 Win32/HiMsg 原始消息层丢弃第二击，不改变系统触摸转译与 Inkeys 自定义触摸转译的既有策略。
6. 不同展开通道互不阻塞；快速先后操作两个不同面板时，两次操作均可执行。
7. 显式关闭按钮和点击浮层外部触发的关闭保持现有行为，不纳入按钮点击合并。
8. 新增代码使用 `Inkeys` 命名；关键门控逻辑保留简短中文注释，并保持原文件编码与 CRLF 换行。

## Acceptance Criteria

- [x] 主按钮、更多、绘制/几何属性、墨迹粗细三角和笔属性三角在 300ms 内收到两次相同 toggle 请求时，只执行第一次。
- [x] 达到 300ms 后再次点击同一按钮，可以正常执行相反的展开/收起动作。
- [x] 静态确认：在选择状态双击绘制按钮时，第一击切换到绘制状态，第二击展开绘制属性。
- [x] 静态确认：在非几何状态双击几何按钮时，第一击切换到几何状态，第二击展开几何属性。
- [x] 快速点击两个不同展开按钮时，不会因另一个通道的时间戳而丢失操作。
- [x] 状态切换、普通命令、粗细预设、FineDial 提交、显式关闭及浮层外点击关闭行为不变。
- [x] 静态检查确认没有在原始输入消息层新增全局去重或吞消息逻辑。
- [x] `Debug | ARM64` 完整构建通过，且 `InkeysHeadlessTests.exe --no-window` 通过；验证过程中未启动 Inkeys 窗口，也未操控桌面。

## Out of Scope

- 调整 HiMsg 消息结构、系统触摸转译开关或 Inkeys 自定义触摸转译策略。
- 对非 toggle 控件增加通用防抖。
- 修改 UI 动画、布局、视觉效果或展开状态机。
- 启动窗口进行人工交互测试。

## Technical Notes

- 推荐在 UI3 交互层集中维护按通道的最近成功 toggle 时间，并通过一个小型辅助函数完成检查和记录。
- 门控位置必须位于业务语义已经确定为“展开/收起”之后，以免误吞绘制/几何按钮的第一击状态切换。
- 本任务范围明确、影响集中，采用 PRD-only 轻量任务。
