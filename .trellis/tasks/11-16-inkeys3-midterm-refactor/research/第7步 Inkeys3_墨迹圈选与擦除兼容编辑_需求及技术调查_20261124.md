## 1. 原始需求

希望为 Inkeys 的墨迹增加类似对象编辑器的圈选能力。用户可用套索选择一个或多个墨迹，并在选中之后进行：

- 平移、等比或非等比缩放、旋转；
- 笔迹类型变更（例如普通笔与荧光笔、不同笔锋形式）；
- 颜色、透明度、粗细、线形（实线、虚线等）的修改。

本次调查关注两个主要矛盾：

1. **圈选后的判定速度。** 页面可能包含大量笔迹和长笔迹；不希望每次圈选都遍历整页全部点或进行全画布像素处理。
2. **被橡皮擦过的墨迹的判定与移动。** Draw3 的橡皮也是独立墨迹操作，通过合成减少下层覆盖率，而非直接删除原始笔迹或切断中心线。因此，用户看见的墨迹可能已经与原始数据完全不同。

第二项必须覆盖以下情况：

- 原始墨迹仍连通，仅被擦去局部边缘或内部区域；
- 被擦断成两段、多段，或形成许多不规则小块；
- 原始中心线完全被擦掉，但两侧仍残留可见面积；
- 墨迹完全消失；
- 同一橡皮作用于多个墨迹，或多次橡皮先后作用于同一墨迹；
- 橡皮的边界带有抗锯齿和连续的透明度，不是简单的二值像素集合。

变换后，擦除形成的缺口、凹口、孔洞、边缘透明度应跟随对应笔迹，而不应意外复原。移动一条墨迹不能顺带移动全局橡皮或破坏其他笔迹原有的擦除痕迹。仍需考虑与其他笔迹重叠时正常的遮挡与显露，而非要求移动前后整个画面所有像素都不变。

性能必须是设计前提：不能为了编辑能力显著牺牲当前实时书写、擦除和白板漫游体验。

## 3. 当前擦除模型及关键数学发现

### 3.1 Add/Retain 操作

令 `C` 表示预乘 Alpha 的 RGBA（包括 Alpha 通道本身），单个操作为：

```text
C_out = A + R * C_in

普通笔（RGB = c，最终覆盖率/不透明度 = a）：
    A = (c.r*a, c.g*a, c.b*a, a)
    R = 1 - a
橡皮（覆盖率 = e）：
    A = 0
    R = 1 - e
```

单个 Stroke 的胶囊段通过 Add MAX / Retain MIN 形成覆盖率并集，避免同一笔迹的相邻几何重复叠加。不同历史项再按时间顺序合成。两个连续仿射操作可以合并：

```text
(A1, R1) 后执行 (A2, R2)：
    A12 = A2 + R2 * A1
    R12 = R2 * R1
```

该组合具有结合性，但不满足一般交换性，因此现有按顺序组织的 CompositionRangeTree 可以缓存并组合历史区间。橡皮与 Porter-Duff 的 Destination Out 语义一致。双源混合使用 `D3D11_BLEND_ONE` 与 `D3D11_BLEND_SRC1_COLOR/ALPHA`，参见第 12 节的官方文档。

需要区分数学上的实数运算与 GPU 实际量化、过滤、舍入以及实时多 contact 合成策略；不能仅凭公式声称任意重放路径都逐像素一致，必须用生产管线对照测试。

### 3.2 为什么不能只改变原始墨迹坐标

例如历史顺序：

```text
Draw Red -> Draw Blue -> Erase E
```

E 同时在红、蓝两笔上留下缺口。如果只移动红笔的几何，原有 E 的坐标仍然固定，红笔可能恢复被擦掉的部分，或者在新位置受到不应该受到的旧橡皮影响；如果将 E 一起移动，则会错误修改蓝笔的擦除结果。

因此：**擦除痕迹需要在编辑时具备对象归属，而不是直接移动全局橡皮。**

### 3.3 每笔单独应用蒙版不等价于全局擦除

这是最重要的合成边界。两条笔迹 Alpha 均为 0.5、完全重叠，之后的橡皮覆盖率为 0.5：

```text
现有全局擦除：
    Alpha_before = 0.5 + 0.5*(1-0.5) = 0.75
    Alpha_after  = 0.75*(1-0.5)      = 0.375

转换成独立对象蒙版、再做 Source Over：
    a1' = a2' = 0.25
    Alpha_after = 0.25 + 0.25*(1-0.25) = 0.4375
```

不但 Alpha 不同，预乘颜色也可能不同。即使普通笔本身不透明，抗锯齿边缘同样会产生分数 coverage。

结论：不能把所有旧橡皮全量迁移为每笔独立 Mask 后，直接认定旧文件视觉不变。需要区分：

- 未编辑内容的旧合成兼容性；
- 独立编辑对象本身的外观；
- 对象移动后正常的遮挡、显露与新重叠；
- 保持原 Z-order 的严格语义（尚未解决/决定）。

### 3.4 擦除保留率与最终画面贡献是不同量

对原始 Stroke `i`，令 `e_k(x)` 是其创建之后、确实对该对象生效的第 k 个橡皮操作 coverage，则：

```text
M_erase_i(x) = product_k (1 - e_k(x))
```

对当前按序合成中的 `i`，其 Add 在最终画面中的贡献，在实数仿射模型下为：

```text
V_i(x) = A_i(x) * product_(j > i) R_j(x)
```

第二个式子不仅包含橡皮，还包含上层普通墨迹/其他后续操作的遮挡。因此 `V_i` 可以用于分析屏幕可见贡献，但**不能直接作为对象永久的擦除蒙版**，否则被其他笔迹盖住的部分也会被当作删除，移动后无法正常显露。

应分别定义“擦除后的固有可见几何”和“当前屏幕上未被其他对象遮挡的可见贡献”。若启用仅选最上层对象等交互，可选用后者。编辑后是否继承某个旧橡皮，必须依据对象版本及生效范围，而不是只依据其原始 Stroke 创建时间。

## 4. 圈选对象与交互语义（待产品决策）

一个原始 Stroke 可能在擦除后拥有多个分离的可见区域，因此应将三种身份分离：

| 身份 | 说明 |
| --- | --- |
| Source Stroke | 原始完整的中心线/几何与初始样式，可保持不可变。 |
| Visible Fragment | 被擦除后的二维连通区域，不一定对应连续的点区间。 |
| Editable Ink Object | 可被选中、变换、修改样式的对象，可以引用一个或多个 Fragment。 |

建议支持渐进式编辑粒度（不是最终交互设计）：

1. 整笔圈选：同一 Stroke 所有未擦除区域一起选中，适合作为基础实现。
2. 可见片段圈选：同一 Stroke 被擦成多块后，可选中并独立移动其中一块或若干块。这是原始需求中第二项的重要能力，不应因首版简化而永久取消。
3. 区域剪切圈选：仍然连通的墨迹也可只移动套索内的部分，属于额外高级能力，暂不强制与前两项一起实现。

套索包围比例阈值、触碰即选/包含一定比例才选、重叠对象选择策略、点击命中容差等需后续确定。对象被橡皮彻底擦除时，常规可见性圈选不应误选；是否提供历史恢复或隐藏对象管理，则是另一项功能。

## 5. 快速圈选判定方案

推荐分为三个层级：空间索引粗筛、实际几何相交、可见性/片段精筛。

```text
套索点输入（屏幕坐标）
  -> 转换到 Canvas 坐标，确定填充规则、AABB、简化轨迹
  -> 查询局部 Tile -> Stroke/Segment 反向索引
  -> 去重、排除无效/隐藏/不可选对象
  -> 结合笔宽、形状执行精确或保守几何相交
  -> 仅对疑似被擦除的候选读取/生成局部可见性信息
  -> 返回 Stroke 或 Fragment ID，建立选区会话
```

### 5.1 空间索引

- 复用现有 `BuildStrokeTileFootprint` 的 Canvas Tile 覆盖计算与 AA 保守边界。现有 `tileBlocks_` 面向合成树，不能直接等同于精确命中索引。
- 建立稀疏 Tile → Stroke ID 的反向索引；长笔迹再按局部 Segment Chunk 建立包围盒/Tile 映射，避免每次命中一个长笔迹就遍历所有点。
- 可单独维护 Eraser 的空间索引，并按历史顺序、作用对象范围和版本过滤。无需为所有笔迹预先建立庞大的两两擦除关系表。
- 抬笔时增量更新索引；Undo、Redo、移动、删除、页面恢复时更新必要的记录。白板无限 Canvas 仅保存有效区域的稀疏索引，避免枚举无墨迹的巨大空白区域。
- 如果极端密集场景的候选数量仍然很大，再评估 R-tree、分层 BVH 或多级网格，而非一开始引入复杂通用空间数据库。

### 5.2 几何相交

- AABB 过滤后进行点在多边形内、线段与套索边界相交、胶囊/荧光笔扫掠几何相交等判定。不能仅依赖中心线。
- 套索可在屏幕误差约 0.5–1 DIP 的候选范围内简化，最终参数需要根据误选情况确定；处理自交、闭合、过小面积、反向绘制等情况。
- 优先考虑 CPU 完成通常的粗筛和精筛。WPF 的 `StrokeCollection.HitTest(lassoPoints, percentageWithinLasso)` 提供了长度占比选择的参考，但不能直接解决 Draw3 的全局擦除问题。
- 可见覆盖率的候选指标为 `套索内固有可见墨迹面积 / 整笔固有可见墨迹面积`。可按实际 coverage 加权，也可使用带笔宽的采样近似；应明确它和原始中心线长度比例不同。
- 对分母为零的对象，不返回普通命中。对亚像素笔迹、小碎片及半透明笔迹设置合理命中容差，不能简单按较高的 Alpha 阈值一律丢弃。

### 5.3 擦除可见性与 Fragment

不建议每次橡皮 Move 都进行所有受影响笔迹的二维分割。建议使用惰性分析：仅提交/记录橡皮变化，按需要让有关可见性缓存失效；圈选命中候选或进入 Fragment 编辑时，计算该对象局部 ROI 内的可见区域。

可选方法：

| 方法 | 作用 | 局限 |
| --- | --- | --- |
| 中心线与橡皮相交、可见区间 | 快速判定普通断笔、长笔迹的局部候选。 | 无法识别边缘残留、内孔、侧向切开、复杂自交，不能作为最终 Fragment 定义。 |
| CPU 矢量轮廓布尔差 | 得到几何意义上的剩余区域；可通过 Direct2D `CombineWithGeometry(EXCLUDE)` 等实现辅助验证。 | 轮廓构造和布尔运算有成本；硬几何差本身不能精确表示所有分数覆盖率。 |
| 局部覆盖率图 + 连通域 | 可判定二维残留块、孔洞以及多段分离。 | 需定义采样分辨率、阈值、四/八连通及边缘归属；GPU 回读可能造成同步。 |
| 混合方案 | 简单几何走快速路径，疑难区域才进行局部覆盖率/拓扑判定。 | 需保证快慢路径的保守性与一致性。 |

Fragment 拓扑应在约定的 Canvas/对象参考分辨率上定义，不应随着窗口 DPI、平移或旋转逐帧重新生成身份。阈值、最小碎片处理、窄桥与对角接触规则需要独立原型。用于命中/连通域的阈值不得直接替代渲染所用的连续覆盖率。

对于大面积、跨 Tile 对象，需要合并 Tile 边界两侧的连通域；仅对套索 ROI 做分析时，不能误以为 ROI 外没有连接路径。整笔连通性需要完整对象范围或可靠的跨区域连接数据。

GPU 路径如确有必要，可采用局部栅格化、GPU 归约或分批 staging readback，而非全屏回读；`D3D11_MAP_FLAG_DO_NOT_WAIT` 可用于不阻塞的 Map 检查，失败时等待后续轮询或使用 CPU 回退，不要在绘制热路径忙等。

## 6. 被擦除墨迹的编辑实现候选

### 6.1 候选 A：移动原始 Stroke / 同时移动橡皮（不推荐）

实现简单，但无法在一个橡皮影响多个对象时保持独立编辑。只适用于未被擦除的墨迹或特意移动整个独立历史组，不能作为通用方案。

### 6.2 候选 B：传统中心线切割或矢量布尔差

传统的点擦除可将笔迹拆成新的 Stroke，或将笔迹轮廓与橡皮轮廓做布尔差，输出独立多边形。优点是后续对象选择和变换较直观。

但中心线分割会丢失一部分 Draw3 支持的自由擦除形态，尤其是局部边缘、孔洞、不规则切面；矢量布尔差若仅保留二值几何，则无法保证原始 AA 与多次擦除累乘效果。将所有笔迹烘焙为轮廓后，也会削弱后续笔型和粗细编辑的能力。

矢量布尔可作为 Fragment 拓扑或候选几何的一部分，而不宜未经验证就替代现有全局橡皮模型。

### 6.3 候选 C：截图/最终颜色纹理提取（不推荐作为权威数据）

直接从 L2 或最终画面截图裁剪选择区域，并变换位图，无法可靠分离重叠的不同墨迹；也无法恢复被遮挡部分或继续精确修改笔型和线形。反复缩放会引入采样误差。

允许将独立对象的覆盖率纹理或临时颜色纹理作为预览缓存，但不能用包含其他笔迹的最终合成截图替代对象数据。

### 6.4 候选 D：原始不可变几何 + 局部擦除蒙版 + 惰性 Fragment（优先研究）

保持原始笔迹数据，建立对象级编辑状态。仅在对象实际需要编辑时提取对应的擦除历史，按需要生成可见片段，并将擦除描述绑定到对象局部坐标。

未编辑的旧内容继续走原有历史重放与合成树路径，不预先对所有 Stroke 做分割和重新合成。已编辑对象使用可重建的局部 Mask、几何与变换描述。

以下结构仅表达设计方向，不是要求直接采用的 C++ API：

```cpp
struct EditableInkObject {
    InkObjectId id;              // 持久、稳定，不依赖 vector 当前下标
    SourceStrokeId sourceId;      // 原始几何引用
    Matrix3x2 localToCanvas;     // 对象局部 -> Canvas
    InkStyleOverride style;      // 样式及宽度/线形覆盖
    EraseMaskRef eraseMask;       // 局部擦除语义
    FragmentClipRef fragmentClip; // 可选片段归属
    uint64_t revision;           // 缓存和异步结果校验
    // 实际设计还需对象版本、合成顺序、历史作用范围等信息。
};
```

建议将擦除描述本身（矢量轨迹、对象版本关联、坐标转换及必要的裁剪信息）作为可序列化权威数据；R8_UNORM/R16_FLOAT 等覆盖率纹理作为按需生成、可淘汰的 GPU 缓存。Fragment 的裁剪归属也必须有持久或可确定重建的表达，不能只保存在临时 GPU 纹理中。若采用栅格归属作为最终权威数据，需要明确精度、版本和序列化代价。

### 6.5 惰性提取与旧橡皮的作用范围

一种可先验证的兼容路径：

1. 进入实际编辑时，读取当前文档版本，找到选中 Stroke/Fragment 及其真正受到的后续橡皮，提取局部擦除保留信息。单纯圈选或取消不应修改文档。
2. 逻辑抑制原有选中部分的绘制贡献，并重建旧位置。其他未选中 Stroke 和旧 Eraser 仍按原有顺序重放。
3. 用局部几何、擦除 Mask 与片段裁剪生成独立编辑对象；预览时按明确约定的前景顺序绘制。
4. 若最终采用前景插入语义，提交后的对象属于新的操作序列位置，旧全局橡皮已通过局部蒙版体现，不得再次作用于新对象；未来的新橡皮则继续对它生效。
5. 再次编辑时只合并上次对象版本之后尚未物化的擦除效果；同一橡皮不能重复累乘。撤回/重做需恢复对应的版本、抑制状态与蒙版关系。

仅移动一个 Fragment 时，原始 Stroke 的其余片段应留在原位置。若其余片段仍走旧全局操作，原位应使用互补的片段裁剪（而不是同时对剩余部分乘上已由旧全局 Eraser 生效的相同擦除 Mask）。若全部迁移为新对象，则应显式处理旧合成语义变化。

**重要：这不是已经证明严格等价的迁移方案。** 前景插入会改变旧 Z-order；部分擦除和半透明叠放的像素结果可能发生变化。修改颜色等非位置编辑是否允许置顶也尚未确定。选中、零距离拖动、取消、原位提交都应优先要求视觉和历史无副作用。

若产品要求对象在编辑后始终保持原有 Z-order、旧橡皮只作用于原目标且半透明结果不变，必须另行研究按对象或分组限定橡皮作用域、按序分解 Add/Retain、局部重放中的目标过滤等更深入的合成模型。不能仅通过把对象重新插回原历史位置或添加一个通用蒙版解决这一问题。

## 7. 变换、抗锯齿和片段归属

### 7.1 局部坐标及逆变换

统一区分屏幕坐标、Canvas 坐标、对象局部坐标和 Mask 纹理坐标。令对象矩阵 `T` 将局部坐标映射到 Canvas（平移、旋转、缩放围绕明确的 pivot）。对目标位置 `p`：

```text
q = inverse(T) * p
coverage = StrokeCoverage(q, screenDerivatives)
alpha = styleOpacity * coverage * EraseRetain(q) * FragmentClip(q)
A = (styleRGB * alpha, alpha)
R = 1 - alpha
```

以上为概念模型：各项覆盖率的求取及 AA 需要与生产光栅化一致。原始 Stroke、局部 Eraser 及 Fragment Clip 必须在相同参考空间内，变换一起生效。对缩放过小、不可逆矩阵、非有限值等需要保护。

普通笔的可变半径胶囊在非等比缩放后不再是简单的等半径圆形扫掠；仅变换中心点、仍在屏幕上使用原半径，会产生形状错误。荧光笔固定竖直笔尖、图形角半径也需要明确随对象旋转/缩放的规则。

### 7.2 AA 与缓存策略

- 矢量擦除轨迹具有任意变换后重建的潜力；可通过现有 SDF/几何栅格化生成局部连续覆盖率，尽可能保持屏幕空间 `fwidth` 的 AA 语义。
- GPU Mask 适合作为拖动预览和常用缩放区间的快速路径；使用连续覆盖率而非只存 0/1，避免锯齿和边缘跳变。R16_FLOAT 可作为高精度候选；R8 的量化影响需要测试。
- 大幅放大、变换变化或分辨率不足时，从原始权威几何/蒙版描述重新生成，不应不断对上一次变换结果进行再次采样。
- 稀疏 Tile/Atlas 应考虑过滤边界和 guard texel，避免旋转或线性采样时出现 Tile 之间的缝隙及相邻对象串色。
- 蒙版保留率与画笔覆盖率分别计算；拓扑标签不能取代连续 AA。对高精度缩放需要比较屏幕空间重新栅格化与预采样 Mask 的误差、速度及内存。
- 使用 `CheckFormatSupport` 等检测具体设备的采样、RenderTarget、Blendable 等能力；不要为新功能强制引入 D3D12、SM6 或仅新系统支持的 API。若未来选择 Compute Shader，可作为可选加速实现，而非基础功能的唯一入口。

### 7.3 片段分割的边缘

假设原始笔迹擦成 A/B/C，移动 B 时，B 的可见覆盖率由原始几何、擦除保留率、片段 B 的归属共同确定；A/C 仍属于其余片段。

不同片段的归属必须有明确互补关系，不能在分割时简单复制整笔三次并随意用各自 AA 裁剪。即使裁剪权重相加等于 1，分别执行普通 Source Over 也不保证与原始单笔覆盖率等价。

未分离的同源片段应尽量保持原始单笔覆盖率语义；实际分离后才按对象定义的混合与叠放规则处理。测试需覆盖亚像素碎片、细窄连接、孔洞、自交笔迹及旋转缩放后的边缘连续性。

## 8. 拖动交互、性能与缓存设计

### 8.1 三阶段编辑会话

1. **准备/开始拖动：** 锁定 Canvas 和对象版本；计算选中对象的局部 Mask/几何和旧位置 Tile；构建排除/裁剪选中对象后的稳定底图。取消前只做临时渲染事务。
2. **拖动、旋转、缩放中：** 原有 L2 保持稳定，通过独立 Selection Preview 绘制选中对象；只更新对象矩阵、局部脏区与必要的覆盖率缓存。不得每帧重建全部历史、写入持久对象或运行全局连通域。该预览应与 L0/L1 实时笔迹职责解耦。
3. **提交/取消：** 提交时一次更新对象版本、空间索引、旧/新 Footprint、缓存 generation 和编辑历史；取消则恢复原视图，不产生 Undo 项。GPU 失败应回退到可信 CPU 状态/重新重放，而不是留下半提交结果。

前景预览是易于实现的候选，不代表最终必须改变 Z-order。如果最终要求保持原层级，拖动预览也需按层级合成，否则提交时会出现明显的跳变。

### 8.2 复用现有 HistoryGpu 的具体注意点

- `CanvasRuntimeHistory::UpdateItemGeometry` 目前主要更新 Footprint、引用计数及 generation，不能直接修改不可变 `InkStroke` 的真实几何。需同时扩展渲染数据来源。
- `CompositionRangeTree::UpdateItemGeometry` 已支持旧、新 Tile 的联合失效；样式或 Mask 变化即使未改变包围盒，也必须使对应缓存失效。
- `RestoreComposition` 的 `excludedItem` 目前仅一个。多对象选区应扩展成批量排除/替换以及按区间重放，不能通过 N 次完整重建实现。
- 若旧历史项仅部分被选中，应能替换其局部渲染 operator，不可将整笔全部隐藏。
- 对候选/预览状态的缓存使用独立 generation 或隔离资源，避免污染仍可信的正式缓存。
- 脏区使用旧位置、新位置及上一次预览位置的 Tile/区域并集，考虑 AA 边界；不要无条件使用包围二者的大矩形导致长距离拖动全屏刷新。

### 8.3 预算及线程约束

现有缓存结构本身已具备预算控制，应为编辑蒙版、Fragment 辅助数据与预览资源设置受控预算，评估其与 Undo/Composition Cache 的共同显存占用，而不是每笔创建全屏纹理。

例如 256×256 单通道 Mask 的纯像素存储为 R8 64 KiB 或 R16_FLOAT 128 KiB，不含分配、边缘填充及索引等开销。一个 3840×2160 的全屏 Mask 约为 7.9 MiB（R8）或 15.8 MiB（R16_FLOAT），若为大量对象分别分配将不可接受。该计算只是理论容量示例，非实际显存或性能测试结果。

CPU 几何/连通域等昂贵工作可在独立任务中处理不可变快照；GPU immediate context 仍由绘制 owner 管理。结果需携带页面/文档身份、对象 revision、选择会话 generation 等，防止切页、Undo、新绘制或取消后安装过时结果。复杂选区应允许分批计算和取消，不阻塞实时墨迹提交路径。

120 FPS 的整帧预算约 8.33 ms（包括输入、渲染、呈现及所有其他工作），不能把全部预算用于圈选或拖动。应独立测量首次选择分析延迟、准备拖动耗时和拖动稳定帧时间。没有实测之前，不承诺具体毫秒指标。

## 9. 样式编辑、历史与持久化

### 9.1 样式编辑

| 操作 | 候选实现 | 需要明确的语义 |
| --- | --- | --- |
| 颜色、透明度 | 更新对象样式并生成新的 Add/Retain。 | 是否保持原 Z-order，遮挡后的部分能否重新显露。 |
| 粗细 | 对原始宽度应用倍率或重建笔尖几何。 | 墨迹变粗后是否允许超出原始可见区域；历史橡皮的局部几何是否继续限制新增部分。 |
| 笔型 | 从已保存的几何与宽度重建新的笔尖形式。 | 完成态数据不一定保存原始压力、时间、硬笔/软笔全部输入信息，转换可能无法还原所有原始动态笔锋。 |
| 实线、虚线、点线 | 根据原始路径弧长和线型参数生成覆盖率。 | 分段后保持虚线相位；虚线的间隔与橡皮造成的 Fragment 应有不同语义。 |
| 平移、旋转 | 改变仿射矩阵。 | 局部擦除和片段裁剪跟随对象。 |
| 缩放、拉伸 | 变换几何及蒙版。 | 候选默认同步缩放笔宽；是否提供固定笔宽模式另行决定。 |

普通笔变粗可能在原来没有墨迹、也没有缓存 Mask 的区域产生新覆盖率；因此不能将旧笔迹裁剪大小的 Alpha 图直接作为完整擦除历史。若允许样式编辑超出旧边界，需要能重新查询、重建相关旧橡皮在新增区域的作用，或在产品层明确另一种语义。对 Fragment 改变笔宽/笔型后，是否允许扩展到原片段外，也需独立决策。

### 9.2 Undo/Redo

当前历史侧重尾部笔迹可见性的切换，需要引入单独的编辑事务，记录多对象的前后状态、对象替换/抑制、变换、样式、片段及擦除作用关系。

- 一次拖动/旋转/缩放或一次批量样式确认对应一个 Undo 项，而不是每帧一个。
- 开始圈选、取消选区、预览本身不修改持久历史。
- Undo/Redo 应和普通绘制、橡皮、清屏及分支丢弃共同工作；原始数据 append-only 与对象版本更新可以并存。
- 必须防止旧的热前像在对象已改变后被误用；沿用或扩展 raster state token、内容 generation、页面身份等校验。
- 合理保留用于撤回的原始几何与蒙版引用，之后再根据安全的历史截断策略回收不再可达的版本。

### 9.3 UInk / 自动保存

调查基线中 UInk 导出以当前可见历史项的样式与点序列为主，白板历史另外记录可见性、顺序和 redo。这里的 `visible` 指历史项启用状态，并不是经过橡皮后的实际可见面积。两者均不足以直接表达未来独立编辑状态。

未来需要检查实际 `.uink` schema、导入/导出及 Lite/Inkeys/Full 的兼容计划，再决定扩展方式。最低要求：

- 旧文件按原全局橡皮操作顺序加载，未编辑内容不能因版本迁移发生视觉变化。
- 新格式能持久保存对象稳定 ID、原始几何引用、变换、样式、Fragment 归属、擦除描述及生效范围/版本等必要信息。
- 需要明确旧阅读器遇到新对象类型/扩展的处理；如提供降级兼容导出，应明确会损失哪些对象编辑能力或外观精度，不能默默丢失擦除痕迹。
- Desktop/PPT/Whiteboard 的保存、冷页加载、清屏恢复、设备丢失恢复等都应使用相同的权威编辑语义，GPU 临时纹理可全部丢弃并重建。
- 是否要求持久化整个编辑 Undo 栈，遵循未来具体格式及现有产品策略，而非在本次背景调查中先行确定。

## 11. 验收、基准和待决定的问题

### 11.1 功能与像素测试

| 场景 | 预期 |
| --- | --- |
| 普通笔、点、荧光笔、长笔迹圈选 | 考虑实际笔宽，正确命中；无关对象不进入精筛。 |
| 完全擦除、仅边缘残留、中心线被擦掉 | 完全不可见者不被常规圈选；有可见覆盖的残留可以命中。 |
| 同一笔迹擦成两段/多段，或内部孔洞 | 整笔模式可选所有剩余区域；Fragment 模式正确识别并独立移动。 |
| 多条墨迹共用橡皮 | 移动其中一条，旧缺口跟随它；其他笔迹保持原擦除关系。 |
| 笔迹覆盖在另一条笔迹上 | 区分遮挡和擦除；移动后原被遮挡而未擦掉部分按约定正常显露。 |
| 半透明重叠、橡皮分数 coverage、多次擦除 | 用当前 GPU 合成作为基准，验证不编辑/取消时无差异；编辑后满足选定的层级及合成语义。 |
| 橡皮之后新绘制墨迹、移动到旧橡皮所在位置 | 不受不应该生效的历史橡皮影响。 |
| 已编辑对象再次擦除/再次移动 | 新擦除随对象移动，旧蒙版不重复累乘。 |
| 整笔与单 Fragment 零位移/取消/原位提交 | 无意外视觉变化、无错误遮挡、无重复 AA；取消不增加历史。 |
| 多次旋转、平移、放大、缩小 | 使用原始数据重建，不积累图像重采样模糊；新旧脏区完整。 |
| 改色、透明度、粗细、笔型、线形 | 缺口与片段语义符合约定；虚线相位、原笔锋、AA 合理。 |
| Undo/Redo 后继续绘制、再次编辑、清屏与恢复 | 历史分支、对象身份、raster token、选区状态一致。 |
| 保存重开、切页/PPT/白板、设备丢失 | 不丢失变换及擦除语义；正式 GPU 缓存可重建。 |

应复用 HeadlessTests/生产 GPU fixture 体系，对比预乘 RGBA 结果，而不仅看截图或中心线。量化误差阈值应针对不变场景、边缘和变换重栅格化分别制定；没有确认规范之前，不把任何非零差异都简单归为 AA 误差。

## 13. 调查结论

该功能具备实现可行性。Draw3 已有的不可变最终墨迹、连续覆盖率 AA、Add/Retain 双源混合、Canvas Tile Footprint、合成树与局部重放机制是有价值的基础，不应为实现圈选而轻易推翻。

现阶段优先研究的方向是 **不可变原始墨迹 + 稳定的可编辑对象 + 对象局部擦除保留蒙版 + 惰性 Fragment 生成 + 空间索引与独立编辑预览**。它能把昂贵的分析从实时绘制/橡皮热路径移出，并为后续的对象级笔型编辑和多画布场景提供统一表达。

核心风险不是套索多边形判定，而是旧全局橡皮的作用归属、半透明叠放的数学非等价性、片段 AA 及编辑后历史的一致性。尤其是“同一橡皮擦过两条墨迹，只移动其中一条”应作为最早的核心原型；还必须包含半透明重叠、部分片段移动和再次擦除的变体。

本文仅作为后续制定详细需求、原型实验、架构决策和开发计划的背景参考。上述候选实现、分期、参数和层级策略尚未定稿；实施前应结合届时实际代码以及实测结果进行选择，不能将未验证的设计直接当成已经成立的技术事实。
