# 第2步-C 性能页设备性能看板

> 状态：需求预告（2026-11-17 用户口述），**待阶段 A、B 完成后再详细调查与设计**。父任务 `11-17-win7-ulw-presentation`；分支 `refactoring/draw`。
> 阶段 A/B 实现时应为本阶段预留采集与口径（见“对 A/B 的前置要求”），可先实现部分记录能力；它与后续探针测试高度重合。

## Goal

在设置 → 性能页最顶端提供一个美观的“设备性能看板”，让用户直观看到当前设备绘制画布是否轻松：平均无限制帧率、负载百分比、综合评估、评估时间与覆盖维度，并按性能充足程度分级配色。数据来自日常使用中低影响的周期性采样，而不是专门的跑分。

## 需求（用户原意整理）

### 采集
- 绘制线程在绘制时简单记录少量数据：每次只记几帧，多了不记（固定小容量，热路径无阻塞、无分配、无 I/O）。
- 抬笔后空闲时再分析，并把结果写入本地 `Inkeys/Memery` 目录下的 JSON（与 `Inkeys/AutoSave` 同级的程序根目录子目录；命名按用户原文 “Memery”，实现前再确认拼写）。
- 不是每笔/每次都计算：按**测试周期**低影响地采样。周期可选、可关闭，默认 1 天为一个周期。
- 综合评定：周期内用户只画了一笔就会产生数据；之后再用激光笔、橡皮、图形等，数据会更完善（多维度累积）。
- 当用户修改性能页的任意设置项后，当前周期重置并开始新的测量。

### 指标与展示
- 平均帧率（无限制帧率，即只按实际工作耗时折算的理论帧率）。
- 负载百分比：越接近 0 说明设备越轻松；100% 表示刚好满足当前预设帧率；超过 100% 表示当前帧率下严重负载。
- 百分比是本周期的平均值：下一次又画了几笔后会更新，不需要和之前的平均（不跨周期累加）。
- 给出评估结论、评估时间（精确到秒，即总结评估的时间）、以及在哪些维度中进行过考量（书写 / 激光笔 / 橡皮 / 图形等）。
- 新周期数据出来之前，显示上一个周期的数据；没有上个周期数据则显示空。
- 位置：设置 → 性能页最顶端。
- 视觉：设计得好看，数字要大（类似网页数据卡片）；按性能是否充足使用 绿色 / 灰色 / 黄色 / 红色 背景，并区分深浅主题。

## 现状线索（待阶段 C 调查时核实）

- 画布调试已有同口径计算：`Draw3.CanvasDebug.cpp:754` 起，`unlimitedFps = 帧数 / 工作耗时总和`，`loadPercent = 平均工作耗时 / (1000 / target_fps) × 100`。
- 运行指标 `Draw3.RuntimeMetrics.*` 已有逐帧 wall/present 统计与分布导出；设置性能页已有画布帧率、渲染与兼容等设置项（`Setting.cpp` 性能页）。
- 自动保存目录由 Host 传入 `<程序根目录>/Inkeys/AutoSave`，可参考其持久化 worker 与路径约定。

## 对阶段 A / B 的前置要求（实现 A/B 时就要满足）

1. **工作耗时口径**：waitable 等待耗时、帧截止睡眠、（ULW 流水线中的）等待 GPU 完成时间，都不得计入“工作耗时”；单独记录。否则看板会把“在等 GPU/合成”误判为 CPU 负载。`Present` 内部阻塞耗时也应可单独区分。
2. **按工具/维度标记帧**：采样记录需能区分书写、激光笔、橡皮、图形、漫游等维度。
3. **采样器形态**：固定容量环形记录（例如每段只记前若干帧），绘制线程只写 POD，分析与 JSON 写入放到空闲/后台；与探针测试复用同一数据结构。
4. **性能设置变更可被观察**：性能页设置项写入时能通知采样器重置周期（启动期设置如帧率、硬件加速、DComp、waitable 开关需定义“重启后算新周期”的规则）。

## Acceptance Criteria（草案，阶段 C 规划时细化）

- [ ] 看板位于性能页顶端，深浅主题下四档配色正确，数字醒目。
- [ ] 默认 1 天一个周期，可修改或关闭；修改性能设置后周期重置。
- [ ] 绘制热路径无可感知开销（与关闭采集时对比）。
- [ ] 无上一周期数据时显示空；新周期出数据前显示上一周期。
- [ ] 评估时间精确到秒，列出已覆盖维度。
