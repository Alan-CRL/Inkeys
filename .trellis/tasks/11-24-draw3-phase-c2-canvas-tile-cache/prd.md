# 阶段 C2：画布瓦片缓存跟随画布、平移与缩放显示

## 背景（2026-11-24 只读调查，行号以调查时为准，实施前复核）

- **三层**：L2（落定画面）、L1（书写中笔画的稳定前缀）、L0（笔尖与预测），都是屏幕坐标。L0、L1 是“算子层”：Add（BGRA8）+ Retain（R16F），`结果 = Add + Retain × 下方`，两个算子可以先合成再作用。
- **热前像**（撤回瓦片，128px）：抬笔落定和重做时，把这一笔要覆盖的 L2 块原样复制出来；撤回命中时拷回 L2，不重画。64 MiB / 20 条，先进先出。它是屏幕坐标缓存，匹配要求视口完全相同，**视口一变就全部作废**（`Draw3.DrawingController.cpp:20626`）。
- **合成缓存**（256px，世界坐标）：笔画按 32 笔一组建隐式二叉树，每个节点在每块世界瓦片上存一对算子；任意区间 [a,b) 能用少量节点拼出。192 MiB，LRU。失效按“所在组到根 × 覆盖瓦片”换新 generation。冷撤回、平移恢复、翻页恢复都靠它把结果逐块写回 L2。
- **平移现状**：视口一变就整屏清 L2；按 0–4ms 预算逐块恢复，缓存全部命中也要逐块写回 L2；可见区没恢复完时用旧快照垫底，速度超过 300 DIP/s 加 9 点运动模糊；全部清晰后整屏复制快照、整屏合成与呈现。
- **惯性**：已有 `CanvasPanDynamics`，速度上限 12000 DIP/s。
- **缩放**：不支持。`IsValidViewport` 要求 `scale == 1`（`Draw3.InkDocument.cpp:17`），rasterKey 的 scale 写死为 1。
- **对象移动**：只有图形可编辑（移动、改尺寸），通过原索引替换保持 Z 序；每次编辑都整体丢弃热前像与合成缓存再重放（`:21857`）。自由笔迹没有选择与移动。
- **白板背景**：点阵和网格仍由 Freeze 窗口用 D2D/WARP 绘制（`kWhiteboardPatternOwner = Freeze`），每秒 22–35 帧，比墨迹晚 3–4 个样本。

## 用户已定的方向（2026-11-24）

1. **热前像跟随画布**：平移后仍可用于撤回；移出视口（或部分移出）的部分可以释放。
2. **合成缓存同样跟随画布**，移出视口的部分可以释放。
3. **平移、缩放过程中只保证显示**：有缓存就用来加速，没有就直接渲染；瓦片等缓存在松手、惯性停止、画面静止后再构建。
4. **去掉运动模糊**。来不及渲染的边缘允许模糊，模糊区域改为半透明，以降低用户的模糊感。
5. **缓存只针对视口**：进入页面后、平移或缩放静止后，缓存只覆盖视口；开始平移或缩放时按意图（惯性方向、速度）提前绘制；静止后释放视口外资源，并为当前视口构建缓存。
6. **缩放**：交互上仍禁用，但渲染与缓存能力这次一起做好。
7. 这一层以后要服务三类用途：中层墨迹或图形的移动（Z 序不变，上方依赖合成缓存）、白板平移（含惯性）与未来的白板/桌面画布缩放、撤回与重做。

## 需求（草案，待逐点确认）

- 热前像、合成缓存改为世界坐标并跟随画布，按视口与静止状态管理驻留与释放。
- 平移与缩放过程的显示路径：已有内容复用，新露出或缺缓存的区域直接渲染；渲染不过来的边缘允许模糊并半透明；不再有运动模糊。
- 静止后按视口构建缓存；运动开始时按意图预绘。
- 缩放：视口、缓存键、显示与直接渲染支持 scale ≠ 1，并有无窗口用例覆盖；交互入口保持禁用。
- 撤回、重做在平移后仍能命中热前像；中层对象移动可以利用合成树的区间查询，不再整体丢弃缓存（是否在 C2 实施待定）。

## 第二轮确认（2026-11-24）

1. **运动中的增量显示**：平移时复用上一帧画面，只处理新露出的矩形或 L 形范围；这块范围先找有没有缓存（包括按意图提前画好的），没有就按笔画顺序直接重画这一块（裁剪到该范围，橡皮按序参与）。
2. **页面级空间索引**（“某块区域里有哪些笔画”）：需要做，同时为第7步的圈选做准备（见父任务 `research/第7步 …墨迹圈选与擦除兼容编辑…md` §5.1）。
3. **亚像素平移**：运动过程中视口可以按小数移动，差别影响不大；停下时必须落在整数坐标（实施前核对现状是否已经如此）。
4. **全页低分辨率概览纹理**：需要，用作来不及渲染区域的模糊占位（半透明显示）。缩放比例不固定：默认如 1/8，页面很大、超过阈值时继续缩小（1/16 等）。
5. **缩放过程**：放大时直接拉伸已有画面，在适当时机或松手时变清晰；缩小时，边缘的缓存有帮助，先模糊贴上再变清晰。
6. **静止后构建缓存**：要可中断、优先级低于书写，因为“静止”可能就是落笔触发的。
7. **缩放边界**：C2 只做底层基本支持（视口比例、缓存键、显示与直接渲染、无窗口用例），交互仍禁用；手势、笔宽与橡皮语义、图形手柄、激光、光标等不在 C2。
8. **白板背景同帧**：不在 C2。第3步会把白板背景与画布合入同一窗口的同一视觉树，在一帧内控制。
9. **中层对象移动**：C2 做查询接口与基础（合成树区间查询“上方区间 + 被移动对象 + 下方区间”、页面级空间索引），不做圈选交互；在本次要改动的地方为第7步的圈选、变换、样式编辑留好规划。
10. **不限于白板**（2026-11-24）：桌面画布与 PPT 未来也可能支持拖动和缩放，与白板同一套逻辑。C2 的缓存、显示与直接渲染不能写成白板专用，要以“画布 + 视口”为单位实现；三处的统一封装在 C3 完成。

## 从 C1.5 移交（2026-11-25）

- **翻页后的 GPU 冷重建**归 C2：C1.5 实测（Debug，98/246 笔页、77/78 块可见瓦片）冷重建命令提交 121–184 ms，占冷页加载 40–45%。现状是每笔在每块 256 合成瓦片上约 2 次清除、3 次绘制、3–4 次上传，跨多块的长笔每块重复上传，全部可见瓦片在一帧内同步完成。数据与分段口径见 `../11-24-whiteboard-uink-load-speed/research/load-timing-logs.md`。
- C1.4+C1.5 联合任务完成后，冷页的 CPU 与 IO 部分已经缩短，C2 应在其基础上重新测基线。
- C1.4 写入的 UInk 1.1 文件已带 `viewport {x, y, scale: 1}`；C2 做好缩放后，读取时再兑现非 1 的 `scale`（联合任务里按缺省回退并写 warning）。

## 从 C1.4+C1.5 联合任务移交（2026-11-26）

- 新基线（真实重页，用户实测，数据见 `../11-24-uink-1-1-adaptation/research/s7b-load-benchmark-20261126.md`）：Release 953 笔页冷读 GPU 冷重建 p50 约 240 ms，占约 78%；Debug 923 笔页约 290 ms，占约 64%。读盘、解码、导入已移到后台（Release 约 22 ms）。
- **足迹必须一并评估**：绘制线程上逐笔计算瓦片足迹，真实重页 Release 35–60 ms、Debug 约 95 ms，随点数线性增长。联合任务裁定不迁移，依据是合成中等页面上只有 6–7 ms；C2 重做冷重建流程时，要同时决定是否把足迹移到后台（随回执带回瓦片列表），或改为按视口懒算。
