# 实施计划：设置组件页主栏拖拽编辑器

## 任务地图与顺序

| 顺序 | 子任务 | 交付 | 前置 |
| --- | --- | --- | --- |
| 1 | `11-20-bar-layout-model`（C1） | 四段布局模型、B 区读持久化、用户分割线、重复实例、旧开关导入、编辑操作、重置 | 无 |
| 2 | `11-20-bar-content-instance`（C2） | 可实例化主栏内容层，真实主栏委托 | C1（避免同时改 Bar 核心文件） |
| 3 | `11-20-component-preview-dragdrop`（C3） | 设置页预览嵌入、通用拖放、全部拖动反馈 | C1、C2 |
| 4 | `11-20-component-library-page`（C4） | 快捷块、重置块、组件库、替换旧开关 | C1；卡片拖动需 C3 |

四个子任务都会改 `Bar.*` 或 `Setting.cpp`，彼此文件重叠，因此串行推进，不拆并行会话。每个子任务开工前补齐自己的 `design.md`（函数级）与 `implement.md`，经 Claude 审定后 `task.py start`（用户已于 2026-11-20 授权直接完成整个实现）。

## 协作分工（2026-11-20 用户指定，C1 第 3 轮起调整）

- Claude：整体规划、进度监督、审核，并**主导代码实现**（细节修复、构建错误、审查意见落地均由 Claude 直接完成）。
- Codex `gpt-6.2-astra`（`service_tier=default`，无 fast）：只用于非常复杂、大规模的调查或实现（例如 C2 抽取可实例化主栏内容层这类跨数千行的重构），由 Claude 判断是否委派。
- Codex `gpt-6.2-sol`（`service_tier=fast`，`--sandbox read-only`）：每个阶段的独立审查。
- 防止委派实现偷懒与多余内容：简报列白名单与逐条需求对照表；Claude 对照白名单检查 `git diff --stat`、搜索桩代码、核对断言变更；Sol 把这两类列为最高优先级。
- 调整原因：C1 前两轮由 Astra 修复细节问题，往返耗时近 1 小时。
- 简报与报告存放在仓库外 `%TEMP%\inkeys-comp\impl\`。

## 每个子任务的通用步骤

1. 对照当前代码核实父 design 中引用的行号与函数（行号会漂移）。
2. 写子任务 `design.md` / `implement.md`，列出改动文件与测试；Claude 审定后 `task.py start`。
3. 实现。源文件保持 UTF-8 BOM + CRLF；不用 Git Bash `sed -i` 改源码。
4. 构建：`InkeysRepo.sln`，`Debug | ARM64`，ARM64 原生 MSBuild，超时 ≥ 5 分钟，检查退出码与首个错误。
5. 测试（最小范围，按子任务选择）：
   - Bar golden：与改动前基线逐字节比较（C1、C2 的硬门禁）。
   - Bar 离屏/属性/第二宿主测试（C1、C2）。
   - headless 新增单测（C1 模型、C3 拖放状态机）。
   - `setting_design_tests`（C4；导航用例单独跑约 24 秒）。
6. 审查与修复（见上）。
7. 用户实机验收后，更新 spec、提交（需用户授权）、归档子任务。
