# 阶段 C1 设计（草案）

基线 `refactoring/draw@cbcccf9a`，工作区另有未提交的诊断代码（脏区统计、阶段耗时、两条原因日志）。本文是 2026-11-23 与用户逐项讨论后的设计草案，**尚未获批准实现**。需求与用户决定见 `prd.md`，现状与数据见 `research/`。行号会漂移，实现前须复核。

标注：**[定]** 用户已确认；**[议]** Claude 的提议，待用户确认；**[待测]** 需要数据才能定。

## 1. 目标与范围

目标：

1. Draw3 有一个通用的脏区模型：接收任意数量的矩形，按使用方的代价参数给出一组两两不相交的区域。**[定]**
2. 一帧内的脏区不提前并成一个；上屏合成、呈现都按多个区域处理。**[定]**
3. L2 侧的写入、撤回、重做也按多个区域处理，并为白板平移做准备。**[定]**
4. 降低大橡皮的填充量与抬笔时的整笔重画（E1–E3）。**[定]** 范围；做法 **[议]**
5. 修复粗荧光笔撤回残留。**[定]**

不做：

- 白板平移本身（C2）；`forceFullPresent` 的各条整屏路径保持不变。
- 光标独立表面、不含叠加物的画面缓存纹理、“按下橡皮已知为空”的快路径：已记到第 3 步。**[定]**
- ULW 提交线程；悬停帧限速（既定决策为不限速）。
- 清空碎裂、粒子效果本身的整屏开销（效果自身的范围，脏区模型帮不上）。

## 2. 数据依据（摘要）

本机 Adreno、2880×1920、DComp、120 Hz、Debug 构建。详见 `research/dirty-stats.md`。

| 现象 | 数据 |
| --- | --- |
| 两指对角书写 | 现在每帧合成 22–78% 画布，实际变化不到 0.15% |
| 两指大橡皮对角 | 每帧 40–64%；所有光标被并成一个矩形是直接原因 |
| 合成段耗时与面积成正比 | 整屏约 2.5 ms（一帧预算 8.33 ms 的三成） |
| 稳态擦除 | 几何与合成合计不到 1 ms |
| 抬笔整笔重画 | 大橡皮 76–214 ms，较小橡皮 26–44 ms，尾段路径 1–2 ms |
| 撤回、重做对角长线 | 单帧 48–77% 画布 |
| 激光留存淡出 | 每帧 67–75%，加粒子 31–100% |
| 实际区域数 | 最多 3 个 |

缺的数据：旧 Intel 核显、WARP、ULW 下的同一组场景；发布版构建下光标精灵跨档的耗时。

## 3. 总体结构

```text
各来源（笔、橡皮、荧光笔、图形、激光、粒子、命令、重建……）
        │  逐个矩形，不提前合并
        ▼
帧区域集合（墨迹与效果）──┐
叠加物清单（光标、笔尖、调试标记）──┤ 闭包：相交才并入
        ▼
按“上屏合成”参数规整 → 合成区域（两两不相交）
        │
        ├─ 上屏合成：每个步骤处理全部区域
        │
        ├─ 交换链：按“Present1”参数再粗化 → 多个脏矩形
        │
        └─ ULW：GPU 拷贝与 DIB 逐行拷贝按“读回”参数；
                 提交按“ULW 提交”参数分多次，或选项关闭时一个外接矩形
```

L2 侧（抬笔写入、撤回、重做）用同一个模型，区域来源是笔画的瓦片足迹。

## 4. 区域模块

### 4.1 位置与形态 **[议]**

新增独立模块 `Draw3.DirtyRegion`（`.cppm` 加 `.cpp`），只依赖 `<windows.h>` 的 `RECT` 与标准库，不依赖 D3D，带无窗口单元测试。需要在 `Inkeys.vcxproj` 与 `InkeysHeadlessTests.vcxproj` 各加文件条目。

现有散落的 `UnionRectInPlace`、`IsEmptyRect`、`ClampRectToCanvas` 等保留在原处不动；新模块自带需要的几个函数。后续步骤里碰到的文件顺手改用新模块，不做全仓库替换。

### 4.2 接口

```cpp
namespace Inkeys::Drawing::Draw3
{
    // 使用方的代价参数。
    struct DirtyCostProfile
    {
        long long fixedCostPixels; // 多处理一个区域的固定开销，折算成像素
        std::uint32_t maxRegions;  // 输出区域数上限
    };

    class DirtyRegion // 固定容量，不分配堆内存
    {
    public:
        static constexpr std::size_t kCapacity = 16;
        void Clear() noexcept;
        void Add(const RECT& rect) noexcept;          // 空矩形忽略；容量满时并入代价增量最小的一个
        void Add(const DirtyRegion& other) noexcept;
        bool Empty() const noexcept;
        RECT Bounds() const noexcept;                  // 外接矩形
        long long Area() const noexcept;               // 各矩形面积之和（规整后才等于像素数）
        bool Intersects(const RECT& rect) const noexcept;
        std::span<const RECT> Rects() const noexcept;
        void ClipTo(int width, int height) noexcept;
        // 规整：结果两两不相交，区域数不超过 profile.maxRegions。
        void Normalize(const DirtyCostProfile& profile) noexcept;
    private:
        std::array<RECT, kCapacity> rects_;
        std::size_t count_ = 0;
    };
}
```

`Add` 只做收集（满了才合并），`Normalize` 才做规整。同一份帧区域可以拷贝后按不同参数规整多次。

### 4.3 规整规则

1. **相交即合并**：任意两个相交的矩形合并为外接矩形，重复到两两不相交。**[议]**
2. **按代价合并**：对任意一对，`浪费 = 面积(外接) − 面积A − 面积B`。`浪费 ≤ fixedCostPixels` 时合并。合并可能产生新的相交，回到第 1 步，直到不再变化。这就是“1+1>2”的量化：多处理这些空白像素，不如少一次固定开销。**[定]** 原则
3. **数量上限**：仍超过 `maxRegions` 时，反复合并“浪费最小”的一对。
4. **退化**：规整后面积之和不小于外接矩形面积的 3/4 时，直接用一个外接矩形。

规则 1 用整合并而不切分。切分（把重叠的两块切成不相交的几块）留给明确需要的场合，C1 不实现。

实现补充（第 1 步）：第 2、3 条在同一个循环里执行，只要“浪费最小的一对值得合并”或“数量超限”就合并。这样结果是不动点，对同一结果按同一参数再规整一次不会改变。

复杂度：输入至多 16 个，最坏 O(n³)，都是整数运算，可忽略。

### 4.4 初始代价参数 **[待测]**

| 使用方 | fixedCostPixels | maxRegions | 依据 |
| --- | --- | --- | --- |
| 上屏合成 | 128×128 | 8 | 每个区域多一次顶点上传与绘制，状态只绑定一次 |
| GPU 读回拷贝、DIB 逐行拷贝 | 128×128 | 8 | 每个区域一次 `CopySubresourceRegion` 与一段行拷贝 |

数据显示收益集中在“相距很远”的场景（差两到三个数量级），阈值取得粗不影响这些场景。ULW 提交的参数等拿到 ULW 下每次调用耗时与面积的关系后再调。

## 5. 帧内接入

### 5.1 帧区域集合

`Draw3.DrawingController.cpp` 帧循环里的 `RECT frameDirty` 改为 `DirtyRegion frameRegion`。诊断阶段已经把 39 处并入点收拢到 `addFrameDirty(rect)`，这里把它的实现换成 `frameRegion.Add(rect)`。

通过引用接收 `frameDirty` 的被调函数（形状界面校验、画布命令、激光烘干、图形构造预览、粒子设置、控制屏障、焦点层）有两种处理：

- 改签名为接收 `DirtyRegion&`：画布命令（撤回、重做）与激光烘干，它们能给出多个矩形（§9、§11）。
- 保持 `RECT&`，调用处用一个局部矩形接住再 `Add`：其余几处，它们本来就是单个矩形。**前提是被调函数不读取传入矩形的原值**，实现时逐个确认。

开工核对补充（2026-11-23）：读取帧脏区的地方比上面列的多，逐个处理如下。

| 使用方 | 处理 |
| --- | --- |
| 平移帧的可信快照合成（按传入矩形，瓦片恢复期间可能不是整屏） | 逐矩形调用 |
| 清空碎裂快照、激光已烘颜色、激光笔画层 | 与每个矩形求交后逐个绘制（都不幂等，依赖矩形不相交） |
| 性能指标的候选冻结（`FreezeCandidates`） | 不能只给外接矩形：外接矩形里有没重新合成的空洞，会把没上屏的内容当成已上屏。改为按实际区域判断覆盖 |
| 调试日志、Host 快照的 `lastDirtyRect`、`canvasDebugInjectedBounds` 的包含判断 | 外接矩形 |
| `processCanvasCommands`（翻页重置时会直接改写成整屏） | 改写语义保留：改写即清空区域并加入整屏 |

仍需要“本帧是否有脏区”的判断处改用 `frameRegion.Empty()`。需要单个矩形的旧消费者（性能指标、调试日志、`canvasDebugInjectedBounds` 的包含判断）用 `Bounds()`。

`forceFullPresent` 为真时 `frameRegion` 重置为整屏一个矩形，与现状一致。

### 5.2 各来源给出的矩形

| 来源 | 现状 | 改为 |
| --- | --- | --- |
| 笔、荧光笔、橡皮的每帧增量 | 三个矩形并入 | 不变，逐个 `Add` |
| 光标 | 全部光标并成一个矩形；任一变化则全部旧、新并入 | 每个光标的旧矩形、新矩形各自 `Add`，只加变化了的光标（§5.3） |
| 激光笔尖 | 同上 | 同光标 |
| 激光留存、淡出 | 整组轨迹的外接矩形 | 每条激光笔画一个矩形；长笔画按点列分段（§11） |
| 粒子 | 活跃批次并成一个矩形 | 活跃批次的矩形逐个 `Add`，由模型按容量合并（§11） |
| 清空碎裂 | 被清墨迹的外接矩形 | 不变 |
| 抬笔写入 L2、撤回、重做 | 整笔外接矩形 | 笔画的分段区域（§9） |
| 共享层重建 | 所有接触并成一个矩形 | 每个接触一个矩形 |
| 视口恢复、翻页、调试板等 | 单个矩形或整屏 | 不变 |

### 5.3 叠加物与闭包 **[议]**

叠加物指直接画在 backbuffer 最上层、不裁剪的东西：橡皮与笔的光标、激光笔尖、调试标记。它们的特点是“下面的画面一旦重新合成，自己就必须重画；自己重画时下面必须先重新合成”。

每帧整理一份叠加物清单，每项有：当前范围、上一帧范围、是否变化、绘制入口。处理顺序：

1. 变化了的叠加物：旧范围与新范围 `Add` 进帧区域。
2. 闭包：对每个未变化的叠加物，如果它的当前范围与帧区域相交，就把它的整个范围 `Add` 进去并标记为“本帧重画”。重复到没有新增（每轮至多新增一项，最多迭代叠加物个数次）。
3. 规整帧区域。规整会把矩形并成外接矩形，范围变大后可能碰到原先没碰到的叠加物，所以第 2、3 两步要循环到不再变化（开工核对修正；提升为整屏时同理，全部叠加物重画）。
4. 合成之后只绘制“变化了的”与“标记为本帧重画的”叠加物。其余的不画：它们所在的 backbuffer 区域本帧没有动过，上一帧的像素仍然有效。

这替换了现在的两条规则：“任一光标变化则全部光标的旧、新位置并入”和“只要有脏区就并入当前光标与笔尖”。

粒子、点击光波是一次绘制画出全部粒子，不能逐个跳过。它们活跃时每帧都在变，所以所有活跃范围每帧都在区域内，按现在的方式整体绘制即可。

这份清单同时是给 C3 和第 3 步的准备：呈现端以后可以把清单里的项交给独立表面。**[定]** 方向

**正确性前提**：未进入帧区域的 backbuffer 像素保持上一帧的内容。现状已经依赖这一点（脏区之外不重画）。交换链路径下由 DXGI 在翻转模型里同步非脏区域来保证，现有单矩形脏区已经这样工作；多矩形下是否仍成立列为验证项（§14）。

## 6. 上屏合成

### 6.1 按步骤组织

`CompositeLayersToBackBuffer(RECT dirty, bool)` 改为接收 `std::span<const RECT>`（已按“上屏合成”参数规整）。每个步骤内处理全部矩形：

| 步骤 | 现状 | 改为 |
| --- | --- | --- |
| L2 拷到 backbuffer | 一次 `CopySubresourceRegion` | 每个矩形一次，没有状态切换 |
| L1、L0 算子合成 | 绑定全套状态，一次 `Draw(6)` | 状态绑定一次；每个矩形更新顶点缓冲并 `Draw(6)`；最后解绑一次 |
| 调试板、白板图案（under 混合） | 一个矩形、scissor | 每个矩形设 scissor 各画一次 |
| 清空碎裂快照 | 与脏区求交 | 与每个矩形求交 |
| 激光已烘颜色、激光笔画层 | 与脏区求交、scissor | 与每个矩形求交 |
| 粒子、光波 | 整体绘制 | 不变 |
| 叠加物 | 全部绘制 | 按 §5.3 只画需要的 |

算子合成和 under 混合都不幂等，所以这里依赖区域两两不相交。渲染器入口加断言（Debug 构建检查不相交）。

`InkRenderer::ResolveOperatorLayers` 增加接收 `std::span<const RECT>` 的重载，原单矩形版本转调它。合成顶点着色器现在按“相邻两个点是一个矩形的两角”取数，多个矩形无法在一次绘制里表达，所以首版用“逐矩形更新顶点缓冲并绘制”，**不改着色器**。如果 E1（§8）反正要重新生成着色器，可以顺带把合成改成一次绘制多个矩形；是否值得由实现时的计数决定。

平移帧的可信快照路径（`CompositeTrustedL2SnapshotToBackBuffer`）是整屏，不变。

### 6.2 L1、L0 两层都空的区域

现有“两层都空则跳过合成、只有一层有内容走单层合成”的选择按整层判断，保持不变。按区域判断层是否为空（例如光标所在区域 L1、L0 没有内容时只拷 L2）是可行的进一步优化，但与第 3 步的画面缓存重叠，C1 不做。

## 7. 呈现

### 7.1 接口

`TransparentPresentationController::Present(RECT dirty, bool presentFull, uint64_t contentRevision)` 增加重载，接收 `const DirtyRegion&`。`DrawingController::PresentFrame` 传帧区域。观测与 Host 快照里的 `lastDirtyRect` 保持为外接矩形，另加区域个数。

### 7.2 交换链（DComp、Win7Dwm）

`PresentSwapChain`：`DXGI_PRESENT_PARAMETERS::DirtyRectsCount` 设为合成区域的个数，`pDirtyRects` 指向同一组矩形。整帧路径不变。不受新选项影响。**[定]**

开工核对修正（2026-11-23，Codex 指出）：草案原写“按 Present1 参数再粗化一次”，这会让提交的脏矩形大于实际重新合成的范围。DXGI 要求脏矩形内的每个像素都是当前帧的内容，所以**提交给 `Present1` 的矩形必须就是合成用的那一组**，不再单独规整。§4.4 表里“Present1 脏矩形”一行的参数因此不使用。

### 7.3 ULW

`UlwDirtyRectPresenter` 的三段分别处理：

| 段 | 改动 |
| --- | --- |
| GPU 拷到 Staging（`IssueCopy`） | 每个区域一次 `CopySubresourceRegion` |
| Staging 到持久 DIB（`CopyAndInspectUlwDirtyRows`） | `Map` 一次，每个区域各拷各的行。透明度与预乘检查按区域累计 |
| 提交（`UpdateLayeredWindowIndirect`） | 选项开：按“ULW 提交”参数规整后每个区域一次调用，各带自己的 `prcDirty`。选项关：一次调用，`prcDirty` 为外接矩形 |

前两段不受选项影响，始终按多区域。**[定]** 持久 DIB 保存着已提交的画面，没拷的像素本来就没变，所以外接矩形提交是正确的。

开工核对补充（2026-11-23）：

- 只有主画布的 ULW 走多区域。选择态、辅助输出用的是同一个类的另一个同步实例，保持按外接矩形或整帧，不改。
- 透明度与预乘检查：对拷贝过的各区域取“与”；“整帧全透明”仍然要求整帧呈现且覆盖整个位图。
- 环境变量 `INKEYS_DRAW3_ULW_FULL_UPDATE=1`（整窗提交的诊断开关）与整帧呈现时仍然只调用一次。
- 提交计划器（节流、与合成对齐）、帧计数保持按“批”计，不按调用次数计。

异步读回的累计脏区 `accumulatedDirty`（跳帧时累计）由单个 `RECT` 改为 `DirtyRegion`，每个 Staging 槽记录自己那次拷贝的区域。累计时直接 `Add`，容量满了由模型合并。

**分多次提交的一致性**：各区域之间可能差一次系统合成，用户已接受，不喜欢可以关选项。**[定]** 提交顺序按区域在集合中的顺序，不做特殊排序。

**失败处理**（开工核对修正，2026-11-23）：草案写的是“失败的区域留在待提交集合里下次再交”，并说这与现状一致。核对发现现状并不保留失败的区域：任何一次调用失败，都是清掉待处理的提交并要求下一次整帧读回。多次调用里任意一次失败时沿用这个做法，不新增“失败区域列表”。失败到恢复之间，已经提交的几块与没提交的几块会同时显示，直到下一次整帧读回成功。

**与合成节拍**：是否提交、何时提交仍由现有的 `UlwCommitPlanner` 与合成对齐决定，本设计不改时机。一次提交里的多次调用连续发出，所以“赶在合成之前”的保证与现在的单次调用相同，只是总耗时变成各次之和。每秒汇总日志增加调用次数与每次调用的面积，用来观察总耗时是否超出对齐余量。未开启对齐、或 Win7 关闭 DWM 时照常分多次。**[定]**

辅助输出 `DrawpadPresentation`（选择态接力、全透明帧）走整帧路径，不变。

## 8. E1：只画新扫过的部分

### 8.1 原理

层内混合是 Add 取最大、Retain 取最小。一个像素被同一笔的多个线段覆盖时，结果等于各线段在该像素的值取最大（或最小），与画的次数无关。所以一条线段只需要覆盖“它相对于已画内容新增的像素”，其余像素不画，结果逐像素相同。

线段 i 的覆盖范围是胶囊（p1、r1 到 p2、r2）。它的前一条线段以 p1 为终点，已经画过以 p1 为圆心、半径 r1 的端帽。所以线段 i 的新增范围包含在“胶囊去掉圆盘(p1, r1)”里。圆盘内部（留出抗锯齿余量后）覆盖率已经到顶，可以跳过。

### 8.2 几何

现在每条线段是一个四边形（6 个顶点），沿线段方向从 `−r1−2` 到 `段长+r2+2`，法向 `±(最大半径+2)`。

改为每条线段 K 个横条，每个横条两个四边形（共 12K 个顶点）。在线段局部坐标里（x 沿线段方向，y 沿法向），记 `R` 为两端半径的较大者、`E = R + 2`，把 `[−E, E]` 均分成 K 条。每条的 y 范围向两侧各多取 0.5 像素（裁到 `[−E, E]`），`ymax`、`ymin` 是这一条里 `|y|` 的最大值与最小值（跨过 0 时 `ymin = 0`）。

- 外沿 `outer = sqrt(max(0, (R+2)² − ymin²))`。这一条的 x 范围是 `[−outer, 段长 + outer]`。它包住了距胶囊 2 像素以内的全部点，同时切掉了四个角。
- 收缩时，`r1' = r1 − 2`。若 `ymax < r1'`，记 `s = sqrt(r1'² − ymax²)`，这一条在 `[−s, s]` 之间整段落在圆盘(p1, r1')内，可以不画：后四边形画 `[−outer, −s]`，前四边形画 `[s, 段长 + outer]`。否则不挖洞，后四边形画整条，前四边形退化为零面积。
- 不收缩的线段（一次绘制里的第一条）不挖洞，但同样切角。

开工核对（2026-11-23）对草案的三处修正：

1. **起点一侧的外圈也要画。** 草案只保留了 `x > s` 的部分，漏掉了圆盘(p1, r1')之外、位于起点后方的那一圈（抗锯齿带）。那里前一条线段的覆盖率不一定不小于本条（两者的抗锯齿宽度取决于各自的梯度方向），不画会与完整几何有差别。所以改为“挖洞”而不是“截断”。
2. **外沿不能写成 `sqrt(R² − y²) + 2`。** `|y|` 接近 `R` 时，距胶囊 2 像素以内的点在 x 方向可以伸出 `sqrt(4R+4)`（R=300 时约 35 像素），远大于 2。改为 `sqrt((R+2)² − ymin²)`。
3. **横条之间要重叠。** 相邻横条的 x 范围不同，公共边上是 T 形接缝，顶点各自取整后可能漏掉个别像素。层内取最大、取最小，重复覆盖无害，所以让相邻横条重叠 1 像素。

实现前复核（2026-11-23，Codex 指出）又修正两处，原因都是**现有四边形本身会裁掉一部分形状**（x 只到 `−r1−2` 与 `段长+r2+2`；两端半径相差很大时，较大的端点圆会伸出这个范围而被截断）：

4. **横条的 x 范围要与现有四边形求交**，即 `[max(−outer, −r1−2), min(段长+outer, 段长+r2+2)]`。否则新几何会画出现在被裁掉的那部分，结果与现状不同。本步保持现状，不修这个既有的截断。
5. **洞的半径要缩到前一条线段实际画过的范围内。** 前一条线段的四边形从它自己的起点后方 `r0+2` 处开始，半径增长很快时（`r1 > 段长' + r0`）圆盘(p1, r1)的后半部分不在其中。洞的半径取 `min(r1 − 2, 前一段段长 + r0)`。顶点着色器因此要读前一个点；一批里的第一条线段没有前一个点，不挖洞（分批上传时后续批次的第一条也不挖，代价可忽略）。

6. **一端圆包含另一端的线段不分条。**（Codex 第二次复核指出）这种线段（`|r1 − r2| ≥ 段长`）正是现有四边形会截断形状的情况，截断边穿过覆盖率为 1 的区域；横条与原四边形的顶点不同，取整后截断边上的个别像素会有出入。这类线段直接按原四边形画（第一个四边形用原来的顶点公式，其余退化），结果与现状逐位相同。其余线段的四边形边缘都在形状外 2 像素以上，那里覆盖率为 0，取整差异没有影响。前一条是这类线段时，本条仍可按第 5 点挖洞。

像素着色器的距离场是两个端点圆的凸包（`sdUnevenCapsule_Vertical`，一端圆包含另一端时退化为较大的圆），所以前一条线段确实包含圆盘(p1, r1)。距离函数的梯度长度不超过 1，抗锯齿宽度不超过 3，圆盘(p1, r1−2)内覆盖率恰为 1。结论：在洞里不画，结果不变。

像素估算（直径 600、段长 10）：新增部分约 6000，加上前后两侧的阶梯余量与外圈。K=32 时每段约 2–3 万像素，现状约 37 万。具体数值以实现后的阶段耗时为准。

顶点数增加可以忽略（1000 段 × 32 条 × 12 = 38 万顶点，无像素开销）；WARP 上的顶点处理开销需要实测。

像素着色器不变，仍按真实的距离场算覆盖率。几何只决定哪些像素参与计算。

### 8.3 适用条件

“前一条线段已经画在同一层里，并且之后没有被清掉”时才能收缩。

第 2 步只做最稳妥的一种：**同一次 `DrawStroke` 调用里，每个上传批次的第一条线段完整，其余线段收缩**。这不需要任何跨调用的状态。

| 情况 | 第一条线段 | 其余线段 |
| --- | --- | --- |
| 整笔重画（路径 B、重建前缀、历史回放、重做）、L0 每帧重画的尾段 | 完整 | 收缩 |
| 每次增量提交到 L1 的一批 | 完整 | 收缩 |

草案里“增量提交接着上一批的末点画时第一条也收缩”**推迟**：它要求跨调用确认 L1 自上一批以来没有被清除、接缝点没有被改过，这些状态属于第 8 步要整理的抬笔路径。稳态擦除每帧一批（通常一到几条线段），本机实测稳态合计不到 1 毫秒，主要收益在整笔重画（上千条线段一次画完）。核显上稳态仍然偏重时再做。

K 由 CPU 按这一批点的最大半径选定，经常量缓冲传给顶点着色器；顶点着色器再按每条线段自己的半径取档（不超过本批的 K），细线段不分条。档位（实机取数后调整，2026-11-23）：半径小于 24 像素保持现状（K=1，走原来的代码路径，输出不变）；24–48 取 8；48–96 取 16；96–192 取 32；192 以上取 64（本机硬件基准显示 128 条相对 64 条没有收益）。每条横条高约 6–12 像素，洞周围的阶梯余量随半径线性增长。横条不能更矮：几分之一像素高的横条会扰动插值坐标，抗锯齿带上的差别超过 1 级。

渲染器保留一个开关（默认开）可以整体退回 K=1，供像素一致性自检对照，也是出问题时的退路。

### 8.5 着色器与兼容

顶点着色器要改（按横条展开顶点、读取起始线段号与 K）。像素着色器不变，所以已有类型的输出不变。规范（`.trellis/spec/native-desktop/draw3-shaders.md`）写的是“改 `inkPixelShader.hlsl` 后必须重新生成 Win7 受保护着色器”；只改顶点着色器是否需要重新生成，实现时核对 `Draw3.Win7GuardedShader.h` 的内容后确定。Win7 WARP 与兆芯由用户实机复验。

### 8.6 验证

- 像素回读自检：同一笔分别用完整几何与收缩几何画进空层，比较 Add、Retain 两张图。洞内与笔画内部应逐像素相同；抗锯齿带上由不同三角形插值出的坐标可能有极小差别，允许不超过 1 级（8 位），并报告有差别的像素数与最大差值。覆盖：等半径、半径渐变（变大、变小）、急转弯、折返、段长远小于与远大于半径、单段、第一批与续接批。
- 现有的抬笔路径像素一致性用例（路径 A 与整笔重放相差不超过 1 级，路径 B 逐像素相同）继续通过。
- 用阶段耗时诊断对比改动前后：稳态 GPU 几何段、抬笔 GPU 几何段最大值。

## 9. L2 侧的多区域

### 9.1 笔画区域的来源

历史系统给每条入库的笔画算瓦片足迹 `StrokeTileFootprint`：128 像素的撤回瓦片列表与 256 像素的合成瓦片列表，都是世界坐标、稀疏的。这就是现成的“沿笔画分段的矩形”。一条倾斜的长线只占沿线的那些瓦片，而不是外接矩形里的全部。

新增函数：把撤回瓦片列表按行合并成连续段，再把上下相邻且左右范围相同的段合并，得到一组矩形；换算到屏幕坐标后放进 `DirtyRegion`，超过容量时由模型按代价合并。因为瓦片是世界坐标的，平移后同一份列表换一个偏移就能得到新的屏幕区域，这是为 C2 留的接口。**[定]** 方向

书写中的笔画还没有足迹，它的区域来自每次提交的矩形累计（§10.1）。

### 9.2 足迹必须与绘制范围一致（含荧光笔修复）

粗荧光笔撤回残留的原因是足迹用了写死的笔尖尺寸（半宽 1.25、半高 25），而绘制用的是随笔宽变化的尺寸（见 `research/highlighter-undo-footprint.md`）。

修法：把“荧光笔笔尖半宽、半高由半径决定”的计算放到一个两边都能包含的小头文件里，`Draw3.InkHistory.cpp` 的两处（逐点外扩量、整笔范围）与 `Draw3.StrokeGeometry.cpp` 的几何生成都调用它，删掉写死的常量。橡皮的非圆形状已经是共用 `ResolveEraserHalfSize`，不用动。

已有文档的影响：足迹是否写入文件需要实现时确认。若只在运行时计算，重新打开文档后自然用新尺寸；若持久化，需要在加载时重算粗荧光笔的足迹。

验收：粗荧光笔（直径大于 50 像素）画对角线后撤回，无残留；重做后无加深；无窗口用例断言足迹覆盖几何范围。

### 9.3 抬笔写入 L2

现在：L0（或 L1 加 L0）合成进 L2，范围是整笔外接矩形，一次绘制。

改为：范围用笔画区域（§9.1），按“上屏合成”参数规整后逐矩形合成。区域外 L0、L1 里没有这一笔的内容，所以结果相同。

随后清 L0、L1 时，写入登记里记的也是分段矩形（登记容量 8，超出时现有逻辑合并），面积之和小了，更容易走局部清除而不是整屏清除。

前像拷贝（`CapturePreimage`）已经是按瓦片的，不变。

### 9.4 撤回与重做

- 恢复前像时逐瓦片写回 L2，现在把各瓦片的屏幕矩形并成一个外接矩形返回。改为返回 `DirtyRegion`（瓦片合并后的矩形）。
- 重做把笔画画进 L0 再单层合成进 L2，范围同 §9.3。
- 画布命令处理函数的输出参数由 `RECT&` 改为 `DirtyRegion&`（§5.1）。
- 翻页、清屏等整屏命令不变。

## 10. E2、E3 与落点印记

抬笔走整笔重画的三个来源（见 `research/dirty-stats.md`）：抬笔时还有别的接触；多指时不是第一个落下的接触；起笔第一帧只有一个点。E1 让整笔重画本身便宜下来，本节减少它发生的次数。

### 10.1 按接触记录写入区域 **[议]**

每个运行时笔画增加一个 `DirtyRegion l1Region`，每次往 L1 提交时把写入矩形 `Add` 进去。重建前缀时重置为重画的范围。

### 10.2 尾段路径的新判据

现在的判据有两处按“整层”判断：路径选择要求除激光外只有一个运行时；前缀精确要求起笔或重画时 L1 整层为空，并且 L1 自那以后没有被清过或被别的内容写过（按层的世代号）。

改为按区域判断。一笔可以走尾段路径，当且仅当：

1. 它自己的前缀与定稿点列逐点一致（现有的点列指纹，不变）。
2. 它的 `l1Region` 与其他所有在 L1 里有内容的接触的 `l1Region` 都不相交。
3. L1 里没有来历不明的内容：渲染器的写入登记没有“未知写入”标记，也没有非接触来源留下的内容（历史直接回放的残留等）。实现上给 L1 增加一个“非接触写入”计数，起笔时记下，抬笔时比较。
4. 它的 `l1Region` 范围内自起笔以来没有被清除过。现有的层世代号是整层的；改为清除时由控制器检查被清的矩形与哪些接触的 `l1Region` 相交，只把相交的接触标为不精确。

满足时的流程：尾段画进 L0；在这一笔的区域内把 L1 与 L0 一次并入 L2；只清这一笔的区域。其他接触的前缀不动，不触发共享层重建，只照常刷新 L0。

不满足时走现有路径 B，行为不变。

这同时覆盖了 E3：仅观察的手掌接触、已取消的接触在 L1 里没有内容，区域为空，不会与任何人相交。

风险：这是抬笔路径里最精细的部分，阶段 B 刚整理过。放在实施顺序的最后，并且只在前面各项稳定后做。

### 10.3 落点印记

起笔第一帧只有一个真实点时，橡皮画的是“单点印记”。改为：圆形橡皮的单点画成以该点为圆心、半径为该点半径的圆（两个相同的点构成的零长度线段；顶点着色器对零长度线段已有默认方向，画出来就是圆）。

论证：整笔重放的第一条线段是胶囊(p0, p1)，它的覆盖率在每个像素都不小于圆(p0)的覆盖率（到线段的距离不大于到端点的距离）。层内取最大、取最小，所以“先画圆再画后续线段”与“只画线段”结果相同。这样单点印记不再破坏前缀的精确性。

只有一个点就抬笔的橡皮（单击）：定稿后的整笔重放画什么需要实现时核对，保证单击橡皮仍然可见、且与重放一致。

普通笔的单点印记影响点击出墨的外观，C1 不动。非圆形橡皮的单点同理可以画成该形状本身，随矩形橡皮一起处理。

## 11. 激光与粒子的来源细化 **[待测]**

## 17. 风险

- **抬笔路径**（第 8 步）：判据从整层改为区域，漏判会让别的接触的内容被提前并入 L2。对策：区域相交判断保守（矩形级），任何不确定都退回路径 B；像素一致性用例覆盖。
- **着色器改动**（第 2、7 步）：Win7 保护版与生产版必须同步；WARP 上顶点着色器按横条展开的性能未知，需要实测。
- **叠加物不重画**（第 3 步）：依赖 backbuffer 在帧区域之外保持上一帧内容。设备恢复、尺寸变化、整帧呈现之后的第一帧必须全部重画；这些路径现在都走 `forceFullPresent`，需要逐条确认。
- **ULW 多次调用更慢**：若内部开销与整窗相关，多步提交会比单次慢。对策：选项可关；参数保守（最多 4 次）；有数据后再调。
- **区域过多**：容量 16，满了合并，最坏退化为现状的单矩形，不会比现在差。

## 19. 实施期间对设计的修正（第 5–8 步，2026-11-24）

前面各节保留原文。以下是实施时与原文不同的地方，以本节为准；细节与验证见 `implement.md`。

### 19.1 L2 侧的多区域（对 §9）

- 足迹与绘制不一致的不止荧光笔：单点笔画实际画成向右伸出 `max(0.25, r×0.05)` 的短胶囊，足迹原先没有算。已一并补上，栅格脏矩形也包含这段。
- 写入 L2 的运算不幂等，多矩形合成必须两两不相交，区域一律先规整再用。
- §9.3 的“清除登记也记分段矩形”没有做。
- 图形（含旧式线段、矩形）仍按整笔外接矩形合成，它们的足迹与圆角处的实际绘制是否一致没有证明。
- 荧光笔的“近重合点去重”一律按局部坐标判断，书写、整笔重放、分瓦片重放三处一致。

### 19.2 矩形橡皮的 E1（对 §8.4）

没有沿用圆形橡皮的横条方案。矩形橡皮每段的图元本来就是“扫掠凸包的外接矩形外扩 2 像素”，前一段的凸包完整包含本段起点处的矩形，所以在“起点矩形内缩 2 像素”的范围内不画，把图元拆成围着这个洞的上、下、左、右四条边带，接缝重叠 1 像素。启用条件：一批至少 3 个点、最大半边长不小于 24 像素；逐段条件：不是本次上传的第一段、起点半宽半高各不小于 6。

### 19.3 激光与粒子（对 §11）

没有先取数，按保守粒度实现：

- 帧区域只在这几种帧折叠成单矩形：平移快照、清空碎裂、有未烘干的激光层要合成、点击光波可见。激光轨迹处于留存或淡出、笔尖可见、粒子在画时不再折叠。
- 已烘干轨迹的合成按帧区域的矩形逐个调用。淡出等动画的脏区按每条已烘干笔画各一个矩形。
- 没有按点列给长笔画分段，也没有按批次给粒子矩形。

### 19.4 E2、E3 与落点印记（对 §10）

- **观察接触（E3）**：没有提升的手掌观察接触不计入接触数。已取消的接触只有在从未画过任何内容时才不计入；画过内容的取消接触仍然计入，因为它的像素还留在共享层里。
- **落点印记**：§10.3 的“先画圆再画线段等于只画线段”在抗锯齿带上不成立（圆与胶囊的抗锯齿宽度不同）。改为：第一帧画圆作为暂存印记；下一批到来时，如果这一笔独占 L1，就先清掉印记、从第一个点开始按真实线段重画，前缀从此精确。不独占时保持不精确，抬笔走路径 B。只有一个点就抬笔的仍走路径 B，最终画面与原来相同（抬笔前的圆比最终的点在右侧短 `max(0.25, r×0.05)` 像素）。
- **按区域判断（E2）**的判据定为：
  1. L1 里的内容全部来自接触的前缀。渲染器记一个“归属世代”：L1 被清空时记下当时的世代号；之后只有“声明了范围的绑定”（只用于接触前缀）不改变世代号，其余任何写入都会改变。世代号等于归属世代，就说明 L1 里没有来历不明的内容。
  2. 每个接触记录自己往 L1 写过的矩形（`l1WriteRegion`）。任何一次写入失败就标为未知，不再参与。
  3. 抬起的这一笔，它在 L1 的矩形、尾段矩形、合成区域的矩形各外扩 4 像素后，与其他每个接触在 L1 的矩形都不相交。
  4. 显卡支持按矩形清除（`ClearView`）；没有活动的图形预览、焦点层、构造预览；本帧没有提交失败。
  满足时：尾段画进 L0，在这一笔的足迹区域内把 L1 与 L0 并入 L2，只清这一笔在 L1 的矩形（不改变世代号），不触发共享层重建，只重画其余接触的尾段。不满足时走路径 B 并重建，与原来相同。
- 前缀“精确”的条件相应放宽：起笔或重画时 L1 非空也可以，只要当时 L1 的内容全部来自接触；这样的前缀只有在上面的判据成立时才允许走尾段路径。
- 总开关 `kRegionalTailPathEnabled`（`Draw3.DrawingController.cpp`，默认开）关掉后回到改动前的判断。
- 没有做的：§10.2 第 4 点“清除时只把相交的接触标为不精确”。现在任何整层清除或来历不明的写入仍然让所有前缀不精确（世代号变化），只有按矩形清除不影响别人。
