# Research: 笔速橡皮大屏历史标定与证据边界

- Query：早期笔速橡皮有哪些大屏/Surface 数据和产品决策，可给白板惯性适配提供什么依据？
- Scope：internal；历史 Trellis 记录、CSV、开发日志、当前生产源码；只读检索历史，不执行 Git、编译或 GUI。
- Date：2026-11-13
- 路径基准：仓库 `D:/Project/Inkeys/Repo/Inkeys`。下文 `file:line` 均相对该根目录；本文件仅记录研究，不批准实现或新参数。

## Findings

### 1. 结论与置信度

1. **存在有来源的大屏真实诊断数据**：教室触摸屏约 139×78 cm、1920×1080、144 DPI；Surface 约 28×19 cm、2880×1920、192 DPI。原始数据在历史记录中被明确标为约 250 ms 的稀疏诊断快照，不能当作完整轨迹、硬件采样率或精确人手速度实测。
2. **大屏行为分类来自用户，曲线数值来自代码和合成控制器**：用户将教室约 270–432 mm/s 的那一段读数对应动作称为普通擦除，认为旧目标 160 DIP 过大，期望在 B 附近。后续设计用连续尺寸先验提高大屏清扫门槛，合成回放证明普通区约为 32–33.1 DIP。不能写成“新大屏手感已经实机验收”。
3. **当前生产仍采用该场景策略**：Touch 物理路径的长边节点为 320/1200 mm，fine/enter/exit/large 为 `30 / (90+260w) / (60+190w) / (250+1050w)` mm/s；小屏端点 `30/90/60/250`，大屏端点 `30/350/250/1300`。已直接核对当前 `Draw3.SpeedEraser.cpp:336–365`。
4. **Mouse、外置板和屏幕笔没有被合并为同一种物理响应**：当前间接模型始终用映射后的系统 DIP；屏幕笔有自己的测速阈值和仅标准以上增量的 beta 补偿，Touch 则不再把整个目标直径做物理补偿。三者不能套用一套“屏越大增益越大”。
5. **早期“合理”数据可作场景先验和验收素材，不能直接变成惯性参数**：橡皮测累计路程以保持往返擦除大小，惯性要保持可靠释放方向和尾段速度；橡皮的清扫阈值、面积下限和证据时间不能直接搬去惯性。

置信度：当前行为为源码直接确认；历史设备数据为当时研究文档对用户上传日志的记录，未在本轮重新获取完整原始文件；数值曲线为历史已保存 CSV/自动化结果；教室新曲线的主观最佳手感仍无现场验收证据。

### 4. 场景修正的原因和仍在使用的策略

#### 4.1 当时的确定缺口

2026-09-23 之前，DirectTouch 在可信物理路径不论 Laptop/LargeScreen 都固定 `30/90/60/250 mm/s`；LargeScreen 仅影响无可信尺寸的经验回退。于是教室普通动作 270–432 mm/s 已高于 250 mm/s 大目标阈值，160 DIP 目标从公式即可解释。不能未经证据归因输入噪声或面积辅助（该段面积已关闭）。来源：`research/touch-profile-20260923.md:6–14`、`validation-touch-profile-20260923.md:7`。

#### 4.2 长边和显式交互模式是不同概念

当前物理/手动标尺先得到表面长边 `L=max(mmX×pixelWidth,mmY×pixelHeight)`，再计算：

```text
x = clamp((L−320)/880, 0, 1)
w_size = x²(3−2x)
Laptop      -> w = min(w_size, .25)
LargeScreen -> w = max(w_size, .25)
Automatic   -> w = w_size  （内部解析枚举）
fine=30; enter=90+260w; exit=60+190w; large=250+1050w  [mm/s]
```

- 320/1200 mm 和 .25 是有界经验先验，不是人体工学常数；尺寸不被当作用户动作长度。
- 已保存的 `paintDevice` 0/1 场景选择不能被 EDID 覆盖。产品 Host 当前仍将 0 传为 LargeScreen，其余传为 Laptop，正式 UI 没有因为内部 Automatic 枚举而自动增加第三项（当前 `Draw3.Host.cpp:1836–1837`，历史 `design.md:31–37`）。
- 权重只决定 DirectTouch 物理路径清扫门槛；每轴物理换算来自实际标尺，而不是通过 w 乘“更大的物理速度”。
- 当前生产对应代码 `Draw3.SpeedEraser.cpp:11–24, 336–365`。同源码 `:377` 明确间接设备不因大屏选项或 EDID 改为物理测速。

这些中间屏是合成明确宽高夹具，不能声称真实 20–32 英寸设备已确认最佳。

#### 4.3 数据怎样约束“普通”和“清扫”

合成 139×78 cm、1920×1080、144 DPI、B=32、中灵敏度、面积关闭、3 秒局部圆弧，不是用户日志逐点重放。`research/touch-scene-curve-20260923.csv:2–12` 保存：

| 速度 mm/s | 参考目标 DIP | 控制器最终实际 DIP |
| ---: | ---: | ---: |
| 100 / 200 / 270 / 300 / 322 | 32 | 32 |
| 400 | 32.4157 | 32.4156 |
| 432.376 | 33.1135 | 33.1135 |

这组数值证明：正常动作不会仅因持续久而“充满”到最大；中间清扫强度仍可达；持续强动作能够接近上限。它并不证明惯性应在 432 mm/s 停多久、滑多远，也不能把 1300 mm/s 直接当惯性上限。

### 5. 时间响应与后续修正的资料

- 用户 2026-09-25 反馈 Touch 和屏幕笔短时间快动过早变大，Mouse 正常，教室新曲线尚未实测。来源 `research/warm-burst-growth-20260925.md:5`。当时不是仅按“设备尺寸”归因，而是将短脉冲证据/动态跟随独立处理，保留曲线和 Mouse。
- 合成 Surface 暖状态：先 `0.6×enter` 移动 2 s 达 B=32、证据清零，强快段 Mouse=2850 DIP/s、ScreenPen=525 mm/s、SmallTouch=375 mm/s。这是各模型的相对激励，不能相互视为同一个真人动作（同文件 `:9`）。
- 100/150/200 ms 后：旧 Touch=43.0987/58.4983/80.3089 DIP，旧 ScreenPen=32.2693/37.1074/45.3882；修正后分别为 32/32.8963/37.957 与 32/33.0491/38.0394。Mouse 保持 32/32.0119/32.8015。500/1000 ms 修正后 Touch≈108.05/155.941、ScreenPen≈112.005/157.386（同文件 `:13–17`）。
- 当前仍是 Touch `evidence start/full/decay=.080/.180/.300 s`、growth tau `.220/.180 s`，ScreenPen `.080/.200/.350 s`、tau `.200/.160 s`（当前源码 `Draw3.SpeedEraser.cpp:321–375`）。这些是泄漏积分和允许尺寸，不是简单固定延迟，不能搬成 fling 的启动等待。
- 2026-09-27 从 160 DIP 用 40 ms 快/120 ms 普通的低占空比循环，旧实现会长期不缩；修正后 Touch 约 3 s 回到32、Pen约2 s回32。80/80 与100/80 高占空比仍可维持中大尺寸。来源 `validation-hold-recoil-20260927.md:7–15`，合成输入/帧独立时钟，不是实机轨迹。
- Surface 主要 Mouse/Touch 体验获认可和面积恢复问题定位见历史 `prd.md:50–52`；最终用户验收范围以 `validation-canary-handoff-20260927.md:3–9` 为准，教室仍待实测。

### 6. 不能混淆的旧版本、单位和设备

1. **最早 OC 参数已失效**：迁入的 `08-15-speed-eraser-oc/prd.md:9–17` 用 20/50/200 px、64 ms 累计路程和0.75/3/24 DIP阈值；这是历史任务材料，不能代替当前生产 24/32/40 DIP 基础预设以及每个 B 的 .5B/B/5B 范围。当前 `ResolveSizes` 在 `Draw3.SpeedEraser.cpp:55–59`。
2. **某些更早验证也是旧参数**：`validation-dip-idle.md:34` 的大屏 650/450/1700 DIP/s 与可信 Touch 25/18/70 cm/s，不是当前大屏物理四阈值。当前应依源码和2026-09-23之后的场景合同。
3. **DIP尺寸与物理测速分开**：Touch仍输出DIP直径，不按 rho 对整个目标补偿。屏幕笔只对标准以上增量用 `g=clamp((.25/rho)^beta,.25,4)`，默认 beta=.5；物理信息不是把整支橡皮改成固定毫米。当前 `Draw3.SpeedEraser.cpp:484–495`。
4. **外置数位板隔离**：当前来源识别对系统报告Integrated但不映射显示器的匹配Pen，降为ExternalPen；非直接来源保持IndirectDip。当前 `Draw3.SpeedEraser.cpp:84–113, 248–269, 377`。不把屏幕EDID当作外置板真实行程标尺。手动ScreenPen响应也不伪造来源或映射，历史合同 `validation-entry-sessions-20260915.md:58–62`。
5. **无可信物理尺寸时并非全都纯DIP同参数**：Touch Laptop/Automatic保持 `100/240/160/700 DIP/s`；LargeScreen且逻辑输出已知走 `100/120/80/400 reference DIP/s` 的经验路径；增益来自逻辑宽高相对1920×1080，`gain=1/clamp(min(longDip/1920,shortDip/1080),.5,4)`。当前 `Draw3.SpeedEraser.cpp:186–194, 303–313, 357–365`。这不是估算出毫米，也不能给惯性入口和出口不对称乘增益。
6. **面积是几何辅助资料**：Surface记录的60.413 DIP下限不是运动速度或屏幕物理尺寸，不能用来调惯性速度。面积开关/锁存/恢复属于橡皮安全行为。

### 7. 给白板惯性规划的可借鉴原则（建议，未批准）

- 后续用户澄清（本任务 R9）：当前 Surface Pro 11 Touch 仅表示快速连续滑动的衔接/抵消已正常，不表示旧距离/时长最佳。下述“基准机”建议应按该正确性参考理解；不得据历史或旧候选要求精确复刻 Surface 参数。
- 先分离“实际设备关系”“可信动作单位”“使用场景/手感参数”。显示尺度事实可以共享，橡皮响应曲线独立；产品 `paintDevice` 和尺寸各提供什么影响须本轮评审，不能由旧任务自动决定。
- 保留当前连续手势的正确性，把体验结果与真实输出的可信 mm/px、系统 DIP/px、输入来源、所选模式一起保存为开发验证证据；距离和时长可按新目标调整。不能直接用过去 Surface 的元数据代替当前测量，也不自动把 .25 mm/DIP 当当前硬件事实。
- 大屏“普通动作”的速度通常与小屏不同，是历史实际问题提供的方向性证据；适配应在普通定位、明确快甩和反向制动间连续过渡。320/1200 mm 可作首版候选范围，不能声称已验证是惯性最佳节点。
- 不以屏幕长边比例直接放大释放速度；可信每轴物理换算应保持拖动几何1:1、释放方向正确。场景参数可选择摩擦/时长，但参数必须在一条fling内锁存，避免滑行中切档跳变。
- 当前惯性使用可靠尾段位移拟合估速，应保留其防抖、反向和Up年龄保护。橡皮为往返擦除累计路程，惯性不能因此丢失方向，亦不能沿用橡皮40/50/80/140ms所有窗口。
- EDID缺失/复制拓扑/映射不明时清楚标为DPI/DIP回退，继续保证有限值和可控上限；旧橡皮的分辨率经验动作单位只能作为候选研究，不等于已经适合平移。
- 验收要分别保存三种证据：纯公式/单位矩阵；确定性生产内核合成回放；标注动作的真人小屏/大屏体验。普通速度、短促快划、持续快甩和反向停止要各有标签，不能从250ms稀疏快照推断完整感受。
