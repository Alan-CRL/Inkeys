## Findings

### 1. 结论

proposal-v1在正数有限输入、统一动作单位和最终模长cap生效的前提下，没有发现单条自由滑行的公式或参数界错误。参数始终正，速度无过冲，Touch在同初速下不比基线短，ScreenPen在同初速下比Touch短；单条自由滑行的距离/时长增幅≤40%（可信物理）/≤20%（DIP回退）可作解析证明，甚至不依赖有限网格采样。

**必须收窄的声明：**40%/20%不是相同多次手势序列的整体距离或每次尾滑上界，因为较慢衰减还会留下更多可继承残余；“低速精确”也不能自动覆盖仍通过boost门的轻放接力。脚本不是booster/输入状态机仿真，更不是硬件最佳手感证明。

**必须补齐的证据：**脚本的“All proposed cap endpoints”只列三项，缺ScreenPenFallback。独立计算确认漏项仍通过，但在覆盖陈述中应补入该项或明确现有三项代表范围。若“All”还包含间接输入，也应列出保留基线。

### 2. 参数与单位

| Profile | 选参 | τ秒 / c动作单位每秒² | 最终速度cap |
|---|---|---|---|
| Touch物理 | a=w·S((h−600)/900)，h为boost前可靠手速mm/s | .30+.12a / 200(1−.25a) | 2400mm/s |
| ScreenPen物理 | 固定 | .20 / 350 | 1800mm/s |
| Touch DIP回退 | 大屏a=.5·S((h·G−750)/1500)，桌面a=0；h为系统DIP/s | .30+.12a / 1000(1−.25a) | 12000系统DIP/s |
| ScreenPen DIP回退 | 固定 | .20 / 1750 | 9000系统DIP/s |

S为clamp到0…1后的smoothstep。Touch物理w由320…1200mm长边先验并以Laptop≤.25/LargeScreen≥.25约束，所以a∈[0,1]；DIP回退a∈[0,.5]。G∈[.25,2]只改变动作意图分类，不能乘手指按住时的几何、真实释放初速、最终位移或冒充mm/px。

每次释放按h选定τ/c，再从旧动画当前残余正投影得到effective v₀并夹对应profile cap；整条fling锁存参数。这里的h与v₀是不同变量，不能把boost后的v₀重新送回选参。

### 3. 解析公式与正性

令s为统一动作度量中的速度模长，q(s)=s/τ+c，τ>0、c>0。自由滑行满足：

- ds/dt=−q(s)，直到s=0；方向始终为本次有效释放方向。
- T=τ·ln(1+v₀/(cτ))。
- D=τv₀−cτ·T。
- 等价积分：T=∫₀ᵛ⁰ ds/q(s)，D=∫₀ᵛ⁰ s·ds/q(s)。

T、D均为有限非负数；v₀>0时为正。随v₀严格增加；τ越大或c越小，q逐点越小，T、D越大。屏幕笔τ=.20小于Touch最小.30，c=350大于Touch最大200（回退1750大于1000），因此同一正v₀下两项都严格更短。

已用独立Simpson积分（20000分段，积分1/q与s/q）对四种cap端点及100mm/s基准复核闭式解：最大距离差约6×10⁻¹¹动作单位，最大时长差约2×10⁻¹³秒。此为数值公式交叉检查，不经过产品控制器或硬件。

### 4. 40%/20%上界的解析证明及正确适用范围

令τ₀=.30，c₀为200或1000，r=τ/τ₀=1+.4a。两种Touch参数均有：

`(cτ)/(c₀τ₀)=(1−.25a)(1+.4a)=1+.15a−.10a²≥1`（0≤a≤1）。

于是对所有s≥0：

`q₀(s)/r ≤ q(s) ≤ q₀(s)`。

在同一个effective v₀积分，得到：

`T₀ ≤ T ≤ rT₀`，`D₀ ≤ D ≤ rD₀`。

物理a≤1→r≤1.4；回退a≤.5→r≤1.2。这个证明允许h和v₀不同，包含合法boost后的v₀；也不依赖w、G具体怎样选，只要a位于合法范围。cap限制使最大端点也有界。

**它只比较“同单位、同effective v₀的一条未被输入或边界中断的自由尾滑”。**不涵盖：

- 相同手指轨迹经不同旧残余得到不同v₀的比较。
- 从Down到最终停住的全手势距离，或多次接力的总距离/总时长。
- 保持中的1:1拖动、release gate/boost gate切换、多指拓扑、世界限位及停机事件。
- 不同物理可信状态间的毫米比较，或实际呈现/输入排队延迟。

### 5. 单调性与连续性的边界

在固定模式、有效w/G、相同输入单位，且不把booster资格切换混入公式时：

- h增加时a连续不减；w增加时a连续不减；τ不减、c不增。
- 若v₀=h或v₀固定，则D/T随h连续不减；w也是如此。固定方向/固定残余、booster资格已保持时，v₀=min(cap,h+残余)也不减。
- cap的饱和只形成平段，不造成模长跳变。
- smoothstep在快甩起止端无参数跳变，但Laptop/大屏的min/max约束可在w=.25处形成导数折点；参数值仍连续，不能宣称处处C1。
- 显式切换模式、设备或可信物理↔DIP是离散上下文切换，不具有跨profile连续性保证，必须按安全合同结束旧手势并清除旧单位残余。
- 既有最小释放和boost资格是离散门；脚本的连续性/单调性检查没有执行这些门，不能宣称完整手势状态机在阈值处也连续。

### 6. 连续同向与真实反向

当前booster规则核实：先检查同来源/窗口、起始方向同向、当前残余与新释放分别过最低速度门，然后沿新方向u只取`max(0,v_residual·u)`；`v₀=min(cap, h+该投影)`。输出向量完全沿新方向，没有旧横向分量（CanvasNavigation.cpp:461–484）。ScrollUpdate逆向或确认反向、取消、source变更等路径清booster（486–526、724–750）。

因此在单位一致、有效上下文隔离、真正用当前残余而非历史初速的前提下，不会因相加把新同向释放抵消，也不会把反向手势改回旧方向。新参数本身不破坏这些向量性质。不同尺度或设备profile切换时必须清旧残余，不能只给新的手速换单位后继续投影旧值。

**相同手势序列并不受单条同v₀倍率约束。**以下是两次同向释放的理想代数反例：旧fling在Δ秒处被下一次Down打断，随后在正常boost窗口内有足够Move并释放；同来源、方向和速度资格均假设成立。不是C++状态机重放。

| 比较 | 手速h / 下一Down时Δ | 第二次effective v₀ 基准→增强 | 第二条D比 / T比 |
|---|---|---|---|
| 物理Touch w=1 vs w=0 | 1500mm/s / .20s | 2240.930706→2400mm/s（增强碰cap） | 1.501715 / 1.407400 |
| 回退大屏最大增强 vs桌面 | 2250DIP/s、G=1 / .40s | 2622.172702→2779.380014DIP/s | 1.274499 / 1.204465 |

用`v_residual=max(0,(v_old+cτ)exp(−Δ/τ)−cτ)`独立计算。差异来源是残余不同，未违反第4节的同v₀证明。多次接力还可进一步积累直至cap；单次尾滑虽有cap，总交互会话可由用户继续任意久。

不建议为了让一个错误的“序列≤40%”声明成立而静默削掉既有同向接力；应将它作为独立验收场景，保留用户已确认的衔接正确性。

### 7. 低速精确目标还需要哪些限制

物理Touch h≤600mm/s时a=0，大屏不额外放长；回退大屏hG≤750时a=0。这个事实只证明没有额外场景增益，**不等于已有基准尾滑一定足够精确**。

无boost的解析例子：

| 可靠释放速度 | Touch基础 D / T | ScreenPen D / T |
|---:|---:|---:|
| 6mm/s | .0844mm / .0286s | .0487mm / .0164s |
| 30mm/s | 1.7016mm / .1216s | 1.0066mm / .0713s |
| 100mm/s | 12.3451mm / .2942s | 7.5778mm / .1775s |
| 300mm/s | 57.7483mm / .5375s | 36.6899mm / .3330s |
| 500mm/s | 109.7953mm / .6701s | 70.6400mm / .4194s |

这些速度必须先通过实际最小释放门才能启动；第一行只是公式示例，不能推断当前/未来一定放行。

如果h虽较低但仍过boost门，继承很大同向残余后v₀可很高：按boost前h选参数避免“boost令自身变快甩档”，但不会主动把继承残余去掉。需在方案/验收中区分：独立慢拖轻放、故意继续同向漫游、主动减速结束接力、以及反向定位。若用户希望轻放无条件取消很大的旧残余，那是新增booster产品规则，不可仅凭本数学审查改掉现有接力。

回退G范围还意味着大屏快甩意图起点为750/G=375…3000DIP/s、饱和点为2250/G=1125…9000DIP/s，相差8倍；虽然它不改变几何或初速，仍需现场检验分类是否合适。

### 8. cap与理论停止时长

| Profile端点 | 最终v₀ / τ / c | 理论自由距离 | 理论停止时间 |
|---|---|---:|---:|
| Touch物理最大增强 | 2400mm/s / .42 / 150 | 910.997622mm | 1.539720s |
| ScreenPen物理 | 1800mm/s / .20 / 350 | 314.007221mm | .657040s |
| Touch DIP回退最大增强 | 12000DIP/s / .36 / 875 | 3904.275524DIP | 1.319760s |
| ScreenPen DIP回退（脚本漏项，独立补算） | 9000DIP/s / .20 / 1750 | 1570.036107DIP | .657040s |
| 保留间接基线（如“All”含此项） | 12000DIP/s / .30 / 1000 | 3265.778514DIP | 1.114072s |

所有端点均<1.6秒。因为T随v₀、τ增而增，随c增而减，各profile合法范围内其余组合不会超过表中上界。

这一结论必须由**boost后、曲线Start前的最终向量模长cap**支撑；只限制原始估速而忘记booster加法后的cap不够。当前生产booster固定12000DIP/s，未来参数化时必须把profile cap接到最终加法，不仅改tracker的上限。脚本`friction`本身不实施clamp，它只计算传入v₀，所以PASS不能充当已验证产品限速的证据。

<1.6秒从数学曲线起点计时，不含释放排队、线程/呈现卡顿、最后一帧迟到等；当前产品从消费帧起步，也不是从真实Up追补队列时间。不要对真实屏幕消失时刻作严格1.6秒墙钟保证。

### 9. 规划中必须修正/明确的项目

1. 对40%/20%统一写成“相同最终有效初速、同单位的单条自由尾滑相对相同单位基线”，不要延伸到相同连续手势轨迹。
2. 补ScreenPenFallback cap离线证据（或缩小“All”声明），并保持boost后最终cap、有限正参数及单位一致为执行/测试合同。
3. “大屏慢拖轻放精准”分为独立轻放与接力上下文；已存在的boost门仍要保留并按新单位验证，不以公式中的a=0证明所有慢放尾滑短。
4. 连续同向、反向、急转、多指末指释放、DPI/显示可信状态改变与source/profile变化必须另做真实控制器回放；脚本没有检验这些行为，不能扩大PASS含义。
5. 1.6秒写为理论单次自由曲线停时上界；不作帧完成/整段会话墙钟上界。

以上主要是证据和验收措辞修正，不发现必须立即重选τ/c数值的数学错误。参数是首版候选，不需要本轮凭直觉再堆另一套曲线。

## 首版硬件校准边界

- Surface Pro 11当前已认可的同向接力/反向/中断正确性必须回归；约28×19cm是历史/用户描述，不替代本轮可信EDID快照。
- 至少区分小型可信触屏和真实教室大屏、屏幕笔及匹配的PenTail（仅当开关已开启）、间接鼠标/板；不自动打开默认关闭的惯性类别。
- 需观察慢拖轻放误差、普通漫游、明确快甩停止位置、同向多次接力、主动减速终止、短反向和快速急转。0.911m最大理论Touch行程、屏幕笔100mm/s仍7.58mm尾滑都应由实际任务裁决舒适性，而不是凭“更短/有界”批准体验。
- 比较可信物理/无物理DIP回退、两种显式模式、常见DPI和分辨率，核查按住后1:1与真实输出方向；不承诺回退下真实毫米一致。
- 320…1200mm长边先验、600…1500mm/s快甩区间与回退750…2250/G都是需要校准的响应参数。橡皮已有数据可描述历史普通擦除动作，不能直接证明这些白板fling区间适用。
- 只读数学评审不能给“所有设备最合适”结论；后续执行经规划批准后，先纯解析/控制器无窗口回归，再按用户授权进行硬件体验验证。未获GUI授权不自行启动。
