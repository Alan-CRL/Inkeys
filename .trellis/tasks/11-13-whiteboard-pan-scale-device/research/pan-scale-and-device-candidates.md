## 2. 尺度问题的独立代数对照

令 `rho=mm/DIP`，相同实际释放手速 `v_mm`、无 boost、未碰世界硬限位：

```text
s = v_mm / rho
T = .30 * log1p(s / 300)
D_mm = (.30*s - 300*T) * rho
slop_mm = 15*rho
```

使用当前公式独立复算，完整数据见 `pan-unit-analysis.json`。这不是 C++ 运行测试，也不是用户当前电脑测量。前两行是说明性尺寸；第三行仅借用历史教室橡皮日志的显示事实，500 mm/s 是假设的平移速度。

| 横向显示事实 | mm/DIP | 500 mm/s 释放的滑行距离 | 停止时间 | 当前 15 DIP 起步距离 |
| --- | ---: | ---: | ---: | ---: |
| 320 mm / 1920 px / 96 DPI（示例） | .166667 | 114.03 mm | .719 s | 2.50 mm |
| 600 mm / 3840 px / 144 DPI（示例） | .234375 | 105.85 mm | .628 s | 3.52 mm |
| 1390 mm / 1920 px / 144 DPI（历史教室横轴） | 1.085938 | 59.10 mm | .279 s | 16.29 mm |

直接结论：当前用 DIP 既影响尾滑，也影响开始拖动所需的真实距离、反向证据和最低释放速度。只给最后距离乘倍率无法修复整条动作。物理一致也不等于同样覆盖屏幕：114 mm 在 320 mm 宽屏上占 35.6%，在 1390 mm 宽屏上仅占 8.2%。是否让大屏快速漫游更远是独立于单位换算的产品取舍；用户后续已选择明确快甩有界延长（R7）。

## 3. 推荐分层，待产品决策

### 3.1 显示事实 → 动作度量 → 响应参数

1. **显示事实**：复用已有 Display 快照和真实 InputSource 映射，取得每轴 DIP/px、可用的 mm/px、输出身份、旋转及失效原因。不要把橡皮灵敏度、面积或开发 override 当成屏幕事实。
2. **动作度量**：可信的直接 Touch / 屏幕 Pen 可用物理参考单位；Mouse / 外置板等间接输入继续系统 DIP。不可信来源明确回退 DIP。
3. **响应参数**：同一可靠估速和向量摩擦内核，只给有限参数。设备决定精细定位/漫游偏好；桌面/大屏模式与可信长边决定直接输入的场景响应。不能让模式修改真实 mm/px。

体验矩阵（设备分工、大屏响应目标和直接输入整段适配范围已确认；模式过渡、回退和数值参数仍待规划）：

| 来源 | 可信动作度量候选 | 响应目标候选 | 说明 |
| --- | --- | --- | --- |
| 直接 Touch | mm / 固定参考运动单位 | 慢拖定位，明确快甩用于漫游；大屏快甩增加有界续滑 | 保留 1:1 跟手；不放大初始释放速度。 |
| 映射可信的屏幕 Pen | mm / 固定参考运动单位 | 以精准定位为主，尾滑短于 Touch | 不能沿旧草案删除已有笔平移；短尾目标已确认，数值待规划。 |
| PenTail | 跟随实际笔来源判定 | 若用户开启惯性，可先沿同支笔的响应 | 默认关闭保持；“尾部”是入口身份，不说明它是直接屏幕笔。 |
| Mouse | 系统 DIP | 开启惯性时保持现有间接输入基准 | 默认关闭保持；OS 指针速度/加速度已在像素输入中；没有用户认定它最优的证据。 |
| 外置数位板 Pen / 无法证实直接映射的来源 | 系统 DIP | 作为间接输入单独评估，先保守基准 | 屏幕 EDID 不能代表数位板表面的手速。 |
| Touchpad | 延期 | 本任务不实现 | 继续 quarantine；不能把现有数值测试当实际输入支持。 |

### 3.2 物理度量与正确性回归参考（按 R9 修订）

用户明确说明：当前参考是 Surface Pro 11、约 28×19 cm 的 Laptop 场景直接 Touch。认可的是快速多次滑动时此前不合理的惯性抵消已改善，当前较正常；不是认可当前距离/时长最优，更不是其它设备的最佳参数证明。

因此原先“测得本机 rho，再归一参数以精确复制旧曲线”的建议不再作为设计要求。需要保留的是实际事件次序、可靠尾段方向、当前残余投影、反向清旧残余、新 Down 中断和来源隔离这些正确性合同；距离、停止时长、物理摩擦参数与空间门槛可以重新设计。Surface 可作为真人体验验证设备之一，不作为所有设备的体验上限或自动标定模板。

可信直接输入优先以真实毫米描述设计参数。实现可直接在 mm 域运行，或定义固定 `r0=mm/U` 使用数值等价的参考域；r0 此时只是内部单位约定，必须同步换算参数，不具有“保留 Surface 旧数值”的产品意义。

```text
x_mm_i = x_px_i * m_i
x_U_i = x_mm_i / r0                 // 若实现选择 U 域
velocity_px_i = velocity_U_i * r0 / m_i
velocity_DIP_i = velocity_px_i * d_i
```

其中 `d_i=DIP/px`、`m_i=mm/px` 分轴保留。统一度量中计算范数、尾段资格、反向、boost、限速和摩擦，最后按轴逆变换；直接拖动闭环保持 1:1，VelocityDip 等出口仍返回系统 DIP。

不能在每台设备首次运行时重新选一个基准来恢复旧 DIP 策略，也不能把任意 `.25` 或 `25.4/96` 说成硬件事实。当前约 28×19 cm 来自用户近似描述，显示 DPI、来源映射、实际业务物理可用性及保存模式仍应由只读证据核实；不凭历史 192 DPI 记录预填本次标定。物理标尺两轴不同时也不能静默取平均。

### 3.3 参数与状态边界

- 可调的少量参数优先是 `tau`、常量减速 `c`、设备专属最低释放/起步策略；不要重新引入多种曲线族。
- 不复制橡皮 90/350/1300 mm/s 等阈值。这些描述擦除尺寸意图；漫游手速的合理区间需要白板轨迹和用户目标决定。
- 旧草案 `tau +20% / c -20%` 没有实机依据；最终首版初值和数学界已另写 design.md，不以擦除数据或旧候选声称最佳。
- 时间窗口、回调 arrival QPC 的真实性限制、导航历史容量、排序、末段减速与反向保护保持；不得用调参掩盖输入信息限制。
- 范围已确认包含起步及反向判定（R8）：15/.05/.1、反向/末段 1、30/150/350/12000 和 c=1000 都须审查空间单位；不能只换算最终尾滑。时间窗口仍按秒保持，直接拖动正反变换仍须 1:1。
- 一次接触批次及其滑行锁存相同事实/度量/响应。显示输出、DPI、旋转或映射真实变化应取消旧运动、清旧残余并吞旧接触到终态；纯响应偏好变化可选择下次手势生效，待规划确定。
- 比较有效签名，不能按任何 snapshot revision 改变就 Stop：橡皮调试、别的显示器变化不应中断当前拖动。映射 generation 与显示 generation 异步时采取保守回退，不能拼接新旧事实冒充可信。
- 预取、tile、blur 继续消费各自的 px/s 或系统 DIP/s；页面/世界安全范围不随物理标尺改变。

## 4. 后续验证形状（未执行）

- 正确性回归：同向快速连续滑动不被旧残余错误抵消、真实反向不恢复旧方向速度、Down 立即停旧动画、跨来源/单位不继承 boost。Surface Pro 11 触摸重点覆盖用户曾遇到的场景；不要求新 profile 的停止距离/时间等于旧值。
- 同一物理轨迹/同 profile 在不同分辨率、100/150/200/300% 缩放、横竖屏、两轴不同密度下：物理门限及自由滑行一致；输出像素闭环与方向正确。
- 可信 / EDID 缺失 / 尺寸异常 / 复制 / 映射未知或冲突 / 外置板 / 失效后恢复；手势中切屏或改 DPI 无跳动、不跨域 boost。
- Mouse、Touch、屏幕笔、外置板、PenTail 的默认开关、模式切换、接管和同帧逆序仍正确。Touchpad 继续断言隔离。
- 所有当前 2240 场景的旧基线用于保护中性的 DIP 路径；有意的新 profile 必须使用新预期，不能要求新行为仍输出相同数值。
- 未来实现再按根 AGENTS.md 构建 `InkeysRepo.sln Debug|ARM64`，运行无窗口专项及完整回归；舒适性仍需要用户真机确认。本轮未运行编译/GUI。
