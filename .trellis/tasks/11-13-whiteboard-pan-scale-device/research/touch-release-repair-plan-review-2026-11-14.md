# 方案独立复审：Touch释放决策、短手势与组级交接

2026-11-14。仅审查方案，不改源码/测试/spec，不构建、GUI或commit。回归提交归属由主会话核查；本文不作Git历史结论。

## 1. 结论与最小位置

建议成立：**把Touch释放判断集中成一次纯值决策，保持原唯一运动曲线。** 先区分输入事实、证据等级、接触群和终态策略，再决定速度/距离来源；不要让支持界、motion-age和boost各自保守一次，却没有最终交接目标。

| 文件/函数 | 最小职责 |
| --- | --- |
| `Draw3.CanvasNavigation.cpp/.cppm`的Tracker | 保留raw/motion真实QPC，导出速度、独立区间、方向、平台观察及质量事实；不把“50ms重复”直接命名为用户停指意图 |
| `CanvasPanDynamics::Step`的Touch Up路径 | 清指针历史前收集事实；维护固定容量的同群候选，最后Up调用一次Touch纯值resolver。Pen/PenTail/Indirect继续原分支与计算顺序 |
| 新小型`TouchReleaseFacts/TouchReleaseDecision`与`ResolveTouchRelease`（名称可调整） | 纯数值、无时钟查询/分配/状态修改；返回模式、速度/距离来源、响应参数来源、是否允许旧residual、原因及降级标志 |
| `CanvasPanGestureDetector::Up` | 保留focus/拓扑和唯一派发职责。当前非最后Up不保存速度，故同群候选应在Step回收history前保存，不把复杂质量策略再塞一份进Detector |
| Dispatch / FlingBooster / FlingController | 只应用已定结果，最多加入一次合法残余，最后向量cap；曲线仍以消费Up的呈现帧起点，不倒回lastMotion补历史跳位 |
| `Snapshot` | 继续区分Touch呈现静止与释放候选，不按无输入空帧乱清速度，也不因frame年龄清排队Up事实 |
| `Draw3.DrawingController.cpp` | 必要的决策原因/交接诊断与已应用位移确认；不在这里再发明第二份Touch释放策略 |
| `draw3_canvas_pan_tests.cpp`及既有生产probe | 先用本次单指/多指/交接记录建立红绿对照和边界，不只检查Ready/非零 |

无需新服务、线程、timer、配置或曲线族。必要的小重构限制在现有Draw3模块及已有测试，不能顺手改压力、橡皮、EDID或输入后端。

## 2. 纯值决策必须分开的事实和结果

事实至少分为：raw新鲜度/合法性；实际motion区间及置信度；同一accepted接触群的真实滚动/净位移；末平台观察；同群已可靠候选；上一fling在新Down保存的当前剩余速度。**同群速度候选与上一fling residual不是同一份状态。** 只按唯一有序Down的accepted结果建立群，Pending/拒收触点不能夺权。

平台字段应叫观察/策略分类，不能没有新证据就声称已识别真实抬手或真实停指。保留原UpQPC、lastMotionQPC、frameQPC；不要通过把age改0或改时间戳伪装成连续性修复。

决策建议显式返回以下互斥模式：

| 模式 | 可以使用的证据 | 限制 |
| --- | --- | --- |
| 成熟可靠速度 | 当前motion或同群仍有效候选 | 保留最终cap、真实方向/停顿保护，允许原合法续甩 |
| 可靠短速度 | 至少三个真实独立点、两个同向运动区间，时间/坐标/来源稳定 | 不再一律强求20ms；仍需多区间一致性和异常末点约束，不能仅数raw点 |
| 仅续用合法残余 | 已实际滚动并有新运动腿方向，但无可靠新速度；旧residual来源/单位/时效均合法且正投影 | 不增加未知手速；不能重复加残余，不能凭残余把Touch响应提成“新高速快甩” |
| 几何预算低置信续滑（建议产品降级） | 已越slop、实际发生新腿滚动，只有方向与确认位移，且无cancel/明确停止/过期等硬拒绝 | 目标尾距受新腿位移预算约束，基础摩擦、禁boost/快甩增强；明确标记不是测得手速 |
| 停止/不给新惯性 | 真tap/未发生有效scroll、取消、失效/过期，或没有可用速度/方向/残余/预算 | 保留点停和安全闭合；不能为了消灭所有0而造速度 |

如果将已经确定的残余或几何seed再传入当前`GetVelocityForFlingStart`，必须禁止它再次叠加旧residual。响应选参也要区分measured hand与最终seed，否则未知手速会被伪装成快甩、由残余自促提档。

## 3. 几何预算分支的可行性和边界

基础摩擦`D(v)=tau*v−c*tau²*log1p(v/(c*tau))`满足`D'(v)=tau*v/(c*tau+v)>0`。因此可在`[0,profileCap]`有界逆解，保证额外尾距不超过`min(确认的新运动腿净画布位移,D(profileCap))`，不需伪造采样时间或换曲线。数值求解用稳定公式、固定次数和可计算浮点误差界，最终float向量量化也要验证不越预算。

预算只来自accepted、同group/epoch/metric、扣slop后的有效新腿；采用净位移/确认方向的投影，不用总路径长度累积抖动。新群Down、真实反向新腿、Stop/cancel、长期停止、来源/单位切换均淘汰旧预算。新加指/减指不能靠绝对focus跳变增加预算；限位轴必须保守折减，不能把没有真正应用的请求位移当运动能量。

**主方案已收敛的预算确认：** Dynamics的requested contentDelta不等于`ApplyToCanvas`已应用位移。由DrawingController现有应用边界携带group/leg/epoch/metric做最小反馈，只用此前已确认的净位移，不预支同帧未知/混组delta；ClearAxis、反向与取消清对应预算。这是可行的保守范围，不需跨帧pending FSM。代价也必须公开：同帧Down/Move/Up尚无已应用预算时，这个低置信距离分支可以不启动；不得因此承诺每个key64形状或不同合批方式都无条件非零。成熟/可靠短速度路径不能被这种预算缺失误拦。

key64旧残余沿新方向投影约**−229.40mm/s**：旧向量约(217.45,−77.98)，新腿位移约(−11.2368,+2.5882)mm，所以“同向旧残余续接”不适用。若用户接受几何预算降级、其它条件成立，可最多续其已确认约9.03mm的新反方向；基础Touch摩擦的示例seed约81.64mm/s、258ms。这不是11mm/.32ms的虚假测量速度，也不承诺该例必有可靠速度或9mm就是最佳手感。

风险：异常点本身若已让画布跳位，几何预算只能限制额外尾滑，不能证明那次held输入真实；明显短拖是否一律采用该降级是待用户审阅的产品选择，不能写成用户已要求“所有移动都必须惯性”。

## 4. 多指和必须保留的安全合同

同群候选在可靠指终态回收前保存，携带原运动QPC/来源/方向/置信度；最后指证据不足不能自动抹掉它。仍需真实反向、停止、过期和群边界检查，不无条件使用“第一根指头旧速度”。本次47/48各人都不满20ms，没有已成熟旧候选可借；它应由可靠短分级独立评审，不能拿不存在的组速度补证据。

必须保持：held1:1；真tap捕停；Down立即停止旧动画；真实反向切断旧腿；raw水位/稳定次序与终态合法性；取消/溢出/Stop不复活；输出单位闭环；残余仅当前正投影；最终向量cap；无新速度或预算不得臆造惯性。多指候选只属于同一accepted群，跨新群旧曲线只能走明确的residual分支。

## 5. 各设备边界及尚未消除的歧义

- Touch：仅此释放方案改变。成熟/可靠短输入争取平滑交接；证据较弱时按明确残余或几何预算降级；tap/取消/过期仍停。50ms平台不再自动等同“真停50ms所以折半并禁接力”，但真实停指与终态延迟的不可区分代价必须公开。
- ScreenPen、PenTail、外置板/Unknown Pen的Indirect路径：保持当前数值、来源映射和开关。笔尾默认惯性关闭及现slop/压力不改。
- Mouse：保持当前路径与默认惯性关闭，不因Touch新策略自动开启。驱动注入数位板仍沿现映射/开关，不能承诺每块板都走Pen。
- Touchpad：双指支持继续延期、quarantine不解除；不暗中启用新的系统手势后端。

日志QPC是软件回调处理时钟；仅凭末位置平台不能证明用户停住，也不能确认Windows/RTS API有bug。若后续必须依赖真实packet/接触边界时间，应单独报告当前源缺少的事实、设备能力与验证结果，不能承诺未测的系统时间属性可用，更不能伪造硬件时钟。

验收应覆盖key64、47/48、成熟主指+短末指、真tap、真实停住、孤立jump、未知平台与连续甩动，并验证实际交接比/无位移间隙、数值/几何预算、旧残余只加一次和nonTouch黄金值。调摩擦或换3点/20ms数字本身都不是这份架构方案的完成标准。
