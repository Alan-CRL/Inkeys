# C1.6a 教学安全模式设置与全部致命退出路径自动重启

父任务：`11-26-inkeys-crash-recovery`。调查：`research/codex-fatal-paths-20261126.md`（Codex Sol High 只读，Claude 已抽查关键事实）。

## 用户需求（2026-11-26）

- 设置“常规 → 基础”里的分组“安全与恢复”改名为“教学安全模式”。
- “崩溃处理方式”标题不变，选项改为三个：**提示并重启**（默认）、**静默重启**、**直接退出**。
- 下方新增开关，默认开：**崩溃重启后自动恢复墨迹**（C1.6b 的写入与恢复都受它控制）。
- 两类路径都要按“崩溃处理方式”处理：
  1. Windows 崩溃回调；
  2. 软件内的报错和致命错误导致的结束或卡死。例：内存满时多指书写导致的致命错误退出；主栏报错并不断重试，最后卡死。这些都应该自动重启。

## 现状（已核实）

- **配置与界面**：`Application.TeachingSafetyMode` 取值 0–3，默认 0；界面在 `UI/Setting/Setting.Pages.cpp:1412–1417`，分组标题键 `SettingsUI.Design.SafetyRecoverySection`，选项键 `SettingsUI.Regular.Tentative.SafeMode`。
- **现有 bug**：实现里 2 是“写报告后返回 `EXCEPTION_EXECUTE_HANDLER`”（静默结束），3 是“返回 `EXCEPTION_CONTINUE_SEARCH`”（交给系统），而中文界面把 2 写成“交由系统崩溃过滤器处理”、3 写成“直接关闭软件”，正好对调（`Helper/Helper.CrashHandler.cpp:619–666`）。本次改成三档后自然消失。
- **重启机制**：未处理异常过滤器（UEF）抢占 `Intent::CrashRestart`，由同一 EXE 以监督模式等待旧进程死亡后拉起一次，新进程带 `-CrashTry`，可以识别“这是崩溃重启”。崩溃重启后 5 分钟内再次崩溃不再拉起（`Helper.CrashHandler.cpp:463–470`）。
- **Windows 回调覆盖缺口**：只注册了 `SetUnhandledExceptionFilter`；没有 `set_terminate`、`SIGABRT` 处理；`_set_purecall_handler`、`_set_invalid_parameter_handler` 设为空。`abort()`、`__fastfail`、栈溢出、堆损坏在 Release 下通常不经过 UEF（推断，C1.6c 实测验证）。
- **软件内致命路径**（详表见调查报告）：
  - Draw3 `Run()` 内存不足或其他异常、设备恢复失败、窗口意外销毁 → Host 停止 → 主循环发现 `ProductRunning()` 为假后“受控退出”，退出码 6（`IdtMain.cpp:4265–4290`），**不重启**。
  - UI3 主栏资源重建失败返回 `Continue`→`Retry`，共享设备恢复失败也持续重试，**没有次数或时长上限** → 界面不刷新、进程不退出。Setting、白板背景、分页、选区、启动预览、Freeze 也有类似的无上限重试。
  - 已知失败后的清理有 `FailedCleanupDeadline` 兜底强退，同样不重启。
  - 没有 UI3 / Draw3 运行期的进展看门狗。
- **启动期错误**：现有“启动失败提示 + Close”路径独立于配置（设置说明“启动过程发生错误时仍会显示提示”）。

## 需求（草案）

1. 设置改名、三档选项、新开关（默认开）；三档对应值 0/1/2，读取与界面范围同步收紧，越界回默认（项目约定旧配置不兼容）。
2. Windows 回调统一接入：补 `set_terminate`、`SIGABRT`、pure call、invalid parameter 等进程内入口，汇入同一套崩溃处理；进程内拦不住的终止方式见待确认 1。
3. 软件内致命错误统一接入：Draw3 意外停止、已知失败清理强退等改为发布“致命故障”，按三档处理（提示并重启 / 静默重启 / 直接退出）。
4. 卡死与无限重试：给 UI3 共享渲染和各客户端的持续失败计时，成功提交清零；给 UI3 调度线程和 Draw3 循环加进展心跳，由主循环监督；超限按致命故障处理。
5. 保留：崩溃重启后 5 分钟内再崩溃不再自动拉起；“等旧进程确认死亡后再拉起”的契约；启动期错误仍显示提示。
   - 2026-11-27 实测后补充（用户决定）：抑制窗口内照常写崩溃报告、dump 与 Critical 日志；“提示”档改为询问“是否重启”（是 → 重启，否、关闭或无法提示 → 退出），窗口外仍是“确定”后重启；“静默重启”与“直接退出”档写报告后直接退出。
6. 内存不足时“提示并重启”的弹窗可能无法显示，此时退化为静默重启（实施时确认）。
7. 从父任务待办并入：Host 正常退出时等待存储 worker 排空已接受的写入，没有超时，磁盘卡住时退出会一直等；退出卡死也要有兜底（设计时确定超时与处理）。

## 用户确认（2026-11-26 第一轮）

1. **只做进程内拦截**，沿用现有 UEF + 监督进程拉起，不加常驻守护进程。补齐 `terminate`、pure call、invalid parameter 等进程内入口；`__fastfail`、栈溢出、堆损坏、被强制结束不保证重启（被强制结束与断电由 C1.6b 的“非正常结束后恢复”兜底墨迹）。
2. **卡死阈值**：界面可见且有待提交内容时持续失败 **10 秒**，或 UI3 / Draw3 线程 **15 秒**没有进展，按致命故障处理。
3. C1.6c 的测试入口不用真正的 `abort()`，改为野指针访问触发（走 SEH → UEF），见 C1.6c。
