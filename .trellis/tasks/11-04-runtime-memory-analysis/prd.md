# 运行时内存采样与低风险优化

## Goal

在 diagnostic/memery 分支采样和分析运行时内存，依据测量实施已批准的内存优化，优先降低普通静止及功能使用后回到桌面的稳定常驻占用，同时保持既有绘图架构、设备隔离、功能与正常流畅度；可自行回落的瞬时峰值降为次要目标。

## Background

- 2026-11-04 已完成工具盘点、生产源码内存结构及候选研究，见 research/memory-overview.md 与三份专题报告。
- 2026-11-05 用户明确批准启动窗口、通过非 Computer Use 的方式操控电脑、采样分析后直接实施低风险优化，并批准 Trellis 修改代码与实现阶段。
- 用户挂机且可能锁屏；优先使用命令行、无窗口或离屏验证，不能依赖用户即时解锁。
- 本机 ARM64；主产品验证沿用 InkeysRepo.sln 的 Debug|ARM64，动态定位 ARM64 MSBuild，不改现有构建系统或依赖。

- 第二批候选2–5已完成实现、最终构建、25项适用验证和普通静止/白板往返实测，详见result-batch2.md；候选1/6本批未改，留后续评估。

## Requirements

- R1：保留工具与源码调查的证据边界；实际采样分别记录 Private Bytes、Working Set、原生堆/VirtualAlloc、图形资源及必要的运行时信息，不相加重叠指标。
- R2：先保存修改前基线，确认二进制/符号与源码身份；若锁屏阻碍真实交互，使用既有无窗口/离屏测试与可自动化场景继续，并明确其代表范围。
- R3：依据源码与采样选择最小、低风险的分配/副本优化，采样后直接实施，不为常规实施选择反复请求批准。
- R4：L0/L1/L2 架构不变；UI 与画布继续使用两个独立 device，UI 继续共享 WARP，画布 hardware-first 与现有 fallback 策略不变；不能为节省内存合并设备或改变后端。
- R5：保持正常路径流畅度，按用户要求静态审查即可，不要求流畅度性能实测证据；避免把大分配/重建/同步/解码搬入连续绘制、输入或每帧热路径。用户已明确接受Laser选中时初始化、离开时销毁的功能边界，不以常驻热缓存替代该策略。
- R6：用户已批准候选2–5进入实现，按research/batch2-boundary.md控制范围。1保存峰值去重与6历史缓存页策略本批不改；架构级大改仍未批准。
- R7：允许启动/操控本任务相关窗口；不使用 Computer Use 工具。不打开 Office/WPS 或用户文档，不绕过锁屏；通过无窗口路径推进。
- R8：保留源码编码/BOM/换行和中文关键注释，最小 diff；完成适当编译/测试，区分代码与环境失败。不 commit/push。

- R9：用户最新明确以普通静止常驻为首要目标，同时关注功能用过后回到普通桌面的回落；可释放的临时快照/编码峰值后置。Laser生命周期方向为选中初始化、离开销毁；用户现已批准实施2–5，1和6后续评估。

## Out of Scope

- 不改 L0/L1/L2、不合并 UI/画布 device、不更换 WARP/hardware 分工、不调低正常绘制品质或帧率。
- 不削减撤销、页内容、语言 fallback、视觉回退或平台/Office兼容范围。
- 不修改全局 Git/SSH 配置或通过依赖/工具链升级绕过本机错误，不安装新软件。
- 不声称未实测的节省比例；流畅度只给静态分析结论，不包装成动态验证。
