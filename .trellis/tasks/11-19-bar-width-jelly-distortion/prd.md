# 修复主栏宽度意外拉伸/压缩

## Goal

修复主栏在非手势场景下被底栏水平果冻映射意外拉伸/压缩的问题。果冻形变只属于用户拖动的捕获/脱离/松手交接；缩放倍率变化、显示环境变化、场景切换自动放置等程序性移动必须保持主栏刚性（宽度恒等于布局宽度），由既有位置动画负责连续性。

## Background

- 用户 2026-11-19 截图：主栏背景、按钮、图标与文字被整体横向拉伸（按钮间距变宽）或压缩（图标与文字被挤扁），主按钮本身不变形。发生时并未进行吸附拖动。
- 已知触发：1. 调整主栏缩放倍率；2. 切换场景（进入/退出 PPT、白板）自动移动位置。
- 关联旧记录：`archive/2026-11/11-06-workspace-dock-placement/followup.md`（“折叠状态进入 PPT/白板（开启自动居中底栏）时进入动画不自然、脏区遗漏”），当时只记录线索未修复；本任务的根因 B 是该遗留问题中“动画不自然”的一部分来源。
- 调查基线：`refactoring/drawpad-ui` / `01e75d2d`。根因与源码锚点见 `design.md`。

## Requirements

- R1：缩放倍率（`configZoom`）变化、显示快照变化（DPI、`uiBaseScale`、显示器、工作区）且没有进行中的拖动手势时，主栏水平映射不得从上一成功像素重新播种远端/抓手弹簧，不得产生 `scaleX != 1` 的形变。
- R2：主按钮根 X 由程序性动画持有时（场景接管的 `workspaceEntryRootTween`、`displayCenterX` 过渡），即使 `centerMode == Centered`，主栏远端也必须刚性跟随根节点，不得钉在最终居中边界上导致中途拉伸/压缩。
- R3：场景接管（Free/折叠 → Centered 底栏）首帧不得因 `presented.centerMode != centerMode` 再次从旧像素播种水平弹簧，覆盖接管时已清零的弹簧。
- R4：保留既有手势果冻合同：拖动中 40 DIP 水平捕获/脱离、松手恢复、拖动期间 DPI/显示交接、释放吸收重基准等仍按 spec 从上一成功像素连续恢复，不改变弹簧频率/阻尼/限值。
- R5：竖向映射、dirty/viewport/capacity 预测、光源逆映射与命中仍与实际水平映射一致；不得引入残影或单帧跳变。
- R6：最小化修改，只改 `Bar.RenderLoop.cpp` 中水平交接与远端目标的判定，以及必要的回归测试与 spec 条目；保持 UTF-8 BOM / CRLF 与中文关键注释。

## Acceptance Criteria

- [x] AC1 / R1：非拖动状态下连续改变缩放倍率（含 0.5↔2.0 往返、滑块连续拖动），每个成功帧 `horizontalMapping.scaleX == 1`（容差内），`visualLeft/Right` 等于布局端点。（实测覆盖 0.8×–1.48× 倍率步进与逐帧滑动，未覆盖 0.5/2.0 两端）
- [x] AC2 / R2,R3：从远离中心的悬浮、悬浮折叠、底栏、底栏折叠四种状态进入 PPT/白板（自动居中底栏开启），以及退出还原，进入动画全程 `scaleX == 1`，根 X 单调无往返，最终居中。（矩阵起点为默认位置而非远离中心，远距离起点待实机确认）
- [x] AC3 / R1：DPI/显示器切换的非拖动过渡（0.4 s 位置与 `uiBaseScale` 动画）全程主栏无水平形变。
- [x] AC4 / R4：既有底栏吸附、居中捕获、脱离、松手恢复、拖动中显示交接相关测试全部通过，结果与修改前一致。
- [x] AC5 / R5（构建与无窗口测试已通过；用户 2026-11-19 实机验证通过）：`InkeysRepo.sln` `Debug | ARM64` 构建通过；相关无窗口/离屏测试通过；实机复现两种场景不再出现截图中的拉伸/压缩。
