# PptCOM 独立进程与多来源联动抽象层规划

> 2026-10-10；总体规划已收敛，P0已完成；用户现批准P1通用合同与仲裁纯逻辑。本文记录总体需求，技术方案见 [design.md](design.md)，分期与验收执行见 [implement.md](implement.md)；P0已归档，P1通过独立子任务执行。

## 目标与用户价值

保留已有效工作的 PptCOM3 dynamic / late-bound 联动能力与资源释放路径，继续默认使用内置类库；在用户开启跨权限兼容时增加独立程序。由统一联动抽象层管理多来源、多文稿和多放映候选，使主程序业务只消费统一状态与命令接口，既能覆盖不同权限域，也能扩展第三方演示软件。

## 背景与确认事实

证据与行号集中于 [research/current-contracts.md](research/current-contracts.md)，以下不代表本轮运行验证：

- 当前源码目录为 `PptCOM/`；项目为 .NET Framework 4.0 / AnyCPU COM 可见类库。
- 类库通过三个 native 指针槽传递旧页码与停止信号，另有纯值 descriptor/session 缓存；当前不存在独立进程可复用的共享内存协议。
- 现有 ROT 扫描包含应用去重和活动优先级，但只返回一个应用；绑定主要观察该应用的 ActivePresentation / SlideShowWindow。完整多候选目录需另行补足。
- native 链路已有文稿、SlideID、结束页、Draw3 成功呈现及 PageControl 回执合同；这些是迁移必须保持的行为。
- `Inkeys/SuperTop/IdtToken.h` 已有普通用户 token 与 token 启动机制，但现有启动函数创建控制台且不保留进程句柄，不能直接承担后台 helper 管理。

## 需求与不可破坏约束

| ID | 要求 |
| --- | --- |
| R1 | 保留 dynamic / late-bound 获取、ROT 兼容、对象所有权和释放行为。用户报告现状可联动 COM 损坏的 PowerPoint；此前线程模型与保护改造曾导致内存释放失败、PowerPoint 卡死和识别回归。此次迁移不得夹带 STA/MTA 切换、多 COM owner 线程或强类型根对象替换。用户提到的“STM”不自行等同于某一种 COM apartment。 |
| R2 | 默认只启用内置类库；开启兼容选项后独立程序与类库并存。管理员主程序的类库负责管理员域，helper 利用普通用户令牌补充普通用户域；普通用户主程序的类库负责普通用户域，helper 通过标准 UAC 提升后补充管理员域。提升仅用于 helper，主程序保持当前权限。取消提升、启动或通信失败仍保持类库支持，本次取消后不自动循环重试。 |
| R3 | 类库通过共享内存发布一致状态，类库接口承担初始化、命令及停止等控制；独立程序通信以 Windows 7 SP1 / .NET Framework 4.0 兼容为前提，ZMQ 保留为候选；如果具体实现不满足兼容、部署或退出要求，可以采用命名管道等方案。抽象层与传输方式解耦，原有 COM ABI、GUID 和旧接口顺序保留。 |
| R4 | 抽象层能管理多个来源及每来源多个放映候选；分别处理同一放映的重复报告、同文件的不同放映、不同文稿同时放映和动态切换。所有可用来源均进入候选目录，不能在传输层提前只留一个赢家。仲裁采用用户已确认的“活动放映优先”：先选活动放映，再在该放映内择优来源。最终仲裁与切换规则统一放在抽象层，PptCOM提供活动性依据；不同后端的本地分值不能直接混比。 |
| R5 | 抽象层维护统一页数、当前页、文稿/放映身份、状态质量、能力与绑定。主程序业务只面向抽象层，Office/共享内存/ZMQ/命名管道细节归适配器。PowerPoint 页事件能触发快速刷新，轮询仍作为兜底。 |
| R6 | 通用模型允许软件没有完整路径、SlideID、HWND 或总页数，缺失必须显式表示；稳定页身份等扩展按能力暴露。低能力来源不得伪造 Office 身份或使画布准入失效。 |
| R7 | 来源切换不产生假放映结束；不同放映切换须隔离画布。旧 epoch、旧候选、乱序消息、迟到命令和确认不得影响新绑定。命令只发送给一个已验证的目标，不广播翻页。 |
| R8 | 保持现有文稿/页级墨迹、结束页独立 slot、Unknown/busy 语义与成功 Present → UI 回执 → 输入 ready 的顺序。检测到页事件不能提前开放输入。 |
| R9 | helper 自身无交互窗口，标准 UAC 提示属于普通用户启动管理员 helper 的必要系统交互；具有握手、心跳、退出和故障撤销机制；通信/序列化工作不接触 Office RCW。正常退出先沿原 owner 解绑和释放，不通过杀死 PowerPoint 解决释放问题。 |
| R10 | 用户确认 net40 的采用目的是兼容 Windows 7 SP1，本任务将 Win7 SP1 / .NET4 运行条件纳入类库与 helper 的验收。不得为了通信方案提高运行时/系统要求或改变 Office 依赖，也不以此缩小主项目其他既有平台声明。helper/传输支持组合在实施前验证；不能把管理员/普通用户两域覆盖写成所有 Office 损坏或所有权限组合均保证成功。 |
| R11 | 为优先级变化提供防反复切换规则：同等级保持、弱活动提示持续确认、软切换回滞；明确前台变更/当前目标失效保留快速路径，不给正常页事件统一增加防抖延迟。抽象层与后端不得并行争夺最终绑定，被动仲裁不自动激活窗口制造活动依据。 |

## 范围

原规划已交付现状研究、需求、架构、协议语义、仲裁与身份及验收矩阵。P0基线、依赖核查、隔离通信探针与既有测试已完成。本轮P1已完成纯值合同、目录与仲裁、fake/可控时间测试；尚未接管生产联动。

后续拟实施范围：内置适配器、共享状态通道、统一仲裁服务、独立 helper 和兼容的进程通信通道、双向权限进程管理、既有业务消费者迁移及多候选补足。按可独立验收阶段拆分；P1纯逻辑交付已通过，P2-P5尚未执行。

本任务不直接实施：pptmon / 希沃白板5 的第三方真实协议（包括它们自有的命名管道协议）；跨机器远程控制；多个画布同时联动；来源选择器或手动固定 UI；新的持久化格式；COM apartment 重构；COM 修复安装器。用户提供的第三方支持情况只作为扩展需求，未经协议和运行核查不声明兼容。

## 可观察验收标准

| ID | 映射 | 验收 |
| --- | --- | --- |
| AC1 | R1,R2,R10 | 兼容开关关闭时不创建 helper；正常/损坏 COM 的既有联动、事件失效轮询和退出行为保持；同一基线轨迹前后比较，Office 不残留由本任务引入的引用，能正常关闭。 |
| AC2 | R2,R9 | 管理员 host + 普通用户 PowerPoint、管理员 PowerPoint + 本权限类库分别识别；两者同时放映进入候选目录。token 或 helper 失败显示可诊断状态，类库继续工作。普通 host 开关关闭时无 UAC；开启后能通过管理员 helper 识别管理员 PowerPoint，同时类库识别普通用户 PowerPoint。取消 UAC 后仍能联动普通用户放映且不重复请求本次提升。 |
| AC3 | R3,R7 | 共享内存及最终选定的 helper 通道（ZMQ 或命名管道等）得到相同语义的完整快照；无撕裂页码/身份。重连从全量恢复；乱序、重复、旧进程消息与未知必需版本明确拒绝。 |
| AC4 | R4,R7,R8 | 类库和 helper 重复报告同一放映只生成一个逻辑放映；来源切换不触发 EndSession 或清除墨迹。同文件在不同进程/窗口放映保持独立；仅标题相同不合并。 |
| AC5 | R4,R5,R7,R11 | 不同文稿并发时优先联动活动放映，其来源权限/backend级别不使后台文稿抢占；前台放映变更后动态切换；操作 Inkeys 自有控件不导致绑定丢失；同优先级稳定、不随报告到达顺序抖动；A/B弱活动提示短暂交替不反复切换，明确实际前台改变能绕过软冷却快速准备新目标，迟到绑定确认不短暂发布旧目标。 |
| AC6 | R5,R8,R11 | 页事件唤醒快速路径，旧慢维护不挡住已获得的纯值更新；日志贯通观察/仲裁/target/Present/UI ack。性能数值以实施前基线和实测结果说明，当前不承诺未经测量的毫秒目标。 |
| AC7 | R6,R8 | Fake 第三方来源可只给临时文稿身份和页序号；支持其已声明的页级能力，不要求 Office SlideID。未知页/总页数保持 Unknown；不能可靠隔离页面时不开放页面墨迹输入，不伪造结束页或稳定保存。 |
| AC8 | R7,R11 | A 的翻页/结束命令在换到 B 后不执行；超时结果不会引发自动重复翻页；迟到 ACK 不更新 B 的 UI；不存在类库与 helper 同时执行一次翻页。新BrokerSelect模式下不出现后端自主重绑与抽象层绑定互相覆盖；被动选择不通过自动激活窗口改变优先级。 |
| AC9 | R1,R9 | 重复启停、放映结束、关闭 Office、关闭兼容选项、host 退出及 helper 崩溃后无错误结束或新场次污染；正常退出取消请求、解绑事件、按所有权释放。实际 Office/WPS 资源验证独立于 fake 单测。管理员 helper 在 host 退出时需独立检测父进程/连接失效并退出，不能依赖低权限 host 一定可以强制管理高权限进程。 |
