# 设置字体与语言热切换：验证结果

## 最终方案与边界

设置窗口固定 ImGui1.92.7，使用固定依赖 FreeType2.14.3、LightHinting、按实际字号生成字形、源密度1及像素基线对齐。保留原字体文件、真实Regular/Bold、语义字号与行框，以及Harmony/Noto字面校准。正文/图标仍分别配置，主栏、PPT/白板分页继续DirectWrite；消息框继续GDI+。

字体CPU图集为Alpha8，支持时GPU为R8；其他图片保留原RGBA路径。无R8支持时保留RGBA展开回退。相同字库的Legacy/Design角色在同一atlas内共享FreeType face，使用独立FT_Size并按实际使用分配合并源字号。已撤回试验性的延迟face/Unicode覆盖缓存，避免无必要复杂度。

切换语言通过候选字体/翻译准备与帧边界提交，覆盖设置、主栏及面板、分页与程序自有提示；已打开消息框保持原语言，新消息框使用一致快照。

## 性能

计量将源注册/Build冷成本、首次实际帧、热态CPU生成、后端调用、EVENT/Flush/GetData完成等待分开。热态每组预热120帧、采样300帧，共3组，串行运行。GPU完成等待是墙钟时间，不能称为纯GPU时间或屏幕FPS。截图在计时之后生成，未预热“冷首帧”。

完整字体矩阵204行，退出0、360.10s。FreeType源初始化约1.4–6.6ms，stb约0.15–0.40ms（所选计时场景）；冷成本有所增加。首次字体帧各场景有升有降，部分增加约30–40ms，因此不宣称冷启动全面加速。

首轮EN100/CN200有波动，随后按相同方法做ABBA独立上下文复核：

## 限制与环境记录

- 未进行原生GUI/触屏/跨真实显示器交互，未宣称Win7/x86/x64实机已通过。
- 额外主栏多目标性能基准的culling门槛仍失败。相同二进制禁用/启用本轮语言探测均为0culled，时间门槛复核通过；仅排除了探测本身，未据此宣称原始提交基线也失败。未为此改动DirectWrite或主栏渲染算法。
- 构建过程中遇到沙箱MSBuild节点无诊断退出、测试先于新依赖安装、调试库名称和增量链接器LNK1000；分别使用原生构建、必要的solution依赖顺序、正确Debug库名及清理工作区生成的.ilk解决，未升级工具链或改变签名配置。
- 像素夹具曾错误使用`ImTextureRef(&data)`，异常转储证明栈地址被当作SRV。固定1.92.7必须使用`data.GetTexRef()`；已修正，临时崩溃处理器/追踪已移除。此为测试夹具问题，不是产品驱动故障。
