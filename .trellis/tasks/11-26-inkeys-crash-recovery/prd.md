# C1.6 教学安全模式与崩溃自动恢复墨迹

父任务：`11-16-inkeys3-midterm-refactor`（中期重构）。本任务是父任务地图中的“C1.6 抬笔立即追加写入与崩溃恢复”，并吸收“异常退出与卡死的兜底”待办。

## 用户原始需求（2026-11-26）

1. **C1.6a**：设置中的“安全与恢复”分组改名为“教学安全模式”；“崩溃处理方式”标题不变，选项改为三个：“提示并重启”（默认）、“静默重启”、“直接退出”。下方新增一个开关，默认开：崩溃重启后自动恢复墨迹。
   - 崩溃重启分两条路径：① 现有的 Windows 崩溃回调；② 软件内自己的报错和致命错误导致的结束。要找出代码中所有这些路径并支持这个保护。
   - 已知例子：内存满时多指书写导致致命错误退出；主栏报错并不断重试，然后卡死。这些场景都应该自动重启。
2. **C1.6b**：追加写入（上方“自动恢复”开启时才有），桌面、PPT 和白板都要。
   - 桌面最简单：抬笔后就往新文件写入。时机：上一个 Clear 之后不创建新文件，Clear 后第一笔抬起时才创建文件并写入第一笔。
   - 这些写入和之前已有的性能记录都必须异步，不得导致下一次落笔出现延迟。
   - PPT 和白板：正常情况下不往回翻页就没有大问题。往回翻页时：① 要记录当前在哪一页（便于恢复）；② 如果在回去的页上落笔，就整理 UInk 结构，把当前页放到最后（UInk 不要求按页码排序），之后继续追加写入。翻到新页时先不整理；退出 PPT 和白板时再整理（按正序）。
3. **C1.6c**：在“调试软件”页加一个 abort 按钮，用来手动测试自动恢复是否正常。

协作方式：与 Codex 合作。规划阶段 Codex 只读调查；实施由 Claude 写代码、Codex（Sol High 只读）审查（用户 2026-11-26 指定）。

## 跨子任务约束

- 最小化修改；保持文件编码与换行（源码 UTF-8 BOM + CRLF）。
- 不新增独立的 stdout / Console 通道，诊断走统一日志。
- 写入与诊断不得进入落笔关键路径。
- 每个进程只写自己新建的文件（C1.4 约定）；恢复时读旧进程文件只读。

## 跨子任务验收（草案）

- [ ] 三种崩溃处理方式在两类路径（Windows 崩溃回调、软件内致命错误/卡死）上行为一致。
- [ ] 自动恢复开启时，用 C1.6c 的按钮在桌面、PPT、白板分别触发崩溃，重启后墨迹恢复到崩溃前最后一次抬笔的状态（具体口径见 C1.6b）。
- [ ] 自动恢复关闭时不做追加写入，也不恢复。
- [ ] 落笔延迟与 C1.4 完成后相比没有可测的退化。
