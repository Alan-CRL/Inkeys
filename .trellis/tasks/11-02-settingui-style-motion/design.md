# SettingUI 样式与转场技术方案

状态：最终规划已获用户批准的实施方案。需求及用户决定以 [prd.md](prd.md) 为准。

## Change Boundary

行为差距集中在：标题栏未共享开屏可见性；正文轨道宽度参与显隐；量化颜色状态可能不落定；页面只有整页淡入，条件块缺少布局动画；resize 与 maximize 的实际成本/材质变化尚缺同源诊断。

| 位置 | 必要职责 |
| --- | --- |
| `Setting.cpp` | 真实会话/路由、标题栏绘制与Win32命中、开屏接入、输入取消、resize消费和材质消息；业务FIFO保持原入口。 |
| `Setting.Pages.h/.cpp` | 语义页面/子页身份、首页开屏衔接、各实际页面的顶级块/条件块登记。 |
| `Setting.Controls.h/.cpp` | 真实行测量/布局、滚动宿主策略、块动画scope、稳定高度及动作单次执行。 |
| `Setting.Design.h` | 复用NavigationTween/时钟/全局开关速率，必要的会话局部页面动效状态。 |
| `Setting.SessionState.h`、`Setting.Base.cppm` | 仅按采样结论修复同尺寸resize、serial消费或RTV/呈现路径的局部浪费；不造另一套资源生命周期。 |
| `Setting.Shell.cpp` | 仅在开屏/真实导航命中或颜色修复需要时接入，保持导航树语义。 |
| `additional/imfluent/imfluent.cpp` | 如实际控件回放确认量化停滞，局部修复共享颜色动画终点；保留原透明加权插值，中文INKEYS PATCH标明原因。 |
| 现有Setting/session/home WARP测试及规范 | 验证真实生产调用，更新改变的滚动/动效合同。 |

默认不新增编译单元；若状态需要独立头文件，可在Setting目录内使用小型内部头，不改变公共模块边界。Shared RenderPipeline、字体、语言配置、资源文件及工具链不改。多个问题共享帧边界、布局和材质，按同一任务分阶段集成，避免各自引入第二套时钟。

## Frame Ownership and Order

1. HWND线程处理系统框架/主题/命中，发布最新尺寸/状态和已冻结的材质请求；不进入D3D资源操作，不等待整帧布局/Present。
2. 唯一共享渲染线程在帧边界消费会话serial、DPI/字体/语言/主题变化，处理必要的资源恢复。
3. 解析权威页面/子页和开屏状态，先决定本帧标题栏四项可见性，再登记绘制与命中。不要依赖上一帧开屏状态而漏一帧按钮。
4. 处理页面动效取消输入，选择稳定正文宽度与当前条件块高度；再提交本帧真实items。旧页触发导航的同一点击不作为新页正文取消。
5. 按实际层级绘制内容、导航、必要覆盖层。业务事件保持真实action单次产生，并在原FIFO域消费。
6. 保留现有纹理检查、FrameSubmissionCache及成功Present确认协议；发生任何状态变化必须有正确的提交键/DrawData，不因旧缓存跳过动态末帧。

不新增线程、timer或永久逐帧日志；必要采样复用现有受控聚合诊断。状态随设置resident session销毁，不持有跨context的ImGui指针。

## R1 Opening Chrome Visibility

四项共享一个本帧状态：`suppressed`（准备、书写、停留、遮盖层未淡完）或`visible`（遮盖层已消失、未播放/取消/失败回退）。保持各项布局槽位与其他标题栏几何，隐藏时不登记能激活的item。

Win32 hit-test快照与绘制使用相同可见性版本，避免透明图标仍可点击、键盘导航可到达，或隐藏槽位成为错误的缩放/路由热区。系统最小化/最大化/关闭及拖动标题保持。现有字标输入取消规则保留；取消帧原有防点穿屏障不能被新的逐块入场策略覆盖。

## R2 Stable Scroll Layout

将正文轨道的布局预算与thumb视觉alpha分开。正文根据真实内容高度、字体、最终宽度和viewport建立布局；如依赖ImGui首次AutoResize结果，复用有界的不可见准备阶段，在首个可见帧前达到一致布局，而非可见后从0宽动画到8 DIP。

优先利用正文既有右侧gutter容纳8 DIP轨道，使滚动阈值变化不再额外挤压条目；保持左右视觉边距和实际控件命中，不能通过事后移动全页顶点或重复扣减ScrollbarsSize补偿。具体内边距/轨道关系在真实BeginChild回放中核对，最窄窗口仍需满足轨道与控件不相交。无溢出的页面没有虚假thumb、额外滚动或新增空白列。

准备阶段只允许布局/测量；不重复执行action、Shell、保存、焦点或active-id操作。采用前帧真实布局暖机时每帧仍仅一次生产绘制；若必须独立测量，应显式使用只读draft和纯测量入口，不能复制业务switch跑两遍。准备失败有界退出并采用可用实际布局，不无限等待，也不能显示旧页闪帧。

缓存键至少包含语义路由+子页、实际宽高、字体/atlas/语言revision、DPI/倍率和条件布局revision。resize/字体/语言使几何失效，不算导航重播。轨道样式仍集中由本地Begin部署管理；导航中段、Combo/flyout等既有轨道动画默认保持，只有直接影响新需求的正文宿主变更。

## R6 Page Entry

- 使用真实语义路由+子页和单调导航generation，当前页重复通知不改变generation。返回保留各页已有滚动状态，只对当前可见内容的动画排序。
- 顶级行/卡片是动画单元；分区标题与其第一项共享节奏，多列同排卡片一起进入，嵌套控件不重复施加动效。自绘首页hero/网格也需显式登记，不能只覆盖SettingRow。
- 当前参数（按2026-11-03用户细化）：旧页125ms淡出；新块位移12 DIP、位置310ms、透明度450ms，顺序延迟约27ms且最多108ms，最后位置418ms到位、558ms完全显示，再用110ms渐显有效thumb。位置使用三次ease-out、透明度使用smoothstep；参数在实际离屏帧验证后微调，不另加配置。
- 延迟按首屏/恢复滚动位置的可见块排序，有界且不取整页所有离屏行数量；滚动时按已确认规则直接落定，不产生滚进新区域又排长队的动画。
- 真实布局使用终态位置/高度；浮入是局部绘制scope中的视觉偏移与alpha，裁剪、子窗口和命中必须配套。点击/滚动/相应键盘触摸操作在items提交前终止入场并用终态坐标执行，不拦截吞掉再伪造重放输入。
- 替换或统一现有contentReveal，禁止将整页alpha再与逐块alpha相乘。导航overlay自身的内容淡化仍独立，明确组合避免同一效果叠两次。
- 播放字标开屏时页面块处于稳定终态，开屏快照/字标归位流程不变；字标完成/取消不派发新generation补播。开屏策略跳过时及正常导航返回首页播放普通逐块入场。

## R7 Conditional Blocks and Scroll Anchors

为实际条件块保留稳定ID、当前/目标可见性、可测量高度和出现/退出进度，复用现有会话时钟/tween，初始过渡180ms。首次提交以当前条件初始化；只有已显示页面上的真实条件改变产生显隐，不把翻译变化或首次布局误当新增。

出现时真实占位高度逐步增加、内容渐显；退出保留必要绘制与插值占位，立即撤销不应再执行的action，结束后完全移除。相关分区标题与子项同组，避免孤立标题或双份空隙。相邻块按同一帧高度自然移动，反向从当前进度续接，不清零重播。

条件为false时如需绘制退出外观，只能使用只读/禁交互状态，不调用原业务action；不能盲目保活整个包含副作用的if分支。现有条件内容盘点以research和R7为底线，实施前遍历全部实际switch补齐。

每个正文滚动owner在高度变化前记录首个稳定可见块及其相对viewport偏移；上方高度改变时补偿锚点。若原来确实贴底且没有主动滚动/拖动则随末端保持贴底，否则不强行吸附。用户滚动/拖拽优先，目标消失时选相邻稳定锚点，最后只按本帧有效总高clamp。thumb按同一动态总高计算，宽度使用R2稳定策略，防止阈值附近反馈振荡。

关闭全局动画即时归位；Hide暂停/清理、重开按真实路由初始化，语言/字体/viewport改变重新测量并平滑重定向或稳定落定，不使用陈旧高度。动态块显隐不重播整页入场。

## R3 Color Endpoint

先以真实NavItemEx连续回放验证残留端点；若确认，修复实际持久化颜色状态的量化停滞。保留premultiplied权重插值的视觉正确性，采用有界到达端点或浮点状态等最小可验证方案；不能简单改成普通RGBA插值、盖不透明背景或仅给设置侧栏打独立颜色补偿。

检查共享AnimateColorU32调用的按钮、输入、导航等代表控件；30/60/120/240Hz、快速反向、透明到浅色、主题切换和不连续提交必须到达精确目标，且选中项保持预期色。

## R4 Resize Performance and R5 Material Continuity

诊断先行：区分窗口消息/边框同步、等待锁、CPU文本测量/布局、ResizeBuffers/RTV、backend、Present耗时及共享客户端调度。复用现有最新尺寸mailbox；同尺寸消重须保留epoch/新presentation首次尺寸与失败重试，不把失败serial误消费。资源resize只在render线程，结束交互保证最新有效尺寸提交，Size期间不使用Move的Idle路径。

先做有证据的局部浪费修复，例如同尺寸重复重建、无变化框架请求或可复用的文本测量。任何测量缓存都必须含字体/语言/宽度revision；不重建字体/图片来处理普通resize，不升级工具链或新增设备。

材质使用由窗口线程拥有的“已成功应用”状态键，包含主题/能力/composition generation及相关真实失效。等价请求不先disable再enable；真实能力变化、失败和窗口生命周期强制重验。系统框架margin、圆角与最大化几何仍按原合同更新，不能冻结旧尺寸去掩盖过渡。

渲染线程每帧只消费一致的backdrop/palette/clear快照；窗口原生材质切换和ImGui底色若跨帧，应使用已有serial边界协调，失败不能谎报新状态。跟踪最大化原生动画及首尾尺寸帧，避免误把底层背景内容变化视为模糊强度跳变。

这两项的主成本与实际DWM行为延后到获准后的诊断，不改变MVP目标。若必须修改共享调度/交换链模式、减少交互刷新或改变视觉质量，提交证据并返回规划；不自动扩围。

## Compatibility, Recovery, and Verification

无配置迁移，不改变页面索引/语言索引。保持现有Windows能力回退、标题栏与外部热区、字体资源和共享epoch。所有几何/缓存状态随resident/session正确释放；失败/Hide/字体/主题/epoch撤销对应缓存，恢复不补播旧动画。

验证重点是生产入口的绘制/命中/scroll/事件次数、真实RTV生命周期及材质调用顺序，不能只测试与实现同形的数学helper。局部调整状态结构时先以稳定帧前后DrawData、事件及业务保存次数证明原行为保持。具体步骤与平台验收见implement.md。

## 2026-11-03 切页柔和度细化（同一在途任务）

用户明确要求旧页先淡出、新页再渐显、放慢速度且透明度晚于位置结束。此轮在既有R6范围实现，不更换渲染管线或增加字体/配置。改动边界为Setting.cpp的实际绘制路由、内部过渡值状态、Controls块时序及真实回归；保持R1-R5/R7和先前用户输入策略。

速率1初值：旧页125ms淡出；新块位置310ms三次ease-out，透明度450ms smoothstep，错峰27ms且最多108ms。最后一块位置约418ms落定、558ms完全显示，随后110ms显出thumb。主题底色、导航和标题栏不参与整页淡出。

目标路由与实际绘制路由分离。旧页阶段保持原内容、滚动位置和当前入场姿态，禁正文输入；alpha为0时才一次提交最新目标。用户在新页入场阶段滚动/点击仍直接到位并执行一次。字标开屏、初次显示、关动画及Hide→Show沿用既有直达/开屏策略，不淡出不存在的旧页。

不得在切页后用新页冒充旧页淡出，也不重复渲染带业务事件的switch。复用原有页内容alpha helper，仅处理正文内容（不重复混合半透明底色）；轨道透明度单独组合一次。

## 2026-11-03 用户澄清：按块整体透明度

各控件图元分别乘透明度会在重叠区域重复混合；应先以原始图元/材质透明度完整合成一个块，再将该合成结果整体应用页面入场/退出透明度。需保留真实交互、裁剪、字体动态纹理、半透明桌面背景、失败恢复和设备epoch；禁止只修toggle颜色或用单图元alpha代替组透明度。用户此明确要求覆盖先前仅做逐顶点alpha的方案。
