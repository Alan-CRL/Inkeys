# 恢复防重复启动与安全启动交接

## 目标
默认阻止同一安装目录重复运行 Inkeys，同时保证正常重启、更新安装/回滚、超级置顶三段式和失败降级能够交接到真正可用的新实例。

## 已确认范围
- 用户确认沿用 Inkeys2：同一安装目录限制，不同目录副本可以同时运行。
- 设置 → 通用 → 安全，在“教学安全选项”下新增“允许软件重复启动”开关，默认关闭。
- 用户已批准实施，task.py start 已将任务置为 in_progress；不启动产品 GUI，不提交或推送。

## 背景证据
- Inkeys2 本地 origin/inkeys2-final:智绘教/IdtMain.cpp:173–247 采用目录命名互斥体，仅 Release 启用，并豁免重启/恢复/超级置顶参数。
- 当前 Inkeys/IdtMain.cpp:1721–1795 仍保留 Release-only 门，已取消 Restart/CrashTry 豁免，但保留 WarnTry/SuperTopComplete 豁免；门位于更新和 SuperTop 处理之前。详见 research/startup-chain.md。

## 需求
R1. 默认不允许同一目录同时运行多个产品实例。并发启动也只能有一个最终实例；正常退出/崩溃不能留下永久占位。保持不同目录相互独立。
R2. 新开关保存到产品配置；缺键或非法值按 false。保存成功后用于后续启动，不强退已运行实例。开启时允许该目录多个独立实例；再次关闭后阻止新增实例，即使旧实例由“允许重复启动”模式启动。
R3. Debug 和 Release 的普通产品入口采用同一策略。合法无窗口测试/监督器入口继续按现有验真规则提前分流，不进入产品单实例门，不为调试保留无条件绕过。
R4. 普通重复启动保持已有实例，给出简洁提示并退出新进程，不终止已有进程，不执行更新替换或 UIAccess 提权副作用；沿用已有提示能力，不新增远程激活/IPC功能。
R5. 正常重启、更新后的启动、更新失败回滚、崩溃恢复和 SuperTop 三段式必须保持可用交接；不能因旧占位尚存就把合法新进程当重复启动退出，也不能仅凭命令行参数放行普通额外实例。
R6. 最终 UIAccess 实例也必须持有目录占位。提权取消、helper失败、握手超时等情况由既有实例降级继续，不能提前丢弃保护或让两个最终实例并行。
R7. 保持现有更新路径/哈希校验、精确旧进程 HANDLE 等待、退出监督截止、教学安全模式及失败回滚合同。不得用扫描进程名、杀死同名进程、固定 Sleep 或全局关闭防重复启动替代交接。

## 验收
A1/R1,R3：缺省配置下，Debug/Release 的普通同目录启动与并发启动只留下一个最终实例；不同目录可各运行一份。
A2/R2：默认关、true/false读写、缺键、非法类型以及三语言设置条目通过验证；位置紧随教学安全选项。开→关后，已存在的多实例不被强退，新增实例被拦截。
A3/R4：拒绝额外实例时，不修改更新文件、不提权、不影响现有实例；提示退出无无限等待。
A4/R5：正常/延迟退出重启、崩溃恢复都只有一次真实新实例；旧进程未退出时不得提前启动最终实例。
A5/R5,R7：待更新启动、installer换包、更新后启动、启动失败回滚分别有确定性测试；不能以 ShellExecute 成功等同于新实例完成单实例准入。
A6/R6：SuperTop关闭/成功三段式/已有UIAccess/用户取消/创建失败/超时降级，各自有明确最终占位者，不靠 SuperTopComplete 永久豁免。
A7/R1,R5,R6：伪造/过期交接、路径身份不符、句柄/父进程不符、占位创建失败及跨权限访问失败均有显式结果；父进程在交接失败时不会先退出造成软件消失。
A8/R7：原退出监督与更新校验回归、完整 solution Debug ARM64 构建、差异/编码检查通过；无真实GUI/UAC/Win7验证时明确标注覆盖边界。

## 不在范围内
跨目录全局单实例、激活已有窗口、配置/墨迹多实例合并、更新器重写、放宽校验与提权安全策略、GUI自动化、自动commit/push。
