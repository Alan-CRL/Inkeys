# 设置窗口半透明背景：统一为 WinUI 3 式单层材质

## Goal

设置窗口启用半透明背景（非 Solid）时，外观向 Win11 设置应用（WinUI 3 NavigationView + Mica）靠拢：标题栏、侧栏、正文区共用同一层半透明底色，只有卡片浮在其上；侧栏选中项是淡灰叠色而非亮白块；各区域之间没有接缝或色差。

## 现象与原因

- 半透明模式下根窗口不画底色，侧栏子窗口画半透明 `AppBase`，正文子窗口画半透明 `PageSurface`，标题栏单独画不透明 `appBase`。三块颜色不同；侧栏与正文的子窗口还带圆角，圆角外侧无填充，接缝处露出窗口背后（黑色缝隙）。
- 侧栏外层压入的 `ChildBg = AppBase` 一直沿用到内部嵌套子窗口（顶部、导航列表、"通用"子项、底部），每层叠一次半透明底色，"通用"展开后颜色明显更深。
- accent Acrylic 自带 `0xCC` tint，再叠 80% `AppBase` 后只剩约 4% 透出：Win11 实测静止时近纯色，只有拖动时切到忽略 tint 的 BlurBehind 才看得到效果。
- 导航选中/悬停使用不透明的 `subtleHover`（浅色 231 灰），在半透明材质上显得发白。

## Requirements

- 半透明模式下，根窗口铺一层半透明 `AppBase`，作为标题栏、侧栏、正文三者唯一的底色；标题栏不再单独铺不透明底色，正文不再铺 `PageSurface`，侧栏平铺时不再自铺底色。
- 侧栏只在外层 pane 决定一次底色，嵌套子窗口不再继承并重复铺色；pane 底色为直角。
- 窄窗口下侧栏展开并覆盖正文时，侧栏使用不透明主题底色，避免正文文字透出。
- 半透明模式下，悬停/按下/选中的 subtle fill 改为与 WinUI 一致的半透明叠色（浅色：黑 9/255 与 6/255；深色：白 15/255 与 10/255），选中项呈淡灰色。
- 静止与拖动/缩放统一使用普通模糊（BlurBehind），着色只由 `AppBase` 一层负责，交互前后颜色不变。
- 卡片、条目、首页横幅/功能块等原本不透明的块按 WinUI 3 透明度取值（卡片 CardBackgroundFillColor、描边 CardStrokeColor、带色块 70%）；控件沿用 ImFluent 预设的 WinUI ControlFill。
- 开屏动画保留原有不透明主题色遮罩；半透明下标题栏在开屏期间使用与遮罩相同的不透明颜色和淡出进度，不透出下面的帧。
- 弹出层、菜单、InfoBar 保持不透明以保证可读。
- Solid 模式的外观不变（侧栏 pane 去掉圆角除外，Solid 下仅在窄窗覆盖时可见）。
- 不改动 ImFluent vendor，不改变 DWM 背景材质或 swap chain。

## Acceptance Criteria

- [ ] 半透明模式下，标题栏、侧栏、正文底色一致，没有接缝、缝隙或圆角露底。
- [ ] 半透明模式下，"通用"展开后的子项区域与侧栏其他部分颜色一致。
- [ ] 半透明模式下，侧栏选中项为淡灰叠色，不是亮白块；悬停反馈仍可见。
- [ ] Win11 上窗口静止且激活时也能看到背后内容的模糊，拖动前后颜色不变。
- [ ] 卡片、条目、首页彩色块半透明，符合 WinUI 3 透明度。
- [ ] 开屏动画期间遮罩不透明，标题栏与遮罩同色同步淡出，看不到下面的帧。
- [ ] 窄窗口下侧栏覆盖正文时，正文内容不从侧栏透出。
- [ ] Solid 模式（含 Win10 以下系统、高对比度）外观与修复前一致。
- [ ] 完整 Solution `Debug | ARM64` 编译通过。

## Out of Scope

- 不处理系统 Mica / DWMSBT 材质（Explorer 等在本机同样不显示 Mica），设置窗口继续只用 accent。
- 不调整 `AppBase` 的透明度数值。
