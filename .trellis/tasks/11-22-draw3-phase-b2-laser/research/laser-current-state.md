## 一、合成路径

### 1.1 资源

激光不占用普通 L0/L1/L2，不进文档。它有四张与画布同尺寸的 RGBA8 纹理（4K 下每张约 33 MB）：

| 纹理 | 内容 | 何时创建 | 何时释放 |
| --- | --- | --- | --- |
| `laserStrokeCoverage` | 当前一笔的稳定段 coverage（四通道：芯、散射、边框、漫反射，MAX 混合）；多指回退时兼作逐笔工作区 | 选中激光工具（`DC:16625` → `R:592`） | 离开激光工具（`DC:18674` → `R:616`） |
| `laserLiveCoverage` | 单指增量路径的实时尾段 coverage | 同上（`RL:315`） | 同上 |
| `laserCompositedColor` | 已结束批次烘好的预乘颜色 | 同上 | 同上 |
| `laserBakeScratchColor_` | 烘焙的事务副本 | 第一次烘焙时按需创建（`R:493`） | 每次 `ClearAllLaserCoverage`（`R:474`），即每次从 Inactive 落笔、清屏、会话复位 |

选中激光时创建三张并各整屏清一次，再做一次零像素预热（`R:611–612`，`RL:431`）。

### 1.2 书写中的每一帧

两种批次模式（`IP:176` `SelectLaserCoverageMode`）：

- **Incremental（单指）**：`UpdateLaserIncrementalCoverage`（`DC:5504`）把新稳定的点追加画进 `laserStrokeCoverage`，用一次矩形绘制（类型 12）擦掉上一帧的尾段矩形，再把尾段与预测画进 `laserLiveCoverage`。上屏时一次绘制（类型 13）同时采样两张 coverage、取 MAX、解析材质（`DC:5689`）。帧脏区 = 旧尾段 ∪ 新尾段 ∪ 新增稳定段，是局部的。
- **FullRedraw（多指，或增量失败后）**：每帧对每支激光：擦掉“层范围 ∩ 帧脏区”、把**整笔全部点**重新上传并重画（带剪裁，`DC:5713–5726`）、解析上屏。逐帧上传量和顶点量随笔画长度增长。一旦进入本批次不再回到增量。

每帧上屏顺序（`DC:24034–24069`）：L2 与墨迹合成 → 粒子 → 已烘颜色（类型 11，乘整组不透明度）→ 活动层 → 笔尖圆点（类型 9）→ 光标。

已烘颜色的那次绘制范围是整个帧脏区，没有与 `laserStableBounds` 求交（`DC:24049–24051`）。

### 1.3 抬笔（整批最后一支抬起）

`ShouldBakeLaserBatch`（`IP:97`）成立时执行 `BakeLaserStrokeLayers`（`DC:5590`，调用点 `DC:23465`；同帧“抬起后立即落笔”在 `DC:18083`）：

1. `BeginLaserBake`（`R:477`）：副本纹理不存在则创建一张全尺寸纹理，然后**整图** `CopyResource`（已烘颜色 → 副本）。
2. 把本批解析进副本：单指走增量解析；多指逐笔擦除、整笔重画、解析。
3. `CommitLaserBake`：交换两张纹理。
4. `ClearLaserIncrementalCoverage`（`RL:341`）：`laserStrokeCoverage`、`laserLiveCoverage` 各**整屏**清一次。

所以每次抬笔至少 1 次整图拷贝 + 2 次整屏清。因为副本在每次从 Inactive 落笔时被释放，一个生命周期里的第一次抬笔还要现分配一张全尺寸纹理。

副本加交换的目的是事务性：多层烘焙中途失败时，已提交颜色保持不变，重试从同一状态起步（`R:501` 注释）。

### 1.4 留存与淡出

生命周期（`IP:112`、`IP:58`）：Active → 全部抬起后 Hold（默认 1 秒，可设，上限 24 小时，`DC:224`）→ Fade 0.8 秒（平滑阶梯）→ Inactive。Hold/Fade 中再落笔，整组恢复满亮并回到 Active。

- Hold：不透明度不变，无内容变化时不重绘。
- Fade：每帧把 `laserStableBounds ∪ laserLiveBounds` 并入帧脏区（`DC:22674–22680`、`DC:23908–23911`）。这块范围内每帧要重新合成 L2 与墨迹，再解析已烘颜色。
- `laserStableBounds` 是并集矩形，在整个生命周期内只增不减；直到 Inactive 后再落笔才归零（`DC:18074–18081`）。屏幕两角各画一笔，淡出期间就是整屏重合成 0.8 秒。

### 1.5 从 Inactive 落笔、清屏、离开工具

- 从 Inactive 落笔（`DC:18074`）：`ClearAllLaserCoverage` → 三张纹理各整屏清一次，并释放副本。此时三张纹理通常本来就是空的。
- 清屏、会话复位等其余六处 `ClearAllLaserCoverage`（`DC:15727、18659、19738、22125、22360、23063`）同样整屏清三张。
- 离开激光工具：结束全部激光触点、释放全部纹理、请求全帧重绘（`DC:18674–18708`）。

### 1.6 与阶段 B 的关系

- 阶段 B 之后激光抬起不再触碰 L0/L1（纯激光抬起的帧只刷新 L0）。阶段 B 开工时测的“纯激光抬起 8 次整屏清”里属于普通层的部分已去掉，剩下的是 1.3 的拷贝与两次清除。
- 阶段 B 已在初始化时探测 `ClearView` 是否可用，并有清除与合成计数的诊断入口，可直接用于本轮的基线测量。
- 激光烘焙的整图拷贝在阶段 A、阶段 B 的任务文档中都被列为“之后处理”。

### 1.7 现有自检

`--draw3-laser-resources-test`（资源随工具分配与退役、尺寸变化保留已烘像素）、`--draw3-laser-raster-failure-test`（两层烘焙失败后重试与参考逐字节相同、合成选择）、`--draw3-renderer-upload-test`（激光与墨迹交替上传）。抬笔帧主流程与真实上屏没有无窗口自检。

## 三、粒子

### 3.1 实现现状

- 固定 2048 槽的 GPU 粒子池（每槽 80 字节），两个 `cs_5_0` 计算着色器：Update 每个活跃帧扫描全部 2048 槽，Emit 按 CPU 指定的循环槽写入（`Draw3.LaserParticleSystem.cpp:191–333`）。
- 绘制：`DrawInstanced(6, 2048)`，死槽在顶点着色器早退；像素着色器类型 10，核心用激光边框色，外加辉光（`RL:388`）。绘制位置在墨迹合成之后、激光主体之前。
- 发射（`DC:23286–23340`）：只给未结束且已有切线的激光发射；真实输入速度决定数量（静止 6 个/秒，运动按 1.8 DIP 间距，上限 90 个/秒，每帧最多 120 个），预测只提供出生位置和切线。
- 脏区：不回读 GPU，按发射批次登记最坏包络和过期时刻（最多 512 条，`Draw3.LaserParticles.cppm:191`），并入帧脏区。
- 默认参数见 `Draw3.LaserParticles.cppm:23–55`（寿命 0.55–0.75 秒，半径 0.28–1.4 DIP，辉光半径 2 倍、透明度 0.18）。

### 3.2 为什么现在看不到

四处关闭（与阶段 B 调查一致，行号已随阶段 B 改动偏移）：

1. Controller 构造时强制 `false`（`DC:15333`）。
2. `SetLaserParticlesEnabled` 忽略参数，只会关（`DC:15508`）。
3. 设置页只有一行禁用说明，写回时固定传 `false`（`Setting.cpp:3975、4017、4055`）。
4. 无窗口生产测试断言“历史配置为 true 也无效”（`DC:12607–12616`）。

配置键 `Drawing.Laser.ParticlesEnabled`（默认 false）和 Host 的传递位（`Draw3.Host.cpp:1864`）都还在。

### 3.3 关闭状态下仍有的开销

初始化渲染器时仍创建两个计算着色器、粒子池、视图、常量缓冲并派发一次复位（`R:1001–1010`）；不可用只记一次警告，画布照常启动。激光预热里包含一次零像素的粒子绘制。

### 3.4 兼容面（未验证）

- 需要 D3D 功能级别 11_0 与计算着色器；Win7 WARP、兆芯、旧集显上的实际可用性与效果没有实机记录。
- 阶段 B 的离屏调查确认两个计算着色器在开发机可执行、粒子会过期；“设置 → Host → Controller”链路、实际合成像素、屏幕效果未验证。
